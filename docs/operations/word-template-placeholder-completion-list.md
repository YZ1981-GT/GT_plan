## 为什么需要你填这个

这些 Word 底稿模板里用 `××` 表示「这里要填内容」。程序读到 `××` 时，只能按**出现顺序**
给它编号：第一个叫 `placeholder_generic`、第二个叫 `placeholder_generic_2`、依此类推。

问题在于：**这个编号不稳定**。一旦有人在模板中间加一个 `××`，它后面所有 `××` 的编号
全部后移一位 —— 审计师之前填在「第 3 个空」的内容，会串到「第 4 个空」上去。已经归档的
底稿数据会指向错误的字段。

所以在线填写与双向回写**无法启用**：程序不敢把数据存进一个随时会改名的字段里。

**解决办法**：给每个 `××` 起一个**固定的名字**，把模板里的 `××` 改写成
`${名字}` 或 `${名字:显示标签}`。名字定了就永不改动，加减别的空也不影响它。

举例：

```
改前： 【前任会计师事务所名称】：××
改后： 【前任会计师事务所名称】：${predecessor_firm_name:前任会计师事务所名称}
```

**你要做的**：看每一行的「上下文原文」，判断那个 `××` 实际要填什么，
在「确认字段名」列填一个英文名（小写字母 + 下划线），在「业务含义」列写一句中文说明。
「建议字段名」列是程序按上下文关键词猜的，**仅供参考**，不对请直接改。

## 🔴 另一类问题：单个 `×` 的填写位**根本没被识别**

上面说的是「字段编号不稳定」。还有一类更硬的问题：

程序识别填写位的规则只认**两个连着的** `××`。模板里那些用**单个** `×` 表示的填写位，
程序完全看不见 —— 不是编号不稳，是压根没有这个字段。

实测：双 `××` 被识别为 **12** 个填写位；单个 `×` 未被识别的有 **12** 个。

全部集中在签署日期上：

```
【20××】年【×】月【×】日
     ↑↑        ↑     ↑
   被识别    看不见  看不见
```

后果：双向回写启用后，审计师能在线填年份，但**月和日永远填不了**、也存不下。

**你要做的**：这三处（年、月、日）一并改成规范形态，例如：

```
改前： 【20××】年【×】月【×】日
改后： ${sign_date:签署日期}
```

整个日期用**一个**日期字段即可（程序会按日期控件渲染），不必拆成年/月/日三个。

## 填写规范

- **字段名**：小写英文字母、数字、下划线；首字符必须是字母或下划线
  （程序的校验正则是 `[a-zA-Z_][a-zA-Z0-9_]*`）
- **同一份模板内字段名不得重复**；不同模板之间可以重复（各自独立命名空间）
- 同一个业务含义在多份模板里出现时，**建议用同一个名字**（如「前任会计师事务所名称」
  统一叫 `predecessor_firm_name`），便于日后跨底稿取数
- **字段名一旦定下不要再改** —— 改名等于换字段，历史填写数据会失联
- 「业务含义」写一句话即可，会作为在线填写时的输入提示展示给审计师
