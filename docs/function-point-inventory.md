# 审计作业平台功能点清单

> 用途：作为后续产品范围确认、开发工时评估、测试范围拆分和验收计划的基础。
>
> 盘点基线：当前工作区源码、前端路由与 CITAR 菜单、后端 router registry、核心 service、启动任务、事件总线、既有 spec 索引。
>
> 状态说明：
> - **已接入**：源码存在生产入口或实际业务调用。
> - **后台能力**：没有单独页面，但属于交付必需的后端、任务或数据能力。
> - **待核实**：源码有实现或路由，但需要浏览器、真实数据或业务人员确认最终行为。
> - **开发中**：路由或组件存在，但明确标记为 developing，或关键链路尚未接通。
> - **疑似冗余**：只有模型、迁移或测试痕迹，未发现生产调用。不能据此直接删除。
>
> ## 工时估算建议
>
> 每个 L3 功能点至少拆分为以下工作项，并分别估算前端、后端、数据、测试和联调工时：
>
> 1. 页面入口、列表、详情、表单和交互状态。
> 2. API、service、数据库读写、事务和幂等。
> 3. 登录、角色、项目成员、底稿范围和对象归属权限。
> 4. 导入校验、计算规则、自动同步、事件传播和缓存失效。
> 5. 异常提示、失败回滚、重试、并发冲突、审计留痕和数据清理。
> 6. 单元测试、接口测试、真实 PostgreSQL、浏览器和导出文件验收。
>

## 十六、范围确认与拆分规则

1. 页面上看不到的逻辑仍然单独计入工时。权限、数据校验、事件同步、后台 worker、缓存失效、并发控制、审计和失败回滚不能合并为“后端杂项”。
2. 同一底层能力只开发一次，但在引用它的所有业务点中列为联调和验收项。例如项目权限、年度上下文、公式求值、文件实体、事件总线、审计链。
3. 每个导入类功能至少拆为上传、识别、映射、预览、校验、暂存、激活、版本、回滚、重算、失败重试和审计。
4. 每个写入类功能至少拆为角色权限、项目归属、对象版本、并发冲突、事务回滚、幂等、审计和通知。
5. 每个计算类功能至少拆为输入来源、字段口径、空值/异常处理、公式顺序、结果存储、来源追踪和重算触发。
6. 每个导出类功能至少拆为数据准备、权限、版本、文件生成、格式核验、下载、失败清理和历史版本。
7. A~S 循环底稿不能只按“底稿页面数量”估算。应按循环、wp_code、册、sheet、子表、取数、手工录入、计算、复核、导出和双向回写继续展开。
8. 页面、路由或模型存在不代表功能已交付。估算时需标注“已接入、后台能力、待核实、开发中、疑似冗余”，并以真实调用和浏览器验收作为完成依据。
9. 当前清单没有替代产品需求确认。涉及业务口径、模板版本、真实数据、角色权限、数据清理和外部服务的项目，应在估算前单独列出确认项。
