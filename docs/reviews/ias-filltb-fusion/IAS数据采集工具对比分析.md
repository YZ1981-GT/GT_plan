# IAS 数据采集工具 vs 当前平台导入：对比分析

> 材料：`C:\Users\baiji\Desktop\智审平台\张总发的资料\IAS作业平台\数据采集工具\数据采集工具`（含子目录共 62 项）。
> 方法：只读。复制到仓库忽略目录 `tmp_ias_collector/` 后静态分析；**未运行**采集工具，未连任何数据库，未破解 `DumpModel.mdb` 的访问密码。
> 平台侧结论用合成样本调用平台纯函数实测（`identifier._match_header`、`converter.convert_balance_rows / convert_ledger_rows`），样本不是真实客户数据。

## 1. 结论

1. 这个“数据采集工具”是**用友审计数据采集工具的换壳版**（帮助文档版权“北京用友审计软件有限公司”，AUD 打包口令写死在宏里，回传地址 `eas4.youdatasum.com/cpasApi`）。它是**现场桌面工具**，负责把被审计单位财务系统的数据取出来打成 `.AUD` 包；会计口径转换在 IAS 服务端按“转换模板”完成。
2. 它和平台的分工不同：平台只接收 Excel/CSV 上传，**不直连客户数据库**。直连、备份还原、SAP RFC 这类能力不适合搬进 Web 平台，保留为现场工具更合适。
3. 真正值得融合的是它的 **Excel 采集模板规则**：四张标准表、字段依赖校验、主键唯一校验、单金额+方向、科目级次规则、文本保前导零。
4. 用它的样例格式测平台，**实测到 4 个会算错金额的问题**（见第 4 节），都应补进 A（导入兼容）。
5. 工具包里有密码破解、读取财务软件 SA 口令、数据恢复等组件，**不能引入平台**（见第 6 节）。

| 规则 | IAS 采集工具 | 当前平台 | 差异与建议 |
|---|---|---|---|

| 表头行 | 固定第 3 行；在 3~10 行找到同义词后回写第 3 行 | 自动探测表头行与合并表头 | 平台更强 |
| 列同义词 | 每表一组：如科目编号=科目编号/科目编码/科目号/科目代码/会计科目；凭证日期含“过账/过帐日期” | 全局别名 + 子串 + 编辑距离 | **平台把“会计科目”误认成会计期间、“科目号”认不出**（实测）。IAS 按表分组的精确同义词应进入 0 的目录再由 A 落地 |

## 4. 用 IAS 模板格式实测平台：4 个会算错的问题

样本取自 IAS 说明表的格式（合成数字），直接调用平台转换函数。

### 4.1 “借贷方向+期初金额借正贷负”被转成错误符号

IAS 余额表样例：`坏帐准备 | 借 | -3221.62`、`累计折旧 | 借 | -466243.97`、`应付账款 | 贷 | -924071.34`。这里“借/贷”是科目方向，金额符号已经是借正贷负。

平台实测结果：

| 科目 | IAS 含义 | 平台结果 |
|---|---|---|
| 1241 坏帐准备（方向“借”，-3221.62） | 贷方余额 3221.62 | `opening_balance=3221.62`、`opening_direction=debit` ⇒ 当成**借方** 3221.62 |
| 1602 累计折旧（方向“借”，-466243.97） | 贷方余额 466243.97 | 期初方向 debit、期末方向 credit，同一科目口径自相矛盾 |
| 2002 应付账款（方向“贷”，-924071.34） | 贷方余额 924071.34 | 方向 credit，结果正确 |

根因：`converter._resolve_direction` 把方向列当作“金额方向”，直接 `abs()` 后按方向定号，原始负号被丢掉。两种含义（科目方向 vs 金额方向）在平台里没有区分。
建议（归 A3）：方向列必须先确认含义；“科目方向+带符号金额”时保留原符号，只用方向列做校核；无法判断时要求人工确认。

### 4.2 “发生金额+发生额方向”的贷方分录被记成借方

样本：同一凭证 `1002 借 100`、`6001 贷 100`，两行都只有“发生金额”列和“发生额方向”列。

平台实测：两行都写进 `debit_amount=100`，`entry_direction` 分别是 debit/credit。**借方合计 200、贷方合计 0**，凭证不平。根因是“发生金额”被别名匹配成 `debit_amount`，转换器只标方向、不改金额栏位。
建议（归 A2/A3）：增加“单金额+方向”语义，按方向拆到借/贷两栏；拆分后逐凭证校验借贷平衡。

### 4.3 SAP 中文导出的带符号本币金额借贷抵消

SAP 序时账样例：`本币金额 -375317094.9（H）`、`375317094.9（S）`，按“借/贷标识”区分。

平台实测：“本币金额”被匹配为 `debit_amount`，“借/贷标识”**无法识别**；两行都进借方，一正一负，**借方合计 0**。“总帐科目”“过帐日期”也只能靠模糊匹配，“分录序号”认不出。
建议（归 A2 + 0 的 SAP 别名）：SAP 中文字段（总帐科目、过帐日期、凭证编号、本币金额、借/贷标识 S/H、反记帐）进入 0 的目录，再在现有 `adapters/sap.py` 里实现；带符号金额按标识拆借贷。

### 4.4 列名误判

| IAS 列名 | 平台识别 | 正确应为 |
|---|---|---|
| 会计科目 | accounting_period（会计期间） | 科目编码或科目名称（需按内容判断） |
| 科目号 | 未识别 | account_code |
| 余额 | opening_debit | 需结合表类型与表头组判定 |
| 金额 | debit_amount | 需结合方向列判定 |
| 借方余额 / 贷方余额 | opening_debit / opening_credit | IAS 把它当期初；但很多软件指期末，必须按期间语义确认 |
| 分录序号、借/贷标识 | 未识别 | entry_seq、direction |

这些都只有 70 分模糊置信度，平台当前阈值 50 就会自动采用，用户不一定看到确认提示。
另：SAP 10 位科目码 `1220100000` 被推断为第 4 级，平台没有地方录入“4-2-2”这类级次规则（归 A5）。

## 6. 风险与边界

- **安全**：`tools\` 下有 `offkey.exe`、`pk83.dll`、`Passware.reg`（Office 密码破解）、`FINALDATA.exe`（数据恢复）、`Sql2005BakClearPass.exe`（清 SQL 备份口令），主程序还含读取用友系统 SA 口令的函数（`U8_getSaPass`，读 `SOFTWARE\UfSoft\...\Login=SAPass`）。这些属于凭据获取类工具，**不得进入平台代码、镜像或交付物**；在客户现场使用也需要客户书面授权。
- **口令硬编码**：AUD 包的 rar 口令写死在宏里；`config.ini` 指向外部云地址并强制静默模式（`IsForceSilentMode=1`）。平台不应依赖或复用这个口令，也不应向外部地址回传数据。
- **许可**：材料版权属用友审计软件公司，转换模板、采集模板库与宏代码不复制；平台只按行为独立实现字段规则。
- **未核实**：`DumpModel.mdb` 有访问密码，本轮没有打开，各软件采集了哪些原始表、字段如何映射仍未知；需要的话应向提供方索取模板说明，而不是破解。直连路线 AUD 的转换规则在 IAS 服务端，本轮没有材料。
