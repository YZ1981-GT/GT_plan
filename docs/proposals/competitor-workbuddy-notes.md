# 竞品参考：WorkBuddy（小龙虾审计系列）

> 来源：小红书"面朝大海春暖花开"（书号 7029158246）| 记录日期：2026-06-21

## 产品定位

"一句话指令→连接 ERP→自动分析→生成报告"的审计数据分析 Agent。
面向不懂技术的审计师，对话式交互，单点效率工具（非全流程平台）。

## 核心架构

```
自然语言指令 → LLM 生成 SQL → 连 ERP 取数 → 规则检测 → Word/Excel 报告
```

## 6 个实战案例摘要

### 案例 1：国企进出口贸易专项审计
- 背景：年进出口额 5 亿美元，Oracle ERP，2 年数据 50 万+笔
- 四阶段：数据接入(1-2天)→异常检测(3-5天)→风险量化(2-3天)→大屏(2-3天)
- 最终产物：PowerBI 大屏 + Word 审计报告

### 案例 2：ERP 连接与数据提取
- 分批提取（按季度，每文件<10万行）
- 自动数据清洗（去重/填充/格式统一）
- 多表关联建模（订单↔报关↔物流↔收款）
- prompt 优化技巧：明确输出格式 / 先处理 100 行确认再全量

### 案例 3：数据质量检查
- 缺失值/重复值/异常值/格式统一
- 对应我们：smart_import_engine 的 validate_l1 + convert_balance_rows + scale_warnings 已全覆盖

### 案例 4：价格异常检测
- 建立价格基准（均值±2σ）→ 检测波动（±20% 预警/±50% 高风险）
- 供应商价格对比（同商品不同供应商差异倍数）
- 行业对标（海关数据）+ 成本加成分析
- 对应我们：可作为未来 auto_data_source resolver 的场景（从 tb_ledger 按科目统计价格基准）

### 案例 5：关联方识别
- 天眼查 API 批量工商查询 + 股权穿透（递归到自然人）
- 关键管理人员重叠分析（董监高比对）
- 交易特征异常（价格/期限/频率关联方 vs 非关联方）
- 对应我们：related_party_registry + A7 程序表已有结构，缺自动工商查询（需付费 API）

### 案例 6：合规检查自动化
- 报关合规（报关金额 vs 合同金额 ±5%/±10%）
- 外汇合规（收付款 vs 合同 ±5%/±10%）
- 税务合规（申报收入 vs 财务收入 ±3%/±5%）
- 对应我们：custom_query + data_quality_service 可实现，缺"一句话全链路编排"

## 与我们的差距分析

| 他有我们没有 | 优先级 | 说明 |
|-------------|--------|------|
| 一句话全链路 Agent 编排 | v3.0 | 把多个已有能力串起来的 workflow |
| 外部数据源连接（ERP/天眼查） | v3.0 | 需付费 API + 安全合规评估 |
| 价格异常统计分析 | 可近期加 | 作为 resolver 从 tb_ledger 计算 |
| 大屏可视化 | 低 | Metabase 已部署可覆盖 |

| 我们有他没有 | 说明 |
|-------------|------|
| 完整底稿体系（686 wp_code） | 他只出报告，不管底稿编制 |
| 审定表↔试算表联动 | 他不做账表核对 |
| 多层复核签字链 | 他没有 QC/复核流程 |
| 附注↔报表公式校验 | 他不涉及报表 |
| 离线 OCR + 规则引擎 | 他纯在线 |
| 跨底稿引用追溯（CCR） | 他没有底稿间联动 |

## 可借鉴方向

1. **程序表 AI 快捷按钮**：在 a-program-console 的关键步骤旁加 ✨ 按钮，点击自动从数据库统计+填入 summary
2. **关联方交易特征 resolver**：`related_party_pricing_analysis`——从 tb_ledger 比较关联方 vs 非关联方的均价/期限
3. **合规阈值检测 resolver**：`compliance_threshold_check`——配置阈值规则后自动标记异常
4. **用户引导/培训材料**：参考他的"6 个实战场景"/"10 件事别自己干"的量化表述方式
