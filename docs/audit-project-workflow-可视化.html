① 总则 · 角色与状态机

先看清楚「谁能做什么」「项目会停在哪些状态」，再进流程

六个角色 · 项目内权限

角色主要职责项目内权限

② 主流程 · 15 环节 5 阶段

阶段只是阅读分组，平台不锁定操作顺序（个别页面除外）

关键回路：⑧ 调整分录通过后 回写试算表调整列、⑨ 审定数 发布到试算表（唯一入口，二次确认）→ ⑪ 报表按审定数生成、⑫ 附注由底稿公式推送。

阶段 A · 建项与准备

①

建项

在哪操作项目 → 新建项目 /projects/new；或批量建项
谁做经理（需企业代码建项授权）
系统自动保存后项目进入「计划中」
完成标志项目卡片出现
要点 只填一步「基本信息」；批量建项走模板上传校验；复制上年继承科目映射、团队、审定数等配置；合伙人 / 管理员建项不受授权限制。
②

团队与分工

在哪操作项目详情 → 团队；人员档案
谁做经理
系统自动—
完成标志成员与签字合伙人已指定

阶段 B · 数据准备

③

导入账套

在哪操作/ledger-import
谁做审计员
系统自动识别文件、列映射、校验、入库四表；激活数据集
完成标志数据集「生效」，状态自动变「执行中」
④

科目映射

在哪操作导入后自动；必要时 /mapping 补全
谁做审计员
系统自动客户科目 → 标准科目自动匹配并重算试算表
完成标志完成率 ≥ 80%，试算表无漏科目
⑤

试算表

在哪操作/trial-balance
谁做审计员
系统自动按映射汇总未审数；调整变化后自动重算
完成标志借贷平衡、一致性校验通过
⚠ 账套年度必须和项目审计年度一致，否则查账、试算表都看不到数据。导入失败可重试 / 接管；导入历史里可回滚到上一个数据集。
试算表公式：未审数 + 审计调整（AJE）+ 重分类调整（RJE）= 审定数。客户自建的费用归集科目（如 6600「成本费用」）系统认不出，需人工指定映射。

阶段 C · 审计作业

⑥

程序裁剪 / 生成底稿

在哪操作/procedures → 生成
谁做经理
系统自动按循环与裁剪结果生成底稿清单
完成标志底稿列表生成
循环分组承接与计划（Q、B）· 控制测试（C）· 实质性程序（D～N、S）· 完成与报告（A）；裁剪掉的底稿进回收站可恢复
⑦

编制底稿

在哪操作/workpapers → 编辑
谁做审计员
系统自动取数、公式计算、跨底稿引用
完成标志底稿「编制完成」
编辑方式网页表单（默认）或在线编辑（OnlyOffice，双向同步）；证据附件就地上传预览
⑩

底稿复核

在哪操作底稿 → 提交复核；复核收件箱
谁做现场负责人 / 经理 / 合伙人
系统自动复核意见、退回修改
完成标志底稿「复核通过」
状态链编制中 → 编制完成 → 复核中 →（退回修改）→ 复核通过 → 归档
⑧

调整分录

在哪操作/adjustments
谁做审计员录入，经理复核
系统自动审批通过后进入试算表调整列，通知相关底稿负责人
完成标志无待复核分录
要点录入 → 提交复核（选复核人）→ 通过 / 驳回；可从 Excel 导入；草稿不进试算表
⑨

审定数发布

在哪操作审定表 → 发布到试算表
谁做审计员
系统自动二次确认后写入试算表审定数
完成标志审定数与审定表一致
⚠ 审定数只有一个入口写入试算表：审定表上的「发布到试算表」，需二次确认。任何其他途径都不会改动审定数。

归档

在哪操作/archive 归档向导

③ 合并项目

各子企业走单体流程，合并数 = 个别数汇总 + 差额

合并六步

合并项目流程
步骤说明
1 建项报表类型选「合并」；子企业项目填上级企业代码
2 企业树按企业代码自动构建，可拖拽调整上级
3 子企业各子企业按单体流程完成试算表、报表、附注
4 合并试算表合并数 = 各子企业个别数汇总 + 差额（调整、抵销分录，一般以负数填列）
5 抵销分录在差额节点录入；与抵销分录汇总表同源
6 合并报表 / 附注合并附注从子企业附注拉数，再按企业树「重新汇总」

另有智能体商店（外部链接）：访谈、OCR、审计、标书、人力助手。

附录 · 已知缺口与待确认

当前实现与预期的差距，需要产品侧决策

1. completion / reporting 状态无自动推进

这两个状态在代码里没有任何地方自动推进，项目会一直停在「执行中」直到归档。待决策：按条件自动推进（例如全部底稿复核通过 → 完成阶段），还是提供手动切换。

2. 「向导六步」已停用

项目向导里的科目导入、科目映射、重要性、团队分工几步已停用，旧文档里「向导六步」的说法已不适用，相关操作均移入项目内各页面。
