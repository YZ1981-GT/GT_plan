## A. 账号、角色与权限

**系统角色**：admin / partner / manager / auditor / qc / eqcr / readonly / site_lead。

**项目级别**（`backend/app/deps.py` `require_project_access`）：
- 三级：edit(3) > review(2) > readonly(1)，高级别包含低级别。
- 成员角色到级别的映射见 `assignment_service.ROLE_MAP`：合伙人、经理、审计员、助理为 edit；质控、EQCR 为 review。
- admin 跳过项目级校验。
- 部门负责人对本部门项目有 readonly。
- 项目已归档时，要求 review / edit 的请求返回 423（只读仍可访问）。

**登录与口令**：
- 连续 5 次密码错误锁定 30 分钟。
- 敏感操作前的密码确认令牌有效期 5 分钟。

**用户管理**：
- 不能删除自己，不能删除最后一个 admin。
- 停用用户后，access token 与 refresh token 均失效。

**部门**：
- 部门名称唯一；部门负责人必须是合伙人。
- 【缺口】部门相关端点只校验登录，不校验角色。

**建项授权**：
- 统一社会信用代码（USCC）校验 18 位 + 模 31 校验位。
- 经理建项需要该 USCC 的建项授权（admin 发放；admin / partner 不受限）。

## B. 项目生命周期

**状态流转**：

| 触发 | 状态 |
|------|------|
| 新建 | 初始状态【未核实】 |
| 建项向导确认 | planning |
| 账套数据集激活 | execution |
| 归档完成 | archived |
| 解除归档 | execution |

- 【缺口】没有代码自动把项目置为 completion / reporting，这两个状态目前只能手工设置或不使用。
- 删除项目为软删除，需要项目 edit 级别，删除过程持有拓扑锁（防止与合并树、批量建项并发冲突）。
- 合并项目通过企业树（三码）组织上下级。

---

## C. 数据导入（四表：余额表 / 序时账 / 辅助余额 / 辅助明细）

- 每次导入产生一个数据集，状态 staged → active → superseded；可见性按状态判断，不按 is_deleted。
- 激活前做完整性检查；同一年度激活新数据集时，旧的 active 自动变为 superseded。
- 激活数据集会把项目推进到 execution。
- 四表查询必须走 `get_active_filter`，不允许直接写 `is_deleted == False`。
- 列识别：按表头命中率分档，阈值为 50% 和 80%（各档的界面处理【未核实】）。
- 科目映射：模糊匹配阈值 0.7；自动映射率低于 80% 时在映射页标出提示。
- 数据集年度必须与项目审计年度一致，否则查账、试算表看不到数据（常见问题）。
- 审计年度取项目 `audit_period_end` 的年份；年度缺失时接口返回 422，前端显示「未设置审计年度」，不再用当年兜底。

## D. 试算表、调整分录、重要性

**试算表口径**：
- 审定数 = 未审数 + 重分类（RJE）+ 审计调整（AJE）+ 底稿调整。
- 只有状态为 approved 的调整分录计入试算表。
- 审定数写入试算表只能走发布门 `POST /api/workpapers/{wpId}/audit-determination/publish-to-tb`，必须带二次确认令牌；不允许在自动保存或页面加载时发布。

**调整分录录入**：
- 金额不能为负；同一行不能同时有借方和贷方。
- 借贷合计必须相等且大于 0。
- 手填编号最长 30 字符，同一年度内唯一；自动编号跳过已占用号码。

**调整分录状态**：draft → pending_review → approved / rejected。
- 金额达到或超过实际执行重要性的分录，必须由合伙人复核。
- 提交、通过、驳回、撤回都会发站内通知（不通知操作人自己）。
- 导入调整分录逐行校验并给出错误原因；覆盖模式跳过待复核的分录。

**重要性**：
- 实际执行重要性 = 整体重要性 × 比例。
- 未更正错报合计 ≥ 整体重要性时给出警告。

## E. 程序裁剪与底稿生成

- 模板是否保留，由离它最近的上级程序行的裁剪决定；没有决定的默认执行。
- 实质性程序循环 D~N 的母码跟随其下级。
- 读取裁剪数据失败时按「不生成」处理（fail-closed）。
- 科目判定使用映射后的标准科目，余额绝对值阈值 0.005。
- 裁剪掉的底稿移入回收站（`kind=trim`）；底稿已有内容时返回 409，要求用户确认。
- 生成计划逐项状态：trimmed（已裁）/ in_recycle（在回收站）/ existing（已存在）/ category_excluded（分类排除）/ to_create（待生成）。
- 生成分两阶段：先锁内预留，再锁外物化，最后锁内校验裁剪范围未变才落正式行；同一操作 id 重复提交返回原回执（幂等）。
- 生成过程中裁剪范围变化时，本次生成作废，不写正式行。

---

## F. 委派与可见范围

- 已裁剪或在回收站的程序行不能委派（409）。
- 跨循环委派必须填写理由。
- 可见范围（`services/wp_visibility/effective_scope.py` `resolve_member_scope`）：
  - 主管（负责人 / 经理 / 合伙人）与项目创建者看全部循环。
  - 其他成员只看被分配的循环；分配为空时什么都看不到。
  - 查询失败按受限空集处理（fail-closed）。
- 程序表（`program_row_guard`）：整表可见，但只能改分给自己的行；只有委派人能把行标为「不适用」。
- 删除项目成员时撤销其委派权限【未核实】。

---

## G. 底稿编辑

- 底稿状态与文件状态的合法流转定义在 `working_paper_service.update_status`（路由 `PUT /working-papers/{wp_id}/status`）。
- 复核通过（review_passed）或已归档后，底稿内容冻结，写入返回 423。
- 编辑锁：心跳 5 分钟；按窗口区分，同一用户多窗口互不冒充。
- 检查表保存使用版本号比较（CAS）：缺版本号 428，版本已过期 409。
- 切换到在线编辑前，必须等页面上所有未落库的写入完成；任一写入失败则不切换。
- 底稿保存发出 `WORKPAPER_SAVED` 事件，触发一致性检查与循环联动。

---

## H. 在线编辑（OnlyOffice）

- 每份底稿能否在线编辑，由 `entry_readiness.py` 的就绪原因表判定（契约未发布、身份脱钩、模板缺失等各有原因码）。
- 以下三条来自历史 spec 记录【未核实】：
  - 模板改动后契约身份会变，已发布底稿需要重新发布才能继续在线编辑。
  - 回到表单时以文件耐久保存为准，合并在后台进行，合并期间表单只读。
  - 公式格的值以公式证据判定：两侧公式一致且输入一致时采纳 OnlyOffice 重算值，否则记为受保护冲突。

---

## I. 公式与公式推送

**推送**：
- `TRIAL_BALANCE_UPDATED`、`WORKPAPER_SAVED` 触发公式推送，链路：试算表 → 底稿明细 / 审定表 / 披露表 → 附注。
- 合并项目不走单体推送；已冻结的底稿跳过。
- 取不到数时附注保留原值，不写 0；写入方取数一律 strict（缺数报原因，不用 0 代替）。

**分层与同步**：
- 有效公式 = 本项目 ?? 全局 ?? 系统预设。
- 同步分类：frozen / inherit / pinned / same / follow / conflict；冲突由用户逐项决定。
- 只有 admin 能写全局公式。
- 删除公式必须带版本号（缺 428，过期 409）。

---

## J. 报表与审计报告

- 报表共六类；资产减值准备表只对国企（SOE）口径生成。
- 生成报表前先重算试算表。
- 报表 xlsx 交付件不能回填到平台。
- 审计报告状态：draft → review → eqcr_approved → final；eqcr_approved 与 final 锁定，不能再改正文。
- 【缺口】`routers/audit_report.py` 只校验登录，没有项目级权限校验。

---

## K. 附注

- 附注编辑门禁（`note_edit_gate`）：需要本项目 review 及以上级别和 `note:edit` 能力；EQCR 只读；合并锁定期间返回 423。
- 附注数据的唯一权威源是底稿推送；交付中心只读，不允许从交付件回填附注。
- 导出附注前做一致性检查：有未同步或过期章节时返回 `requires_confirmation`，用户确认后才导出。

---

## L. 合并

- 合并数 = 各子企业个别数汇总 + 调整 + 抵销（差额表只记调整与抵销，一般为负数）。
- 合并范围只包含企业树中的子企业。
- 合并附注「重新汇总」（`services/consol_note_subtree_reaggregate.py` `reaggregate_subtree`）：
  - 按子树后序处理，每章一个保存点。
  - 叶子按明细映射拉数，未绑定的跳过；差额节点按公式填入；汇总节点 = 直接下级已保存数 + 差额。
  - 下级出错时上级本章不汇总；手工格、锁定格不动。
- 合并锁定（`consol_lock`）期间写入返回 423。

---

## M. 签发与质控

- 签发清单 6 项，任一项读取失败按阻断处理（fail-closed）。
- 签字就绪检查 11 类，归档就绪检查 12 类。
- 项目成员需提交独立性声明。
- EQCR 复核通过后才能进入最终签发。
- 门禁读不到 AI 待确认状态时阻断，不放行。

---

## N. 交付件与归档

**交付件**：
- 只有审计报告正文支持回填；对附注回填返回 400。
- OnlyOffice 回调状态 2、6 都落版本；同一内容哈希幂等；回调体的版本键不符时拒收并记安全日志。

**归档流程**：gate（门禁）→ package（打包）→ push_to_cloud（上传）→ lock（锁定，保留 10 年）→ purge_local（清本地）。
- 失败后从失败步骤重试；24 小时内同一请求幂等。
- 门禁由服务端现算，不信任前端带来的评估结果。
- 归档包按库内清单打包，manifest 逐项 sha256，缺件即失败。

**解除归档**：
- 仅 admin / partner；必须填写原因，并输入项目名称确认。
- 【缺口】前端要求输入密码，后端不校验密码。

**回收站**：
- 底稿不能从回收站彻底删除。
- 附件彻底删除前过 3 道守卫（见 O）。
- 【缺口】回收站容量限制未实现。

---

## O. 附件

- 上传校验文件类型与扩展名白名单，并做恶意文件扫描；单文件默认上限 50MB（其他入口另有上限）。
- 落盘路径必须在存储根目录内。
- 底稿内上传与 OCR 统一先建附件再识别；行级证据只写证据链接表。
- OCR 识别结果的确认与文件哈希绑定，文件变了需要重新确认。
- 删除守卫：项目已归档 423；处于法律保全 423；仍被底稿引用 409。

---

## P. 函证

- 函证类型 6 类。
- 回函状态为三态（具体取值【未核实】），前后端各有唯一的归一函数；字符串「否」不能当成已回函。
- 证据声明按工作簿族逐笔判定是否满足。
- 函证、附件、挂载记录都必须属于路径中的项目。

---

## Q. 知识库

- 访问级别：public / private / project_group，子文件夹继承上级。
- 只有 admin 能建或改公共文件夹。
- 批量上传时每个文件一个保存点，单个失败不影响其他文件，并返回中文失败原因。
- 扫描件由后台 OCR 补正文，上传请求内不做识别。

---

## R. AI 与模型路由

- 总开关 `WP_AI_SERVICE_ENABLED`，默认关闭；关闭时 AI 接口返回「AI 服务未启用」。
- 保存模型 Key 需要配置 `ENCRYPTION_KEY`。
- 模型端点必须是 HTTPS 或在允许清单内。
- 每个模型有信任域；任务注册表（`ai_task_registry`）规定每类任务允许的信任域，例如 `chat.general` 只允许 local_device / firm_private。信任域不符时返回 engine_unavailable。
- 路由：本机优先，失败改用下一个；冷却 30 秒；连续失败 3 次熔断。
- AI 产出先进待确认产物，人工确认后才写回；AI 不能产生业务上的「通过」结论。

---

## S. 工时

- 单条 0~24 小时，单日合计不超过 24 小时。
- 状态：draft → submitted → approved / rejected。
- 显示偏好按用户保存。

---

## T. 系统通用规则

- 业务数据软删除。
- 审计日志为哈希链，只追加，不删除。
- 健康检查 `/api/health`：
  - unhealthy：数据库或 Redis 不可用。
  - degraded：迁移失败、关键 schema 漂移、审计链分叉未确认、存在死信、热重载失败、审计日志写入失败。
- 数据库迁移在启动时由 MigrationRunner 执行 `backend/migrations/V*.sql`；版本号不能重复。
- 所有 2xx JSON 响应包装为 `{code, message, data}`。
