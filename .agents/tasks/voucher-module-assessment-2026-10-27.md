# 凭证模块评估：多对多分录回写底稿、预审/年审不重复（2026-10-27）

> 范围：序时账穿透与挂凭、抽凭引擎、底稿凭证检查表回填、序时账导入版本、调整分录跨阶段。只读评估，未改代码。
> 证据：代码现读 + 一次性扫描探针 + 真库只读 SQL（6 套真实序时账）。真库 `workpaper_extraction_log` / `sampled_vouchers` / `sampling_records` 均为 0 行，抽凭与挂凭没有使用记录可对账；凡涉及「使用之后会怎样」的结论都是按代码路径推出的。

## 一、结论

两条要求现在都不能保证。

- **多对多回写**：后端已允许一张凭证挂到多张底稿（V166），每张底稿按自己的科目前缀取分录，这个方向是对的。但凭证身份键、回填合并键、多借多贷金额三处有错，回写后会混入别的凭证、吞掉分录行、金额对不上。
- **预审/年审不重复**：78 个抽凭宿主没有一个能发出「预审」；年审排重依赖的分录行 id 在年审重导账套后全部失效；数据管理里的「增量追加」实际是整年替换。

## 二、链路与入口

| 环节 | 入口 | 落点 |
|---|---|---|
| 挂凭 | 序时账穿透 → 挂凭到底稿弹窗 | `POST /ledger/sample-voucher` → `sampled_vouchers`（`batch_id` 为空） |
| 挂凭回拉 | 60 个底稿的「从序时账挂入导入」 | `useAttachedVouchers.pullSamplesForWorkpaper` → 宿主回填函数 |
| 抽凭 | 78 个宿主内嵌 `GtVoucherSamplingEngine` | `voucher-extract` → `cutoff-fill` 写 `workpaper_extraction_log`，投影到 `sampled_vouchers` / `sampling_records` |
| 回填 | 各宿主 `use*VoucherCheck` 等回填函数 | `checklist_responses` 行 JSON |
| 账套 | 序时账导入 / 数据管理「增量追加」 | 每次导入新建 staged 数据集，激活后旧版本整体 superseded |

1. 凭证号单独定位不了凭证；(日期, 凭证号) 在带凭证字（FY/ZZ/AP/AR…）的账里也定位不了。例：四川物流 2025-01-07 的「0003」同时是 FY-0003（其他应收款个人往来 10 万借贷对转）和 ZZ-0003（借其他应收款 67,401.16 / 贷营业收入 61,835.93、销项税 5,565.23）。6 套账里唯一一致的键是 **(日期, 凭证字, 凭证号)**。`ledger_penetration_service.get_voucher_entries` 注释用「(date,no) 借贷 100% 平衡」证明唯一，这个推理不成立：两张平衡凭证并在一起也平衡。
2. 多科目凭证占三到四成，多借多贷 4%~28.5%，不是边缘情形；汇总凭证单张可达上万行。
3. 红字（负数）分录占 3%~19.5%。
4. 分录序号 `entry_seq` 在 5 套账里 100% 为空，分录行没有天然序号；年审重导后行 id 全部换新。

## 四、多对多回写的问题

**M1 凭证身份键错（P0）**
- 只按凭证号：抽样单位「整张凭证」按号聚合（`ledger_sampling_service._build_locate_projection` 与内存路径 `voucher_map`），医疗器械银行存款 8,592 张凭证被当成 692 个抽样单位，抽中一个号会带出全年同号凭证；项目级已抽排除 `project_level_extracted_voucher_nos`、跨底稿重复提示 `cross_workpaper_duplicate_vouchers`、引擎登记 `register_sampled_vouchers`（不写日期）、回填幂等键 `derive_idempotency_key`、宿主 merge 去重，都是同一口径。
- 按 (日期, 号) 但不含凭证字：凭证穿透 `get_voucher_entries`、对方科目补全 `enrich_counterpart_accounts`、挂凭去重、回拉分录 `fetchVoucherLines`。上面「0003」的例子里，把 ZZ-0003 挂到其他应收款底稿，回拉时会把 FY-0003 的两行也带进来；对 ZZ-0003 的收入行推断对方科目，会因混入 FY-0003 变成「多科目」。

**M2 多借多贷金额被错配（P0）**
- `expandMultiAccountVouchers` 把对方分录的金额写进样本行。例：四川物流 FY-0012（借管理费用 3,680、借应付职工薪酬 3,680 / 贷银行存款 2,000、贷银行存款 1,680、贷应付职工薪酬 3,680）。货币资金底稿抽中「贷银行 2,000」，展开成两行借方合计 7,360，是样本金额的 3.7 倍；按金额配对，这两笔付款（2,000 + 1,680 = 3,680）对应的是应付职工薪酬，不是管理费用。
- 对方科目推断（前端 `inferCounterpart`、后端 `enrich_counterpart_accounts`、展开函数）都按「金额 > 0」判借贷方向，红字分录被漏掉或判反。
- 只有 6 个回填实现按对方分录展开（D2、G5、G7、G9、G12、K1）；H1 等宿主自己内联拼接对方科目（与无调用方的 `joinMultiAccountNames` 同逻辑，重复实现）；其余只写「多科目」。展开不设上限，汇总凭证会一次灌入上千行。

**M3 回填合并吞行或重复（P0）**
- D2 把引擎的 append 映射成 replace（`fillMode === 'merge' ? 'merge' : 'replace'`），而年审阶段引擎强制 append，所以 D2 每次抽凭都清空整表，已填的核对结果和附件一起丢失。
- merge 按凭证号去重（D2 `mergeVoucherRows`、D3 `applyVoucherFillMode` 等）：同一凭证展开的多行只留第一行，别月同号凭证被吞掉。
- 「从序时账挂入导入」每次重拉该底稿全部挂凭；60 个支持该入口的底稿中 23 个显式按 append 回填，已抽查 D3、H1 不去重，点两次就重复一遍。
- 同一底稿里手工挂凭和引擎抽到同一张凭证会出两行，不提示：引擎排除和重复检测都只看引擎批次（`batch_id IS NOT NULL`）。
- 78 个宿主都没传 `existing-samples`，引擎的 merge 和 `before_data` 快照基于空前态；撤销抽凭只改日志与登记，引擎不通知宿主、宿主行不动，提示语却是「已撤销，底稿数据已恢复」。
- K3 关联方往来（`K3TabRelatedParty.vue`）的回填函数读 `payload.voucherNo`，而引擎和挂凭导入传的是 `{ samples, ... }`，抽凭回填与挂凭导入都是空操作。

**M4 一张凭证挂多张底稿（P1）**
- 后端去重键已含底稿（V166），但弹窗只能单选一张底稿，同一凭证要挂 E1、F3 得操作两次；序时账页面看不到「这张凭证已挂/已抽于哪些底稿」；批量挂凭单张失败被静默吞掉，只报成功数。`useAttachedVouchers.attachVoucher` 注释仍写「已挂则更新 working_paper_id」，已过期。

## 五、预审/年审不重复的问题

**Y1 阶段从未启用（P0）**
- 78 个宿主：67 个写死 `phase="final"`；D2/F1/F3/F4 用常量 computed 返回 'final'；D3 取 prop 默认值（父组件不传）；E1 银行流水的 ref 从不改；G5、K1、J1、M1、M2 把 phase 挪作「本期/期后」传 'current'/'post'（不是合法值，后端照收，历史抽屉把它显示成「年审」）。没有一个宿主能发出 'preliminary'，后端「年审排除预审已抽」的分支走不到。
- 引擎只有「仅预审/仅年审」视图筛选，没有阶段选择；`phase-changed` 声明了但从不 emit，也没有宿主监听。
- 底稿凭证检查行结构都不存 phase，挂凭回拉一律标 'final'，底稿上分不出哪些行是预审做的。

**Y2 年审排重键失效（P0）**
- 分录行单位按 `filled_unit_ids`（即 `tb_ledger.id`）排除。年审导入新账套后行 id 全部换新（真库 26 个被替换的旧版本里 16 个已清空行），预审抽过的分录能再次被抽中，加上年审强制 append，底稿出现重复行。
- 旧日志和「整张凭证」单位按凭证号排除，会把别月同号的凭证一起排掉：抽样框被缩小，总体金额少算，样本有选择偏差，而且界面上看不出来。
- 回填幂等键只由（底稿, 类型, 模式, 凭证号集合）派生，不含阶段和日期。

**Y3 「增量追加」实际是整年替换（P0，代码路径判定，需在【测试】项目实测一次确认）**
- 数据管理「增量追加（12 月）」→ 普通导入 → 新 staged 数据集激活 → 旧 active 整体 superseded；四表可见性只认 active 数据集（`get_active_filter`）；导入管线没有继承旧版本其他月份的逻辑；`ledger_import_v2.submit` 也没把 `incremental` 传给 `ImportOrchestrator.submit`。弹窗提示「系统将自动检测并只追加新月份」不成立：追加 12 月后 1~11 月不可见。现有测试 `test_incremental_apply.py` 只测月份差集纯函数。

**Y4 预审样本在年审账套中的存续没人核对（P1）**
- 客户在预审后修改、删除、重编号凭证很常见。底稿行是抽样当时的快照，年审重导后没有逐行比对（未变 / 金额变 / 已删 / 疑似重编号），只在抽样历史上标「账套已更新」。

**Y5 两阶段评价没有合并口径（P1）**
- 评价按批次落库。年审总体若是全年，推断错报要合并预审和年审样本；若年审只做剩余期间（如 10~12 月），总体描述要写明，并保留预审到年末的滚动程序记录。现在两种口径都没有。

**Y6 调整分录跨阶段重复（P1）**
- `adjustments` 没有阶段字段、没有「客户已入账」状态，也不关联客户凭证。预审提出的 AJE 若客户在年底前已入账，年审重导账套后未审数已包含这笔，AJE 再进试算表就是重复调整。

## 六、其他要注意的点（P2）

1. 期后凭证：截止测试、期后收款的日期窗口跨到次年时，查询带 `year` 过滤，只取到本年部分；真库没有一行跨年数据。需要定下次年账导入到哪个年度、跨年怎么查。
2. 导入质量闸门：辽宁卫生（项目 37814426 等三个同数据项目）82.9% 的分录借贷两栏填了同一金额，方向靠科目类别推断，回填到底稿的借贷金额会错。另外应检查整行重复、单张凭证不平衡、带凭证字的账缺凭证字。
3. 红字分录的方向按借贷栏判断，不按正负号。
4. 汇总凭证展开要按对方科目汇总并设上限。
5. 同一凭证在不同底稿结论冲突（一处「异常」一处「正常」）应提示。
6. 多主体账要把 `company_code` 纳入凭证键（现 6 套账都是单主体）。
7. 「本期/期后」区块要单独一个字段，不能占用 phase。

## 七、建议方案（分批）

| 批 | 内容 | 主要改动面 |
|---|---|---|
| A 凭证键 | 统一凭证键（年度, 主体, 日期, 凭证字, 凭证号）和分录指纹（凭证键 + 科目 + 借贷栏 + 金额 + 摘要 + 组内序号），后端一个 helper、前端一个工具函数；替换第四节 M1 列出的全部凭证号 / (日期, 号) 用法；挂凭表与登记表补凭证字（登记表补日期），回拉与穿透接口带凭证字 | 后端约 6 个服务/路由 + 1 个迁移；前端挂凭弹窗、回拉、引擎 |
| B 回写契约 | 一个共享回填函数，78 个宿主分批接入并配棘轮守卫：按分录指纹去重、保留已填核对结果与附件、不动其他阶段的行、挂凭导入幂等；多借多贷先按金额精确配对，配不上的标「多科目」并附完整分录，不编造金额；汇总凭证按对方科目汇总；撤销通知宿主真回滚。D2 的 replace 与 K3 的空操作先单独修 | 共享 composable + 宿主接线 + 平台守卫 |
| C 阶段 | 项目级「当前阶段 + 预审截止日」决定默认阶段，宿主不再写死；行内存阶段、批次、凭证键；排除改用分录指纹；年审重导后跑「预审样本存续核对」；评价支持两阶段合并或剩余期间两种口径 | 项目设置 + 引擎 + 宿主 + 抽样评价 |
| D 导入 | 增量追加修成真追加（新版本继承旧版本非重叠月份）或先下线入口；导入后出「与上一版本的凭证差异」报告 | 导入管线 + 数据管理弹窗 |
| E 调整分录 | 调整分录加阶段与「客户已入账」状态；年审重导后提示疑似已入账的预审 AJE，确认后不进试算表 | `adjustments` 迁移 + 调整分录页 + 试算表取数 |

验收要在【测试】项目上真实写入：预审抽凭并检查 → 导入全年账 → 年审抽凭 → 核对底稿无重复行、预审行只读、排除命中、存续核对结果正确；多借多贷凭证挂到两张底稿后各取各的分录，金额能与凭证对平。

## 八、需要拍板的事项

1. 多借多贷在底稿行上的口径：a 整张凭证全部分录逐行列出；b 按金额精确配对，配不上的标「多科目」并附完整分录（建议）；c 按比例分摊并标注「推算」。
2. 年审抽样总体：a 只抽剩余期间；b 全年扣除预审已检样本、两阶段合并评价（建议默认 b，允许选 a）。
3. 增量追加：先下线入口、只允许全年重导（建议，风险最小），还是本轮直接修成真追加。
4. 调整分录的「客户已入账」是否纳入本轮。
5. 是否按 A~E 立 spec 三件套后实施（建议 A、B、C 一个 spec 分阶段，D、E 各自独立）。

## 附：核对口径

- 宿主统计：扫描 `audit-platform/frontend/src` 下全部 `<GtVoucherSamplingEngine>` 标签（按引号外 `>` 截取，避免 `=>` 截断）与 `pullSamplesForWorkpaper(` 调用点；阶段取值逐个核对到变量定义。
- 序时账统计：只读 SQL，按 active 数据集、`year=2025`、`is_deleted=false`；「实际凭证数」= DISTINCT (voucher_date, voucher_type, voucher_no)；「同日同号混凭证字」= (voucher_date, voucher_no) 组内 DISTINCT voucher_type > 1 的组数；非 1 对 1 = 借方或贷方涉及 2 个以上不同科目。

## 九、拍板结果（2026-10-27 用户答复）

1. 多借多贷：按金额精确配对，配不上的标「多科目」并附整张凭证分录，不推算金额。
2. 年审抽样总体：弹窗让用户选 a 只抽剩余期间 / b 全年扣除预审已检样本、两阶段合并评价，默认 b。
3. 增量追加：直接修成真追加。
4. 调整分录「客户已入账」：本轮一起做。
5. 立 spec：凭证键、回写、阶段合成一个 spec 分阶段做；导入、调整分录各自单独立。
