## 评分规则与逐项得分不自洽，40/2.0 不能按文复算

**阻断，规则（2）部分 confirmed、第 25 项 likely。** 位置在 `report.md` §1.2 单项规则（1）（2）与第 1、6、10、18、25 项。

规则（2）写的是“live 采用为 0 **或**无登录态写入型 UAT，最高 2 分”。§0.1 自述“当前没有任何能力达到 L4（未做登录态写入型 UAT）”，§11.4 第 2、4 条确认未做登录态 Playwright、未调用任何写 API。按字面，这条规则会把 25 项全部封顶 2，可第 6 项（TB 主链恒等式）、第 10 项（Formula Push）都是 3 分。这两个 3 分在实质上说得通——前者是 live 数据验证的只读正确性，后者有真实用户触发的写入 run，强于 UAT——但规则文字没有表达这层意思，第三方按文复算会得到不同分数。

第 1 项更直接：依据栏写“六表存在；业务行全 0”，正好命中“live 采用为 0”，却计 3 分；第 18 项面对同一 live 事实（“live 六表为 0”）计 2 分。两项也许有“结构已部署”与“机制从未运行”的区别，报告没有写，按现有文字两项应同为 2。

第 25 项“生产形状与用户旅程门禁”计 2，依据引用 `[A] §七` 与 `[D] §4`，而这两节记录的恰是确定性假通过：`test_unified_lineage_service.py` patch 掉真实 `trace_upstream/downstream` 后全绿，生产 wrapper 却恒返回 `[]`（`[D] §2.3` 第 4~5 条、§4.2）；166+117 例绿测没有发现 Runtime 18/18 错值、报表 50/410 漂移和 trace 矛盾（`[A] §七`）；timeline 测试把“异常→空”当成功（`[C] §8.3 C3、§14`）。规则（1）明确包含“假通过”且“与 P 级无关”，报告 P3-3 也认定这些是假绿，因此该项应封顶 1；若作者认为门禁项只计生产形状门禁、不计 Mock 测试，需要在规则里写明，并说明依据栏的“代表测试”为何仍算正面证据。

## P1-4 中“错值以 ok 返回”的情形未按收窄后的 P0 ① 说明定级

**非阻断，likely。** 位置在 §6.1 P0 ①、§6.2 P0-2、§6.3 P1-4、§9.1 R2。

`[V]` P1-4 实测：`IF(1>0,1)` 返回 0 且 ok（条件为真也返回 0）；`MAX()`、`AUX('1122')`、带多余参数的 `NOTE(...)` 均返回 0 且 ok；`ROUND(1.005,2)=1.00`。收窄后的 P0 ① 是“产出或交付错误业务数值，含以成功/fresh 状态返回或展示”；同类的 L1 `1/0`、缺行返回 0 已归入 P0-2，R2 验收也写了“未知、除零、缺引用、少参非 ok”，P 级表却把参数个数和舍入留在 P1-4 且未给理由。
