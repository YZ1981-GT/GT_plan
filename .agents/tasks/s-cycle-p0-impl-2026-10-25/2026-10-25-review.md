# S-cycle P0: applicable_when chain, orphan wiring, and sidebar routing

This change implements the P0 slice of the S-cycle spec across 16 files: a new `match_workpapers` module with a 4th applicable_when path (OR across dict keys), `chain_orchestrator` biz_ flag construction, frontend trimming via `ipoProjectUtils.ts` and `GtWpRenderer` overlay, 12 orphaned s-checklist components wired through `wp_code_overrides.json` + registry, and S-segment routing in `resolveProcedureSheetKey.ts`. The refactoring of match logic out of chain_orchestrator into a dedicated module is a welcome structural improvement.

Watch for: The `isWpNotApplicable` computed in GtWpRenderer.vue is defined inside the `handleRedirectNavigation()` function body instead of at `<script setup>` top level — the template binding `v-else-if="isWpNotApplicable"` will fail at runtime (confirmed, blocking).

**Verdict**: CHANGES_REQUESTED

## High-level view

The backend applicable_when chain is correctly implemented: `match_workpapers` iterates all dict keys with OR semantics using `_KEY_FLAG_PREFIX`, and `chain_orchestrator` constructs the four `biz_` flags from `Project.business_category`. The `_WP_APPLICABLE_WHEN` loader with bundle parent aggregation is clean. The `wp_render_config` response injects `applicable_when` at the response construction point.

The frontend `ipoProjectUtils.ts` utility is correct and well-tested. `useAProgramData` correctly handles both string and dict `applicableWhen`. `useD4FormulaEngine.isIpoGroupVisible` delegates properly while preserving `fraud_risk`. However, the GtWpRenderer integration has a placement bug that blocks the overlay from rendering.

The s-checklist orphan wiring is thorough: Group A (7 overrides changed), Group B (5 per-sheet overrides added with openpyxl-verified tab names), 12 new types in `VALID_COMPONENT_TYPES`, `htmlRendererRegistry.ts` type union, `specialized.ts` entries, and `_ONLYOFFICE_HTML_WHITELIST`. S17-11/S17-21 correctly left as `a-program-console`.

The S-segment routing follows the established long-prefix-first pattern. S16/S11 fallback to e1a before S1, preventing startsWith mismatches. Test coverage is solid with 16 new cases covering all routing paths including edge cases.

In Vue `<script setup>`, only top-level bindings are auto-exposed to the template. A `const` inside a function is a local variable, invisible to `v-else-if="isWpNotApplicable"`. At runtime this will either be `undefined` (falsy, overlay never shows) or throw a reference error depending on the Vue compiler's handling. The fix is to move the entire computed block above `function handleRedirectNavigation()`.

The computed's logic itself is correct: it reads `renderConfig.value?.applicable_when`, extracts `business_category`, reads project context, and delegates to `isIpoProject`. The data source path (`renderConfig.project_context.business_category`) was confirmed by the FEAT-001 implementer.

## match_workpapers 4th path and chain_orchestrator flags

The new module cleanly separates matching logic. The 4th elif branch correctly uses OR semantics across dict keys via `_KEY_FLAG_PREFIX`. The `else: hit = False` after the for loop's else clause is correct Python (for/else fires when the loop completes without break). `chain_orchestrator` correctly adds `Project.business_category` to the SELECT, builds 4 biz_ flags with substring matching, and delegates both the TB_ACCOUNT_FLAGS table and match_workpapers call to the new module. The refactoring also fixes two stale account codes (`1631`→lease codes, `5401`→`6604`/`1704`).

## Render-config changes beyond the spec

The `wp_render_config.py` diff includes several changes beyond §1.3.2: an `ovr` variable hoisted out of the loop (fixing an `UnboundLocalError` on empty sheet lists), `_should_skip_historical_sheet` filter added to the HTML side (MC-24 fix), `audit_sheet_account_codes` helper replacing inline JSON loading, and `annotate_sheet_identity`/`annotate_sheet_identities` helpers at the bottom. These are unrelated to the S-cycle spec but appear to be concurrent improvements. They don't interfere with the spec's `applicable_when` injection, which is a clean single-line addition at the response dict construction.

## Registry and overrides completeness

All 12 new componentType strings are consistently added across four locations: `VALID_COMPONENT_TYPES` set, `_ONLYOFFICE_HTML_WHITELIST` set, `htmlRendererRegistry.ts` type union, and `specialized.ts` entry objects. The Group B per-sheet override keys use real tab names from openpyxl (e.g., `S1-S1-1对法律法规的考虑记录表`, `S8-审定表S8-1`). The `useSSpecialImportExport.ts` endpoints (`/api/s-special/{wp_id}/*`) were confirmed not implemented in the backend (per FEAT-002 findings) — this is a known gap for future work, not a regression.
