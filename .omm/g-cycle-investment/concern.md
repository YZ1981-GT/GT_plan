# 关注点 / 已知脆弱处（G 循环）

## 1. 🔴 科目编码与平台标准科目表不一致，且存在撞码

对照 `backend/data/standard_account_chart.json` 实证：

| 前端常量 | 值 | 标准科目表里该码是 | 标准表里正确码应为 |
|---|---|---|---|
| `G1_ACCOUNT_CODE` | `1501` | 持有至到期投资 | 交易性金融资产 = **1101** |
| `G4_ACCOUNT_CODE` | `1501` | 持有至到期投资 | 债权投资 = **1504** |
| `G4_IMPAIRMENT_ACCOUNT_CODE` | `1502` | 持有至到期投资减值准备 | 债权投资减值准备 = **1505** |
| `G6_ACCOUNT_CODE` | `1503` | 可供出售金融资产 | 其他债权投资 = **1506** |
| `G8_ACCOUNT_CODE` | `1503` | 可供出售金融资产 | 其他权益工具投资 = **1507** |

正确的：G2=1132 / G3=1131 / G5=1531 / G7=1511 / G9=1519 / G10=2101 / G11=6111 / G12=6103 / G13=6101 / G14=6702。

**风险**：
- **G1 与 G4 都用 1501**、**G6 与 G8 都用 1503** → 两个底稿对同一 TB 科目取数与回写会**互相覆盖**
- 用旧准则码（持有至到期/可供出售）取新准则账套的数会取不到或取错

**未核实**：这些码可能是刻意迁就客户账套的旧准则习惯（G9 注释就写了"历史项目可能仍用 1510/1504"），
也可能是历史遗留错误。改动会影响 TB 回写与报表取数 → **不擅自改，先与科目映射/报表口径核对**。

## 2. G4/G6/G7 拆分入口之间的回流

sppi / ecl / method / subsidiary 的结论都要回到 main 的审定表。
跨入口靠共享 `g{n}CrossHelpers.ts` / `g{n}StorageContract.ts` 的存储键，
**改键名必须四处（main / sppi / ecl / 或 method / subsidiary）同步核**，否则"算了但审定表看不到"。

## 3. 附注跳转的历史坑（勿回退）

- `G1_DISCLOSURE_SHEET_*` / `G10_DISCLOSURE_SHEET_*` 曾写 `附注上市` / `附注国企` ——
  那是 **OnlyOffice sheet-name 映射**，不是 `workpaper_sheet_classification` 的真实 tab 名
  （G1/G10 真实为 `附注披露信息（上市公司）` / `附注披露信息（国企）`，全角括号）→ 精确匹配失败会回退到底稿目录
- 禁用 `syncedSheet.includes('附注披露信息（上市公司）')` 判定底稿：**全循环披露 sheet 同名**，只能靠章节号精确谓词
- G1（五、2/五、3）与 G10（五、34/五、35）互不抢占，靠精确 `===` 区分

## 4. 附注取数曾被 union 兜底污染

`note_template_bindings` 生成器对无 `account_codes` 的分类行会退化成"该 section 全科目求和"，
G1 的 五、2 因此把每行都填成并集值（且 `wp_account_mapping` 把应收票据 1121 误映射到 五、2）。
修法：分类行显式 `account_codes: []`（手工，由 G1 披露同步而非 TB 伪造）。
→ 新增附注分类行时**不要留空 account_codes 让生成器兜底**。

## 5. G7 的历史缺陷（已修，勿回退）

- G7-17 存读键不一致（写 `G7-17-rows` 读旧 `G7-17-impairment-test`）
- G7-1 曾在 mount 时就回写 TB（应仅在保存且 `writebackTb:true` 时回写）
- G7-18 凭证检查曾是只读 htmlData，且 `el-table` 的 `fixed="right"` 在 `el-tabs border-card` 内导致表体右漂

## 6. G12 净敞口套期是低频 + 高专业度

CAS24 套期会计，多数客户不适用。适用性判断应能整包裁剪，不要留空表；
其处置结转对方科目是 `4104 利润分配—未分配利润`（与 M6 未分配利润枢纽相关）。

## 7. 变动率阈值不统一

多数科目 0.3（30%），**G11/G12 是 0.2**，G11 还有 `RETURN_RATE_CHANGE_THRESHOLD=0.05`。
写"变动超 30% 必填原因"的通用文案时要按科目取各自常量，不要硬编码。
