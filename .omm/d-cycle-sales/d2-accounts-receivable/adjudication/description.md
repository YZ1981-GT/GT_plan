# D2-1 审定表（嵌套元素）

D 循环审定表的参考实现。**双维度**：按性质分类 + 按账龄分类，**同一总额的两种视图**——两者恒等，绝不相加。

## 列模型

| 列 | 来源 |
|---|---|
| 期初未审 / 期末未审 | 明细表 SUMIF 聚合（或四表 seed，D2 不 seed） |
| 账项调整（AJE） | D2-3 调整分录按性质/账龄分组回写 |
| 重分类调整（RJE） | 同上 |
| 审定数 | = 未审 + AJE + RJE（computed，只读） |
| 试算平衡表数 / 差异数 | `trial_balance` 1122 的 `audited_amount ?? unadjusted_amount`，差异 > 阈值告警 |

## 三条勾稽

1. **审定表 ↔ 明细表**：分类合计 = 明细 SUMIF（`sumAgingBySegments` / 按信用风险组合）
2. **性质维度 ↔ 账龄维度**：两个区块合计必须相等（不等即录入错误）
3. **审定合计 ↔ TB**：差异 > 1 元 warning（不是错误，可能是明细未编完）

## 带入按钮

- 「从 D2-2 明细带入未审数」：按明细清单重建行，**同名行保留既有 AJE/RJE 与行 id**，空名全零行跳过
- 「从集中登记带入调整」：按科目 1122 拉集中 `adjustments` 净发生额，**逐笔弹窗选目标分类行**（`guessTargetRowKey` 智能猜默认），累加而非替换

## 下游

审定数变化 → `writeback`（D2 以核对为主）+ `eventBus.emit('substantive:adjudicated')`
→ 披露 tab `applyAutoFill` 自动按分类名取审定数 → 附注 `五、5` / `八、5`。

**披露表不直接取调整分录**，取的是审定数（审定数已含 AJE/RJE），所以"调整 → 审定 → 披露 → 附注"是一条链，不需要在披露层再带入调整。
