# 关注点 / 已知脆弱处（I 循环）

## 1. I6 与 K9 同码 6602

研发费用在会计上属管理费用（6602）下的明细，I6 与 K9 管理费用**共用 6602**：
两者都对 6602 取数/回写 → 若都做全额回写会互相覆盖。
I6 应只处理研发明细口径，K9 处理管理费用整体，二者的审定合计不能各自独立回写同一 TB 行。
（同类共码情况：K5 预计负债与 L5 长期应付款都用 2701、M6/M8 都用 4104。）

## 2. I2 资本化时点是主要审计风险

开发支出资本化五条件的判定几乎全靠人工判断 + 文档证据；平台能做的是
①五条件逐项判定留痕 ②截止测试防跨期 ③与 I6 费用化金额的分流合理性对比。
**不要臆造"自动判定资本化"**。

## 3. I2 / I6 截止测试历史缺陷（已修，勿回退）

- `useCycleCutoff.loadFromAutoSampling` 曾调**不存在的** `POST /ledger/cutoff-samples` → 恒 404；
  且 `i6Integration.spec` / `useI6Cutoff.spec` mock 该死 URL **把 bug 锁进测试**（修端点必须同步改断言）
- 现改调 `POST /sampling/cutoff-test`，并显式传 `cutoff_date`（否则后端按 `year-12-31` 推导，期中/短期审计会误判前后分段）
- 缺双侧证据（记账侧或原始凭证侧任一日期缺失）时结论必须是**"证据不完整"**，不能判"正常"

## 4. I2 曾有前后端保存路径 bug

`I2TabDisclosure` 等曾出现 `PUT /workpapers/.../checklist-responses` **缺 `/api` 前缀** → 404 静默不落库
（`http` 的 baseURL 是 `/`，不自动加 `/api`）。这是 I/H 族的高频坑。

## 5. I3 商誉减值的资产组认定容易空转

若资产组未认定或商誉未分摊到资产组，减值测试无对象。
平台应在无资产组时给出明确阻断/提示，而不是让 DCF 表算出一个无归属的数。

## 6. I5 是兜底科目，口径最容易乱

"其他非流动资产"内容随客户差异极大（预付设备款 / 长期待摊 / 待处理财产损溢…）。
内置 10 类 + 从 D7/M12/G2-13 带入是为了减少手打，但**带入后必须核对分类归属**，
否则会出现同一笔既在 I5 又在来源科目重复列报。

## 7. 摊销年限与税法差异

I1 摊销年限（含"使用寿命不确定的无形资产不摊销只减值"）与税法规定不同 → 税会差异进 N1/N3。
"购入摊销年限小于/大于税法规定的资产"是 N1/N3 附注的固定行项，需与 I1 数据对得上。
