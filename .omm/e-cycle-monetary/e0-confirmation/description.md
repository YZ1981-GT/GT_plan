# E0 银行函证（复用 D0）

E0 **没有独立实现**：银行函证走 D0 开发的 9 个 `confirmation-*` componentType（见 `.omm/d-cycle-sales/d0-confirmation/`）。

## E1 侧的消费点

- **回函回写**：`confirmation:received` → E1-3 银行存款明细按**开户行名规范化匹配**回写 `confirmAmount`
  （只对 bank 类型做名称匹配，避免误配其他类型；早期实现读 `payload.reply_amount/account_no` 这类 hub 载荷里不存在的字段，恒 no-op）
- **账户完整性**：函证回函是 E1-10 账户清单四路交叉验证之一（清单 / 征信 / 函证 / 账面）
- **覆盖率**：函证覆盖率的分母应是**科目审定总额**（1001+1002+1012），取不到时显示占位而不用行合计冒充

## 银行函证的特殊性

银行函证一函多项（余额 + 借款 + 担保 + 质押 + 授信），回函信息会同时影响 E1（货币资金）、
L1/L3（借款）、或有事项披露 —— 所以它天然是**跨循环**的，这也是把函证做成共享能力而非各循环自建的原因。
