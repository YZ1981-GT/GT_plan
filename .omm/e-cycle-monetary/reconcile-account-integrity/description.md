# 余额调节与账户完整性（E1-6 · E1-10 · E1-11）

这三张表共同解决**"账面是否等于银行"与"账户是否全"**两个认定：计价准确性 + 完整性。

## E1-6 银行存款余额调节表（`E1TabReconciliation`）

银行对账单余额 ± 未达账项（企业已收银行未收 / 银行已收企业未收 / 企业已付银行未付 / 银行已付企业未付）
= 调节后余额，应等于账面余额。
与 E1-3 银行明细做 `reconciliationCrossCheck`（调节后余额 vs 明细账面），差异出告警。

## E1-10 银行账户核对 / 账户清单（`E1TabAccountList`）

来源：企业提供的账户清单 + 征信报告 + 银行函证。
- 四表取数从 1002 叶子 seed（账面有的账户）
- **双向差集告警**：
  - `missingFromBankDetail` = 清单有 / 银行明细无
  - `missingFromAccountList` = 银行明细有 / 清单无
- `hasBookRecord === 'N'` 的行数 → 主入口全局告警"存在 N 个疑似账外账户（清单有/账面无），需关注完整性认定"
- 支持 OCR（`E1AccountListOcrConfirmDialog`）从清单/征信截图识别账号

## E1-11 账户完整性承诺书（`E1TabAccountCommitment`）

管理层声明"已披露全部银行账户"，OCR 确认弹窗 `E1CommitOcrConfirmDialog`。
它是完整性认定的**声明性证据**，不能替代 E1-10 的独立核对。

## 完整性认定的证据链

`E1-11 管理层声明` + `E1-18/19 征信报告（独立第三方）` + `E1-10 双向差集` + `E0 银行函证`
→ 四路交叉，任一路发现账面无记录的账户即为账外账户红旗（联动舞弊应对 E1-29 银行账户分析）。
