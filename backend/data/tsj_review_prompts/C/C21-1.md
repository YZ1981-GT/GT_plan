# C21-1 IT审计发现汇总表 复核提示词

## 概述

本提示词针对 IT 审计发现汇总表（C21-1）的复核，聚焦 IT 专家/IT 专业成员测试所发现的信息技术控制缺陷的完整汇总、缺陷性质与影响评价、缺陷分级、以及对系统信息可靠性和自动化控制信赖的传导影响（CAS1421、CAS1211）。C21-1 是 C21（IT 专家利用）和 C22（IT 一般控制测试）发现的收口底稿，任何 IT 缺陷若未在此完整汇总并评价影响，均会导致对系统的信赖失去依据。

**法规依据：**
- 《中国注册会计师审计准则第1421号——利用专家的工作》
- 《中国注册会计师审计准则第1211号——通过了解被审计单位及其环境识别和评估重大错报风险》
- 《中国注册会计师审计准则第1231号——针对评估的重大错报风险采取的应对措施》

---

## tips

1. **IT 发现汇总须完整不得选择性遗漏**：C21 和 C22 测试过程中识别的每一项 IT 控制缺陷都须汇总进 C21-1，遗漏任何缺陷都会使对自动化控制的信赖失真。
2. **缺陷须评价影响而非仅罗列**：每项 IT 发现须评价其对哪些系统、哪些自动化控制、哪些认定的影响，仅列缺陷清单而不评价影响属复核缺口。
3. **ITGC 缺陷会放大到应用控制**：一般控制（尤其访问安全、变更管理）失效会削弱对所有依赖该系统的自动化应用控制的信赖，缺陷影响须沿此传导链评价。
4. **IT 缺陷须按严重程度分级**：区分控制缺陷、值得关注的缺陷、重大缺陷，分级须结合缺陷对财务报表相关系统信息可靠性的影响程度。
5. **补偿性控制与人工控制须一并评估**：某项 ITGC 缺陷是否构成实质影响，须评估是否存在有效的补偿性控制或人工复核控制可缓释风险。
6. **发现须传导至实质性程序**：无法信赖的自动化控制或系统信息须转为扩大实质性程序，C21-1 的结论应明确对下游审计程序的调整要求。

## checklist

### 一、发现汇总完整性

- [ ] C21（IT 专家）和 C22（ITGC 测试）识别的缺陷是否全部汇总入表
- [ ] 每项发现是否记录了所属 ITGC 领域（访问安全/变更管理/运行/开发）
- [ ] 每项发现是否记录了受影响的系统/应用名称
- [ ] 是否遗漏了穿行测试或运行有效性测试中发现的例外

### 二、缺陷性质与影响评价

- [ ] 每项发现是否评价了缺陷性质（设计缺陷/运行缺陷）
- [ ] 是否评价了缺陷对相关自动化应用控制的影响
- [ ] 是否评价了缺陷对系统生成信息/报告可靠性的影响
- [ ] 是否识别了受影响的具体财务报表认定
- [ ] 是否评估了补偿性控制或人工控制能否缓释缺陷影响

### 三、缺陷分级

- [ ] 每项 IT 缺陷是否按控制缺陷/值得关注的缺陷/重大缺陷分级
- [ ] 分级是否结合了缺陷对财务信息可靠性的影响程度
- [ ] 多项缺陷的组合影响是否评估（单项轻微但组合后严重）
- [ ] 重大缺陷与值得关注的缺陷是否已沟通治理层与管理层

### 四、传导影响与结论

- [ ] 不可信赖的自动化控制是否已明确转为扩大实质性程序
- [ ] C21-1 结论是否已联动更新相关业务循环的控制测试策略
- [ ] IT 发现是否影响对系统生成的报表数据、账龄、计算类数据的信赖
- [ ] 是否评估了 IT 缺陷对整体审计意见的潜在影响

## risk_areas

### 高风险

1. **重大 IT 缺陷未汇总**：访问权限失控、变更未授权等重大 ITGC 缺陷未纳入 C21-1，却仍信赖自动化控制，掩盖了系统性错报风险。
2. **缺陷影响未沿传导链评价**：ITGC 缺陷对依赖系统的应用控制影响未评估，导致对下游自动化控制的信赖缺乏依据。
3. **缺陷分级过低**：将重大缺陷误评为一般控制缺陷，未相应扩大实质性程序，检查风险未被有效控制。
4. **不可信赖系统信息仍被采用**：系统生成的账龄、折旧计算、库存数量等信息因 ITGC 缺陷不可靠，却仍作为审计证据使用。

### 中风险

1. **补偿性控制评估缺失**：未评估人工复核等补偿性控制能否缓释 IT 缺陷影响，导致缺陷影响评价失真。
2. **组合影响未评估**：多项轻微缺陷组合后可能构成值得关注或重大缺陷，未做组合评估。
3. **结论未传导下游**：C21-1 结论未明确说明对实质性程序性质、时间、范围的具体调整。

### 低风险

1. **受影响系统标注不清**：发现未明确标注受影响的具体系统与应用，影响缺陷影响范围判断。
2. **底稿索引不完整**：C21-1 与 C21、C22 及相关业务循环控制底稿缺乏交叉索引。
3. **缺陷描述格式不统一**：缺陷描述、影响、分级的记录格式不规范，影响汇总分析。
