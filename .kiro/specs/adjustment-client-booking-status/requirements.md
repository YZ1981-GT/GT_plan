# 需求文档：调整分录阶段与「客户已入账」（adjustment-client-booking-status）

## 概述

问题来源：`.agents/tasks/voucher-module-assessment-2026-10-27.md` 第五节 Y6。用户 2026-10-27 拍板：调整分录的「客户已入账」状态本轮一起做。

预审提出的审计调整，客户常在年底前自己入账。年审重导账套后，未审数已经包含这笔调整；平台若仍把这张 AJE 计入试算表与底稿审定数，就是重复调整。现在 `adjustments` 没有阶段字段、没有「客户已入账」状态，也不关联客户的入账凭证。

目标：

- 每组调整分录记录提出阶段（预审 / 年审）；
- 审计师可以把 AJE 标为「客户已入账」并指明客户的入账凭证；只要当前账套已包含该入账凭证，这组 AJE 就不再进入任何计算，但仍列在调整分录清单里，作为已更正错报；
- 年审重导账套后，平台列出疑似已被客户入账的 AJE 供确认。

关联：

- 阶段取项目「当前审计阶段」（`voucher-identity-writeback-and-audit-phase` 需求 6）；该字段未落地前缺省为年审。
- 入账凭证用凭证键（`backend/app/services/voucher_identity.py`）记录与匹配；未落地则按该 spec design §2 先建。

铁律：

1. 计算口径只有一处：调整额取数的单一来源（`adjustment_amount_source.adj_net` / `adj_net_batch`）与试算表调整列重算（`trial_balance_service.recalc_adjustments`）共用同一个「是否已由客户入账」判定，守卫钉住三处同源。
2. 「已入账」只在当前账套包含入账凭证时生效；账套回滚到入账前的版本，这组 AJE 自动恢复计入。
3. 平台只给建议，不自动标记；标记与撤销都留痕。
4. 真库 PG 测试与【测试】项目浏览器实测验收。

术语：

- **入账凭证**：客户在其账套里记录这笔调整的凭证，用凭证键指明，可多张。
- **生效**：标记时所在账套版本不晚于当前 active 版本（按版本创建时间比较）。

## 需求 1：调整分录的提出阶段

1. 新建调整分录组时，阶段取项目当前审计阶段；同组各行一致；编辑权限可改阶段，改动写审计日志。
2. 列表、详情、导出显示阶段；列表可按阶段筛选。
3. 存量分录阶段为空，显示「未标」，可编辑补填。

## 需求 2：客户已入账标记

1. 只对审计调整（AJE）且已审批的分录组开放；重分类调整（RJE）不适用。
2. 标记时必须选择至少一张入账凭证：从当前 active 账套里按凭证键选，或从需求 4 的疑似建议中选；记录入账凭证、标记时的账套版本、标记人、时间、说明。
3. 撤销标记须填原因；标记与撤销追加记录、不覆盖历史，详情可看全部历史。
4. 编辑权限可标记与撤销；只读权限可查看。

## 需求 3：计算口径

1. 「已入账且生效」的 AJE 组不进入：试算表调整列、ADJ() 底稿呈现、交叉核对、报表、公式推送、审定表回写，即 F2 所列全部计算调用。
2. 判定只有一个实现，被 `adj_net`、`adj_net_batch`、`recalc_adjustments` 共用；守卫断言这三处调用同一判定，并断言没有第四处绕开它直接聚合 `adjustment_entries` 参与计算。
3. 列表、导出、错报沟通类展示照常列出这组 AJE，标「客户已入账（不再计入调整）」；调整分录汇总导出把它单列为「已由客户更正」。
4. 生效规则：标记时的账套版本创建时间 ≤ 当前 active 版本创建时间。无 active 版本、或回滚到更早版本 ⇒ 不生效，AJE 恢复计入。
5. 标记、撤销、账套激活、账套回滚后，试算表调整列与审定数重算，下游按现有链路标记过期。
6. 底稿本地数据不自动改写（F3：各底稿结构不同，自动扣减会改错数）。改为三道提示：标记或撤销后，涉及该组科目的底稿标过期，原因写明分录组编号与「客户已入账」；打开这些底稿时显示提示条，列出生效的已入账分录组，提醒从审定表、明细调整列与调整 tab 中移除；发布审定数时，若发布科目涉及生效的已入账分录组且请求未确认，返回 409 与分录组清单，用户确认「本底稿未再计入」后带确认重发，确认写审计日志。

## 需求 4：疑似已入账建议

1. 调整分录页打开时（及账套激活后首次打开），对已审批、未标记的 AJE 组，在当前 active 账套中查找入账凭证候选：同一张凭证内能为该组每一行找到科目对应（标准科目经项目科目映射到客户科目）、借贷栏相同、金额相等的不同分录。不按凭证日期过滤（年审调整常被客户倒记到 12 月 31 日），候选按凭证日期与分录组创建日期的接近程度排序。
2. 有候选的分录组显示提示条「检测到 N 组调整疑似已由客户入账」，逐组列出候选凭证（凭证键、日期、摘要、匹配的分录），由用户确认后才标记。
3. 只按金额与科目精确匹配，不做模糊匹配；同一组有多个候选时全部列出由用户选。

## 需求 5：界面

1. 调整分录页：阶段列、入账状态列与筛选；分录组操作「标记客户已入账」（选择入账凭证、并排显示调整分录与凭证分录）、「撤销标记」；提示条见需求 4.2。
2. 底稿调整 tab 的「集中登记」状态标签同时显示「客户已入账」（82 个 tab 的标签改用一个共享组件）。
3. 所有用户可见文字中文。

## 需求 6：验收

1. 真库 PG 测试（回滚事务内）：已审批 AJE 计入调整列 → 标记已入账（入账凭证在当前账套）→ 调整列与 ADJ() 取数都不再含它 → 回滚账套到入账前版本 → 自动恢复计入 → 撤销标记。
2. 疑似建议：在回滚事务内往 active 账套插入一张与 AJE 完全对应的凭证，建议能列出；改一分钱则不列出。
3. 每条守卫有磁盘变异证明。
4. 【测试】项目浏览器实测：建 AJE → 审批 → 重导含入账凭证的账套 → 提示条 → 确认标记 → 试算表调整列不再含该组、涉及底稿出现过期与提示条、发布审定数出现确认框 → 撤销；清理走平台路径并对账。
