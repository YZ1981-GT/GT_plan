# 凭证模块联动、流程与溯源收口 — 需求

## 背景

2026-11-02 凭证模块评估（序时账挂凭、抽凭引擎、客户入账、凭证证据、溯源）给出 P0~P2 建议，用户要求「按建议逐一修复」。
前序 spec `voucher-runtime-integrity-and-visibility-closure`（13/17，代码在工作区、未入库）由本 spec 承接收尾，
其改动与本 spec 同一次提交（R1.5）。

范围按优先级：

- P0：挂凭写入的底稿级门禁；外围端点鉴权与伪实现退役；迁移未执行时明确报错。
- P1：序时账 ↔ 底稿流程；抽凭引擎只读与重复提交；抽样增强页；客户入账的凭证选择与建议条。
- P2：他稿结论提示；异常样本处置；试算表行溯源与附注溯源去伪。

不做的事见 design §13。

## 术语

- 挂凭：序时账里手工把凭证挂到底稿，记在 `sampled_vouchers` 手工侧（`batch_id` 为空）。
- 凭证键：`VoucherKey` 规范串 `["年度","主体","日期","凭证字","号"]`。
- 行身份 `_gt`：凭证检查行上的元数据（`vk` 凭证键、`lfp` 分录指纹、`src` 来源等），由 `voucherCheckFill` 写入。
- 底稿写权限：与「保存凭证检查表」同一授权矩阵动作（`workpaper.checklist_save` / `save_checklist`）。

## R1 挂凭写入的底稿级门禁（P0）

用户故事：作为项目主管，我希望只有能编辑某张底稿的人才能往它挂凭或取消挂凭，别人改不动我底稿的抽样清单。

1. 单笔挂凭 `POST …/ledger/sample-voucher` 必须指定目标底稿；未指定返回 422 `WP_REQUIRED`。
2. 单笔与批量挂凭对每张目标底稿判定底稿写权限；无权时单笔返回 403 `WP_NOT_WRITABLE`，批量逐条 `failed` +
   `WP_NOT_WRITABLE`，该条不返回底稿编码与名称。
3. 取消挂凭对记录所属底稿判定写权限，无权返回 403 `WP_NOT_WRITABLE`；没有底稿的旧记录只校项目级编辑权限。
4. 按底稿取挂凭清单（`GET …/sampled-vouchers?working_paper_id=`）判定该底稿的读权限，无权返回 404。
5. 承接前序 spec：归属校验（`WP_NOT_IN_PROJECT` / `SAMPLING_RECORD_NOT_IN_PROJECT`）、项目级清单与已挂查询按底稿
   可见性过滤、四个投影函数的保存点、D2 合并按「凭证号 + 日期」去重，行为不变；旧身份治理脚本在共享库干跑
   （只读）的分类结果与真实数据一致。

## R2 迁移未执行时明确报错（P0）

用户故事：作为审计员，服务器的数据库结构落后于程序时，我希望看到「数据库未升级」的说明，而不是「服务器内部错误」。

1. 未捕获的异常是「表或列不存在」（PG 42P01 / 42703），且磁盘上有未执行的迁移时，返回 503 `MIGRATION_PENDING`，
   消息写明库里最高版本、程序最高版本与未执行个数。
2. 没有未执行的迁移时照旧返回 500，真实代码缺陷不被说成迁移问题。
3. 判定过程本身读库失败时照旧返回 500。
4. 未执行迁移的判定结果最多缓存 60 秒。
5. 调整分录页的客户入账建议遇 503 时显示后端给出的说明，不显示笼统的「读取失败」。

## R3 序时账 ↔ 底稿流程（P1）

用户故事：作为审计员，我在序时账挂了凭证之后，希望一步到达目标底稿并知道哪些凭证还没导入检查表；看完底稿能回到原来查账的位置。

1. 序时账凭证层移除「抽中本凭证」按钮（它登记的凭证不属于任何底稿，没有后续落点）；挂凭只经「挂凭到底稿」。
2. 「挂凭到底稿」提交后，弹窗显示结果：逐张底稿列出新挂、已挂、失败条数和失败原因；有成功条目的底稿给「打开底稿」，
   打开的地址带返回地址与「来自挂凭」标记。
3. 凭证层「已挂底稿」标签可点击打开对应底稿（底稿已删除或未指定底稿的不可点）；已挂查询失败时显示
   「挂接状态未知」和「重试」，不显示「尚未挂到底稿」。
4. 已挂标签对手工挂凭附带导入状态：「已导入」或「未导入」；判定不了时不显示。
5. 底稿编辑页带返回地址打开时显示「返回序时账」按钮；返回地址只接受本站以 `/projects/` 开头的路径。
6. 打开底稿时，如果有手工挂到本底稿、但凭证检查表里按凭证身份找不到的凭证，底稿顶部显示待导入提示：张数、
   前 5 张凭证的称呼（可点开序时账里的这张凭证）与操作说明；从挂凭结果打开时提示默认展开；可在本次会话内关闭。
7. 提供按凭证键生成序时账凭证层地址的统一函数，供凭证检查行、待导入提示、抽样增强页共用。

## R4 抽凭引擎与抽样增强页（P1）

1. 抽凭引擎的只读判定同时看宿主传入的只读与底稿运行时上下文的只读（归档、编辑锁、复核身份、后台合并）；
   只读时不能确认回填、撤销批次或编辑样本行。
2. 「确认回填」进行中再次点击不重复提交，按钮显示进行中。
3. 抽样预览弹窗随引擎只读；样本超过 100 行时分页显示。
4. 抽样增强页的年度取项目审计年度（没填时提示去填，不按日历年兜底），账龄基准日默认为审计期末；年度上限不写死。
5. 抽样增强页的凭证总览只在切到该页签时加载；加载失败显示原因和「重试」；行上可打开所在底稿、可打开序时账里的这张凭证。

## R5 客户入账（P1）

1. 没有自动匹配候选时，用凭证选择器标记客户入账：输入凭证号（可加日期），在当前账套中定位；命中多张时列出候选供选择；
   显示选中凭证的分录；不再要求粘贴凭证键。
2. 建议条只对有编辑权限的用户显示操作按钮；列出全部建议（不只第一条），每条都能单独确认。
3. 确认建议时，分录不在当前页也能打开。
4. 标记弹窗说明对试算表的影响，内容与后端实际行为一致：当前账套中找到全部所选凭证时，本组 AJE 不再计入试算表调整；
   账套重导后找不到这些凭证，本组 AJE 自动恢复计入。

## R6 他稿结论提示（P2）

1. 凭证检查行的「来源」列：同一凭证在其他可见底稿也有检查行时显示「他稿 n」；其中有判为异常的显示「他稿异常」。
   点开列出底稿编码、结论（异常 / 正常 / 未判定），可打开该底稿。
2. 结论只读白名单字段，按固定取值表判定；不在表内的一律算「未判定」。只做提示，不阻断保存。
3. 只列当前用户可见的底稿；查询失败显示「他稿结论加载失败」，不显示成「无」。
4. 单次最多查 500 个凭证键；按「项目 + 年度」合批，结果缓存 60 秒。

## R7 异常样本处置（P2）

1. 本行判为异常且底稿可写时，「来源」列给「处置」入口，含「记入未更正错报」与「去调整分录」。
2. 「记入未更正错报」由用户填写错报金额（大于 0，默认留空）与错报类型（事实、判断、推断，默认事实），经既有 A13
   错报桥写入；描述包含凭证称呼与日期。同一分录以相同金额、相同类型重复记入时只落一笔。
3. 「去调整分录」打开本项目的调整分录页。

## R8 溯源（P2）

1. 试算表行的「数据溯源」返回上游：本科目审定数的构成（未审、调整、重分类、审定）、已批准且影响本科目的调整分录
   （有来源底稿时可定位）、向本科目发布审定数的底稿、本科目在各底稿的抽凭与挂凭张数。
2. 附注章节溯源按年度和章节对应科目取试算表行（不再取任意 5 行）；序时账明细按年度和科目取金额最大的前 10 笔，
   并注明取数口径；查询失败如实报告，不用空结果冒充无数据。
3. 统一溯源中试算表行子源失败时只标记 partial，不影响附件子源。

## R9 外围端点（P0）

1. 附注溯源的两个端点（章节溯源、发现汇总）要求项目只读权限。
2. 底稿 AI 序时账分析端点要求项目只读权限。
3. 底稿单据识别端点退役：调用返回 410 并指明替代入口（底稿证据上传、附件识别）；不读附件、不调模型；
   删除没有挂载的识别对话框。

## R10 验证（贯穿）

1. 新增或改动的后端端点都有 TestClient 端点级用例，包含无权用户。
2. 每个修复点至少有一个磁盘变异能让对应测试打红，变异后逐字节还原。
3. 浏览器实测在隔离的临时库和独立端口上完成，console error 为 0；共享库只读。
4. 全量 vue-tsc 相对 HEAD 不新增错误；改动文件过行数门。
