# 需求：批量建项与合并企业树导入收口

## 背景与现状（2026-10-29 现读 / 浏览器只读实测）

平台项目页、左侧项目栏和合并大厅共用 `BatchImportDialog` 与 `/api/projects/batch-*`。现有链路能下载模板、上传预校验、创建项目、补合并根并按三码构树，但存在以下边界：

- 标准模板的 4 行合法示例原样上传会通过校验并可创建脏项目。
- 预校验不读数据库，按企业代码而非 `(企业代码, 年度, 报表口径)` 判重复；循环和树构建失败不阻断。
- 正式导入再次上传、再次解析，并逐行重复查唯一性；500 行至少产生两轮逐行唯一性查询。
- 行内数据库异常执行全事务 rollback，却保留此前成功计数，回执可能与实际落库不一致。
- 自动合并根按控制方代码而非 `(控制方代码, 年度)` 记忆，多年度批次可能漏根。
- 批量端点只校验登录；任意项目 ID 的导出没有项目级可读校验；非全局可见角色创建后可能看不到项目。
- `/batch-export` 无前端入口；导出已有项目再回导仍是 create-only，不能维护现有集团关系。
- 四行预览在 1710×827 视口已使弹窗高约 988px，确认按钮落到首屏外；大树默认全展开。

## 实施裁决

1. 保留一套解析、规划、创建和构树内核；平台与合并入口只通过 `mode=project|consolidation` 改变模板说明、导出入口和预览重点。
2. 500 行内保持同步请求，不引入新任务队列；采用“上传一次生成持久计划，确认时按计划执行”的两阶段流程。
3. 预校验必须合并数据库现状并展示最终树。计划有效期内，确认请求不再接收文件；请求摘要、操作者和计划归属必须匹配。
4. 正式执行默认整批原子：全部计划动作成功才提交。数据库并发冲突返回稳定错误和零成功，不保留半棵树。
5. 新模板只创建项目；现有树导出模板允许 `新建 / 更新集团关系 / 跳过`。更新只覆盖三码关系字段，不批量改名称、年度、准则或项目状态。
6. 更新已有项目必须逐项目 edit 鉴权、锁行并校验集团字段基线摘要；同企业同年度的单户/合并两口径继续由现有集团关系服务同步。
7. 项目创建仅允许 admin/partner/manager；导出按项目 readonly 权限；新项目把 manager 创建者挂为项目经理和 edit 成员，复用已有根不得覆盖原团队。
8. 不新增 npm/Python 依赖；迁移号实施时动态取，V/R 配对。

## R1 模板与上传边界

1.1 “数据”sheet 不含可导入示例；示例移入独立“填写示例”sheet。

1.2 项目类型、会计准则、报表类型、与上级关系均有 Excel 下拉；冻结并保护表头，必填列有说明。

1.3 模板含可验证版本；导入严格校验“数据”sheet 和必需表头，旧 9/10 列模板继续兼容但给升级提示。

1.4 年度只接受 4 位整数，拒绝小数静默截断；上传只接受 XLSX，先限制压缩包字节数、sheet 行列规模，再解析。

1.5 同步 openpyxl 解析移出事件循环；错误响应只给中文业务原因，不返回 SQL、绝对路径或异常堆栈。

## R2 数据库感知预校验与持久计划

2.1 批内重复键与数据库唯一键一致，允许同企业、同年度的单户和合并项目同时存在。

2.2 预校验一次性预取已有项目、上级企业和控制方；每行分类为 `create/update/unchanged/skip/error`。

2.3 树预览由“库存项目 + 本次计划覆盖层”构造；循环、重复冲突、找不到更新目标和树构建失败均阻断。

2.4 持久计划记录操作者、mode、文件 SHA-256、规范行、基线集团字段摘要、预览、汇总、状态、过期时间、最终回执与时间戳。

2.5 同一操作者、同一幂等键、同一请求摘要返回原计划/回执；同键不同摘要返回 409。其他用户不能查看或执行该计划。

2.6 计划只能从 validated 进入 applying，再进入 applied/failed/expired；terminal 不重开。确认时过期、权限变化或基线变化均拒绝且零业务写。

## R3 原子执行、成员与树

3.1 创建动作复用单项目建项校验和集团字段规范化，但消除重复唯一性查询；数据库唯一索引仍是最终防线。

3.2 全批次同一事务执行创建、关系更新、自动根、创建者成员、派生链接和最终回执。失败时 success_count=0，数据库零部分业务写。

3.3 自动根按 `(ultimate_code, audit_year)` 唯一处理；名称、准则和项目类型优先继承该组显式根或批次默认，不再静默固定错误口径。

3.4 manager 创建的新项目写 `manager_id`，并经团队委派服务形成 `ProjectAssignment(manager)` 与 `ProjectUser(manager/edit)`；admin/partner 不强制生成虚假经理委派。

3.5 执行结果分别返回创建、更新、未变化、跳过、自动根和失败数量，以及每个受影响项目 ID；自动根不能藏在成功数之外。

## R4 安全导出与集团关系回导

4.1 保留选中项目导出，但必须验证全部 ID 存在、未删除且当前用户可读；混入一个无权 ID 时整体 403，不静默少导。

4.2 新增按合并根导出当前企业树的端点；服务端自行计算树内项目，不能信任客户端提交的后代 ID。

4.3 导出行附项目 ID、动作和集团字段基线摘要。用户可新增行或把已有行标为“更新集团关系/跳过”。

4.4 更新动作只调用集团关系单一入口，校验 USCC、自引用、跨年、循环和 counterpart；整批只在末尾按受影响年度各重算一次链接。

4.5 关系更新写项目 ORM 与 wizard_state，并留下操作者、旧值、新值和同步项目的审计记录。

## R5 前端体验

5.1 弹窗使用步骤式布局；主体最大 80vh 独立滚动，操作栏固定可见；窄屏可用。

5.2 合并模式提供“下载新建模板”和“导出当前集团树”；普通模式不展示误导性的集团维护入口。

5.3 预览顶部显示新增、更新、未变化、跳过、自动根和阻断数量；树默认展开两级，只突出异常和改动节点。

5.4 校验成功后使用 validation_id 确认，不二次上传；网络错误可按计划 ID查询原结果，重复点击不会重复建项。

5.5 部分或整体失败时保留文件和校验结果；支持下载带行号与原因的错误 Excel。成功后刷新扁平列表与树，并可直接进入新建合并根。

5.6 前端展示后端真实中文错误；不会把 403、413、409 和模板版本错误统一替换成“文件格式错误”。

## 非功能与验收

- 500 行目标：本机 PG 预校验 ≤2 秒、确认提交 ≤5 秒；若实测未达标，报告真实瓶颈，不以放宽门槛收尾。
- 后端覆盖 service、真实路由鉴权、事务故障、幂等、CAS、多年度和 PG 唯一冲突；前端覆盖两种 mode、步骤流、错误恢复和固定操作栏。
- 浏览器仅在名称含【测试】的项目执行写入；原样模板只能得到 0 行而不能创建示例项目；验收后经平台路径清理并对账。
- 不修改真实项目集团关系，不自动提交或推送。
