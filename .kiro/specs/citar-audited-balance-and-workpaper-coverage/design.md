# 设计：审定报表平衡与税审底稿取数补全

## 1 审定报表未分配利润（R1）

- 新函数 `PL_UNCLOSED()`（零参，`formula_engine._REGISTRY` 登记 ⇒ 保存 / 发布不被「未注册函数」拦截）。值只在单体报表生成路径有：
  `report_engine.evaluate_formula_result` 在 TB 代入之前按 `resolver.resolve_pl_unclosed()` 代入数值；没有该方法的 resolver（合并）
  严格模式报错、否则按 0（与原行为一致）；其余求值路径走到 L1 handler 报错，不代 0。
- 取数 `standard_balance_view_service.unclosed_pl_amount`：损益类标准科目（5 / 6 开头，与 `recalc_unadjusted` 同一判据）叶子期末余额
  借正贷负合计 + 已批准非底稿来源调整（借 − 贷）+ 底稿发布调整（自然正数按方向转借正贷负），取反（利润为正）。
  与 `build_standard_balance_view.adjusted_closing_balance` 同口径。未审口径只取余额；期初口径 0（`ReportFormulaParser._use_opening`）。
  按口径缓存在 parser 上（逐行求值）。
- 公式：`report_total_formulas.STANDALONE_OVERRIDES` 只覆盖单体准则（soe BS-125 / listed BS-084）=
  `TB('3104')+TB('3201')+PL_UNCLOSED()`；合并准则不变。`fixes_for(standard)` 统一取用（fill_all_formulas / 发布脚本 / 守卫）。
  现有库经 `fix_report_total_formulas.py` 全局发布（request_id 按内容哈希，旧发布不回放）。
- 增量重算 `_is_affected`：公式含 `PL_UNCLOSED()` 时任一损益科目变动都算受影响。
- 为什么不做成 TB 的新列名：TB 列名表在十多个求值器各有一份（推送 / 底稿 / 预载 / ACNR），新列名在它们那里静默为 0；
  为什么不在引擎里后处理未分配利润行：公式与数值对不上（穿透 / 过期重算 / 追溯各路径都要另改）。

## 2 重导后的新客户科目（R2）

`mapping_service.auto_match` 每次都调 `_generate_client_accounts_from_balance`（原只在客户科目表为空时）；后者改为一次查出已有编码、
按剥「.0」比较，只建没有的。激活事件与「自动匹配」按钮走同一入口。

## 3 按行标签分类取数（R3）

- 运行时 `tax_workpaper_classify.classify`：一级科目（`AccountBook.resolve`，只认映射）下有余额 / 发生额的末级，按层次找归属：
  末级名称最后一段（全等 / 别名全等 / 包含别名 / 行名包含末级名 ≥ 4 字）→ 末级名称前几段（全等）→ 上级科目（全等）；
  同层多行命中：全等 > 包含，再比匹配词长度、行序。泛称（其他 / 杂费 / 其他销售费用）跳过；`not_contains` 命中末级全路径的行不参与。
- `RuleRunner`：`op=classify`（组、行号）取该行末级的 measure；`lists[mode=classified]`（组、类别 / None=其余）复用名称列表与溢出合并；
  其余明细按一级科目的直接下级合成一行（下级的末级全部是其余时）。末级合计与一级科目不等时第一行给原因；一级科目取不到只第一行报。
- 生成器 `scripts/gen/tax_workpaper_supplements.py`：行号 + 别名表（2-07 / 2-08 / 2-09 / 2-10 / 3-03-04），生成时逐条核对样表行名、
  目标格不是公式、不重复；输出 `model.classify_groups`、补充取数项与列表。别名按两个案例审计员的归类与辽宁真实科目名校准
  （福利费含员工住宿费、折旧摊销含装修改造款摊销、低值易耗品摊销不进、平台佣金服务费不进佣金）。
- 口径：2-07 ~ 2-10 借方发生额（R12 未结转扣减照旧）；3-03-04 本年摊销额 = 贷方发生额。
