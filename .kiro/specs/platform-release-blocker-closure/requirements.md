# 平台发布阻断项收口 — 需求

## 目标

在不扩展业务功能的前提下，使当前分支形成可复现、可登录、可保存、可复核、可出具、可判定就绪的候选版本。所有结论以干净检出、一次性 PostgreSQL、浏览器真实请求为准。

## R1 可启动与故障隔离

1. 登录后项目主界面不得因 AI、公式或其他可选面板的模块错误而整体加载失败。
2. `ChatNoteSaveDialog` 与 `useAiNoteCapture` 的导入导出契约必须由类型检查和运行时 import smoke 同时验证。
3. 可选 AI 面板只在用户打开时加载；加载失败应显示中文局部错误，不影响项目、底稿、报表页面。

## R2 保存真实性

1. Univer 和自动保存只在后端 2xx 且业务回执成功时清除 dirty。
2. 401/403/409/423/5xx、返回 `false`、网络异常均保持 dirty，并给用户可见原因。
3. 保存期间又发生编辑时，旧回执不得清除新一代 dirty。
4. 强制覆盖必须再次显式确认，不以关闭冲突弹窗作为覆盖指令。

## R3 复核主链单一来源

1. 单笔和批量提交必须复用同一提交服务和同一组门禁。
2. 前端不得以 `pending_review` 调用底稿文件状态端点。
3. 旧 `batch-status` 与不写库的 `workpapers/batch-submit` 不得继续提供假成功。
4. 退回后修改、标记编制完成、重新提交必须形成合法闭环。
5. 末级复核通过后，所有正文、公式、附件及结构写入口都必须由后端统一判为不可写；修改须先创建新修订并撤销复核结论。

## R4 项目隔离与操作者可信

1. Metabase 嵌入 URL 必须登录；带项目参数时必须有该项目只读权限，无项目的全局资源仅 admin 可签发。
2. 临时 `/api/_debug/*` 端点不得进入生产路由。
3. 导入 SSE 的 `job_id` 必须属于路径项目。
4. 复核意见的 `review_id` 必须属于路径底稿，操作者只能取当前登录用户，不接收客户端 UUID。
5. 复核配置 GET/PUT 必须校项目权限；PUT 继续限制 manager/partner/admin。
6. 未完成项目隔离的进程内用户公式 v2 接口必须返回 410，不得暴露全局内存仓。

## R5 出具权威源

1. 交付中心“一键生成全套”必须调用正式 trio readiness 与 trio job，不再走旧 full-deliverables。
2. 报表生成前 TB 重算失败必须阻断，不得用旧 TB 清除 stale。
3. 合并附注 Word 必须读取合并项目根节点的 `ConsolNoteData`，不得以不存在的 `DisclosureNote` 代替。
4. trio snapshot 必须包含数据集、TB、调整、公式运行、报表、附注的内容/版本摘要，而不只包含数量。

## R6 迁移与就绪

1. 启动只有在磁盘迁移均已登记、无迁移失败时才能标 migration complete。
2. hot-reload 子进程即使跳过执行迁移，也必须只读核对磁盘与 DB 版本集合。
3. `/readyz` 遇待迁移、迁移失败或 critical schema drift 必须返回 503。
4. `/api/health` 必须明确列出待迁移版本；不能以 `failures=[]` 表示数据库已最新。

## R7 发布门

1. `spec/**` 分支 push 必须触发 CI，或由等价的强制 PR 门覆盖。
2. stable 模式必须运行类型检查、Vite 构建、包体预算、构建产物 smoke，再切换服务。
3. `build:verify`、`bundle:check`、verified preview 与 Dockerfile 中引用的脚本必须真实存在且可执行。
4. 候选树必须在干净检出中通过后端导入、前端构建、一次性 PG 迁移和浏览器主链 smoke。

## R8 验收与边界

1. 使用【测试】项目验证登录、项目、TB、底稿保存、提交/退回/重提、报表、附注、trio readiness。
2. 安全端点需验证未登录、非成员、只读、可编辑和管理员角色。
3. 不在本批执行共享库写迁移、审计链分叉确认、索引重建或真实项目内容重算；这些动作须另行授权。
4. 不实施 0/48 的双向回写全量 entry 收口，也不新增业务页面。
