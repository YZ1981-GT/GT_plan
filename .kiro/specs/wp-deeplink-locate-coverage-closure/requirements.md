## 需求 1　目录单元格坐标纠错

1.1 未停用、且不在既有判定（`keep_semantic_unverified` 33 格）里的单元格逐格复核；证据（模板册、tab、该格类别、值、同行文字、列头）都能由模板现算。
1.2 处置：
- 坐标处内容与语义相符的保留；
- E1-14 三格按模板改指：C10「货币资金余额变动率」→ I18（合计行本期变动），C15「货币资金占总资产比例」→ C34（模板里最接近的比例「银行存款÷资产总额」本期），B30「分析程序结论」→ A50（「四、审计结论：」）；
- `purpose=conclusion` 且所在 sheet 恰有一个「审计结论」标签格的，改指该标签格（新增单元格，标签「审计结论」）；
- 其余停用，`replaced_by` 指父 sheet。
改指 = 新增正确坐标的单元格，原单元格停用并 `replaced_by` 新单元格（addr_id 与 A1 不可变）。
1.3 停用前核对引用：PG 公式类列、`backend/data` 静态引用；有引用的点名处置，不静默停用。
1.4 经生成器重新发布目录（新批次、快照、报告），发布门禁 blocking 为 0，`--check` 通过；依赖目录内容的守卫按新目录更新，判据不放宽。
1.5 守卫：新判定与保留格的证据由模板逐格现算并与记录相等；新增单元格在模板里的文字符合改指规则；目录里任何未停用、未豁免的单元格都必须在复核台账里有记录（以后新增坐标不经复核即红）。

## 需求 2　网页视图定位覆盖

2.1 渲染器定位顺序在「组件钩子 → `[data-cell-ref]`」之后加一级文字锚点：按目录生成的对照（sheet 编码 + A1 → 锚点文字，现只有「审计结论」）在本渲染器根元素内找唯一、可见、不在表格单元格里的同名标题，高亮其所在卡片 / 表单项（没有则标题本身）；找不到或不唯一时照旧提示。
2.2 对照由目录生成（生成脚本带 `--check`），只含未停用单元格；目录变了对照必须重生成。
2.3 按使用频率核对：真实底稿数前列、且目录里有结论格的组件，结论区标题能被文字锚点认出（单测覆盖标题的几种写法；浏览器抽样实测）。
2.4 E1-14 新增三格：C34 定位到比例表本期格，A50 定位到审计结论卡片，I18（合计行网页无对应）给「没有对应位置」提示。
2.5（实施中浏览器实测查明）模板页签的渲染配置不给 `sheet_code`（E1 / D4 / H3 全部页签），查对照所用的 sheet 编码须能从页签名取得；重组件（D4）取完数才渲染结论区，登记了锚点的位置不得在结论区出现前就提示「没有对应位置」；没有登记锚点的格提示时间不变。
2.6 结论区标题的常见序号写法（「2、」「2.」「（三）」「IV.」）与中文序号一样能认出，且不因此让原本唯一的标题变得不唯一。

## 需求 3　定位入口

3.1 溯源弹窗点「定位」：按 `wp_code` 取本项目底稿实例后打开编辑器并带 `?sheet=&cell=`；节点已带 `wp_id` 时直接用；取不到时中文提示。
3.2 同类入口一并修：`LineageGraphPanel` 节点在当前底稿时交渲染器定位、不在时跳转；复核意见列表打开编辑器（不再进列表页）；`usePenetrate.toWorkpaperFromNote` 同。
3.3 共用一个打开函数；守卫：全仓不得再以 `wp_code` 当 `wpId` 发定位事件，不得把 `sheet` / `cell` 带到底稿列表页。

## 需求 4　Univer 路径就绪

4.1 `UniverEditorCore` 接收 `initial-sheet` / `initial-cell`；Univer 未就绪时收到的定位请求排队（只留最后一个），就绪后切 sheet，带单元格时选中该格。
4.2 编辑器不再用固定延时发定位事件。
