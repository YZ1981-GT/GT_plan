承接 `oo-formula-recompute-not-tamper`（11/11）design §11 的范围外清单，以及 2026-10-26 复盘发现的问题。

用户原话：

- 2026-10-25「D1 / D2 / D3 / D5 / D6 / D7 明细表，以及 G2-2 和四张坏账表 … 按模板从「期初未审」起算。D5-2 的期末审定还是包含重分类；前端和模板还有其他口径不一致的按模板中的修改；用户在公式格敲了数字、裁决保留服务器值后，发布出去的文件里那一格仍是数字，公式没有还原 … 要实测。转置表拿不到公式信息，照旧按冲突处理也要解决。引用别的行或别的表的公式，插行后签名会变，仍按原规则报冲突，这个也要修复；代码里「受保护字段」有三处定义互相不一致的问题也得改；usePeriodAdjudication 如果是死代码，就删掉。此外，你需要把 1937 例失败、771 例报错逐条修复好。」
- 2026-10-26「模板本身算错的几处，这个你看下实际情况，如果真的模板错误就按正确的来；D5-2 改成 L+M+N（包含重分类），可能也是模板错了吧；只做测试项目。」

## R1 模板公式错误按正确口径修正

1.1 逐格核实过的模板公式错误（清单见 design §2）按会计上正确的口径改模板，只改清单里的格，其余单元格、合并区、样式与其他 sheet 不变。
1.2 改过的模板，其契约（模板哈希、结构哈希、定义哈希、审核依据文本）、模板快照、预填定位表与 provider 冻结常量随之更新；golden 摘要门禁与契约校验全绿。
1.3 只有名称带「【测试】」的项目按新模板重新发布在线编辑产物；真实项目不重发布，报告里列出受影响但未重发布的项目与表。

## R2 前端与模板口径一致

2.1 D5-2 期末审定 = 期末未审 + 账项调整 + 重分类调整（L+M+N），前端与模板一致。
2.2 上一轮登记的 D1~F5 口径不一致项（design §3.1）按模板改前端；模板本身错的先按 R1 改模板。
2.3 G~N 普查出的不一致项（design §3.2）同样处理。
2.4 新增「前端 ↔ 模板公式」对拍守卫：同一组输入，模板公式与前端算出的值不一致即报红；暂不能对齐的逐条登记理由，登记表只许减少。

## R3 契约受管字段与前端字段接通

3.1 契约受管字段名在前端处理同一 store item 的代码里不存在的（design §4，现算下界 198 个），逐表改到两侧使用同一字段名；模板有、前端没有的列，前端补上该列的录入或显示。
3.2 新增字段名对拍守卫：每份契约每个受管字段，在前端处理该 store item 的代码中必须出现；例外逐条登记理由，只许减少。

## R4 篡改裁决后公式还原

4.1 用户在 OO 的公式格里敲了数字、裁决保留服务器值后，发布出的文件里该格恢复为模板公式，值为服务器值。先写测试复现现状，再修。
4.2 裁决采用 OO 值（用户确认要数字）时，行为与现在一致，不受本条影响。

## R5 转置表补公式证据

5.1 五张转置表（D4-29 / D4-12 / G4-9 / G5-9 / G6-11）的公式格产出与行表同口径的签名，OO 重算值按上一轮规则采纳；无公式的格不受影响。

## R6 插行后公式签名稳定

6.1 OO 里插入 / 删除行之后，引用他行（如合计行）或他表的公式，签名在「已发布坐标」下比较，不因行号平移报冲突。
6.2 公式真被改写、或被换成数字，仍按原规则报冲突。

## R7 「受保护字段」统一一个判定

7.1 `contracts.PROTECTED_MODES`、`FieldValue.is_protected`、`merge._protection` 收成一个判定来源；25 个 cross_sheet 字段（G3 21、G11 4）的保护归属在 design §5 裁定并逐条测试。

## R8 删除死代码

8.1 `usePeriodAdjudication.ts` / `CycleTabAdjudication.vue` 确认零挂载后删除，连同 `components.d.ts` 登记。

## R9 后端测试红清零

9.1 以完整检出（非稀疏 worktree）的基线为准，逐条修复失败与报错；修主代码或修过期测试，均写明根因；不跳过、不降级断言。

## R10 验收

10.1 每条修复配磁盘变异（变异必须打红，且红在预期断言上）。
10.2 前后端回归与改前逐条对比，新增失败为 0。
10.3 浏览器实测【测试】项目：D5-2 与至少一张字段接通的表双向改值、公式格敲数字后裁决保留服务器值并核对发布文件。
10.4 只提交本 spec 的文件与改动块，推送到 `spec/disclosure-note-doc-upload-and-batch-fill`。
