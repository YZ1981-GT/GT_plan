# 平台性能收口的范围外发现 — 需求

> **本文件是回填件（2026-11-06）**。本 spec 立项时只写了 design + tasks，缺 requirements，
> 导致 `R1`~`R12` 这些编号在 tasks.md 里被引用却没有定义处，验收标准只能从 design 的叙述里推断。
> 回填内容全部有出处，不新增范围：R1~R7 来自 design §1 的 2026-10-31 现状核实与 §3 逐项设计，
> R8~R12 来自 design §8 的六个待裁决项与用户 2026-10-31 的裁决（§9），R13 是本次补的验收口径去重。
> **不回填改写 design 与 tasks 的既有结论**（append-only）；与代码不一致处以代码为准并在 design §7.1 已登记。

## R0 交付边界

1. 本 spec 只收口 `platform-performance-user-experience-closure` design §12.6 登记的范围外发现，不扩业务功能、不做性能工程。
2. 遮蔽与重复注册只许用「调注册顺序 / 删死实现 / 改名其中一条路径」三种修法，不得引入 Starlette 路径转换器（理由见 design §2：会连带多份按路径登记的台账、把非法 id 的 422 变 404、把 `path_params` 的值类型从 str 变成 UUID / int）。
3. 只改本 spec 登记的改动块；主工作树有并发会话改动，不得 stash、clean、reset 或整树覆盖。
4. 标完成须有代码 + 测试证据；未实测标 `[ ]*` 并写明缺的是什么环境或数据，不得用「接口调通」冒充界面走查。
5. 「HEAD 红」类证据必须在 HEAD 干净 worktree 上复跑同一用例确认，不把预存失败算作本 spec 引入，也不把本 spec 引入的失败推给预存。

## R1 后端路由可达性

1. 全应用路由表里不得存在同方法的遮蔽：后注册的路由不得被先注册的路由抢先匹配。判定与 design §1 的探针同口径（`{x}`→`x0`、`{x:int}`→`1`、`{x:uuid}`→合法 UUID；同方法才算，HEAD / OPTIONS 不计）。
2. 守卫 `backend/tests/test_route_shadow_guard.py` 的允许集必须为空，且必须在未修代码的 HEAD 上逐条报出现算的 13 条遮蔽；修复后全绿。守卫须配双向变异：恢复任一处旧注册顺序即打红，只加注释的对照组保持绿。
3. 重复注册（同路径同方法注册两次）清零，`test_duplicate_route_registration_baseline.py` 的 `_KNOWN_DUPLICATES` 为空。每组必须先判定「生效的是哪一份、前端按谁的契约写」，再删另一份；删除时把被删那份独有的能力（鉴权声明、取数口径）移到留下的一侧，不得连带丢失。
4. 去重 / 解除遮蔽后**才真正生效**的端点，鉴权级别必须与同域端点一致，不得因为「以前不可达所以没人管」而留一个无项目隔离的活端点。
5. 两个不同功能占用同一路径时，改名其中一条而不是让一方静默失效；改名后原来恒空 / 恒 422 的调用方必须实测恢复。
6. 修改不得改变任何 `route.path` 字符串（R0.2 的后果）；台账（`wp_bound_entry_coverage.json`、鉴权基线）如有增减必须逐条归因，归因不到本 spec 的不动。

## R2 报表页附注列与导出同源

1. 报表页附注列的编号必须与导出 Excel 的附注列逐格相同，唯一来源是导出用的同一份编号方案（`services/report_note_refs.py`），不得在前端另算一套。
2. 前端不得猜编号：没有年度不请求；响应缺 `_meta`（旧后端）返回 null ⇒ 附注列不显示编号。删除按金额计数的回退编号与前端写死的映射表（删前须全仓零调用）。
3. 模板格挂到报表行按行名（限同一张表）；库内没有同名行的格不登记 —— 模板与库内是两套编码，按编码硬挂会挂错行。
4. 带项目的取数必须校验项目只读权限；只给准则时原样返回静态映射。
5. 验收以真实项目对拍为准：同项目同年度导出 Excel 的附注列与端点 `display` 逐行比较，差异为 0；页面不挂的格必须能说明原因（项目报表无此行）。

## R3 去重后调用方契约对齐

1. A16 程序表推荐版本：前端只读生效那份实现的字段（`recommended_code` / `all_versions` / `always_required`），不得保留只有死实现才会返回的分支（`business_category` / `main.code`）。
2. A18-2 导出检查：分发到专用导出服务的检查端点返回统一契约 `{complete, missing_fields, wp_code, reason}`；A18 原先返回 `{has_incomplete, count, incomplete_topics}`，一旦生效即 500 ⇒ 必须在模块级分发函数里映射到统一契约，类方法 `check_completeness` 不动。
3. 前端按 `complete === false` 与 `missing_fields` 提示，不得按旧字段名判断。
4. 每个契约改动都要有「按真实响应形状」的用例，并补一条「旧形状不再生效」的反向用例 —— 否则两种形状都认的 mock 会让契约漂移看不见。

## R4 公式端点登记

1. 四个现存但未在前端路径表登记的公式后端端点必须有访问器，并被实际使用的面板调用，不得留字面量路径。
2. 路径 barrel 补齐导出；`formulaPaths.spec.ts` 的提取器必须按各 `router` 变量自己的前缀取路径（按文件取前缀会把同文件里挂在另一个 router 上的路径算错），并配自检用例。

## R5 前端运行时卫生

1. 字典标签类型在一处规范化：颜色为空串返回 Element Plus 的默认值（外观不变）、非法值返回 `info`；两个预览同口径。模板里写死空串类型的 `<el-tag>` 按 ROI 只计数登记（仅开发态 warn、生产无影响、与并发会话改动面重叠）。
2. 同页同参数同时发起的重复 GET 必须收敛；参数不同（如 sheet 变化后重取）属正常行为，登记不改。重复请求的定位必须用浏览器 initiator，不凭 `watch` 写法推断。
3. 公式管理弹窗改为首次打开才挂载（四个宿主共用一个组合式，`visible` 第一次为真后不再回落）；按挂载断言的既有测试相应改为「先打开再断言」。

## R6 测试卫生

1. 判据与生产代码必须共用同一份实现 / 同一份语义，不得测试里另写一份（`tabToRoute` 两份、`guidanceBar` 用 `text()` 去空白、G6 空列头、S34-16-1 的 C23 假设都属此类）。
2. 修判据前必须先复现反例并定位根因是生产代码还是判据；根因在生产代码的改生产代码。
3. 测试不得改写已跟踪产物：生成类脚本提供 `--out`，spec 写临时文件并断言已跟踪产物字节不变。
4. 修出来的真缺陷（如页签跳不存在的路由名、落 404）必须单独登记，不混在「测试卫生」里一句带过。

## R7 前端请求路径前缀

1. 前端字面量请求路径必须带 `/api` 前缀 —— `utils/http` 的 baseURL 是 `/`，只有 `/api`、`/wopi` 转给后端；少前缀的 GET 会拿到首页 HTML、写请求 404，而调用方普遍 catch 静默 ⇒ 整条功能从未生效且不报错。
2. 现算的 15 处必须全部修复，且修复后的请求要么有浏览器证据、要么有跨语言契约用例（前端用例读后端响应字段名）。
3. 守卫 `apiPathPrefixGuard.spec.ts`：全仓字面量调用须带 `/api`、`apiPaths` 字面量须带前缀、**断言扫描面不小于 2000**（防止收窄范围后判据恒绿）、配自检用例；守卫须在 HEAD 上打红。
4. 修好路径后进入其他守卫视野的（如行级证据小眼睛）按该守卫的既有写法补齐，豁免清单只许删、不许加。

## R8 A16 推荐版本与补充声明开关（design §8 第 3 项，用户裁决：删旧分支）

1. 删掉 `WorkpaperWordEditor` 读 `main.code` 的旧格式分支 —— 去重后已无数据来源。
2. 补充声明是否必填：先读字段覆盖（`onSupplementToggle` 写的就是它），有值按它；没有记录或取不到年度时按 `always_required` 的默认集合。
3. mock 全部改成真实响应形状，并补「旧形状不再生效」「字段覆盖优先于 `always_required`」两个用例。

## R9 A18-2 只在用户改动后保存（design §8 第 6 项，用户裁决：改为只在改动后保存）

1. 挂载流程（读议题定义 → 读已存内容 → 表头为空时带出）全程不保存；结束时记下基线载荷。
2. 监听回调里基线为空不动作；与基线相同则撤掉待发的保存；不同才防抖保存；保存成功后基线更新为本次发出的内容。
3. 读已存内容失败时**不记基线**、本页不自动保存并提示刷新 —— 否则一改动就会用带出值覆盖已存表头（PUT 按 item_id upsert，表头整行覆盖）。
4. 卸载时只补发「已经待发」的那次保存，不新发。

## R10 附注编辑页切年度（design §8 第 4 项，用户裁决：写路由）

1. 切年度写路由 `?year=`，整页按新年度重挂；带 `?year=` 打开时年度选择器与路由一致。
2. 未保存必须拦截，取消则年度选择器回到当前年度；确认放弃后清脏标记，更新守卫不得再问第二次。
3. `changeYear` 先于 `router.push`，使 `year:changed` 落在旧实例上、重挂后的新实例不亮「数据已更新」。
4. push 的 query 只带年度：`section` / `table_index` / `noteTemplate` 是一次性参数，挂载后已用 `history.replaceState` 清掉，但 `route.query` 里还在，整体展开会把它们带回去。
5. 「没有附注就自动生成」交给重挂后的挂载流程执行，触发条件不变。
6. 未保存拦截抽成一个函数，离开守卫与更新守卫共用。

## R11 GET 共享在途（design §8 第 5 项，用户裁决：改为共享在途）

1. `utils/http` 的 GET 去重语义从「取消先发的那次」改为「共享在途」：同页两个调用方同时取同一地址时，两边都拿到结果，不得让先发方静默失败。
2. 每个调用方一个订阅（各自的 signal、登录身份代际边界）；底层请求不带任何调用方的 signal；成功与失败都出在途表（不缓存结果）。
3. 后加入者必须在结算时（任何调用方代码运行前）拿到拷贝，不得共享同一可变对象。
4. 新鲜度屏障：非 GET 请求发出 / 结束、项目事件流收到任一事件时推进屏障；屏障变化后的新请求不再复用旧在途（旧请求照常交付已有订阅者）。
5. 重试、401 刷新、全局错误提示只在生产者那一条链上发生一次；非 GET 的防重复提交语义不变。
6. 既有为绕开旧语义写的在途表 / `_dedupe:false` 不删（语义仍成立），注释保留原因。

## R12 复核工作台（design §8 第 1 项，用户裁决：方案 A 配置驱动状态机）

1. 唯一状态机：按项目 `review_config.levels`（2~4，缺省 2 级）动态生成合法转换表，不得两套状态机并存（零调用的那份删掉）。
2. `pending_levelN` 与 `levelN_in_progress` 都可以直接通过或退回 —— 去掉「必须先进复核中」的强制中间步骤（界面上本来就没有入口进「复核中」，保留该约束等于任何底稿都走不完复核）。
3. 非末级通过自动推进下一级待复核；末级通过把底稿标为复核完成。
4. 退回必填原因、建复核记录、底稿标「需修改」。
5. 批量通过 / 退回逐张走同一状态机，不符合的跳过并写明原因回报，不得整批失败也不得静默跳过。
6. 与 AI 批量复核的路径冲突必须改名解决（两个功能不占同一路径），改名后原调用方实测可用。
7. 前端发当前级对应的状态值、补齐三 / 四级标签、列表查询条件覆盖到三 / 四级；项目设置里要有复核层级入口（后端 `/review-config` 已存在、前端原先无入口）。
8. 换规则前须确认存量数据不受影响（现算：3820 张底稿全是 `not_submitted`、0 个项目设过 `review_config`）。

## R13 验收口径与界面走查去重（2026-11-06 回填）

立这一条的原因：A18-2 的界面走查在 tasks.md 里被三个任务各自要求了一次（任务 28「批 F 界面走查」、
任务 23a「A16 推荐标记、A18-2 导出的界面走查」、任务 34 的第二个 34.5「浏览器实测」），三处都停在
`[ ]*`。同一件事挂在三个编号下，既数不清还差多少，也会让其中任一处被单独勾掉时产生「已验收」的错觉。

1. **界面走查只认一处口径**：A16 推荐标记、A18-2（检查 / 导出 / 读写）、I 循环在线编辑切换、H3 勾稽、
   K10 识别五项归并为一份界面走查清单，由**任务 28** 唯一承载；任务 23a 与任务 34 的浏览器项只引用
   任务 28 的结论，不各自重复验收。
2. **阻断原因必须写成可解除的条件，而不是「缺数据」三个字**。现算阻断（design §7.3、tasks 28 / 23a）：
   - 五项所需底稿在存活的【测试】项目里都不存在；
   - 在真实项目上打开 A18-2 会占用编辑锁、且修复前每次打开都会触发自动保存写库（R9 修后挂载流程不再保存，
     但仍会占锁）⇒ 走查前置 = 在【测试】项目里按平台路径生成这五类底稿。
   - 任务 34 的流转走查前置 = 存在一张 `pending_level1` 的底稿（现算真库 3820 张全是 `not_submitted`）。
3. **去重后 tasks.md 里重复的编号要改掉**：第二个 `34.5` 改为 `34.6`，使每条任务有唯一编号（本次已改）。
4. **`[ ]*` 的含义统一**：代码与单测 / 契约证据已完成、只差真实环境或测试数据的界面层确认。
   凡只有接口层证据的，一律不得改勾成 `[x]`，也不得在 INDEX / memory 里写成「已实测」。
5. 本 spec 收口时的真实剩余量按 R13.1 的归并口径计：**界面走查 1 项（任务 28，含 23a 与 34 的浏览器项）
   + 任务 34 的流转走查 1 项**，其余编号任务已完成。
