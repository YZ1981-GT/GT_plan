# 附注取数残留与治理收口 — 需求

## 背景

承接 `note-pull-followup-closure` 的 23.1、design §3.3 待定项与 2026-10-28 交付复盘中仍未落地的治理项。用户 2026-10-29：
「未做的按你建议来，逐一落地修复，之后再整体复盘下，是否还有进一步优化改进建议」。

本轮范围只包含经当前 HEAD 重新验证仍存在的缺口：

- G12 / G13 挂载回填会覆盖或漏存数据，H3 已存数据读回断链，H5 补充文字保存为空操作；
- M1 / M2 / M3 / M8 自动同步签名错误，M6 / M9 / M10 还同时存在模板结构不一致；
- 离屏同步 78 个 wp_code 中仍缺 11 个：`E1 F1 G7 H1 H3 K3 L4 L5 M6 M9 M10`；
- 公式推送把原生 `_tables` 旧格式误标为 `_source=workpaper`；
- edit 级鉴权清册被 3 个动态级别门禁阻断；项目鉴权棘轮可从 166 / 238 收紧到当前值；
- `06be17bbe` 引入的 18 条域边界新增违规；全仓其余新增债务不在本轮冒领、不抬基线；
- 原 Task 23.1 的真实合并拉数 / 前 N 名浏览器写入尚未完成。

超过 3 个组件并跨前后端，实施前必须以本三件套锁定设计。任何写入型验收只允许使用名称含 `【测试】` 的项目。

## R1 挂载回填与持久化安全

1. G12 必须区分“来源不存在”和“来源明确为 0”：不存在时保留已存值且不保存；明确 0 时允许更新为 0。
2. G12 只有在来源存在、数据确实变化、当前可写时才持久化；只读挂载和无变化挂载不得发写请求。
3. G13 必须先完成本期与上期的全部内存 patch，再一次性持久化最终状态；不得先保存本期、再只在内存里改上期。
4. G13 没有来源时不保存；只读挂载可回显但不得写；每次挂载最多保存一次完整状态。
5. 所有回填测试必须使用非零已存值，并覆盖“来源缺失”“明确 0”“单边来源”“只读”四类反例。

## R2 H3 / H5 单一数据源

1. H3 枚举键、读取值、编辑值和保存值必须来自同一个响应 Map；禁止宿主 Map 与内部空 Map 混用。
2. H3 上市 / 国企、成本 / 公允价值四种口径必须能重新挂载读回已存非零行、说明及层次数据。
3. H3 无来源时不得把默认 0 自动同步到附注；修复读回后再接离屏 provider。
4. H5 国企补充披露文字必须通过显式保存依赖写入共享 Map 和 checklist 端点；禁止默认 no-op 注入。
5. H5 编辑、AI 回填、刷新重挂、只读四条路径必须有宿主到子 Tab 的集成测试。

## R3 自动同步契约

1. `useDisclosureAutoSync` 只能接选项对象；`scheduleAutoSync` 必须收到一个可调用同步函数。
2. M1 / M2 / M3 / M8 改为正确调用、只读门禁、卸载取消；编辑后 800ms 内合并为一次同步。
3. M6 / M9 / M10 在载荷结构修复前不得因“修签名”而开始发送错误数据；结构与模板逐表对齐后再启用。
4. 覆盖守卫必须用 AST 判断调用形态，不能只查字符串出现；逐处摘掉参数或传错首参必须打红。
5. 接入自动同步的组件必须在卸载时取消待执行任务，避免切 Tab 后旧上下文继续写。

## R4 共享章节写权与模板对齐

1. `五、42 / 八、42` 采用科目唯一 owner：L2 只拥有应付利息行，M1 只拥有应付股利行及其明细，K3 只拥有其他应付款行及其明细。
2. 三个 owner 必须使用行域 / 表域浅合并，不得整表覆盖或通过 `_removed_table_keys` 删除其他 owner 的数据。
3. M6 行名、顺序、小计和字段必须与 `五、61 / 八、63` 模板逐项一致；公式小计可以展示，但不得从同步快照丢失模板要求行。
4. M9 上市资产负债表口径和利润表口径必须使用两份独立数据；行名去掉底稿内部批注并补模板分组；国企第二张表须明确接入或明确不适用。
5. M10 不得发送只有金额而其他列全空的“基本情况”、空“持有者信息”或恒 0 数量列；缺少真实输入时只浅合并实际拥有的变动表。
6. 所有共享章节测试必须覆盖不同 owner 先后写入，结果与顺序无关。

## R5 剩余 11 个离屏同步 provider

1. F1 现有孤儿 provider 必须先通过真实 Tab 请求体等价测试，再登记；新增“生产 provider 必须登记或具名冻结”的反向守卫。
2. H3、L4、L5、M6、M9、M10 必须先完成非零读回与模板对齐，再接 provider。
3. K3 必须在 R4 写权裁决落地后接入；不得覆盖 M1 / L2。
4. H1 离屏上下文必须取得与宿主相同的 `templateType/reportScope`，不得退化为只看 `applicableStandards`。
5. G7 的 `previouslySyncedTables` 必须改由附注侧原子记录 owner 状态；provider 不得为推进删除基线而写底稿。
6. E1 主表仍由公式推送维护；离屏只复用 Tab 同一状态 / builder 处理说明、外币和受限资产章节，并保留 `row_scope_unresolved` 回报。
7. 每个 provider 必须证明：真实 Tab 与 provider 的逐章节请求体逐字节相等、fixture 含非零值、离屏零底稿写入、listed / soe 分别覆盖。
8. 完成后 `NOT_YET_HEADLESS` 为空、78 / 78 注册；磁盘孤儿 provider 为 0。
9. K strict 域保留历史基线，新增文件用 append-only 账本解释；不得直接抬高 367 / 753 / 899 等冻结数字。L strict / wide 差集保持原判据。

## R6 公式推送来源语义

1. JSON `_source` 只表达存储 / 投影结构；公式推送修改原生 `_tables` 时不得把它改成 `workpaper`。
2. ORM `last_sync_source=formula_push` 继续表达最近动作来源；公式推送不得写底稿同步指纹。
3. 只有真实创建 / 维护 `sub_table_data` 结构的路径才允许设置结构来源；历史误标数据仍必须无损读写。
4. 提供只读 dry-run 存量识别；若实写修复，只允许【测试】项目，并必须排除真实底稿同步章节。
5. 现有把误标行为钉成契约的测试必须反转；后端、前端 projector / 保存回写形成闭环。

## R7 edit 级鉴权清册与鉴权棘轮

1. OCR 缓存分支改为显式 readonly / edit 字面门禁：仅完整缓存读取可 readonly，可能写缓存或启动 OCR 的路径必须 edit。
2. `require_attachment_permission` 作为正式 `project_object` GateSpec 登记，级别由调用实参决定；项目必须来自附件对象。
3. `confirmation_project_gate` 作为正式 router gate 登记，GET / HEAD 为 readonly，其余方法为 edit；生成器按路由 HTTP 方法解析级别。
4. 不得把动态门禁加入忽略名单，也不得把整个函证 router 固定标成 edit。
5. 清册生成器必须通过内置正反样例与逐处变异，随后重生 `edit_level_impact_inventory.json`，`--check` 返回 0。
6. identity-only 直接路径基线按现算值从 166 收紧，前缀维从 238 收紧；body 维不得增长。只许向下，不得放宽相等断言。

## R8 本轮域边界治理

1. 精确清零 `06be17bbe` 引入且当前仍在的 18 条边，不把全仓其余债务写进 baseline。
2. checker 必须忽略自动生成的 `components.d.ts`，但仍扫描普通 `.ts/.vue` 违规 import。
3. Python `from package import submodule` 必须解析到真实 submodule，不得错误记到 package `__init__.py`。
4. 为合并附注、附注公式和 `src/composables/workpaper/**` 补精确 owner；禁止通过扩大整个 domain 的 `may_depend_on` 掩盖倒置。
5. 前端纯算法 `noteTotalTerms` / `noteColumnTree` 移到共享低层并更新全部引用；后端 decimal helper 移到 notes 可依赖的低层。
6. `wp_disclosure_sync_service -> note_push_ownership` 通过 notes 侧窄接口或编排反转，不得将 workpapers→notes 违规加入基线。
7. `--write-baseline` 在存在新增违规时必须拒绝；提供 shrink-only 更新方式或等价安全行为。
8. 本轮验收以“18 条归因边为 0、baseline 不增”为完成条件；全仓其他 573 条只登记 owner，不冒领完成。

## R9 合并拉数 / 前 N 名真实浏览器验收

1. 动态识别名称含 `【测试】`、`report_scope=consolidated` 的集团及所有测试子企业；任何非测试叶子立即中止。
2. 普通章节用已确认映射完成叶子拉数与根节点汇总；前 N 名章节走专用路径，不伪造映射。
3. 前 N 名数据必须包含跨企业同名单位、超过 N 个外部单位、至少一个集团内单位和可独立计算的金额 / 比例分母。
4. 验收必须使用真实浏览器、真实 HTTP、真实 PG；检查 POST、独立 GET、页面硬刷新、控制台和持久化值，toast 不能作为唯一证据。
5. 写前备份完整相关行和主键集合；写后按主键精确恢复，规范化 `row_to_json` 哈希和主键集合均零差异。
6. 服务或测试集团不可用时不得假绿；修复环境后继续，不以 synthetic Playwright 或单测替代。

## R10 回归、复盘与交付

1. 每个交付单元先加防御测试 / 变异，再改生产代码；发现一处同类反模式须全仓 grep 并一次收口。
2. 后端、前端、循环 strict 守卫、鉴权清册、域边界、全量 vue-tsc 候选对基线均不得新增失败。
3. 改动后用 `http://127.0.0.1:3030` 做 Playwright 实测；写操作只在【测试】项目。
4. 整体复盘按合伙人 / 项目经理 / 质控 / 审计助理 / EQCR 五个视角检查，并对新增建议做收益、文件数、风险评估。
5. 只实施高收益、低至中风险、与本链直接相关的改进；其余明确登记，不做无关重构。
6. 提交前在干净临时检出跑要提交的树并重生两份鉴权清册；fetch 后把改动重放到远端最新提交。
7. 不新建分支、不使用 stash、不跳过 hooks；当前分支单提交并用 `push_version.py` 带版本号原子推送。
