# 需求文档：高级查询联动闭环（advanced-query-linkage-closure）

## 概述

来源：`.agents/tasks/advanced-query-linkage-assessment-2026-10-26/report.md`（下称「评估」）及其 `00-ground-truth.md` / `10-architecture.md` / `11-coverage-matrix.md` / `evidence/` / `browser/`。断点编号 AQ-xx 只引用、不复述；评估中的数值都是 2026-10-26 快照，验收一律以实施时测试内独立 SQL 现算的「金标准」为准，不写死进判据。本文是第 2 轮，按同目录 `design-review.md`（HIGH 2 / MEDIUM 16 / NIT 17）修订，逐条回应见 design §13。

现状：业务视图 11 个取数器在真实数据上只有试算表、底稿清单 2 个结果正确；查询结果走不出查询框（下钻、引用、完整导出、模板全部断开）；构建器 SQL 层正确，但项目隔离、JOIN 基数与准入有缺口。断点 37 个（P0 6 / P1 19 / P2 12）。

目标（用户 2026-10-26：「一定要打通联动起来才可以」）：高级查询能拿来取证，并与平台其余模块联动：查得对（口径、隔离、计数、分页）、查得到（数据源齐全、条件生效）、走得出（下钻到权威页面、复制经地址库校验的公式引用、服务端完整导出、模板可复用、从业务页带上下文进入）。

优先级（用户批示）：修断点、接通已有功能 ＞ 交付历史 spec 承诺而未落地的联动 ＞ 新能力。历史设计未承诺且「没有它也能用」的一律进 design §11 待拍板（附推荐默认值），本 spec 不做。

约束（实施逐条遵守，细节见 `#conventions`）：新 router 在 `backend/app/router_registry/{group}.py` 注册（本 spec 只改既有 router，不新建）；service 只 flush、router 统一 commit；提交前的非阻塞逻辑包 `begin_nested()`；迁移 `V{n}__` / `R{n}__` 成对、DDL 一律 `IF NOT EXISTS`、版本号实施时现扫 `MAX+1`；三层一致（迁移 + ORM `Mapped[]` + service）；项目级鉴权经 `require_project_access` / `ownership_guard` 且数据层查询带项目条件；判断「代码是否做了 X」用 AST / symtable，禁文本 `in`；新模块与调用方同一次提交。

术语：**金标准** = 测试内独立 SQL 现算的期望值，不调用被测代码；**真 PG** = `pg_only` 标记、连本机 `audit_platform`，写入型只用回滚事务或名称带【测试】/【UAT】的项目；**审计年度** = `services/project_audit_year.resolve_project_audit_year` 的结果；**SQL 源** = 结果来自数据表、可在数据库内计数排序分页的数据源；**内存源** = 结果来自 JSON 列或 xlsx（附注表格、合并工作底稿、底稿选区）；**下钻** = 打开权威页面并定位到对应对象；**引用** = 复制经地址库校验的公式引用（TB / ROW / NOTE / WP）；**循环范围** = 成员行 `scope_cycles` 经 `deps.get_user_scope_cycles` 解析出的审计循环限制（admin / partner 不受限）。

## 1. 功能需求与验收标准

### R1 四表数据集口径（AQ-02）
- R1.1 业务视图的科目余额、序时账、辅助余额、辅助明细只返回该项目年度当前生效数据集的行，与 `dataset_query.get_active_filter` 逐行一致；宜宾临港店科目余额的行数与 Σ期末等于金标准（快照 812 行 / −659,481.68）。查询生效数据集失败时返回带追踪号的 500，不退化为不按数据集过滤。
- R1.2 构建器查询 tb_balance / tb_ledger / tb_aux_balance / tb_aux_ledger 时由服务端注入同一口径，用户 DSL 的任何条件都不能放宽；`is_deleted = true` 的行查不出。
- R1.3 项目年度没有生效数据集时按平台既有降级规则（未删行）返回，并在 warnings 写明「该项目年度没有生效数据集，按未删除行返回」。

### R2 计数、排序、分页与聚合（AQ-03、AQ-26 排序部分、AQ-28、AQ-36）
- R2.1 SQL 源的 total 等于满足全部条件的行数（金标准 COUNT），不受 5,000 行上限影响；和平药房序时账 total = 金标准（快照 1,147,414）。
- R2.2 排序在数据库内对全量生效，空值一律排在最后（业务视图与构建器一致）；和平药房序时账按借方降序第 1 行借方 = 金标准最大借方（快照 241,944,666.92）。
- R2.3 offset ≤ 100,000 时任意页可达，逐页并集 = 全集且互不重叠；offset 超出 total 返回空页、total 不变；offset > 100,000 返回 422 并提示改用导出。
- R2.4 分组 / 透视：参与行数 ≤ 5,000 时按全量计算；> 5,000 时返回 400 `AGGREGATION_TOO_LARGE` 并提示改用高级构建器；不再返回基于截断样本的结果（和平药房科目 1002 分组借方合计不再出现 24,512,071.03 这类截断值）。
- R2.5 内存源取数超过 5,000 行时返回 400 `RESULT_TOO_LARGE`，不返回截断结果。
- R2.6 构建器 total 为全量行数（分组时为组数），不再等于本页行数；弹窗、页面版、构建器都有翻页控件并显示真实 total；弹窗的本地文字筛选标注「仅筛选本页」。
- R2.7 试算表默认按标准科目编码升序（华氏首行科目码 = 金标准最小码）。
- R2.8 内存源默认保持取数原始行序（附注表格合计行仍在最后，底稿单元格按行列顺序而非字符串顺序）；用户排序时同值行保持原序。

### R3 构建器隔离、上下文与准入（AQ-06、AQ-18、AQ-19、AQ-21、AQ-27 构建器部分）
- R3.1 构建器只返回未删除项目的数据：projects 表只返回可访问且未删除的项目（admin / partner 为全部未删除项目），其余表只含未删除项目的行；e2e_manager 只能查到其可访问项目。
- R3.2 staff_members 只对系统角色 admin / partner 开放；其余角色引用它（含作为 JOIN 目标）返回 403 `TABLE_ROLE_FORBIDDEN` 中文提示。
- R3.3 计划中每张带项目维度的表（基表与 JOIN 目标）都施加项目作用域，带 `is_deleted` 列的表只取未删除行；左连接不因作用域丢失基表行（没有匹配目标行时目标列为空、基表行保留）。报表配置的项目副本行（`project:{项目}`）只对能访问该项目的用户可见。
- R3.4 每条登记的 JOIN 都声明基数：多对一的不改变基表行数（华氏 `trial_balance LEFT JOIN account_chart` 行数 = trial_balance 行数）；一对多的在 schema 与结果 warnings 中标明「该关联为一对多，结果行数可能多于基表行数」；「报表行次映射 → 报表配置」登记删除（理由见 design ADR-AQL-09）。
- R3.5 从项目页打开构建器时默认限定当前项目与审计年度，结果显示「范围：当前项目」；可显式切到「跨项目」（可访问项目 > 1 或 admin / partner 时才出现）；显式指定不可访问项目返回 403 且不执行。
- R3.6 准入：系统角色 admin / partner / manager，或在至少一个未删除项目中项目角色为 manager / partner 且权限级别 edit 的用户可以使用构建器，作用域为其可访问项目。前端入口与后端判定同源（同一接口）；无权时入口可见但禁用，并显示与后端一致的中文原因（含合伙人）。
- R3.7 构建器的公式引用只对试算表行生成，且每条都能通过地址库校验；科目余额表行不再生成引用。
- R3.8 循环范围（ADR-AQL-19）：被分配了审计循环的成员，在业务视图的试算表、调整分录、附注目录、附注章节与指标树附注分支中看到的范围，与试算表页、调整分录页、附注页一致；查询范围外的附注章节返回 403 `SECTION_OUT_OF_SCOPE`「该附注章节不在您被分配的审计循环内」；对本人设有循环范围的项目不进入构建器作用域（warnings 写明排除数），显式指定这类项目返回 403 `CYCLE_SCOPED_PROJECT`。

### R4 写入安全（AQ-04、AQ-05、AQ-23）
- R4.1 cell-writeback / writeback-preview / writeback-confirm 只接受 workpaper、note 两个模块，tb / adj / report 返回 422；tb / adj / report 三个写入实现删除。
- R4.2 回写定位目标行时以请求项目为查询条件，他项目的底稿与合并附注记录既不被读取也不被加锁：底稿返回 404 `WRITEBACK_TARGET_NOT_FOUND`，合并附注返回 404 `NOTE_RECORD_NOT_FOUND`（403 `NOTE_OWNERSHIP_MISMATCH` 只在同项目内年度、章节、节点不一致时出现）。以项目 X 定位项目 Y 的一张已提交底稿、以【UAT】子公司A 定位【UAT】合成集团母公司的合并附注记录：行内容前后逐值不变，另一会话对该行 `FOR UPDATE NOWAIT` 成功。
- R4.3 `tb_audited_writer.publish_rows` 的生产调用方冻结为登记清单（AST 判定）；高级查询包内出现任何调用即测试失败。
- R4.4 查询路径（wp-sheet-preview、底稿单元格区域取数）不写 storage：底稿没有文件时返回「该底稿尚未生成文件，请先在底稿编辑器中打开一次」；公式重算只在临时副本上进行；请求前后 storage 文件的字节与 mtime 不变。
- R4.5 writeback-preview 只要有目标无法定位（`found=false`；目标不属于请求项目时 error 为 `target_not_in_project`，且不读其旧值），就不进入确认（`enter_confirmation=false`）并提示无法定位的目标数；同一组目标调 writeback-confirm 返回 409 `WRITEBACK_CONFLICT`，一个目标都不写。

### R5 数据源正确（AQ-01、AQ-07、AQ-08、AQ-10、AQ-11、AQ-12、AQ-26、AQ-33）
- R5.1 报表源结构与报表生成同口径（项目适用准则的行 ∪ 本项目独有的行），金额取自项目已生成的报表结果（financial_report）：华氏资产负债表 BS-002 货币资金本期 = 金标准（快照 822,999,085.83）；本项目独有行出现在结果中；项目未生成该报表时金额为空并在 warnings 写明「该项目尚未生成此报表」；存在过期行时 warnings 写明「报表数据已过期」。
- R5.2 调整分录源按平台枚举查询：华氏「审计调整分录(AJE)」行数 = 金标准（快照 2）；「重分类调整」更名为「重分类调整分录(RJE)」并映射 rje；旧键 `adj_rcl` 与大写值 AJE / RJE / RCL 兼容；不带类型的通用调整分录源返回全部类型（含 cf）并带类型列。
- R5.3 报表行次源可查询并按行号排序，不再 500；只含准则行与本项目的项目副本行。
- R5.4 单体项目的附注树按该项目该年度的实际章节生成，章节集合与顺序同附注编辑器目录（含口径过滤）；章节查询逐表返回、列随该表表头、行序与原表一致，响应附该章节的表清单供切换；新增「附注目录」源，列出章节 × 表（章节号、标题、表名、行数、需更新）。华氏「八、1 货币资金」返回其第一张表的数据。
- R5.5 单体项目不显示合并工作底稿类叶子与合并试算平衡表；「科目明细」更名为「试算平衡表（科目）」；合并项目保留原叶子。
- R5.6 新增「辅助余额」「辅助明细」数据源（业务视图）与 tb_aux_balance / tb_aux_ledger / financial_report（构建器白名单），口径同 R1；辅助明细未按科目或辅助类型筛选时返回 400 `AUX_FILTER_REQUIRED`「辅助明细请先按科目或辅助类型筛选」；辅助余额未按辅助类型筛选时 warnings 提示「辅助核算按维度冗余存储，跨维度合计会重复」。
- R5.7 试算表返回期初、未审、重分类调整、审计调整、审定五列；科目余额与辅助余额带期初 / 期末方向列；指标树每个叶子声明的列 = 实际返回的列（由同一定义生成）。
- R5.8 回归：华氏试算表 Σ审定与底稿清单结果继续等于金标准。

### R6 条件、字段选择与标签（AQ-13、AQ-15、AQ-35）
- R6.1 页面版条件以结构化条件（字段、算子、值 + AND / OR）发送，服务端转为参数化谓词；和平药房序时账「借方发生额 > 100,000,000」的 total = 金标准 COUNT，且每行满足条件。
- R6.2 未登记的条件字段、算子、筛选键、列，以及无法转换的值，返回 400 中文提示（指明对象与可用项），不再静默忽略；「包含」类条件按字面匹配用户输入里的 `%`、`_`。不支持条件的数据源（附注表格、合并工作底稿、底稿选区）在界面上禁用条件区并说明原因。
- R6.3 字段选择生效：响应 `columns` 只含所选列（下钻所需键随行返回但不显示）；导出同样只含所选列。
- R6.4 条件值输入框在条件行内可见可输入（宽度 ≥ 120px）；字段下拉与字段勾选框显示中文列名。
- R6.5 页面版与构建器的「ACNR 选字段」面板标「开发中」，请求不再携带 `acnr_targets`，其余功能不受影响。
- R6.6 序时账、辅助明细的 summary 列显示「摘要」，合并试算的同名列显示「汇总数」；结果表与导出一致。

### R7 下钻与引用（AQ-14、AQ-17、AQ-24 以引用交付、AQ-27）
- R7.1 每类结果行可一键在新标签打开权威页面并定位（目标见 design ADR-AQL-01）；每类至少一条浏览器实测落到目标页且定位正确（科目、凭证、辅助项、报表行、附注章节与表、调整分录组、底稿 sheet 与单元格）。报表行在普通与对比模式下定位到该行；权益变动表、减值准备表只打开对应报表并提示「该报表为矩阵格式，已打开对应报表」；报表页与地址库跳转用同一种深链。
- R7.2 底稿单元格结果打开底稿编辑器时 sheet 与单元格都被定位（`?sheet=&cell=`）。
- R7.3 试算表、报表、附注表格、底稿单元格结果可「复制引用」：按地址库语法生成，按项目准则类型与审计年度经地址库校验，通过才可复制，否则按钮不可用并显示原因；底稿单元格只对地址目录里登记过的坐标可用，未登记的显示「该单元格未登记为可引用地址」。
- R7.4 右键「跳模板溯源」不再 500：底稿编码按模板目录解析，打开模板库对应页签并定位到该底稿模板；没有模板定义的结果给出一致提示。
- R7.5 查询结果不写回底稿、附注、试算表、调整分录（裁决见 design ADR-AQL-02），界面不出现回写入口。

### R8 完整导出（AQ-20）
- R8.1 弹窗、页面版、构建器的「导出全部」由服务端按当前查询（条件、列、排序）流式导出全量结果：数据行数 = total（金标准 COUNT），表头为界面所见中文列名，另附「查询说明」sheet（项目、年度、数据源、条件、行数、导出时间、导出人）。
- R8.2 结果超过 1,000,000 行时在生成文件前返回 400 并提示缩小范围，不产生不完整文件；和平药房序时账按单月筛选可完整导出。
- R8.3 「导出当前页」保留为次选项；中文文件名按 RFC 5987 编码。
- R8.4 每次导出记一条审计（操作者、项目、数据源、行数）。
- R8.5 导出文件里以 `=`、`+`、`-`、`@` 开头的文本（含表头与「查询说明」）按文本写入，不成为公式。
- R8.6 同一用户同时只能有 1 个导出，同一服务进程同时进行的导出不超过 4 个；超出返回 429 `EXPORT_BUSY`「已有导出在进行，请稍后再试」，不产生文件。

### R9 模板（AQ-16、AQ-30、AQ-25 模板部分）
- R9.1 「仅我可见 / 指定项目共享 / 公开」三档保存与更新都成功（页面版与弹窗 💾），入库 scope 为规范值；保存校验失败返回 4xx 中文原因，不再 500。
- R9.2 可见性单一判定：本人、公开（含历史 global）、指定项目共享（对任一共享项目有访问权）、历史 team（锚点项目成员）；列表、详情、执行三处结论一致。审计员能看到并执行管理员公开的模板；读取或执行不可见模板返回 403 `TEMPLATE_NOT_VISIBLE`「无权访问该模板」。
- R9.3 弹窗内可打开「我的模板」，选中模板后按当前项目经服务端模板执行端点执行（重新鉴权、可翻页）；年度取目标项目审计年度，取不到时返回 422 `YEAR_REQUIRED` 并要求指定。
- R9.4 页面版与弹窗共用同一个模板选择组件；「载入」把数据源、条件、列、排序、每页行数还原到界面。
- R9.5 删除需二次确认并进入回收站；模板在回收站对作者与 admin 可见、可恢复、可彻底删除；恢复后重新出现在模板列表（写后读回）。

### R10 入口上下文与年度（AQ-22、AQ-31、AQ-34 页面级、AQ-37）
- R10.1 每次打开弹窗都以当前路由项目为准；模板库按钮带来的项目优先于路由；非项目页打开时不自动选中任何项目。
- R10.2 弹窗年度依次取：路由 `?year` → 所选项目审计年度 → 取不到时留空并要求选择；布局传给公式管理与一键刷新的年度不变；CustomQueryDialog、SheetCellRangePicker、CustomQueryTab 不再以今天推算年度（前端年度兜底棘轮删这三条，ThreeColumnLayout 条目保留）。
- R10.3 从试算表、报表、附注、调整分录、账簿查询、辅助汇总页打开弹窗时预选对应数据源。
- R10.4 页面版指标树带项目加载「骨架 + 附注分支」，不再拉取不带项目的全量树；同一会话内附注重新生成、对齐或切换年度后，弹窗与页面版都不再使用旧的指标树缓存。

### R11 错误与提示（AQ-09、AQ-29）
- R11.1 查询失败显示中文原因与可复制的追踪号，不显示为「暂无数据」；确定性错误（4xx、带追踪号的 500）不自动重试、不出现「服务器暂时异常，正在重试...」。
- R11.2 参数校验错误（422）显示中文（字段中文名 + 规则），不显示 pydantic 英文明细。
- R11.3 构建器无权提示与后端准入判定一致。

## 2. 非功能需求
- N1 性能（本机 PG 实测并记录）：和平药房序时账首页（含 COUNT）≤ 3 s；辅助明细首页（按科目筛选）≤ 5 s；10 万行导出 ≤ 60 s；业务视图查询受语句超时保护，超时返回 408 中文提示。不达标时不放宽阈值，按 design ADR-AQL-06 预案处理；预案用尽仍不达标的，相关任务保持未勾并附实测数据与执行计划。
- N2 安全：不新增未鉴权端点；本 spec 触及的端点全部进入权限配方表；所有用户值参数化绑定；导出受并发闸约束（R8.6）。
- N3 兼容：execute 响应既有字段与类型不变（`columns` 仍为字符串数组，仅新增可选 `meta`）；`wp-id-by-code` 契约不变；未知数据源、非法排序等既有错误码不变。
- N4 行数门：ReportView.vue、DisclosureEditor.vue 不增行（HARD_CAP）；custom_query.py 拆分后白名单基线下调为真实行数；新文件 ≤ 800（后端）/ 1500（前端）。
- N5 可用性：界面文本中文（SQL / API / UUID 等技术名词保留英文）；下钻、复制引用、翻页、导出控件有 aria-label，可用键盘操作。

## 4. 假设
- A1 本机 PG `audit_platform` 可用，评估用到的华氏、和平药房、宜宾临港店、【UAT】子公司A / B、【UAT】合成集团母公司数据在实施期间不被删除；被删时改用同类活项目并在任务说明记录。
