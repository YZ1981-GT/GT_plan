# 需求文档：高级查询联动闭环（advanced-query-linkage-closure）

## 概述

来源：`.agents/tasks/advanced-query-linkage-assessment-2026-10-26/report.md`（下称「评估」）及其 `00-ground-truth.md` / `10-architecture.md` / `11-coverage-matrix.md` / `evidence/` / `browser/`。断点编号 AQ-xx 只引用、不复述；评估中的数值都是 2026-10-26 快照，验收一律以实施时测试内独立 SQL 现算的「金标准」为准，不写死进判据。本文是第 3 版：第 2 版按 `design-review.md`（第 1 轮）修订（回应见 design §13）并纳入 W3 / W6（design §14）；本版按 `design-review-r2.md`（第 2 轮，HIGH 2 / MEDIUM 9 / NIT 14）修订，逐条回应见 design §15。第 2 轮评审新发现的断点记为 AQ-38（R10.5）。

现状：业务视图 11 个取数器在真实数据上只有试算表、底稿清单 2 个结果正确；查询结果走不出查询框（下钻、引用、完整导出、模板全部断开）；构建器 SQL 层正确，但项目隔离、JOIN 基数与准入有缺口。断点 37 个（P0 6 / P1 19 / P2 12）。

目标（用户 2026-10-26：「一定要打通联动起来才可以」）：高级查询能拿来取证，并与平台其余模块联动：查得对（口径、隔离、计数、分页）、查得到（数据源齐全、条件生效）、走得出（下钻到权威页面、复制经地址库校验的公式引用、服务端完整导出、模板可复用、从业务页带上下文进入）。

优先级（用户批示）：修断点、接通已有功能 ＞ 交付历史 spec 承诺而未落地的联动 ＞ 新能力。历史设计未承诺且「没有它也能用」的一律进 design §11 待拍板（附推荐默认值），本 spec 不做。例外：W3（常用审计预置模板）与 W6（业务页行级「按此查询明细」入口）按用户 2026-10-26 决定纳入（R13、R14），排在全部断点任务之后实施。

约束（实施逐条遵守，细节见 `#conventions`）：新 router 在 `backend/app/router_registry/{group}.py` 注册（本 spec 只改既有 router，不新建）；service 只 flush、router 统一 commit；提交前的非阻塞逻辑包 `begin_nested()`；迁移 `V{n}__` / `R{n}__` 成对、DDL 一律 `IF NOT EXISTS`、版本号实施时现扫 `MAX+1`；三层一致（迁移 + ORM `Mapped[]` + service）；项目级鉴权经 `require_project_access` / `ownership_guard` 且数据层查询带项目条件；判断「代码是否做了 X」用 AST / symtable，禁文本 `in`；新模块与调用方同一次提交。

术语：**金标准** = 测试内独立 SQL 现算的期望值，不调用被测代码；**真 PG** = `pg_only` 标记、连本机 `audit_platform`；写入只在回滚事务里进行，且只写名称带【测试】/【UAT】的项目（含在回滚事务里新建、并复制真实项目所需行的【测试】项目）；真实项目只读（只读查询，以及 R4.2 对已提交行的 `FOR UPDATE NOWAIT` 加锁验证）；**审计年度** = `services/project_audit_year.resolve_project_audit_year` 的结果；**SQL 源** = 结果来自数据表、可在数据库内计数排序分页的数据源；**内存源** = 结果来自 JSON 列或 xlsx（附注表格、合并工作底稿、底稿选区）；**下钻** = 打开权威页面并定位到对应对象；**引用** = 复制经地址库校验的公式引用（TB / ROW / NOTE / WP）；**循环范围** = 平台入口 `deps.get_user_scope_cycles` 给出的审计循环限制（口径 `wp_visibility/effective_scope`：系统 admin / partner 不受限；本项目主管不受限——委派角色属合伙人、签字合伙人、项目经理、质控、EQCR（含中文别名），且链路唯一：本人恰有一条未删人员记录、在本项目恰有一行未删成员行；其余成员 = 团队分配勾选 ∪ 委派扩大的循环，可为空）；**构建器作用域** = 可访问项目 − 已删项目 − 本人循环范围受限的项目。

## 1. 功能需求与验收标准

### R1 四表数据集口径（AQ-02）
- R1.1 业务视图的科目余额、序时账、辅助余额、辅助明细只返回该项目年度当前生效数据集的行，与 `dataset_query.get_active_filter` 逐行一致；宜宾临港店科目余额的行数与 Σ期末等于金标准（快照 812 行 / −659,481.68）。查询生效数据集失败时返回带追踪号的 500，不退化为不按数据集过滤。
- R1.2 构建器查询 tb_balance / tb_ledger / tb_aux_balance / tb_aux_ledger 时由服务端注入同一口径，用户 DSL 的任何条件都不能放宽；`is_deleted = true` 的行查不出。
- R1.3 项目年度没有生效数据集时按平台既有降级规则（未删行）返回，并在 warnings 写明「该项目年度没有生效数据集，按未删除行返回」。

### R2 计数、排序、分页与聚合（AQ-03、AQ-26 排序部分、AQ-28、AQ-36）
- R2.1 SQL 源的 total 等于满足全部条件的行数（金标准 COUNT），不受 5,000 行上限影响；和平药房序时账 total = 金标准（快照 1,147,414）。
- R2.2 排序在数据库内对全量生效，空值一律排在最后（业务视图与构建器一致）；和平药房序时账按借方降序第 1 行借方 = 金标准最大借方（快照 241,944,666.92）。
- R2.3 offset ≤ 100,000 时任意页可达，逐页并集 = 全集且互不重叠；offset 超出 total 返回空页、total 不变；offset > 100,000 返回 422 并提示改用导出。
- R2.4 分组 / 透视：参与行数 ≤ 5,000 时按全量计算；> 5,000 时返回 400 `AGGREGATION_TOO_LARGE` 并提示改用高级构建器；不再返回基于截断样本的结果（和平药房科目 1002 分组借方合计不再出现 24,512,071.03 这类截断值）。
- R2.5 内存源取数超过 5,000 行时返回 400 `RESULT_TOO_LARGE`，不返回截断结果。
- R2.6 构建器 total 为全量行数（分组时为组数），不再等于本页行数；弹窗、页面版、构建器都有翻页控件并显示真实 total；弹窗的本地文字筛选标注「仅筛选本页」。
- R2.7 试算表默认按标准科目编码升序（华氏首行科目码 = 金标准最小码）。
- R2.8 内存源默认保持取数原始行序（附注表格合计行仍在最后，底稿单元格按行列顺序而非字符串顺序）；用户排序时同值行保持原序。

### R3 构建器隔离、上下文与准入（AQ-06、AQ-18、AQ-19、AQ-21、AQ-27 构建器部分）
- R3.1 构建器只返回构建器作用域内的数据：projects 表只返回作用域内的项目（admin / partner 为全部未删除项目），其余表只含作用域内项目的行。e2e_manager 只能查到其作用域内的项目：现库它只经委派访问一个项目、没有成员行（链路不唯一 ⇒ 受限），期望 0 行且 warnings 写明排除数；另以一名「人员记录 1 + 成员行 1 + 经理委派」的现场经理作正例，只返回其项目（身份实施时现查）。
- R3.2 staff_members 只对系统角色 admin / partner 开放；其余角色引用它（含作为 JOIN 目标）返回 403 `TABLE_ROLE_FORBIDDEN` 中文提示。
- R3.3 计划中每张带项目维度的表（基表与 JOIN 目标）都施加项目作用域，带 `is_deleted` 列的表只取未删除行；左连接不因作用域丢失基表行（没有匹配目标行时目标列为空、基表行保留）。报表配置的项目副本行（`project:{项目}`）只对能访问该项目的用户可见。
- R3.4 每条登记的 JOIN 都声明基数：多对一的不改变基表行数（华氏 `trial_balance LEFT JOIN account_chart` 行数 = trial_balance 行数）；一对多的在 schema 与结果 warnings 中标明「该关联为一对多，结果行数可能多于基表行数」；「报表行次映射 → 报表配置」登记删除（理由见 design ADR-AQL-09）。
- R3.5 从项目页打开构建器时默认限定当前项目与审计年度，结果显示「范围：当前项目」；可显式切到「跨项目」（构建器作用域内的项目数 > 1 或 admin / partner 时才出现）；显式指定不可访问项目返回 403 且不执行。
- R3.6 准入：系统角色 admin / partner / manager，或在至少一个未删除项目中项目角色为 manager / partner 且权限级别 edit 的用户可以使用构建器，作用域为构建器作用域。前端入口与后端判定同源（同一接口）；无权时入口可见但禁用，并显示与后端一致的中文原因（含合伙人）。接口返回的可访问项目数按构建器作用域计；准入通过但作用域为空时入口可见但禁用，显示「您可访问的项目均设有审计循环范围，请在业务视图中查询」。
- R3.7 构建器的公式引用只对试算表行生成，且每条都能通过地址库校验；科目余额表行不再生成引用。
- R3.8 循环范围（ADR-AQL-19）：业务视图的试算表、调整分录、附注目录、附注章节与指标树附注分支，对同一用户的可见范围与试算表页、调整分录页、附注页一致，口径是平台唯一入口 `deps.get_user_scope_cycles`（= `wp_visibility/effective_scope`：系统 admin / partner 看全部循环；本项目主管——委派角色属合伙人、签字合伙人、项目经理、质控、EQCR（含中文别名），且本人恰有一条未删人员记录、在本项目恰有一行未删成员行（链路不唯一一律按受限）——看全部循环；其余成员看团队分配勾选的循环 ∪ 委派扩大的循环，为空即什么都看不到）；查询范围外的附注章节返回 403 `SECTION_OUT_OF_SCOPE`「该附注章节不在您被分配的审计循环内」；对本人循环范围受限的项目不进入构建器作用域（warnings 写明排除数），显式指定这类项目返回 403 `CYCLE_SCOPED_PROJECT`。

### R4 写入安全（AQ-04、AQ-05、AQ-23）
- R4.1 cell-writeback / writeback-preview / writeback-confirm 只接受 workpaper、note 两个模块，tb / adj / report 返回 422；tb / adj / report 三个写入实现删除。
- R4.2 回写定位目标行时以请求项目为查询条件，他项目的底稿与合并附注记录既不被读取也不被加锁：底稿返回 404 `WRITEBACK_TARGET_NOT_FOUND`，合并附注返回 404 `NOTE_RECORD_NOT_FOUND`（403 `NOTE_OWNERSHIP_MISMATCH` 只在同项目内年度、章节、节点不一致时出现）。以项目 X 定位项目 Y 的一张已提交底稿、以【UAT】子公司A 定位【UAT】合成集团母公司的合并附注记录：行内容前后逐值不变，另一会话对该行 `FOR UPDATE NOWAIT` 成功。
- R4.3 `tb_audited_writer.publish_rows` 的生产调用方冻结为登记清单（AST 判定）；高级查询包内出现任何调用即测试失败。
- R4.4 查询路径（wp-sheet-preview、底稿单元格区域取数）不写 storage：底稿没有文件时返回「该底稿尚未生成文件，请先在底稿编辑器中打开一次」；公式重算只在临时副本上进行；请求前后 storage 文件的字节与 mtime 不变。
- R4.5 writeback-preview 只要有目标无法定位（`found=false`；目标不属于请求项目时 error 为 `target_not_in_project`，且不读其旧值），就不进入确认（`enter_confirmation=false`）并提示无法定位的目标数；同一组目标调 writeback-confirm 返回 409 `WRITEBACK_CONFLICT`，一个目标都不写。

### R5 数据源正确（AQ-01、AQ-07、AQ-08、AQ-10、AQ-11、AQ-12、AQ-26、AQ-33）
- R5.1 报表源结构与报表生成同口径（项目适用准则的行 ∪ 本项目独有的行），金额取自项目已生成的报表结果（financial_report）：华氏资产负债表 BS-002 货币资金本期 = 金标准（快照 822,999,085.83）；本项目独有行出现在结果中；项目未生成该报表时金额为空并在 warnings 写明「该项目尚未生成此报表」；存在过期行时 warnings 写明「报表数据已过期」。
- R5.2 调整分录源按平台枚举查询：华氏「审计调整分录(AJE)」行数 = 金标准（快照 2）；「重分类调整」更名为「重分类调整分录(RJE)」并映射 rje；旧键 `adj_rcl` 与大写值 AJE / RJE / RCL 兼容；不带类型的通用调整分录源返回全部类型（含 cf）并带类型列。
- R5.3 报表行次源可查询并按行号排序，不再 500；只含准则行与本项目的项目副本行。
- R5.4 单体项目的附注树按该项目该年度的实际章节生成，章节集合与顺序同附注编辑器目录（含口径过滤）；章节查询逐表返回、列随该表表头、行序与原表一致，响应附该章节的表清单供切换；新增「附注目录」源，列出章节 × 表（章节号、标题、表名、行数、需更新）。华氏「八、1 货币资金」返回其第一张表的数据。
- R5.5 单体项目不显示合并工作底稿类叶子与合并试算平衡表；「科目明细」更名为「试算平衡表（科目）」；合并项目保留原叶子。
- R5.6 新增「辅助余额」「辅助明细」数据源（业务视图）与 tb_aux_balance / tb_aux_ledger / financial_report（构建器白名单），口径同 R1；辅助明细未按科目或辅助类型筛选时返回 400 `AUX_FILTER_REQUIRED`「辅助明细请先按科目或辅助类型筛选」；辅助余额未按辅助类型筛选时 warnings 提示「辅助核算按维度冗余存储，跨维度合计会重复」。
- R5.7 试算表返回期初、未审、重分类调整、审计调整、审定五列；科目余额与辅助余额带期初 / 期末方向列；指标树每个叶子声明的列 = 实际返回的列（由同一定义生成）。
- R5.8 回归：华氏试算表 Σ审定与底稿清单结果继续等于金标准。

### R6 条件、字段选择与标签（AQ-13、AQ-15、AQ-35）
- R6.1 页面版条件以结构化条件（字段、算子、值 + AND / OR）发送，服务端转为参数化谓词；和平药房序时账「借方发生额 > 100,000,000」的 total = 金标准 COUNT，且每行满足条件。
- R6.2 未登记的条件字段、算子、筛选键、列，以及无法转换的值，返回 400 中文提示（指明对象与可用项），不再静默忽略；「包含」类条件按字面匹配用户输入里的 `%`、`_`。不支持条件的数据源（附注表格、合并工作底稿、底稿选区）在界面上禁用条件区并说明原因。
- R6.3 字段选择生效：响应 `columns` 只含所选列（下钻所需键随行返回但不显示）；导出同样只含所选列。
- R6.4 条件值输入框在条件行内可见可输入（宽度 ≥ 120px）；字段下拉与字段勾选框显示中文列名。
- R6.5 页面版与构建器的「ACNR 选字段」面板标「开发中」，请求不再携带 `acnr_targets`，其余功能不受影响。
- R6.6 序时账、辅助明细的 summary 列显示「摘要」，合并试算的同名列显示「汇总数」；结果表与导出一致。

### R7 下钻与引用（AQ-14、AQ-17、AQ-24 以引用交付、AQ-27）
- R7.1 每类结果行可一键在新标签打开权威页面并定位（目标见 design ADR-AQL-01）；每类至少一条浏览器实测落到目标页且定位正确（科目、凭证、辅助项、报表行、附注章节与表、调整分录组、底稿 sheet 与单元格）。报表行在普通与对比模式下定位到该行；权益变动表、减值准备表只打开对应报表并提示「该报表为矩阵格式，已打开对应报表」；报表页与地址库跳转用同一种深链。
- R7.2 底稿单元格结果打开底稿编辑器时 sheet 与单元格都被定位（`?sheet=&cell=`）。
- R7.3 试算表、报表、附注表格、底稿单元格结果可「复制引用」：按地址库语法生成，按项目准则类型与审计年度经地址库校验，通过才可复制，否则按钮不可用并显示原因；底稿单元格只对地址目录里登记过的坐标可用，未登记的显示「该单元格未登记为可引用地址」。
- R7.4 右键「跳模板溯源」不再 500：底稿编码按模板目录解析，打开模板库对应页签并定位到该底稿模板；没有模板定义的结果给出一致提示。
- R7.5 查询结果不写回底稿、附注、试算表、调整分录（裁决见 design ADR-AQL-02），界面不出现回写入口。

### R8 完整导出（AQ-20）
- R8.1 弹窗、页面版、构建器的「导出全部」由服务端按当前查询（条件、列、排序）流式导出全量结果：数据行数 = total（金标准 COUNT），表头为界面所见中文列名，另附「查询说明」sheet（项目、年度、数据源、条件、行数、导出时间、导出人）。
- R8.2 结果超过 1,000,000 行时在生成文件前返回 400 并提示缩小范围，不产生不完整文件；和平药房序时账按单月筛选可完整导出。
- R8.3 「导出当前页」保留为次选项；中文文件名按 RFC 5987 编码。
- R8.4 每次导出记一条审计（操作者、项目、数据源、行数）。
- R8.5 导出文件里以 `=`、`+`、`-`、`@` 开头的文本（含表头与「查询说明」）按文本写入，不成为公式。
- R8.6 同一用户同时只能有 1 个导出，同一服务进程同时进行的导出不超过 4 个；超出返回 429 `EXPORT_BUSY`「已有导出在进行，请稍后再试」，不产生文件。

### R9 模板（AQ-16、AQ-30、AQ-25 模板部分）
- R9.1 「仅我可见 / 指定项目共享 / 公开」三档保存与更新都成功（页面版与弹窗 💾），入库 scope 为规范值；保存校验失败返回 4xx 中文原因，不再 500。
- R9.2 可见性单一判定：本人、公开（含历史 global）、指定项目共享（对任一共享项目有访问权）、历史 team（锚点项目成员）；列表、详情、执行三处结论一致。审计员能看到并执行管理员公开的模板；读取或执行不可见模板返回 403 `TEMPLATE_NOT_VISIBLE`「无权访问该模板」。

### R13 常用审计预置模板（W3，用户 2026-10-26 纳入；ADR-AQL-05）
- R13.1 模板列表顶部出现只读「系统预置」分区，列出 design ADR-AQL-05 的 10 条预置；定义只在 `backend/data/custom_query_presets.json` 一处，不建系统用户、不加迁移；预置不能修改、删除或直接执行，只有「载入」「另存为我的模板」两个操作；页面版与弹窗用同一个模板选择组件。
- R13.2 「载入」由服务端按当前项目与审计年度解析参数，把数据源、排序、每页行数还原到界面，条件与条件逻辑填进条件编辑器（页面版与弹窗共用 `QueryConditionEditor`），不自动执行，用户修改后点「查询」才执行；「另存为我的模板」先载入，再打开既有保存对话框（默认名「{预置名}（我的）」），按 R9.1 保存。取自参数的条件值（重要性阈值、截止窗口）按参数占位保存，用户在编辑器里改过的值按字面保存；含参数占位的用户模板每次载入、执行都按目标项目与年度重新取值，取不到时执行返回 400 `CONDITION_VALUE_REQUIRED`，message 写明原因（如「本项目 2025 年度未设置重要性水平，请填写阈值」），不沿用保存时那个项目的值。
- R13.3 与平台现有规则用同一份定义：特殊事件关键词与 C24 异常分录规则 11 是同一份（C24 引擎改读由该 JSON 生成的常量）；默认模糊词与 C24 规则 12 的默认词表是同一份（C24 底稿组件的默认值改读同一生成常量）；「借、贷都有金额」「没有摘要」与 C24 规则 9、13 是同一判断；大额与抽凭 / 截止测试同一表达式（借、贷较大者 ≥ 阈值，不取绝对值）；期末前后窗口与截止性测试同一函数与默认天数（前后各 5 天）。
- R13.4 大额阈值默认取本项目该年度「实际执行的重要性水平」，条件编辑器上方写明「当前阈值：本项目 {年度} 年度实际执行的重要性水平 {金额} 元」；该年度没有重要性记录、值不大于 0 或读取失败时阈值留空并写明原因（如「本项目 2025 年度未设置重要性水平，请填写阈值」「本项目重要性水平为负数（-507,095,295.59），不能作为阈值，请填写」），留空时不能查询、不能保存，不给默认值。金额一律按千分位、两位小数显示。
- R13.5 新增条件能力：「开头是」（与旧筛选键科目编码前缀同一实现，`%` `_` 按字面匹配）；「星期为」（值为 0~6 的整数，0 = 周日，参数化绑定，只能用于日期字段，否则 400 `WEEKDAY_FIELD_INVALID`，值非法 400 `INVALID_WEEKDAY_VALUE`）；「为空或空白」（值为空、空串或只有空格，只能用于文本字段，否则 400 `BLANK_FIELD_INVALID`）；序时账增加只能作条件的「发生额（借贷较大者）」，按数值比较（前端传字符串阈值也按数值绑定）；条件编辑器补「大于等于」「小于等于」；除「为空」「不为空」「为空或空白」外条件值为空返回 400 `CONDITION_VALUE_REQUIRED`「条件「{字段}」未填写值」。
- R13.6 节假日：平台没有节假日日历来源（核实见 design §14），本 spec 只做周末；「周末分录」载入时说明「只按周六、周日筛选：调休上班日也会列出，法定节假日不在其内」。
- R13.7 验收（真实项目只读，金标准为测试内独立 SQL）：每条预置经执行端点跑出的 total、第一页逐值（凭证日期、凭证号、科目、借、贷、摘要）与金标准一致；结果 ≤ 5,000 行的逐页取全量，Σ借、Σ贷与金标准一致。项目：和平药房（指定科目 1002、冲销 / 红字、负数金额、周末、特殊事件、含模糊词；大额在没有重要性记录时留空提示）；宜宾临港店（期末前后 5 天，和平药房序时账只到 10 月底，该预置在和平药房 = 0 行也对账）；华氏（大额手填阈值 1,000,000 对账，并验证负数重要性的留空提示）；辽宁卫生服务（借、贷都有金额；和平药房 = 0 行也对账）；没有摘要（有序时账的真实项目现均为 0 行，在和平药房对账 0 行，命中路径在回滚事务里给【UAT】子公司A 造空值、空串、纯空格三行验证）。参数占位：在回滚事务里新建两个【测试】项目，A 上把大额预置另存为用户模板、B 上执行，阈值取 B 的实际执行的重要性；B 没有重要性记录时 400 `CONDITION_VALUE_REQUIRED`。
- R13.8 预置定义校验：每条的数据源已登记、字段可作条件、算子在白名单内且是条件编辑器提供的选项、参数与词表已登记、排序字段属该源可排序列且方向为 asc / desc、page_size 在 1..2000；校验失败的条目不出现在列表并记 ERROR；以单元测试与变异证明钉住。
- R13.9 C24 与预置的特殊事件词表、默认模糊词表来自同一 JSON：生成文件与 JSON 一致（`--check`），C24 既有测试保持通过。

### R14 业务页行级「按此查询明细」（W6，用户 2026-10-26 纳入；ADR-AQL-20）
- R14.1 入口：试算表右键菜单（与「📊 查看明细」并列）、报表「查看穿透」弹窗（与构成科目表并列）、附注表格右键菜单（与「📊 穿透到序时账」并列）、底稿编辑器工具栏（HTML 与在线编辑两种工具栏）。点击后打开高级查询弹窗，按上下文预选项目（当前路由项目）、年度（宿主页面取数用的年度，由宿主传入：附注编辑器页内切年只改页面状态、不写路由，入口仍带页面所显示的年度；宿主年度为空时才按 R10.2 取项目审计年度，任何一步不用日历年）、数据源与筛选并立即执行；弹窗顶部显示上下文（如「试算表 1002 银行存款」）、解析出的科目和「清除上下文」；用户手动换数据源即清除上下文。
- R14.2 落点：试算表行 → 该科目序时账，可一键切到科目余额、辅助余额、辅助明细（同一科目）；报表行 → 构成该行的试算表科目（取该行已生成报表的取数科目，单码按前缀、区间按起止，与报表取数同口径），结果行「查明细」打开该科目序时账并可返回上一查询；附注章节 → 该章节附注表格（第一张表，可切换表），可切到「相关科目（试算表）」（章节标题 → 附注科目映射表 → 底稿 → 科目）；底稿 → 该底稿登记科目的序时账（底稿编码未登记时取主编码），可切到余额类。
- R14.3 取不到科目时给中文原因、不报 500：报表行未生成（400 `REPORT_ROW_NOT_GENERATED`）、非合计行没有直接取数的科目（如矩阵报表的行，400 `REPORT_ROW_NO_ACCOUNTS`）、附注章节不存在或没有登记科目（400 `NOTE_SECTION_NOT_FOUND` / `NOTE_SECTION_NO_ACCOUNTS`）、底稿没有登记科目（400 `WP_CODE_NO_ACCOUNTS`）；试算表的合计行、小计行入口不可用并显示原因；报表合计行本就打不开「查看穿透」弹窗（现有行为），因此到不了入口。
- R14.4 可见范围：落到的数据源按 R3.8 过滤，附注章节在范围外时 403 `SECTION_OUT_OF_SCOPE`；账簿类源与账簿页同口径，不按循环过滤。
- R14.5 页面只留最小接线：TrialBalance 2 行（1 行挂载 + 1 行 import）；DisclosureEditor 净增 0 行（原 4 行的「穿透到序时账」块压成 2 行，腾出的 2 行放新入口与 import，HARD_CAP 保持等于实际行数）；WorkpaperEditor 3 行（每个工具栏 1 行 + import）；ReportView 0 行；上下文映射只在 `queryEntryContext.ts`，业务对象到科目的解析只在后端一处。
- R14.6 验收（真 PG 金标准）：华氏 BS-002 构成科目结果 Σ审定 = 报表本期金额（快照 822,999,085.83）；回滚事务给【UAT】子公司A 造一个子科目行后，单码前缀口径仍与报表取数一致；和平药房试算表 1002 → 序时账 total = 独立 SQL `account_code LIKE '1002%'` 计数，且等于经 account_mapping 映射的计数（快照均 116,443）；华氏「八、1 货币资金」相关科目 = {1001, 1002, 1012} ∩ 本项目试算表；底稿 E1 → 序时账 total = 三个前缀的独立计数（和平药房快照 116,562）；底稿 A1 → 400 `WP_CODE_NO_ACCOUNTS`。
- R14.7 浏览器：四处入口各走通一次（落点、上下文、切换、清除、「查明细」与返回），截图存档。

## 2. 非功能需求
- N1 性能（本机 PG 实测并记录）：和平药房序时账首页（含 COUNT）≤ 3 s；辅助明细首页（按科目筛选）≤ 5 s；10 万行导出 ≤ 60 s；业务视图查询受语句超时保护，超时返回 408 中文提示。不达标时不放宽阈值，按 design ADR-AQL-06 预案处理；预案用尽仍不达标的，相关任务保持未勾并附实测数据与执行计划。
- N2 安全：不新增未鉴权端点；本 spec 触及的端点全部进入权限配方表；所有用户值参数化绑定；导出受并发闸约束（R8.6）。
- N3 兼容：execute 响应既有字段与类型不变（`columns` 仍为字符串数组；新增可选键 `meta`，没有内容时省略）；`wp-id-by-code` 契约不变；未知数据源、非法排序等既有错误码不变。
- N4 行数门（按合入远端后的树计，design §9）：ReportView.vue、DisclosureEditor.vue 净增 ≤ 0，HARD_CAP 保持等于实际行数（`test_hard_cap_ratchet` 零余量）；custom_query.py 拆分后白名单基线下调为真实行数；其余改动文件不超门限；新文件 ≤ 800（后端）/ 1500（前端）。
- N5 可用性：界面文本中文（SQL / API / UUID 等技术名词保留英文）；下钻、复制引用、翻页、导出控件有 aria-label，可用键盘操作。

## 4. 假设
- A1 本机 PG `audit_platform` 可用，评估用到的华氏、和平药房、宜宾临港店、【UAT】子公司A / B、【UAT】合成集团母公司数据在实施期间不被删除；被删时改用同类活项目并在任务说明记录。

- A3 现场经理在系统中通常是「系统 auditor + 项目 manager（edit）」，R3.6 按此定义「项目经理」。
