# 需求：税审底稿取数、公式计算与保存

来源：用户 2026-11-03「为什么税审底稿里面，没有根据规则取出来的数据」→「根据你的建议 做完所有的事」。
承接上一轮：162 张税审底稿已按样表「税审底稿10.16.xlsx」还原表格结构（`views/tax-workpapers/sheets/`），但公式格留空、取数规则未接、页面不连后端。

事实来源：样表 xlsx（不入库，生成脚本 `--src` 指定）。样表里 38 张表有「取数规则」区共 202 条（`@直取` 167 / `@说明` 35；来源「底稿取数余额表」189、「试算表」11、其他 2）；全部底稿共 7,064 个公式格，1,515 个跨表引用；表头经「填写参数（无需打印）」页取被审核单位、期间、编制人等。

## R1 取数规则结构化（第一批）
- 202 条中文规则全部转成结构化定义（目标格、科目路径、取哪一列、是否按月、状态），由生成脚本从样表产出，提交到 `backend/data/`。
- 解析不了的规则让生成脚本失败并点名，不静默跳过。
- 规则原文有明显笔误的（目标列与文字不一致、长期应付款表写成「长期应收款」等）按目标格与表名纠正，纠正处逐条登记。

## R2 按项目取数（第一批）
- 后端按项目、年度读当前有效账套的客户科目余额表（`tb_balance`）与序时账（`tb_ledger`），经科目映射找到标准科目，再按规则里的明细科目名找到客户明细科目，取期初 / 借方发生额 / 贷方发生额 / 期末 / 按月发生额。
- 「底稿取数余额表」与「试算表」两种来源在本平台都按客户科目的账面数（未审数）取：底稿里「账载金额」列取账面数，「审计调整」「审核调整额」列由人工填写。
- 找不到科目时格子留空并说明原因（「未找到明细科目：XXX」），不写 0。
- 「末级科目 / 其他科目」类规则按客户明细科目逐行列出名称与金额；行数不够时超出部分合并进最后一行并注明。

## R3 `@说明` 规则（用户 2026-11-03 按建议采纳）
- 能按规则文字确定口径的照取，标「待确认」（格子着色 + 悬停显示规则原文），由审核人员确认或修改。
- 需要人工判断、账上分不出来的（如「含有非货币性资产交换特征」）不取数，标「需人工填写」并显示规则原文。

## R4 公式计算（第二批）
- 样表里的表内、表间公式（SUM / IF / IFERROR / MIN / MAX / SUMIF / AND / OR / ISNUMBER / ABS / ROUND / LEFT / COUNTA）在后端按 Excel 口径计算，取数结果与手工填写进入计算后显示在对应格子。
- 引用申报表（A 类 sheet）、索引页、参数页的公式照样计算（这些 sheet 一并纳入计算模型）。

## R5 表头信息（第二批）
- 「填写参数」页的被审核单位、统一社会信用代码、法定代表人、期间、编制人、复核人、编制日期、复核日期、报告号、行业 / 企业类型等，默认取项目信息（被审核单位 = 客户名称、法定代表人、期间 = 审核年度 + 「年度」），可在页面上修改并保存，修改后全部底稿表头跟着变。

## R6 手工填写与保存（第三批）
- 空白数据格、取数格可以手工填写；公式格不能改。
- 手工值覆盖取数值，可「恢复取数」。
- 保存按项目 + 年度 + 编号落库，带版本号，并发修改返回冲突提示不静默覆盖。
- 保存后重新计算并刷新页面。

## R7 约束
- 读接口项目只读权限、写接口项目编辑权限；新端点有接口级测试（未登录 401、无权限 403、有权限能用）。
- 新表走运行时迁移 V/R 配对，ORM / 迁移 / service 三层一致。
- 生成脚本幂等，`--check` 无差异 exit 0。
- 浏览器实测：取数、公式结果、表头、手工填写保存与刷新后读回。
