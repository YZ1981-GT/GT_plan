# K 类底稿（管理循环）— 需求文档

## 1. 概述

K 类底稿覆盖"实质性程序—管理循环"阶段（审计循环代号 K），根据 B50 风险评估结果和 C11（管理循环）控制测试结论，执行实质性程序。包含 **13 大科目组 + 1 函证组、14 个模板文件、约 70+ 个子底稿 sheet**。

K 类涵盖"其他"类科目（其他应收款/其他应付款/其他流动资产/负债/预计负债/持有待售/递延收益）以及管理费用/销售费用/营业外收支等。K5（预计负债）涉及或有事项判断，K8/K9（费用明细）需从 tb_ledger 取数。

## 3. 术语表

- **管理循环系统（Management_Cycle_System）**：平台中负责 K 类底稿的子系统
- **预计负债（Provisions）**：因过去事项产生的、金额或时间不确定的负债（K5）
- **或有事项（Contingencies）**：可能导致经济利益流出的不确定事项
- **持有待售（Held_for_Sale）**：拟在一年内出售的非流动资产/处置组（K6）

## 5. 各组详细需求

### K0: 管理循环函证
与 D0/E0/F0/G0/H0 模式一致。K0→ConfirmationHub（cycle=K），K0-1~K0-5 用 `d-form-table`。

### K1: 其他应收款
**需求：** K1A程序表 + K1-1审定表 + K1-2明细 + K1-3账龄分析 + K1-4坏账准备 + K1-5检查 + K1-6调整分录

### K2: 其他流动资产
**需求：** K2A程序表 + K2-1审定表 + K2-2明细 + K2-3检查 + K2-4调整分录

### K3: 其他应付款
**需求：** K3A程序表 + K3-1审定表 + K3-2明细 + K3-3账龄分析 + K3-4检查 + K3-5分析 + K3-6调整分录

### K4: 其他流动负债
**需求：** K4A程序表 + K4-1审定表 + K4-2明细 + K4-3检查 + K4-4调整分录

### K5: 预计负债（或有事项）
**需求：** K5A程序表 + K5-1审定表 + K5-2明细 + K5-3或有事项评估 + K5-4最佳估计数计算 + K5-5律师函回函分析 + K5-6调整分录
- K5-3 或有事项评估（三级可能性判断：很可能/可能/极小可能）→`d-form-table`
- K5-4 最佳估计数计算（上下限+加权平均）→`audit-sheet`
- K5-5 律师函回函分析→`d-form-table`

### K6: 持有待售资产和负债
**需求：** K6A程序表 + K6-1审定表 + K6-2明细 + K6-3分类条件检查 + K6-4调整分录
- K6-3 持有待售分类条件（CAS42 五条件）→`d-form-table`

### K7: 递延收益
**需求：** K7A程序表 + K7-1审定表 + K7-2明细 + K7-3政府补助分摊 + K7-4调整分录

### K8: 销售费用
**需求：** K8A程序表 + K8-1审定表 + K8-2明细（**从 tb_ledger 取发生额**）+ K8-3分析 + K8-4检查 + K8-5大额检查 + K8-6调整分录
- K8-2 需要从 tb_ledger 按明细科目取数→`audit-sheet`
- K8-3 分析（同比/环比趋势+异常波动识别）→`audit-sheet`

### K9: 管理费用
**需求：** K9A程序表 + K9-1审定表 + K9-2明细（**从 tb_ledger 取发生额**）+ K9-3分析 + K9-4检查 + K9-5大额检查 + K9-6调整分录
- K9-2 需要从 tb_ledger 按明细科目取数→`audit-sheet`

### K10: 其他收益
**需求：** K10A程序表 + K10-1审定表 + K10-2明细 + K10-3政府补助验证 + K10-4调整分录

### K11: 资产减值损失
**需求：** K11A程序表 + K11-1审定表 + K11-2明细 + K11-3减值测试汇总 + K11-4调整分录

### K12: 营业外收入
**需求：** K12A程序表 + K12-1审定表 + K12-2明细 + K12-3检查 + K12-4调整分录

## 7. 技术约束

- wp_code 规则：K0~K13 共 14 组
- componentType：或有事项/分类条件→d-form-table，费用明细/分析→audit-sheet
- 审定表回写正则：`^K\d+-1$` 匹配 K1-1~K13-1（13 个审定表）
- K8/K9 费用明细取数：auto_data_source 从 tb_ledger 获取明细科目发生额
