# 需求：两个税审案例全链路取数排查与修复

来源：用户 2026-11-03 提供两个案例（输入账套 + 期望底稿 + 期望四件报告），要求从导入账套到出报告逐段排查取数问题并按建议修改。

- 案例 1（六部 / 平台项目「ABC餐饮有限公司」）：审计软件导出的科目余额表 + 序时账，企业会计制度科目体系
- 案例 2（激光科技 / 平台项目「北京GGGGGG激光科技有限公司」）：SAP 导出的「终审余额表」+「1-11 月序时账」+「12 月序时账」三个文件，10 位平铺科目码

## 排查结论（证据见 design §1）

模型本身可信：用案例底稿的填写值跑平台计算模型，案例 1 申报表 403 格一致 401、案例 2 483 格一致 481。全链路失真全部出在「取数」之前或取数本身：

| 层 | 问题 | 影响 |
|---|---|---|
| 导入 | R1 列映射页确认 / 修改的映射没被 pipeline 用（读 `mappings`，前端发 `mapping_entries`），一律按自动识别 | 用户改不对识别错的列 |
| 导入 | R2 中文 4 字表头编辑距离 2 即算命中：过账代码/原因代码→科目代码、凭证名称→科目名称、业务范围→业务日期、累计余额→期初余额、凭证种类/业务说明→凭证日期 | 案例 2 序时账科目码变成 40/50、金额全空；余额表整表丢弃 |
| 导入 | R3 不认 SAP 导出：总账科目 / 短文本 / 已结转余额 / 累计余额 / 单金额列 + 借/贷标识 S、H / 期间「2025.011」 | 只上传用户说的三个文件时，余额表 0 行、序时账全是垃圾行 |
| 导入 | R4 余额表「借贷方向 + 带符号金额」读丢符号（贷 → -abs） | 案例 1 进项税额、住房公积金、利润分配反向；父子科目对不上 2 处 |
| 试算表 | R5 贷方科目未审数取 abs，借方余额（累计亏损、留抵）变正数 | 案例 1 资产负债表差 19,469,933.96；案例 2 未分配利润 6,388 万亏损变成正数 |
| 底稿取数 | R6 收入 / 成本分类表只认名字叫「其他」的明细，客户明细叫不上类别名的整笔丢掉 | 案例 1 营业收入 43.8 万（应 3,859.9 万）、成本 0、利润总额 -2,384 万；案例 2 收入成本 0 |
| 底稿取数 | R7 平铺科目表（SAP 10 位码、名称里带「一级-明细」、无上级行）取不到明细 | 案例 2 福利费、公积金、固定资产分类、其他业务收入、营业外收支全空 |
| 底稿取数 | R8 一级科目本身没有下级时，「其中」明细 / 「其他」类别列表为空 | 案例 2 其他收益 4 万丢失；案例 1 固定资产整笔不进折旧表 |
| 底稿取数 | R9 企业会计制度把工会经费挂在其他应付款，规则只在应付职工薪酬下找 | 案例 1 职工薪酬多调增 189,928.20 |
| 底稿取数 | R10 「处置非流动资产损失」与「非流动资产处置损失」字序不同认不出 | 案例 1 营业外支出 8,778.73 进了「其他」 |
| 审核说明 | R11 样表资产损失段写死「XX元」 | 报告出现字面「XX元」 |
| 导入 | R3b（实施中发现）合并单元格向下填充把合计行（科目为空）填成上一行科目 | 案例 2 余额表多出 6711030000 借贷各 1.58 亿一行 |
| 取数 / 试算表 | R12（实施中发现）没结转的损益科目（SAP）对方发生额是冲减，只取本方向发生额 | 案例 2 主营业务成本取 14,502,719.31，底稿未审数 12,392,785.55 |
| 底稿取数 | R13（实施中发现）事业单位 / 民非专用表（2-01（3)、2-04（3)）规则含企业同名科目（投资收益、管理费用），企业账套也取数 | 案例 2 投资收益填进事业单位收入表，广告费扣除基数多 323.26 |

## 本次修改范围

R1~R11 全部修。不改：审计判断类差异（餐饮收入算劳务还是其他、个税手续费返还算不算政府补助、按凭证摘要拆其他收益、案例 2 底稿里手工录入的审计调整与重分类、案例 2 改过的弥补亏损公式），在报告里逐条说明。

## 验收

- V1 只用用户说的文件重跑导入识别：案例 2 三个 SAP 文件余额表 85 行、序时账 9,459 行，借贷合计与源文件一致；案例 1 父子科目 0 处不一致
- V2 平台取数全链（导入 → 取数 → 模型）对案例成品：营业收入、营业成本、利润总额、纳税调整增减、应纳税所得额与案例一致（案例 2 以未审数口径对照，审计调整差额单列）
- V3 单体财务报表（企业会计制度）案例 1 资产负债表平衡，未分配利润 -5,010,411.91
- V4 改动涉及模块的既有测试全部通过，新增测试覆盖 R1~R11
