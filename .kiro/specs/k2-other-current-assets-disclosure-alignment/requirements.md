# Requirements Document

K2 其他流动资产 披露表 ↔ 附注对齐

## Introduction

K2「其他流动资产」的两个披露底稿 Tab（上市 / 国企）与附注 §五、13 / §八、14 存在结构性偏离：底稿列结构是自造的「变动矩阵」（期初 / 增加 / 减少 / 期末 / 占比 / 备注），而源模板与附注模版都是「项目 / 期末 / 期初」三列明细列示表；附注上市侧另有两张条件性披露表（合同取得成本、碳排放配额变动）在底稿侧完全缺失。

### 三源实证（2026-07-30）

**源 xlsx**：`backend/wp_templates/K/K2 其他流动资产.xlsx`，两个披露 sheet 皆 `A1:M13`。

| sheet（tab 名） | 标题行 | 表头 | 数据行 | 蓝字要求 |
|---|---|---|---|---|
| `附注披露信息（上市公司）` | 其他流动资产（注：根据实际情况列示；不存在的项目请删除） | 项 目 / 期末数 / 期初数 | A7:A11 引 `='明细表K2-2'!A11~A14,A17`（红字=可改名占位）+ A12 `合 计`=SUM | A13「（金额较大的其他流动资产，应说明其内容、性质）」 |
| `附注披露信息（国企）` | 其他流动资产 | 项 目 / 期末账面价值 / 年初账面价值 | A8:A12 同上 + A13 `合 计`=SUM | A6「（根据性质选择披露方式）」 |

**附注模版**（`note_template_listed/soe.json`，交付物权威）：

- §五、13：3 张表 —— ①其他流动资产（项目/期末余额/上年年末余额，13 固定行+合计）②合同取得成本变动（转置：行=期初余额/本年增加/本年摊销/本年计提减值损失/期末余额，列=资产主要类别+合计）③碳排放配额变动（项目/本期发生额/上期发生额，10 行）；`text_sections` 10 条。
- §八、14：1 张表（项目/期末余额/期初余额，8 固定行+合计）；`text_sections` 1 条。

**校验预设**（`note_check_preset_formulas.json`，裁决者）：`F13-1` 报表期末=①合计行期末余额；`F13-1a` 报表期初=①合计行期初余额；`F13-2` sum(明细行)=合计行（逐列）。表②③无预设 → 条件性披露表。

### 裁决结论

附注是交付物 → **列结构与行名随附注模版**；源 xlsx 决定「底稿只有一张明细表 + 数据来自 K2-2」的取数逻辑；表②③是上市条件性披露，底稿需提供录入入口但可关闭。

## Glossary

| 术语 | 含义 |
|---|---|
| 条件性披露表 | 源 xlsx 无、附注模版有的表；项目不存在该业务时不披露（源模板「不存在的项目请删除」） |
| 转置结构 | 行为变动项目、列为资产主要类别的表（附注 §五、13 表②） |
| `_removed_table_keys` | 同步载荷元数据键，令后端删除附注侧已废止/未推送的子表名 |
| `flat` | `ColumnDef` 显式单级表头声明，抑制后端 `_infer_groups_from_headers` 前缀推断 |
| 固定行 | 行名取自附注模版、不可改名不可删除的行 |

## Requirements

### 需求 1：底稿披露表列结构对齐附注模版

**用户故事**：作为审计助理，我在 K2 披露 Tab 录入的列结构要和最终附注一致，避免同步后表头错位或数据落空。

#### 验收标准

1. WHEN 打开上市披露 Tab THEN 主表列为「项目 / 期末余额 / 上年年末余额」三列，不含占比、备注、本期增加、本期减少。
2. WHEN 打开国企披露 Tab THEN 主表列为「项目 / 期末余额 / 期初余额」三列，不含本期增加、本期减少、变动原因。
3. WHEN 渲染主表行 THEN 行名取自附注模版固定行（上市 13 行、国企 8 行）+ 合计行，不使用自造行名（`预付款项-待转` / `理财产品` / `待摊费用` 等）。
4. WHERE 项目实际存在模版未列示的其他流动资产 THE SYSTEM SHALL 支持经 `ElMessageBox.prompt` 命名后新增明细行。
5. WHEN 合计行渲染 THEN 其值为各明细行之和（只读公式列，虚线下划线 + tooltip 说明来源）。

### 需求 2：上市侧补齐两张条件性披露表

**用户故事**：作为现场经理，我要能在底稿里录合同取得成本与碳排放配额的披露数据，而不是等到写附注时手工补。

#### 验收标准

1. WHEN 上市披露 Tab 渲染 THEN 存在「合同取得成本」区块，行为期初余额 / 本年增加 / 本年摊销 / 本年计提减值损失 / 期末余额，列为资产主要类别（默认「佣金支出」，可增删改名）+ 合计。
2. WHEN 类别列数值变化 THEN 合计列 = 各类别之和；期末余额行 = 期初余额 + 本年增加 − 本年摊销 − 本年计提减值损失（公式行只读）。
3. WHEN 上市披露 Tab 渲染 THEN 存在「碳排放配额变动情况」区块，10 个固定行名逐字取自附注模版，列为「项目 / 本期发生额 / 上期发生额」。
4. WHERE 本项目不存在合同取得成本或碳排放权资产 THE SYSTEM SHALL 提供区块启用开关（对应源模板「不存在的项目请删除」），关闭时同步不推该表并将表名列入 `_removed_table_keys`。

### 需求 3：文本框内容取自附注模版而非自造标题

**用户故事**：作为业务合伙人，我要底稿文本框的提示与附注最终正文口径一致。

#### 验收标准

1. WHEN 上市披露 Tab 渲染 THEN 文本区分三段：金额较大项目的内容与性质说明、合同取得成本的判断与摊销方法说明、碳排放权相关信息说明；每段标题行右侧均有 AI 辅助按钮。
2. WHEN 国企披露 Tab 渲染 THEN 文本区为一段「其他流动资产说明」，方法论上下文引用源模板「（根据性质选择披露方式）」与附注模版【提示：…】原文。
3. WHEN 文本同步到附注 THEN 经 `_note_texts` 推送，附注 `text_content` 呈现 `【段标题】\n正文`。
4. THE SYSTEM SHALL NOT 自造披露正文；AI prompt 须写明源模板 / 15 号文口径与「不得虚构」约束，长度 ≥20 字。

### 需求 4：附注模板结构修订

**用户故事**：作为质量控制复核合伙人，我要附注 TAB 的表名、列头、编制提示都能追溯到源模板。

#### 验收标准

1. WHEN 修订 §五、13 THEN 表②名由段落文本泄漏值 `[披露与合同取得成本有关的资产相关的信息…例如：` 改为 `合同取得成本`，说明文本移入 `guidance`。
2. WHEN 修订 §五、13 THEN 表③名由表头首格泄漏值 `项  目` 改为 `碳排放配额变动情况`，并删除 `row_type: header_label` 假数据行。
3. WHEN 修订 §五、13 表② THEN `headers[0]` 由 `[佣金支出]` 修正为 `项目`（md 重建丢失的标签列），类别列 seed 为 `佣金支出`。
4. WHEN 修订完成 THEN §五、13 的 3 张表与 §八、14 的 1 张表全部带 `columns`（显式 `flat`，源模板为单行表头）与 `guidance`。
5. THE 修订 SHALL 做成幂等脚本 `backend/scripts/fix/fix_note_k2_structure.py`，支持 `--dry-run` / `--check`，并写 `_aligned_by` 标记。

### 需求 5：同步链路口径修正

**用户故事**：作为审计助理，我要附注里点「打开同步底稿」能准确跳回 K2 的披露 sheet。

#### 验收标准

1. WHEN 构建同步载荷 THEN `sheet_name` 逐字等于源 xlsx tab 名 `附注披露信息（上市公司）` / `附注披露信息（国企）`（**全角括号**）；现值为半角，属漂移。
2. WHEN 构建同步载荷 THEN 每张表的 `columns` 至少一列带 `flat: true`（源模板单行表头，抑制后端前缀推断）。
3. WHEN 表名变更或区块关闭 THEN 载荷携 `sub_table_data._removed_table_keys`，含历史表名与本次未推送的表名。
4. WHEN 修改 `K2_DISCLOSURE_SHEET_NAME` THEN 重跑 `python backend/scripts/gen_note_wp_sync_registry.py --write` 使 registry 同步。

### 需求 6：守卫与实测

**用户故事**：作为 EQCR 技术复核人，我要这次对齐有自动化守卫，不会被下一次 md 重建或并发会话回退。

#### 验收标准

1. THE SYSTEM SHALL 提供 `k2NoteSubtableContract.spec.ts`，经共享 helper `runDisclosureSubtableContract` 覆盖 P1~P5。
2. WHEN 新增 `buildK2ListedColumns` / `buildK2SoeColumns` THEN 在 `disclosureColumnsCoverage.spec.ts` 的 `P1_ROUTE` 登记。
3. THE SYSTEM SHALL 提供后端 `test_note_k2_structure.py` 锁住模板修订结果（表名 / 列数 / flat / guidance / 无假数据行）。
4. WHEN 实现完成 THEN 经浏览器实测「录入 → 自动同步 → 附注章节落库」，以 `disclosure_notes.table_data` 的 `sub_table_data` / `_sub_table_columns` / `_last_sync_at` / `text_content` 为准。
