# 需求：TB 重分类自动保存与合并汇总穿透收口

## 背景

`excel-style-table-editing` 已统一格内编辑，但 TB 重分类格提交后仍需点“保存”或 Ctrl+S；合并页“汇总穿透”会把刚建立的右键目标覆盖成占位值并提前返回。本 spec 只修这两个已确认缺陷。

## R1 TB 重分类提交即保存

1. 用户提交普通数据行的重分类借方或贷方后，系统应在 200ms 内排入自动保存；同一窗口多格只写一次。
2. Enter、Tab、失焦、粘贴、Delete、撤销和重做产生的最终提交均应走同一保存入口；Esc、未改值、分类行、合计行、无编辑权限或无审计年度不得写入。
3. 自动保存应保留当前编辑模式，不逐格弹成功消息；界面应显示“自动保存中 / 自动保存失败”。
4. 自动保存失败不得谎报成功或丢弃用户输入；版本冲突不得无 CAS 重试覆盖他人数据。

## R2 保存正确性与并发

1. 同一工作表任一时刻最多一个 PUT；飞行中继续编辑应进入下一批，并使用上一批响应的新版本。
2. 每批必须冻结项目、年度、期间、报表类型、sheet key 与行快照，切换上下文后不得把旧数据写到新表。
3. 加载成功时应记录版本；加载失败或版本未知时应阻止自动覆盖。
4. 新增的手工重分类标记应只覆盖用户实际编辑的格；未编辑的 RJE 继续以已审批调整分录的计算结果为准。旧存量数据保持原兼容读法。

## R3 显式保存兼容

1. 工具栏“保存”和 Ctrl+S 应与自动保存共用同一串行队列，并等待最新 revision 落库。
2. 只有显式保存成功才退出 TB 编辑模式并提示“试算平衡表已保存”。
3. 原有未审数、期初表和手工断开公式的显式保存能力不得退化。

## R4 合并汇总穿透

1. TB 与普通合并报表右键时应创建不可变目标快照，至少包含来源、row code、report type、node key、期间、标题和值。
2. 打开穿透不得覆盖目标，也不得从旧选区首格反推行身份；TB 不依赖合并报表是否已加载。
3. 当前期请求应使用本次右键行及页面真实节点；真实零与空值必须区分。
4. 快速连续查看时旧响应不得覆盖新目标；切项目、年度、Tab、报表类型或节点应使旧目标失效。
5. 上期数仍不按当前企业树分解，应给出中文说明且不误发当前期请求。

## R5 验收

1. 行为测试与故障注入必须覆盖合批、串行 CAS、失败保留、上下文隔离、目标快照、零值、上期限制和陈旧响应。
2. 相关测试、SFC 编译、单区域类型检查和 ESLint 不得新增失败。
3. 浏览器只用【测试】项目验证自动保存刷新回读、显式保存兼容、TB / 合并报表穿透请求与 direct / leaf 数据；写入数据验收后恢复。

## 非目标

- 不把手工重分类改造成 Adjustments 模块的 RJE 分录，不改变审批链与会计权威源。
- 不新增数据库迁移；沿用 `consol_worksheet_data` 的整数 CAS。
- 不新增上期企业树分解、权益变动表 / 减值表汇总穿透或数据节点分摊能力。
