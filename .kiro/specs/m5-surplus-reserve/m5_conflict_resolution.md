## 2. 权益类方向确认

### xlsx证据
明细表M5-2公式:
- `G12 = B12 + C12 - E12` → **期末 = 期初 + 贷方(增加) - 借方(减少)**
- 附注公式: `E7 = B7 + C7 - D7` → **期末 = 期初 + 增加 - 减少**（同向）
- 审定表M5-1从M5-2引用，结构一致

### md证据
明细表M5-2列结构:
- `期初数 | 本期增加(金额/增加方式) | 本期减少(减少方式) | 期末数`
- 提示第2条: "《公司法》第一百六十七条...应当提取利润的百分之十列入公司法定公积金"

### 交叉验证

| 验证点 | xlsx | md | 一致性 |
|--------|------|-----|--------|
| 科目方向 | 贷方（期末=期初+贷方-借方） | 权益类（增加在贷方） | ✅ 一致 |
| 增加方向 | C列=贷方增加（计提） | 本期增加=计提 | ✅ 一致 |
| 减少方向 | E列=借方减少（转增/弥补） | 本期减少=转增资本/弥补亏损 | ✅ 一致 |
| 期末公式 | G=B+C-E | 期末=期初+增加-减少 | ✅ 一致 |

**结论**: ✅ **权益类贷方科目方向完全一致**。设计文档ADR-1正确：期末=期初+贷方-借方。

## 3. 法定盈余公积10%计提规则

### xlsx证据（M5-4 计提检查表）
```
row8:  表头（法定盈余公积 / 任意盈余公积 / 合计）
row9:  本年净利润（B9=法定, C9=任意, D9=B9+C9）
row10: 弥补以前年度亏损（同结构）
row11: 计提基数 = 净利润 - 弥补亏损（B11=B9-B10, C11=C9-C10, D11=B11+C11）
row12: 计提比例（值=0.1，即10%）
row13: 应计提 = 基数 × 比例（B13=B11*B12, C13=C11*C12, D13=D11*D12）
```

### md证据（M5-4 盈余公积计提检查表）
```
项目内容           | 未审金额 | 审计调整 | 审定
一、本期净利润：   |          |          | 0
减：弥补亏损       |          |          | 0  
二、弥补亏损后盈余公积计提基数  | 0 |    |
计提比例           | 0.1      |          |
三、本期应提取盈余公积          | 0 |    |
```
md编制说明第3条: "《公司法》第一百六十七条　公司分配当年税后利润时，应当提取利润的百分之十列入公司法定公积金。"

### 交叉验证

| 验证点 | xlsx | md | 一致性 |
|--------|------|-----|--------|
| 计提基数来源 | 净利润 - 弥补亏损 | 弥补亏损后盈余公积计提基数 | ✅ 一致 |
| 法定计提比例 | 0.1 (10%) | 0.1 (10%) + 公司法167条引用 | ✅ 一致 |
| 应计提公式 | 基数 × 比例 | 计提基数 × 计提比例 | ✅ 一致 |
| 法定vs任意分列 | B列=法定, C列=任意, D列=合计 | md仅展示单列（简化结构） | ⚠️ 细粒度差异 |

**差异说明**: xlsx将法定/任意/合计分为3列并行计算，md以单列展示简化结构。**以xlsx列结构为准**（列名/分列方式），md的业务逻辑（10%比例+公司法引用）为补充。

**结论**: ✅ **法定10%计提规则完全一致**。设计文档Requirement 4正确。

## 5. M6-M1联动关系

### M6→M5方向（M6净利润 → M5计提基数）

#### xlsx证据
M5-4 row9"本年净利润"在xlsx中为**手工输入单元格**（无公式引用M6）。传统Excel模板中M5-4的净利润是由审计人员从M6底稿手工抄录。

#### md证据
M6-2未分配利润明细表:
```
四、本期净利润 | (审定数)
五、利润分配
  1、提取法定盈余公积 | 0
  2、提取任意盈余公积 | 0
  3、应付现金股利     | 0
```

M5-4计提检查表:
```
一、本期净利润：(来自利润表/M6审定)
```

**联动逻辑**: M6确定本期净利润 → M5-4接收作为计提基数的输入 → M5计提结果回流M6（作为"提取法定盈余公积"行）

#### 交叉验证

| 验证点 | xlsx | md | 设计方案 |
|--------|------|-----|----------|
| M6→M5数据流 | 手工抄录（无跨workbook公式） | 语义关联（M6净利润→M5计提基数） | EventBus 'm6:net-profit' |
| M5→M6数据流 | 无直接引用 | M6明细"提取法定盈余公积"行 | EventBus反向通知 |
| M5→M1联动 | 无直接引用 | M6明细"应付现金股利"→M1 | 通过M6中转，非M5直接联动M1 |

### M5→M6方向（M5计提 → M6可供分配利润）

#### md证据
M6-2明细表中"五、利润分配 → 1、提取法定盈余公积 / 2、提取任意盈余公积"明确显示：M6的可供分配利润要减去M5计提数。

### M5→M1联动

**重要发现**: xlsx和md中M5与M1**无直接联动**。联动路径是:
- M5审定(盈余公积计提) → M6(利润分配-提取盈余公积) → M6(应付现金股利) → M1(应付股利)
- 即 M5↔M6↔M1 是**两跳**，非直接联动

**结论**: 
- ✅ M6→M5联动: md权威确认，前端实现EventBus订阅'm6:net-profit'正确
- ✅ M5→M6联动: md权威确认，M5计提结果发布给M6用于计算可供分配利润
- ⚠️ **M5→M1**: 设计文档提及"联动M1股利分配"实际是**通过M6中转**，非直接EventBus。建议设计文档中将M1联动标注为"间接(经M6中转)"

## 7. 明细表M5-2列结构对比

### xlsx M5-2 (38×17)

### md M5-2 列头描述
```
明细项目 | 未审数(期初/本期增加-金额-增加方式/本期减少-减少方式/期末) | 账项调整 | 重分类调整 | 审定数(本期增加/本期减少) | ...
```

### 交叉验证

| 验证点 | xlsx | md | 一致性 |
|--------|------|-----|--------|
| 总列数 | 17列(A~Q) | md表格~17列（含合并） | ✅ 一致 |
| 未审区块 | B(期初)/C(贷方增加)/E(借方减少)/G(期末) | 期初/本期增加/本期减少/期末 | ✅ 一致 |

| 行项目 | 法定/任意/利润归还投资/其他/合计(4数据行+1合计) | 同 | ✅ 一致 |

**结论**: ✅ **明细表结构完全一致**。xlsx有更精细的列拆分（H~M分6列展示AJE/RJE明细），md用分组表达。

## 12. 附注补充规则（md独有）

来自md M5-2编制说明（xlsx无对应公式但为重要业务规则）:

1. **公益金制度**: 2006年1月1日起不再提取公益金，旧余额转盈余公积管理
