# 需求：账号「允许修改」开关

来源：用户 2026-11-04「做成一个修改配置，可以控制能否修改，可以放到账号权限里面加一列」。承接 `citar-table-manual-edit`（表格数据都可人工修改）。

## 需求

- R1 账号权限页（用户管理）加一列「允许修改」，管理员逐个账号开 / 关，即时保存；改动记安全审计。已有账号与新建账号默认允许（行为不变）。
- R2 关闭后，该账号不能人工修改自动生成的数据，界面不给修改入口、后端拒收（403，提示去「账号权限」开启）：
  - 税审底稿 / 汇算申报表：公式格、自动取数格（「需人工填写」的除外）、样表预置数字，含「恢复自动值」；
  - 报告正文摘录表金额、审核说明段落（改 / 删 / 恢复）、审定报表金额、单体财务报表金额；
  - 科目余额表、序时账的行修改与恢复；
  - 试算平衡表点审定数生成调整分录草稿（界面入口；调整分录页本身照常）。
- R3 关闭后照常可用：查看、导出、税审底稿手填格与「需人工填写」的取数格、表头信息、是否填报、报告日期、调整分录、科目映射、数据导入、生成报表。
- R4 别人保存过的手工值，未开通的账号保存同一张底稿时原样保留（只是不能改动它们）。
- R5 开关变化后，该账号进入项目时重新读取账号信息，不必重新登录。

## 验收

- V1 后端：未开通账号改公式格 / 自动取数格 / 恢复他人手工值 → 403；改手填格、保留他人手工值 → 200；四个只做人工修改的接口与余额表 / 序时账写接口 → 403；用户接口能改、能读回、记审计。
- V2 前端：用户管理开关只发 `allow_manual_edit`；表格组件未开通时公式格不能点开、手填格照常。
- V3 浏览器实测：管理员关掉自己的开关 → 各页无修改入口 → 打开恢复，实测后复原。

## 修订（用户 2026-11-04 第二条：「关闭之后，不允许表格中的数据显示编辑手填格，不显示关于修改和保存的按钮。以及不允许编辑底稿中的文档，并不显示编辑相关的特效」）

R2 / R3 / R4 / V1 / V2 中「手填格照常可填、只拦自动生成的数据」作废，改为：

- R2′ 关闭后该账号只能查看。全部表格（税审底稿 / 汇算申报表所有格子，含手填格与「需人工填写」格；底稿中的文书类表如 1-01 正式报告、1-10 委托方声明书同样）、底稿表头信息、是否填报、报告日期与摘录表金额、审核说明、审定报表、单体财务报表、科目余额表 / 序时账、试算表生成调整分录、调整分录（新增 / 编辑 / 删除 / 导入）、科目映射（新增 / 修改 / 智能匹配）一律不可改，后端拒收（403）。
- R2″ 界面不显示修改 / 保存 / 放弃修改 / 恢复 / 删除 / 导入 / 新增类按钮，也不显示编辑效果：可点高亮、悬停描边、文本光标、编辑框、勾选框、日期框，以及「点击修改」「可手工修改」类提示文字。数据本身的标记（取数状态底色、手工修改标记与原值）照常显示。
- R3′ 照常可用：查看、导出、刷新 / 智能取数 / 重新计算 / 智能生成、生成报表、重算试算表、数据导入（账套）、调整分录的提交复核 / 复核 / 撤回复核（属复核流程，由复核权限控制）。
- R4 作废（整表只读后不存在「保留他人手工值」的场景）。
- V1′ 后端：未开通账号对上述全部写接口 403（含手填格、表头信息、是否填报、报告日期、调整分录增删改与导入、科目映射写接口），数据不动；开着的账号照常（对照）。
- V2′ 前端：表格组件未开通时任何格子都不可点、不出编辑框、提示中没有「可修改」字样。
