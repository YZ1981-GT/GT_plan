# 附注模板按四版 Word 重新对齐 + 存量项目修复 + 编辑留痕补齐 + 大模型改为手动 + 和平药房重建

## 1. 背景

用户 2026-10-16 拍板（原话）：「你先需要按四版word来修复json，并修复现有的附注模块下的章节和表格样式等；其他模块以用户身份改附注时，不更新「最近一次编辑」这个要补。交付模块会单独开任务修复，你这里不可以不用管。LLM只支持用户手动单击时调用。和平药房需要清理就数据，或者可以先清空现有数据，重新根据四表库生成新的数据。」

来源：`disclosure-note-doc-upload-and-batch-fill` 的「Word 权威比对」（2026-10-14）与第 23 / 24 / 26 / 27 组登记的待拍板项。上一 spec 明确不改结构模板（会改全部项目的章节编号），故另立本 spec。

## 2. 权威与口径

- 权威 = 四版 Word：`backend/data/audit_report_templates/disclosure_notes/{soe,listed}_{standalone,consolidated}.docx`。本 spec 不改这四份文件。
- 章 = Heading 1；节 = 国企 Heading 2∪3、上市 Heading 2（`note_section_kind.SECTION_HEADING_LEVELS`）；更深的标题是节内小标题，不是节。
- 标题比对口径 = `note_section_kind.normalize_title`（去【…】批注、空白、前导序号、尾部（…）、末尾冒号）。
- 种子 = `backend/data/note_template_{soe,listed}.json`：每个准则一份，按节的 `scope` 派生单体 / 合并两个口径。`section_number`（库内 `disclosure_notes.note_section`）是章节标识，显示编号按位置计算（`note_section_numbering`）。

## 4. 用户故事与验收标准

### US-1 种子章节树与四版 Word 一致

- AC-1.1 四个口径按 scope 派生的章节树与该口径 Word 一一对应：章名、章序、节名、节所属章、节序一致。对不上的只允许出现在比对工具的显式白名单中，每条写明理由。
- AC-1.2 节放错章：改挂到 Word 所在章，编号前缀改为新章号；旧编号记入该节 `legacy_section_numbers`，`normalize_section_code` 把旧编号归一为新编号（两个准则都适用）。`section_id` 不变。
- AC-1.3 Word 有、种子无的节补入种子（标题、正文模板段落、表格按 Word 生成），编号取该章未用过的编号；已有编号不重排。
- AC-1.4 只在合并版 Word 出现的节 `scope=consolidated_only`；单体、合并都出现的 `both`；只在单体版出现的 `standalone_only`。章名随口径不同时（上市「财务报表项目附注」/「合并财务报表项目附注」）按口径取名。
- AC-1.5 种子有、Word 无的节：提示语误做成的节删除；「X、1 章名」章正文叶子保留（它是章正文的载体），比对把它对应到所属章。
- AC-1.6 比对工具可重跑，输出确定（无时间戳）；`--check` 有白名单外差异时 exit 2 并逐条点名。

### US-2 种子表格与四版 Word 一致

- AC-2.1 对上的节逐张比对：表格数量与顺序、表名、列数、叶子表头、多级表头分组、行标签。差异逐条列出。
- AC-2.2 修复只改与 Word 不一致的展示结构，保留种子里 Word 没有的机器字段（列 key、format、row_type、is_total、report_row_code、account_codes、勾稽 / 公式预设）。列 key 变化时同步依赖它的绑定、公式、勾稽。
- AC-2.3 种子派生数据（编号索引、绑定、公式数据、国企↔上市差异、共享表段、章节类型索引、底稿同步注册表、变体矩阵）重生成，各自的 `--check` 与守卫通过。

### US-3 存量项目附注章节与表格修复

- AC-3.1 修复工具先 dry-run 输出每个项目的计划（改编号 / 改父节点与顺序 / 改标题 / 补章节 / 调表格结构 / 脱树旧行），再备份、再写入。可重跑：写入后再 dry-run 计划为空。
- AC-3.2 改编号同步改：`disclosure_notes`（含已软删行）、`formula_push_state`（`note_section` 与 `addr_id`）、`note_section_instances`、未过期的 `note_section_locks`。历史留痕不改写：校验结果、批量写入明细、trace 事件、交付件章节状态。
- AC-3.3 用户内容不丢：正文、表格数值、本地改写标记、状态、编辑人原样保留。表格结构调整按「行标签 + 列」搬移数值，搬不过去的值写进报告，不丢弃。
- AC-3.4 脱树旧行（父节点不存在或编号不在种子里）逐项目列出：能确定对应种子节的按规则处置；不能确定的保留并在报告中标出，等用户确认。
- AC-3.5 目标项目：安徽、医疗器械、华氏、宜宾、首汽、测试集团甲 / 乙。和平药房走 US-6 重建。
- AC-3.6 修复后浏览器实测：编辑器章节树顺序与 Word 一致，表头与 Word 一致，抽查数值不变。

### US-4 其他模块以用户身份改附注时盖「最近一次编辑」

- AC-4.1 用户操作写附注时写 `updated_at` 与 `updated_by`（当前用户）：继承上年 / 从上年 Word 导入、集团基线下发、集团模板下发、三格式编辑保存、离线导入、单元格模式切换、回收站恢复、程序裁剪联动。
- AC-4.2 系统路径（生成、刷新、公式推送、过期标记、交叉引用重算）不盖用户编辑，也不得把已有编辑人改成 NULL。
- AC-4.3 AST 守卫覆盖 AC-4.1 的全部写入方，不只 `routers/disclosure_notes.py`。
- AC-4.4 盖章所在写入方自身的缺陷一并修：无鉴权、读不存在的属性、原地改 JSONB 不落库、按 ID 越权。否则盖章无从生效。

### US-5 大模型只在用户手动单击时调用

- AC-5.1 生成附注、刷新、校验、公式引擎等自动路径不调用大模型。生成正文顺序改为「上年附注 → 模板正文」。
- AC-5.2 用户手动入口保留：AI 续写 / 改写 / 生成政策 / 生成分析 / 检查、AI 填充、批量 AI 填充、AI 对话。
- AC-5.3 守卫：把大模型客户端换成计数桩跑完整生成附注，调用次数为 0；手动入口仍能调到。
- AC-5.4 生成确认框与说明文案和实际行为一致（不再提 AI 生成）。

### US-6 和平药房按四表重建附注

- AC-6.1 先备份 2025 年度全部附注（含软删行）与 `formula_push_state` 到 `backend/backups/`。
- AC-6.2 物理删除后按项目四表 / 试算表重新生成（不调大模型），再跑公式推送填数。
- AC-6.3 重建后章节树与国企单体 Word 一致、无脱树旧行；抽查科目数值与试算表 / 报表一致；浏览器实测。

## 5. 范围外

- 交付模块（模板块占位、回填、交付件版式与编号）：由 `deliverable-trio-generation-accuracy` 处理。其 Task 16「通用大模型提示词」在本 spec 之后只剩手动入口适用。
- 四版 Word 文件本身。
- 合并模块的合并附注模板（`consol_note_sections_*.json`）。

## 6. 非功能要求

- NFR-1 种子只经可重跑脚本修改（`--check` / `--write`），不手改。并发会话也在改种子：脚本对当前文件重放，改完即提交。
- NFR-2 真库写入：先 dry-run 报数，再备份，再写；每个项目一个事务，失败整项目回滚。
- NFR-3 编号变化后，旧编号在运行期经 `normalize_section_code` 仍可解析（上传文档、旧公式、旧前端映射不致断链）。
- NFR-4 每组修复：先红测、再修、做变异、更新 tasks.md、提交、经中转工作树推送。
