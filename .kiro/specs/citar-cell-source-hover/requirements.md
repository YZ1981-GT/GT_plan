# 需求：表格单元格悬浮显示数据来源（数据溯源）

用户 2026-11-05：「把表格中每个数据从哪里来的，鼠标悬浮的时候展示出来」。同日确认：
①账务查询的数据来自导入时的字段映射 ⇒ 悬浮显示映射信息；②卡片里的链接可点，跳到来源并定位；
③税审底稿取数口径按建议处理（卡片如实写「不含审计调整」，改口径另立 spec）；④报表相关接口的项目鉴权一起补。

现状核对（2026-11-05，只读探针）：
- 各表格只有浏览器原生悬停提示（`title`），写的是怎么改、取数规则原文，看不出数由哪些科目 / 格子组成。
- 税审底稿：后端算值时已有命中的客户科目（`RuleResult.nodes`）和公式原文（`wb.formula_text`），`compute_sheet` 没返回。
- 试算平衡表：`standard-view` 只给汇总数；旧接口 `/trial-balance/trace` 没有前端调用，不限末级、不看方向，与本页算法不一致。
- 报表：行上存了公式和 TB 科目码，没有每项金额；`drilldown` 只按科目精确匹配，合计行的构成为空。
- 账务查询：6 个 active 数据集都能经 `ledger_datasets.job_id → import_jobs.custom_mapping` 查到用户确认过的字段映射
  （文件 / sheet / 原表头 / 列号 → 标准字段）；导入行没有保存源文件行号。
- 全部项目只有 1 张已批准的调整分录（辽宁卫生服务_2025，2 行）。

## R1 通用悬浮卡片
1. 鼠标在有值的格子上停约 0.4 秒弹出卡片；移出格子后 0.2 秒内移入卡片不关闭；按 Esc、滚动、切页签时关闭；同一时间只显示一张。
2. 卡片内容：来源类型标签（智能取数 / 公式计算 / 手工修改 / 导入数据 / 按下级合计 / 样表预置 / 表头参数）、
   格子名称（表 · 行 · 列）、格值、来源说明、构成明细（每项名称 + 金额，最多 20 项，多出的写明还有几项）、
   合计与「＝ 格值」核对、说明 / 问题、跳转链接。
3. 能拆成线性构成的格子：各项之和必须等于格值（差额 < 0.005）；对不上时卡片写明差额，不隐藏。
   含 IF / MIN / MAX / ABS / ROUND 或两个引用相乘除的公式只列引用项和值，写明「非线性公式，不做合计核对」。
4. 手工值：显示自动值与两者差额；有修改人、修改时间的显示出来，没有的不编造。
5. 来源数据在第一次悬停这张表时才请求，同一张表缓存；表格数据刷新（保存 / 重算 / 生成）后作废重取。请求失败时卡片写明原因。
6. 去掉被卡片取代的原生 `title`，原来提示里的编辑说明（「点击修改」等）放进卡片，不叠两层提示。点击格子进入编辑的行为不变；编辑中的格子不弹卡片。
7. 卡片文字全中文；规则型来源写「智能」，不写「AI」。

## R2 链接可点，跳到来源并定位
1. 链接目标：科目余额表行（客户科目）、序时账（按科目筛选）、底稿映射（客户科目 → 标准科目）、试算平衡表行（标准科目）、
   调整分录（某组分录）、审定报表行、单体财务报表本页格子、税审底稿某格、汇算申报表某格、数据导入页。
2. 跳转后滚到目标并高亮：行级沿用 `.citar-located`，格级新增高亮样式；目标页找不到时提示原因，不静默。
3. 当前页有未保存的修改时，离开前先确认（沿用单体财务报表、税审底稿现有的确认做法）。
4. 新增定位入口：税审底稿 / 汇算申报表按「编号 + 格子」定位（编号不进路由 query，沿用 sessionStorage）；
   调整分录按分录组定位；审定报表按「页签 + 行」定位。

## R3 税审底稿与汇算申报表
1. 取数格：来源表与列（期末余额 / 本期借方发生额 / 本期贷方发生额 / 期初余额 / 某月借方…，中文写法）、科目路径、
   命中的客户科目（编码、名称、金额，各项之和 = 格值）、映射到的标准科目、取数状态（照取 / 待确认 / 需人工）、
   取不到的原因、样表取数规则原文（默认收起，可展开）。
2. 口径如实（用户 2026-11-05 选建议方案）：取数格写「科目余额表（导入数，不含审计调整）」；
   命中科目对应的标准科目有已批准调整分录时，列出这些分录并写明「未计入本格」；按回退科目取数时写明（如工会经费取其他应付款）。
3. 公式格：公式原文；引用的每一格写「编号 · 格子 · 行名」和当前值；引用他表的格子可点，跳到该格；
   区域引用展开（最多 20 格）；线性公式做合计核对；引用的表不在目录里显示时写明「该表不显示，只能经取数或手填」。
4. 手工值格：手工值和原公式值 / 原取数值 / 样表原值；本表最近保存人与时间（手工值不按格记人）。
5. 引用表头参数的格子：写「取自填写参数（未填时为项目信息）」。样表预置值写「样表预置」。

## R4 试算平衡表
1. 期初余额：由哪些客户科目汇总（科目余额表期初，经映射），各项之和 = 格值。
2. 本期借方 / 贷方：客户末级科目发生额汇总（经映射），各项之和 = 格值。
3. 借方 / 贷方审计调整：已批准的调整分录逐组列出（编号、摘要、金额，不含底稿来源），之和 = 格值；未批准的另列并写「不计入」。
4. 调整后期末 / 审定数：= 未审期末 + 借方调整 − 贷方调整 + 底稿发布调整，逐项列出；审定数与该式对不上时写明差额和「试算表需重算」。
5. 「底稿取数余额表」页签同理（本期借贷含调整，期末为审定数）。
6. 页脚说明「底稿取数读的就是这一列」改准确：平台审计底稿读这一列；税审底稿取数读科目余额表（导入数，不含审计调整）。

## R5 审定报表 / 报表分析 / 单体财务报表
1. 本期：公式原文 + 逐项：TB 项写标准科目（含按前缀并入的下级科目）、取的列（审定数 / 未审数 / 期初余额）、金额与正负号；
   ROW / SUM_ROW 项写被引用行的行名与值（可点，跳到该行）；未结转损益（PL_UNCLOSED）写金额与含义；ADJ 写调整净额；
   NOTE / WP 写来源与值；报表生成时恒按 0 的 PREV / AUX 写明「报表生成时按 0」。线性公式做合计核对。
2. 上期 / 期初：写明来源——本年试算表期初（资产负债表）/ 本项目上年试算表 / 上年项目「X」的报表同行 / 上年项目试算表 / 无来源（附原因）；
   取本年期初或本项目上年时同样逐项拆分。
3. 未审报表（报表分析「未审」「对比」）按未审口径拆分；对比模式的「调整」列写明 = 审定 − 未审，两边各自可悬停。
4. 手工值：手工值、自动值、修改人、修改时间（`manual_amounts.by / at`）。
5. 报表行在库里的值与按当前试算表重算的值不一致时，写明「报表已过期，请重新生成」。
6. 单体财务报表（企业会计制度格式）：取数行按配置逐科目项列出（前缀、剔除的下级、取反、未结转损益）、合计行按引用行列出、
   现金流量表行写明取自平台现金流量表的哪些行、跨表行（如补充资料净利润）指到被引用的格子；企业会计准则格式同 R5.1~R5.5。
7. 隐藏页签（现金流量表 / 权益变动表 / 现金流附表 / 减值准备表）本轮不做；恢复显示时再接。

## R6 账务查询（科目余额表 / 序时账）
1. 每列写明来自导入文件的哪个 sheet 的哪个表头，映射是用户确认的还是自动识别的；数据集的导入时间与操作人。
2. 推导出来的列写推导方式：期初 = 期初借方 − 期初贷方（或余额 + 方向列）、年初列优先于期初列、本年累计优先于本期发生额、
   方向的依据（借贷分列 / 方向列 / 按科目类别推断）、单金额列按借贷标识拆分、会计期间取自凭证日期等。
3. 同一字段映射了多列时，写明实际采用的列和被舍弃列的值（取自导入时留存的 `_discarded_mappings`），并提示「映射有冲突，请核对」。
4. 页面按下级汇总补出的上级行：写「按下级合计」并列出下级科目；导入时由辅助明细汇总出的科目行：写明汇总了几条辅助明细。
5. 人工修改过的行：导入原值、修改人、修改时间、原因。
6. 序时账「辅助核算」「币种」两列：写明取自导入文件中没映射的哪个表头。
7. 查不到映射记录（旧导入、迁移来的数据集）时如实写明；不提供源文件行号（导入时未保存）。

## R7 报表相关接口补项目鉴权（用户 2026-11-05「一起补」）

## R9 账务查询来源项点开导入记录（用户 2026-11-05「悬浮的详情可以直接点击，并跳转到导入文件相应的详情」）

   定位并高亮这一列的映射行。
2. 导入记录详情（只读）：导入时间、导入人、状态、是否当前生效数据集、各表入库行数；按文件 → sheet 列出表类型、确认方式、
   每列「原表头 → 字段」（字段写中文）。同一页给「返回账务查询」「开始新的导入」。
