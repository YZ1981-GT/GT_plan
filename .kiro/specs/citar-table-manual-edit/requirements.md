# 需求：CITAR 表格数据可人工编写修改保存

来源：用户 2026-11-04「所有表格数据都需要可以人工编写修改保存」。本会话核查现状后，用户拍板：试算表改数生成调整分录草稿（方案 A），余额表 / 序时账要能改，审核说明要能改段落文字。

## 现状（2026-11-04 核查）

| 页面 | 现状 |
|---|---|
| 税审底稿 / 汇算申报表 | 手填格、取数格可改；公式格前端 `startEdit`、后端 `save_sheet_inputs` 都拒收；样表预置数字（税率等 112 处）没有 ref 不能改；清空存 null，没有办法回到自动值 |
| 试算平衡表 | 只读；审定数只能经调整分录或底稿发布门进入（铁律） |
| 账务查询（余额表 / 序时账） | 只读，后端没有行级写端点 |
| 审定报表 | 只读；`financial_report` 无手工标记，重新生成无条件覆盖 |
| 单体财务报表 | 只读，每次现算无存储 |
| 审核说明 | 只读，只能导出 Word 后改 |
| 报告正文 | 只有报告日期可改；25 行金额来自 1-01 公式 |
| 调整分录、客户科目 → 标准科目 | 已可编辑保存 |

## 需求

- R1 税审底稿与汇算申报表：公式格、取数格、手填格、样表预置数字都能点开修改保存；手工值盖过公式 / 取数结果，下游公式、申报表导出、报告正文、审核说明都按手工值算。改过的格标「手工修改」，悬停可见原值；每个改过的格可「恢复自动值」（与清空成空白是两回事）。审核说明规则表（RN-*）仍为配置、不开放。
- R2 试算平衡表：点审定数（审定科目余额表的调整后期末余额 / 底稿取数余额表的期末余额）填目标金额，按差额生成一张借贷平衡的调整分录草稿（本科目 + 用户选的对方科目），不直接改试算表；草稿批准后才进试算表。有未批准分录的科目在审定数旁标出。期初、本期发生额提示去科目余额表改。
- R3 科目余额表：真实导入的末级科目行可改期初余额、本期借方、本期贷方、期末余额；上级科目随下级同步（标「下级已修改」）；合成的汇总行不能直接改。改完试算表未审数按新值重算。
- R4 序时账：每条分录可改日期、凭证号、摘要、科目编码、科目名称、借方、贷方。序时账修改不回写余额表。
- R5 余额表 / 序时账每次修改记原值、新值、修改人、时间；改过的行标出，可恢复导入原值。重新导入账套生成新数据集，旧修改不带过去；导入页在当前账套有手工修改时提示。
- R6 审定报表：资产负债表 / 利润表每行的本期、上期金额都可改；重新生成报表保留手工值（同时更新自动值），合计按手工值重算；标「手工修改」、悬停看自动值、可恢复。
- R7 单体财务报表：企业会计制度格式各表金额可改，合计行、跨表取数、平衡校验、导出都按手工值；企业会计准则格式即平台审定报表，改动写同一处（与 R6 一致）。标记与恢复同 R6。
- R8 审核说明：每段正文文字可改、可删除本段、可恢复自动文字；编号仍自动（删段后重新编号）；预览与导出 Word 用改后的文字。自动文字因数据变化而变时标「自动文字已变化」；改过的段因数据变化不再显示时给出提示，可丢弃该修改。
- R9 报告正文：25 行金额在本页可改（写入 1-01 同一格，等同 R1），预览与 Word 随之变化。报告日期照旧；正文措辞仍为法定文书表述，不开放。

## 不改

- 报表分析各面板、科目 → 底稿：计算结果，改源头即可。
- 账务查询里的未审资产负债表 / 利润表：读时由试算表未审数现算，改余额表即可。
- 旧版 `PUT /reports/cell`（权益表 / 减值表矩阵）不动。
- 表格增删行不在本次范围（税审底稿行次固定）。
- `import_templates.py` 调用不存在的 `upsert_trial_balance_row`：用户未答复是否修，记录待办。

## 验收

- V1 各需求单测：公式覆盖与恢复、下游传播；报表手工值重新生成后保留且合计重算；单体报表合计 / 平衡；审核说明改 / 删 / 恢复与编号；余额表改后上级同步、试算表重算、恢复原值；序时账改与恢复。
- V2 改动模块既有测试通过（HEAD 同现失败单列）；生成器 `--check` 通过。
- V3 浏览器实测各页修改 → 保存 → 刷新仍在 → 恢复；写入型验收只用【测试】项目或用完复原。
