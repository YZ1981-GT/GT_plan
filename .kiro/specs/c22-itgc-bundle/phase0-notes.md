## 4. 子页内部结构（SA-3 / PE-3a 实测模板）

固定区块顺序：
1. `控制编号`（B1，引用矩阵 C 列）/ `控制活动`（B2，引用矩阵 D 列）
2. 设计有效性：`设计有效性标准审计程序 | 设计有效性执行的审计程序` → `审计证据`（含证据索引号）→ `设计有效性测试结论`（有效/无效）
3. 执行有效性：`测试期间&样本总量` → `抽样数量` → 测试步骤表（标准程序/执行程序）→ `执行有效性测试结论`
4. `样本记录`表（抽样>1 时记录其余样本）
5. `缺陷评估`：`是否发现异常`(Yes/No) → `缺陷描述` → `索引至<C21-1> IT审计发现汇总表`（缺陷编号）

## 5. 缺陷字段映射（子页 缺陷评估 → C21-1 汇总）

C21-1 主表（本年度发现，第 8 行表头）列：
`缺陷编号 | 类别 | 控制类型 | 涉及应用程序 | 问题描述 | 补偿性控制及有效性 | 风险及影响 | 相关报表项目 | 财务报表认定 | 对相关财务报表审计工作的影响 | 备注`
其中「财务报表认定」跨 9 子列：`发生/完整性/准确性/截止/分类/存在/权利和义务/计价和分摊/列报`。
C21-1 另有第二张表「**上年度/上次审计发现整改情况**」（第 16 行表头）：`缺陷编号 | 类别 | 控制类型 | 涉及应用程序 | 审计发现 | 可能存在的风险及影响 | 整改情况 | 客户回复`。

| 子页字段（来源） | ItgcDefect 字段 | → C21-1 列 | 说明 |
|------------------|-----------------|-----------|------|

| `索引至<C21-1>` 值（如 `ITGC#1`） | `defectNo` | 缺陷编号 | 编号规则 `ITGC#{N}`（区别于证据索引 `C22.{控制点}-{序号}`） |

`ItgcDefect` 建议扩展（对齐 design + C21-1 实列）：
```typescript
interface ItgcDefect {
  controlId: string   // 子页控制编号 SA-7
  group: string       // 信息安全/运行维护/程序变更/新系统
  sheet: string       // 来源 sheet（双向追溯，Req 12.3）
  description: string  // 缺陷描述 → 问题描述
  defectNo: string    // ITGC#N（索引至 C21-1）
  appSystem?: string  // 相关应用系统（矩阵 E 回填）
}
```

## 6. C21 结构（3 段）

1. **一、具有信息技术专业技能的项目组成员**：三选一（`由IT审计团队执行` / `项目组自行执行` / `其他情况`）+ 成员表（姓名/职级/所属办公室/工作邮箱/项目中角色/主要职责）。依据《审计指引第42号-信息系统审计(2024修订)》。含 **22 个命名区域**（下拉数据验证，Req 8.2）。
2. **二、具体工作**：14 步程序表（序号|程序|是否适用|执行人|执行情况说明|索引号）。
3. **三、底稿完成情况**：序号|对应底稿|编制人|复核人|是否完成(是/否/不适用)|备注（列 B22A-4/B22A-4-1…B60-2-2 等）。

## 7. spec vs 实测 差异清单（类比 c1 九节发现）

| # | 差异 | 影响 | 建议 |
|---|------|------|------|
| D1 | **PE 组实为 8 sheet，非 design 所列 6**（多 `PE-5.1`、`PE-8.1`） | P2 分组完整性 / P4 进度统计 | TabDef 增补 2 个 `itgc-aux`（续页），归 PE 组但**不计入控制点/缺陷统计** |
| D2 | **33 子页中仅 31 为真正控制点**（有缺陷评估）；PE-5.1/PE-8.1 无缺陷评估、无矩阵引用 | Req 4.1「33 控制域子页」措辞偏差；completionMap/defects 应基于 31 | completionMap 与 defects 仅遍历 31 个 itgc-sheet |
| D3 | 🔴 **PM-4c 源模板公式损坏**：B1/B2 = `='C22 IT一般控制测试'!#REF!`（应指向矩阵 C32/D32） | 子页控制编号/活动无法从矩阵取数 | 渲染兜底：#REF! 时回退显示「PM-4c」并从矩阵行 C32 手工映射，不崩 |
| D4 | 矩阵 36 数据行含 **5 行多控制续行**（行 22/25/26/27/30） | 矩阵↔子页非严格 1:1 | 多控制子页（PE-3d/PE-6/PE-8）引用多个 D 行；矩阵点击行→子页需按控制编号聚合 |
| D5 | **NS-5.x/6.x 仅引用 D 列**（无 C 列控制编号引用） | 子页 B1 控制编号为空 | 视为父 NS 控制的子活动；控制编号可留空或继承父级 |
| D6 | 工作簿 **sheet 顺序 SA-12 在 SA-11 之前**，与矩阵编号顺序（C16=SA-11、C17=SA-12）不一致 | Tab 排序 | TabDef 按**矩阵控制编号顺序**排列更符合审计逻辑（本表已按此） |
| D7 | C21-1「财务报表认定」为 **9 子列** + 含**上年度整改**第二张表 | design 缺陷汇总结构未列出这些列 | C21-1 汇总视图需支持 9 认定勾选 + 保留上年度整改表（只读/沿用模板） |
| D8 | 缺陷编号格式 `ITGC#N`；证据索引格式 `C22.{控制点}-{序号}`（如 C22.SA-3-1） | Req 11.2 证据编号规则、Req 5 缺陷编号 | P8 证据编号建议规则确认为 `C22.{控制点}-{序号}`；缺陷编号 `ITGC#{N}` |
| D9 | 源模板路径为 `数据\致同…` 目录（脚本实测有效）；记忆/任务描述引用 `基础数据\` | 无（脚本已用正确路径） | 后续读模板沿用脚本内 `ROOT` 路径 |
| D10 | C21-1 文件名双空格 + 主 sheet 名 `IT 审计发现汇总表`（含空格） | wp_index / render-config 解析 | 解析 wp_id 时按 wp_code=C21-1 而非 sheet 名匹配 |

> 结论：design 的 4 大类框架与实测一致，但需修正 **PE 组 6→8（含 2 续页）**、明确 **31 控制点 vs 33 子页**、处理 **PM-4c #REF! 兜底**、补充 **C21-1 九认定列/上年度整改表**。这些将在 Wave2/3（后端注册与 composable）落地。
