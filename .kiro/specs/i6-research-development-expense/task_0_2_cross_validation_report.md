# Task 0.2 底稿模板库md交叉验证报告

## 验证目标

核对I无形资产循环底稿模板库.md中I6/I7研发费用相关业务语义，与spec三件套（requirements.md / design.md）的一致性。

---

## 1. 编码映射确认

| 源 | 研发费用编码 | 说明 |
|---|---|---|
| 源xlsx（I6 研发费用.xlsx） | **I6**-1~I6-6, I6A | 实际底稿编码，平台使用此编码 |
| 底稿模板库md | **I7**-1~I7-14, I7A | 致同2025修订版md使用I7编号（19个底稿） |
| md底部实际目录表 | **I6**-2, I6-6 | md文件末尾"底稿目录"引用xlsx真实编码I6 |

**结论**：md主体用I7编号（模板库逻辑分类），但实际底稿索引号引用I6（xlsx物理编码）。spec正确使用I6编码，与xlsx一致。**无冲突。**

---

## 2. I6↔I2联动规则验证

### md中的业务语义

- **I7A程序表**第4步："检查研发项目资本化时点判断"→索引号I7-6
- **I7-6**："判断研发项目的资本化时点"，列含：技术可行性/市场可行性/资本化时点
- **I2A程序表**："检查开发支出的增加"→与I6费用化金额对应
- **I2-1审定表**：开发支出（资本化部分）的期末余额
- **隐含联动**：I7(I6)费用化 + I2资本化 = 研发总额

### spec中的定义

- **Requirement 4**：I6↔I2双向联动，VR-I6-01: I6费用化 + I2资本化 = 研发总额
- **Design ADR-2**：EventBus 双向（research:expense-updated / development:capitalized-updated）
- **cross_wp_references**：静态跳转 + EventBus动态通知

### 交叉验证结果

| 维度 | md业务语义 | spec定义 | 一致性 |
|---|---|---|---|
| 联动方向 | I7→I2(资本化时点判断)，I2→I7(开发支出→无形资产) | I6↔I2双向 | ✅ 一致（md隐含双向） |
| 校验规则 | 费用化+资本化=研发总额（从I7-6资本化时点判断推导） | VR-I6-01 | ✅ 一致 |
| 联动触发 | md无技术实现说明 | EventBus publish/subscribe | ✅ spec补充了技术方案 |

## 3. VR-I6-01校验规则验证

### md中的依据

- **I7-5 会计政策检查**：检查项含"资本化条件"/"费用化条件"
- **I7-6 资本化时点判断**：核心判断点——某研发支出应费用化还是资本化
- **I7-7 研发项目构成明细**：按项目/阶段追踪投入金额
- **隐含恒等式**：研发总投入 = 费用化（计入I6/I7损益） + 资本化（计入I2资产）

### spec中的定义

- `validateVRI601(expenseI6, capitalizedI2, expectedTotal)` → `{isValid, difference}`
- 校验失败时红色警告"费用化+资本化≠研发总额，差额xxx"
- 审定表I6-1底部联动面板显示：费用化(I6)|资本化(I2)|合计|校验状态

### 交叉验证结果

| 维度 | md | spec | 一致性 |
|---|---|---|---|
| 恒等式 | 研发总额=费用化+资本化 | VR-I6-01同 | ✅ |
| 校验位置 | I7-6（资本化时点判断）是核心 | 审定表I6-1底部面板 | ✅ spec更具体 |
| 失败处理 | md无明确说明 | 红色警告+差额 | ✅ spec补充了UI行为 |

## 4. 截止测试规则验证

### md中的业务语义

- **I7-13 截止性测试（单据到账）**：单据日期→入账日期方向
  - 列：单据日期|单据金额|入账日期|入账金额|差异|审计评价
- **I7-14 截止性测试（账到单据）**：入账日期→单据日期方向
  - 列：入账日期|入账金额|单据日期|单据金额|差异|审计评价
- **I7A程序表**第11步："检查研发费用的截止性"→索引号I7-13, I7-14

### spec中的定义

- **I6-5 Cutoff_Forward**：账簿→单据（期末±5天）
- **I6-6 Cutoff_Backward**：单据→账簿（期末±5天）
- Requirement 5.4 列：日期|金额|费用类型|记账期间|单据日期|归属期间|是否跨期|结论
- useCutoffAutoSampling自动提取序时账样本

### 交叉验证结果

| 维度 | md | spec | 一致性 |
|---|---|---|---|
| 方向 | I7-13(单据→账)/I7-14(账→单据) | I6-5(账→单据)/I6-6(单据→账) | ✅ 方向一致，编码映射正确 |
| 时间窗口 | md无明确说明期限 | 期末±5天 | ✅ spec具体化（5天是审计惯例） |
| 列结构 | 6列基础 | 8列增强（加费用类型/归属期间/是否跨期/结论） | ✅ spec增强，不冲突 |
| 自动抽样 | md无技术说明 | useCutoffAutoSampling | ✅ spec补充实现 |

**编码映射**：
- md I7-13 = spec I6-6（单据到账 = Cutoff_Backward）
- md I7-14 = spec I6-5（账到单据 = Cutoff_Forward）

## 5. 损益类取数规则确认

### md中的业务语义

- **I7系列标题**："研发费用"——明确是费用/损益类科目
- **I7-1审定表**：列仅"未审数|调整数|审定数"（简化版，无借贷方向列）
- **I7-4实质性分析**：列含"本期金额|上期金额|变动率"——说明取发生额而非余额
- **I7-2明细表**：列含"发生金额"——明确是发生额

### spec中的定义

- **Introduction**：科目6602研发费用（损益类！贷方科目，取发生额非余额）
- **Requirement 10**：损益类取发生额，6602为借方科目：借方=费用增加，贷方=冲回/结转
- **Design ADR-1**：I6使用calcIncomeStatementNet（与H10同款），TB回写发生额

### 交叉验证结果

| 维度 | md | spec | 一致性 |
|---|---|---|---|
| 科目性质 | 费用/损益类 | 损益类 | ✅ |
| 取数方式 | 取"发生金额"（I7-2明细表列名） | 取发生额非余额 | ✅ |
| 借贷方向 | md无明确说明 | 6602借方=费用增加 | ✅ spec具体化 |
| 变动率分析 | I7-4含变动率列 | calcChangeRate=(本期-同期)/同期×100% | ✅ |

## 6. md特有信息（spec未覆盖但无冲突）

md模板库中I7有19个底稿，比spec的11 sheet多出：

| md底稿 | 内容 | spec处理 |
|---|---|---|
| I7-4 实质性分析 | 本期/上期/变动率 | 部分融入审定表+月度波动（Req 9） |
| I7-5 会计政策检查 | 资本化/费用化条件 | 融入I6-4针对性检查（Req 6） |
| I7-6 资本化时点判断 | CAS6五条件 | 已由I2 spec覆盖（CAS6五条件面板） |
| I7-7 研发项目构成明细 | 项目/阶段/投入 | 融入I6-2明细表（按项目分行） |
| I7-8 研发材料投入检查 | 材料/项目/凭证 | 融入I6-4针对性检查 |
| I7-9 研发人员认定检查 | 人员/岗位/项目 | 融入I6-4针对性检查 |
| I7-10 研发人员工时检查 | 工时/金额 | 融入I6-4针对性检查 |
| I7-11 委外研发检查 | 委托方/合同 | 融入I6-4针对性检查 |
| I7-12 其他针对性检查 | 通用 | = I6-4 |

**结论**：md的19个底稿在spec中被合理压缩为11 sheet。多出的细分检查表合并入I6-4（针对性检查），资本化判断交由I2处理。**合理精简，无信息遗漏。**
