# J1 应付职工薪酬披露表 ↔ 附注模板对齐

## 背景

`j1-disclosure-note-linkage`（已归档）建立了 J1 披露表 → 附注（五、40 / 八、40）的推送链路，
但当时**允许了两处对模板的偏离**，且未核对源模板的披露逻辑与内部勾稽。

2026-07-30 用逐格精读 `backend/wp_templates/J/J1 应付职工薪酬.xlsx`（运行时权威副本，
无参考副本）+ `consol_note_sections_{listed,soe}.json`（第 4 方印证）复核，
发现 **11 项结构/内容欠账**，其中 3 项会导致附注数据实际丢失。

### 源模板披露逻辑（实证）

两个披露 sheet 各含 **3 张五列变动表 + 若干说明文本区**，构成"汇总 → 明细"的递进披露：

| # | 上市（`附注披露信息（上市公司）` A1:E54） | 国企（`附注披露信息（国有企业）` A1:E44） |
|---|---|---|
| 表1 | `应付职工薪酬`（R6 表头，4 类 + 预留行 + 合 计） | `（1）应付职工薪酬列示`（R8 表头，5 类 + 合  计） |
| 表2 | `（1）短期薪酬`（R17 表头，13 项 + 合  计） | `（2）短期薪酬列示`（R16 表头，12 项 + 合  计） |
| 表3 | `（2）设定提存计划`（R40 表头，8 项 + 合  计） | `（3）设定提存计划列示`（R31 表头，8 项 + 合  计） |
| 文本 | 短期薪酬说明 2 条（R37/R38）、设定提存说明（R50）、辞退福利说明（R53） | 说明 3 条（R42/R43/R44） |

列头差异（**底稿口径 vs 附注交付口径**）：源 xlsx 上市侧写「上年年末数 / 期末数」，
国企侧写「期初余额 / 期末余额」；`consol_note_sections_listed.json` 两侧统一为
「期初余额 / 本期增加 / 本期减少 / 期末余额」→ **附注侧一律用后者**（沿用已冻结的 Decision 2）。

行结构差异（源 xlsx 实证）：

- 上市表2 有独立「非货币性福利」行；国企表2 **无**该行（源公式 `B28='明细表J1-2 '!J30+J31`
  把它并入「其他短期薪酬」）
- 上市表2 社保其中项 = 医疗 / 工伤 / 生育 + `……` 预留；国企 = 医疗 / 工伤 / 生育 / 其他
- 国企表1 多一行「其他」

### 源模板内部勾稽（逐格读出的 Excel 公式，是本次的核心价值）

| 规则 | 源模板证据 |
|---|---|
| 表1 合计 = Σ 各类别行 | 上市 `B12=SUM(B7:B11)`；国企 `B14=SUM(B9:B13)` |
| 表1「短期薪酬」= 表2 合计 | 两者同引 `'明细表J1-2 '!J33`（上市 B7 / 国企 B9） |
| 表1「离职后福利-设定提存计划」= 表3 合计 | 两者同引 `'明细表J1-2 '!J46` |
| 表2「社会保险费」= Σ 其中项 | 上市 `B20=SUM(B21:B27)`；国企 `B19=SUM(B20:B23)` |
| 表2 合计排除「其中」明细行 | 上市 `B35=SUM(B18:B20)+SUM(B28:B34)`；国企 `B29=SUM(B17:B28)-SUM(B20:B23)` |
| 表3「离职后福利」= Σ 其中 4 项 | 上市 `B41=SUM(B42:B45)`；国企 `B32=SUM(B33:B36)` |
| 表3 合计 = 离职后福利 + 其他长期职工福利 | 上市 `B49=B41+B46`；国企 `B40=B32+B37` |
| 期末 = 期初 + 增加 − 减少 | 国企 E 列全部显式 `=B+C-D` |
| 本期减少合计 ≈ 现金流量「支付给职工…的现金」 | 上市 R54 红字注（除代扣税未交 / 实物发放） |

## Requirements

### R1 附注模板结构对齐源模板（P0，数据丢失级）

**User Story:** 作为审计助理，我在 J1 披露表点「同步到附注」后，附注八、40 的三张表都应收到数据。

1. WHEN 读取 `note_template_soe.json` 八、40 THEN 第 3 张表名 SHALL 为 `设定提存计划列示`
   （现为 `短期薪酬列示`，与第 2 张**重名**；前端推送键是 `设定提存计划列示` → 现状产生
   孤儿子表，模板第 3 张表永远为空）
2. WHEN 读取 五、40 / 八、40 的全部 6 张表 THEN 每张表 SHALL 有 `columns`（5 列）
   且标签列标 `flat`（现全部缺失 → seed 路径被 `_infer_groups_from_headers` 按
   「本期增加 / 本期减少」共同前缀反猜出源模板**不存在**的「本期」父表头）
3. WHEN 读取 6 张表 THEN 每张表 SHALL 有 `guidance`（附注 TAB 页签编制提示；现全部缺失）
4. WHEN 读取 五、40 表2 THEN SHALL 不含 `……` 占位行（源模板的"可添行"提示，
   被 md 重建脚本落成假数据行 → 附注渲染出一行空披露数据）；语义移入 `guidance`
5. `columns` 的标签列头 SHALL 与该表 `headers[0]` 逐字一致

### R2 附注模板文本区补齐（P0，交付物缺内容）

**User Story:** 作为业务合伙人，我在附注模块看 J1 章节时，表格下方应有源模板要求的说明文本。

1. WHEN 读取 五、40 `text_sections` THEN SHALL 包含源模板 4 个说明段的口径
   （非货币性福利计算依据 / 短期利润分享计划计算依据 / 设定提存计划性质与缴费公式 /
   辞退福利性质内容与计算依据），现状**一条都没有**（只有【提示】块）
2. WHEN 读取 八、40 `text_sections` THEN SHALL 包含源模板 R42~R44 的 3 条说明，
   现状只有 3 个 `###` 表标题（`_is_table_title_paragraph` 判为标题 → 不进任何输出 →
   国企附注 J1 文本区 seed 恒空）
3. 五、40 SHALL 保留现金流量勾稽注（源模板 R54 红字）
4. 文本段 SHALL NOT 以 `####` 开头（会被 `_is_table_title_paragraph` 静默丢弃）

### R3 底稿披露表内部勾稽（P1，核心价值）

**User Story:** 作为现场经理复核 J1 披露表时，我要能一眼看出三张表是否互相勾稽、
差异出在哪一行，而不是自己拿计算器对。

1. WHEN 表2/表3 中某非缩进行下方紧跟连续缩进（「其中：」）子行
   THEN 该父行的期初/增加/减少 SHALL 自动等于子行之和，并以公式单元格样式（虚线下划线 +
   tooltip 说明来源）呈现，不可手工编辑
2. WHEN 表1「短期薪酬」行与表2 合计不一致 THEN 勾稽面板 SHALL 报差异（容差 0.01 元），
   并可追溯到具体列
3. WHEN 表1「离职后福利-设定提存计划」行与表3 合计不一致 THEN 同上
4. WHEN 任一行 期末 ≠ 期初 + 增加 − 减少 THEN 勾稽面板 SHALL 报差异
5. 勾稽面板 SHALL 采用 H1 已验证范式（纯函数引擎 + 紧凑单行 bar + 折叠明细表 + 规则 tooltip）
6. 勾稽规则 SHALL 只取源模板可判定的关系（上表 8 条），不得自造审计判断

### R4 底稿披露表内容纠偏（P1）

1. 上市版辞退福利说明 placeholder 现为「本期减少一般**不得超过期初数加本期增加数之和**」，
   SHALL 改为源模板 R54 原文口径（与现金流量表「支付给职工以及为职工支付的现金」一致，
   除代扣税未交、实物发放等）——现状是自造内容
2. 国企版 3 条说明 SHALL 拆为 3 个独立文本域，每个带 AI 辅助按钮
   （现为单一 textarea，且第 3 条 placeholder 被截断改写，丢了"及其变动、对未来现金流的影响、
   重大精算假设及有关敏感性分析等。设定受益计划情况详见附注八、47"）
2. 源模板红字提示 SHALL 以琥珀色方法论上下文块呈现在对应功能区**上方**（平台 UI 铁律），
   而非只塞进底部 `details`
4. 未使用的 `import GtIndexChip` SHALL 删除（死代码立即删除）

### R5 AI 辅助不空转（P1）

1. WHEN 前端以 `section=j1-disclosure-{listed|soe}-*` 调用通用 AI 端点
   THEN 后端 SHALL 有对应的针对性 prompt（现状落到通用兜底
   「请根据提供的上下文信息生成专业的审计文本。」→ 放任模型自造披露内容）
2. 每条 prompt SHALL ≥20 字、写明源模板 / CAS 9 口径，并含"不得虚构"约束

### R6 同步载荷对齐（P1）

1. WHEN 国企变体同步 THEN `_note_texts` SHALL 输出 3 段（对应 R4.2 的 3 个文本域），
   现为 1 段
2. WHEN 任一变体同步 THEN 子表键 SHALL 与修订后的模板 `tables[].name` 逐字一致
3. 载荷 SHALL 保持「附注是交付物」口径：列头用「期初余额…期末余额」，
   不外溢底稿的「上年年末数 / 期末数」

### R7 守卫与实测

1. SHALL 有幂等修订脚本（`--dry-run` / `--check`）+ CI job，防并发会话回退
2. SHALL 接入共享契约 helper `runDisclosureSubtableContract`（5 条 Property）
3. 勾稽引擎 SHALL 有纯函数单测（含反向断言：制造差异时必须报出）
4. SHALL 用浏览器实测「底稿录入 → 同步 → 附注两个 TAB 表格与文本区」全链
   （`_last_sync_at` + 字段值双证，非截图）

## 非目标

- 不改 J1-1 审定表 / J1-2 明细表（本次只动披露表与附注）
- 不做披露表导入导出（F2 范式，另立任务；见 tasks.md 可选项）
- 不做 `el-input-number` → `WpAmountInput` 存量替换（平台级另有 spec 收口）
- 不动 五、49 / 八、54 长期应付职工薪酬（独立章节）
