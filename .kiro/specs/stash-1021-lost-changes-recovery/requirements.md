# 需求：10 月 21 日 AI 采纳与笔记恢复

## 背景

2026-10-21 17:56 的 `git stash push -u -m temp-for-push-reconcile` 生成救援对象 `112bfabec`。同日 18:15 的强制 checkout 清除了所有已跟踪文件的未提交改动，只有部分未跟踪文件后来被提交。结果是 `ChatAdoptTargetDialog.vue`、`ChatNoteSaveDialog.vue`、`chatTargetOptions.ts`、`aiChatWireError.ts` 与 `note_target.py` 已在目标分支，但连接它们的面板、composable、router 和服务层仍停在事故前行为。

本 spec 只恢复 AI 面板的“采纳选目标”和“转存笔记”链路。其余 82 个完整丢失文件与 24 个未跟踪文件只登记处置，不在本次直接恢复。

## R1 采纳选目标恢复

1. 对底稿或附注宿主，用户点击“采纳”必须保持就地采纳，不弹出目标选择框。
2. 对全局知识、报表、知识库文档或文件夹宿主，用户点击“采纳”必须先显示目标选择框，选定底稿或附注后才发起请求。
3. 选定目标时，请求的 `host` 必须是目标，`source_host` 必须是消息所在会话的当前宿主；没有目标时不得发送注定失败的请求。
4. 成功后必须仅刷新目标项目的待确认横幅，不能重复发送事件或发送缺少 `projectId` 的事件。

## R2 跨宿主采纳安全恢复

1. 服务端必须按目标宿主执行 `adopt` 授权，按来源宿主执行 `history` 授权。
2. 仅全局知识、报表和知识库类来源允许重定向到底稿或附注目标；来源与目标必须同一主体，来源带项目时必须同一项目。
3. 不带 `source_host` 时必须维持原有的同宿主严格绑定。任何拒绝路径都不得创建待确认内容或占用收据。
4. 审计记录必须保留来源宿主类型和 ID，且不记录 AI 正文。

## R3 转存笔记恢复

1. “转存笔记”必须显示名称与保存位置对话框，而不是在全局宿主直接报“没有项目”。
2. 有项目的会话只允许保存到该项目的“AI 对话笔记”文件夹。无项目会话可选择有写入权限的项目或知识库文件夹。
3. 前端请求体必须是与后端模型一致的扁平字段；`session_id` 可省，由服务端按选中的 assistant 消息反查唯一会话。
4. 服务端必须在创建幂等收据、文件夹或文档之前完成消息归属、项目范围和目标权限校验。
5. 成功响应必须包含实际保存位置、文档 ID 和站内跳转地址。失败后对话框须保留用户输入以便重试。
