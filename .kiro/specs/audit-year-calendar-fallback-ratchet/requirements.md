# 审计年度兜底取今年 / 写死年度 —— 棘轮与收口（audit-year-calendar-fallback-ratchet）

> spec `formula-fetch-followup-defect-closure` design §10.9 范围外第 4、5 条。2026-10-24 用户：「另立 spec，先加一道只许减少的守卫。」
> 现状为 2026-10-25 在提交 `bf7685b1d` 的干净检出上现算；计数会漂，判据不写死行号。
>
> 首版草稿随 `25a506a57` 入库（只有前端，口径「不减 1 且行内含 year」，2026-10-24 现算 250 处，其中 7 处在注释行）。实施守卫时口径改为：
> ①注释不计 ②减 1 也计（同样是按日历猜年度）③后端同类一并冻结。前端 340 处 = 草稿口径的 243 处代码 + 97 处减 1。

## 背景

审计年度有单一来源：后端 `app/services/project_audit_year.py`（审计年度 → 审计期末 → 向导 → 项目名后缀，都没有返回 None），
前端 `utils/resolveAuditYear.ts`（`resolveAuditYearFromProject` 同口径；`resolveEffectiveAuditYear` 多来源合并，全部缺失时返回去年）。
很多调用方不经单一来源，拿不到年度时直接用今天的年份（或减 1），或写死 2025。2025 年度项目在 2026 年打开时，这些入口按 2026 取数 / 写数；
往年项目、新项目未填年度时同样静默取到别的年度，界面上看不出来。

| 端 | 出现处 | 文件 | 分布 |
|---|---|---|---|
| 前端 | 340 | 288 | 兜底写法（`\|\|` / `??` / 三元）251 · 初值 / 直接赋值 38 · 其他（实参 / 运算 / 模板）51；取今年 243、取上一年 97；底稿组件 266 |
| 后端 | 130 | 72 | 今天的年份 34（其中减 1 的 13）· 写死年度 96：参数默认值 54（`year: int = 2025` 26、`Query(2025)` / `Field` 28）、`x or 2025` 27、`.get("year", 2025)` 8、赋值 7 |

几处要点：

- 写请求也在猜：`WritebackResultPanel.vue` 回填请求体 `year: props.year || new Date().getFullYear()`。
- 后端 `routers/wp_prefill_preview.py` 预览 / 应用两处：项目没有审计期末时按 2025 预填（也不看 `audit_year`）。
- 后端大量端点的 `year` 查询参数默认 2025：前端漏传年度时不报错，静默按 2025 取数。
- 前端单一来源与两个通用组合式函数（`useAuditContext`、`useProjectSelector`）的最终兜底是去年（计在表里，见 R3 待拍板项）。

## R0 优先：程序表执行人填的状态 / 执行说明刷新后看不到（任务 0，2026-10-25 用户：「在本 spec 里优先处理」）

现象：执行人在程序表（如 H1A）改状态、填执行说明，刷新后变回「待执行」、说明为空。现查根因有两个，写与读对不上：

| | 写（前端） | 读（后端 render-config `a-program-console`） |
|---|---|---|
| 年度 | 路由 `year` → 今年（2026） | 项目审计年度（2025） |
| scope | `procedure_table:` + 传入的 sheetName（整册嵌入时没传 ⇒ 写进 `A1`；A 类顶层是「审计程序A7」这类表名） | `procedure_table:` + 按表名解析出的表码（`resolve_program_template_code`） |

同一写法还有 A1 仪表盘 / A2 / A3 控制台与 G8~G12 循环的「回填程序表」6 处（表名当 scope、年度兜底今年）。真库现有 10 行写错位置：测试项目 2 行、和平药房 2 行（A7 / A8，scope 是表名）、重药安徽 6 行（A1 ×3、A17 ×2、K1A ×1）；其中 K1A 是循环程序表（只靠字段覆盖显示），用户的编辑确实看不到了；A 类顶层表另有整表保存，覆盖只用于进度统计。

1. 写程序表字段覆盖的年度只取项目审计年度（单一来源，`GET /api/projects/{id}` 的 `audit_year`）；取不到时不发请求，提示「未设置审计年度，请先在项目基本信息中填写」。同组件里配对的读请求用同一个年度，取不到时不传年度。
2. scope 以读取方为准：render-config 在 `a-program-console` 的 html_data 里回传它读取覆盖用的 `override_scope`，前端写入一律用它；没有时按表名解析表码（与循环程序表壳同一函数），仍解析不出就不写。
3. G8~G12 六处「回填程序表」收口成一个写入函数（年度、scope 同上），各自保留原来的完成事件。
4. 下调年度棘轮基线；测试含「执行人改后刷新仍在」的端到端（真库回滚事务）与前端变异。
5. 存量 10 行：正式工具 dry-run 列出「现位置 → 读取方位置」及冲突；真实项目写库须用户确认后再 `--apply`。

## R1 守卫：只许减少（任务 1）

1. 前端：vitest `src/__tests__/auditYearCalendarFallbackRatchet.spec.ts`，按文件计数的基线 `auditYearCalendarFallbackBaseline.json`。
   计 src 下非测试源码（跳过测试目录与 `*.spec` / `*.test` / `*.stories`）里「今天的年份」表达式：`new Date().getFullYear()`、
   `(new Date()).getFullYear()`、`new Date(Date.now()).getFullYear()`、`dayjs().year()`、`moment().year()`；整行注释与行尾 `//` 注释不计；减不减 1 都计。
2. 后端：pytest `tests/test_audit_year_calendar_fallback_ratchet.py`（AST，基线在文件内）。计 `backend/app` 下：
   `datetime.now / utcnow / today(...).year`、`date.today().year`（含模块前缀写法）；名字含 year 的参数默认值、变量 / 属性赋值、
   `x or 2025`（前项含 year）、`x if … else 2025`、`.get("…year…", 2025)` / `getattr(x, "…year…", 2025)` 里的 2000~2099 整数字面量。
   全大写常量（校验边界）、注释、docstring 不计。
3. 两边规则相同：①基线外的文件、或文件里比基线多 ⇒ 红；②文件里比基线少 ⇒ 红（把基线下调到现算值，为 0 删条目）；
   ③只是挪动代码时把条目一起挪过去，基线总数不得超过冻结值；④扫描口径自检（应计 / 不应计样例、文件过滤、扫描文件数下限）。
4. 变异：新增一处、修掉一处不改基线、注释口径失效、扫描根写错、漏认一种写法、基线净增、测试文件 / 测试目录也计入，各自打红在预期断言上。

## R2 逐处判定（任务 2）

每处归为：①写请求的年度 ②读请求 / 展示的年度 ③日历本身就该取今年（年度声明、年份下拉上限、趋势图终点等）④单一来源自己的最终兜底。
③④类进豁免表并写明理由，豁免须可证伪（该处仍命中扫描口径），不再算作待修；①②类按 R3 / R4 修。

## R3 前端收口（任务 3、4）

1. 核心改法：调用方改为取项目审计年度（单一来源），不再自己拿日历猜。
2. 🔶 **待拍板：单一来源的最终兜底**（全部来源都缺时）——
   A. 维持去年（现行 `resolveEffectiveAuditYear`，首版草稿的方案）：改动最少；缺年度的项目仍可能静默显示别的年度。
   B. 返回 null 并提示「未设置审计年度，请先在项目基本信息中填写」：不会显示 / 写入别的年度；缺年度的老项目从「显示去年」变成「提示先填年度」。
   建议 B（写请求无论选哪个都按 B：年度缺失时不发请求）。
3. 读请求：按所选兜底处理；后端已按单一来源取年度的端点（参数可选）可不传年度。
4. 每改一组同步下调基线；浏览器实测用【测试】项目，含一个未填审计年度、未填审计期末的项目。

## R4 后端收口（任务 5、6）

1. `wp_prefill_preview.py` 两处先改：改用单一来源，取不到 ⇒ 422「未设置审计年度」（预填会写底稿，年度错了写错数）。
2. 写死年度的参数默认值：改为可选、缺省时按单一来源取，取不到 ⇒ 422；或改为必填（按调用方现状二选一，见 design）。
3. `datetime.now().year` 兜底：改单一来源；日历用途进豁免表。
4. 每改一组同步下调基线；端点级测试（未设置年度 ⇒ 422、设置了 ⇒ 用项目年度、显式传年度 ⇒ 用传入的）。
