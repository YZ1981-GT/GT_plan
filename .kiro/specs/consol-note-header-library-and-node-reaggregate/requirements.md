# 合并附注标题行库 + 节点子树重新汇总 — 需求

承接 `consol-note-pull-from-standalone`（v3，收口到 V186 明细映射）。用户 2026-10-22：

> 你还是需要收口管理的，对于续表类的表格标题行的识别要注意，想着是不是有可能对国企和上市的单体和合并的标题行做个标题行的库，也便于维护和识别对应呢。重新汇总应该是激活合并节点下的各节点的数据更新和汇总动作。

## 现状（2026-10-22 grep + 探针实证）

1. 表头识别散在三处、口径不一：
   - 读取层 `consol_note_standalone_reader` 自带多级表头解析（`_multi_header_raw_paths`，空格沿用左侧 / 纵向合并的启发式，平表头按「/」拆段），与展示 / Word 导出用的 `consol_note_headers.multi_header_rows` 不同：合并种子 753 张表里 15 张逐列路径不一致（如「利得/损失」被拆成两段、「期末余额/本期发生额」被拆成两个期间、listed 五-9-4~7 首列路径不同）。
   - 期末 / 期初同义词表在读取层 `_END_WORDS` / `_PRIOR_WORDS` 与 `formula_push/note_writer` 各有一份。
   - 映射生成器 `gen_consol_standalone_note_mapping._is_continuation_name` 与读取层 `_is_continuation` 都用「表名含『续』」判续表，会误判 永续债 / 继续涉入 / 后续采用 / 连续五个会计年度 / 存续期 等表（前端 `useNoteTableProjection` 已用精确标记，后端没有）。
2. 续表在四版种子里有三种写法，没有统一认定：
   - 单体种子：顶层期间写进表名（「（期末数）」「（续：期初数）」「（续：上年年末余额）」），`continuation_of_index` 同时被用于并列表（应付债券增减变动、继续涉入表），还有 2 处自指（国企 八、9 #16、八、18 #4）。
   - 合并种子：期间在多级表头里；`continuation_of` 的实际含义是「接在上一张表后」（72 / 55 处），不等于续表；裸「续：」「续（1）：」表名。
   - Word：表前段落「续：」或标题带「（续）」。
3. 单体↔合并按表名对应，续表场景会取错表：国企 五-4-3（期初数续表）按名字精确命中单体「按坏账准备计提方法分类披露应收票据（续）」（单项计提表，列完全不同），正确的是「（续：期初数）」表。
4. 合并种子自身有表头缺陷：上市 五-9-4~7 多级表头错一列且第 4 行混入数据行（「1年以内」）；国企从 五-10 起章节编号与现行四版 Word 错位（标记 `八、16:0` 对到 7 列表）。
5. 「🔄 重新汇总」= 只对所选节点按公式填入（`fill_note_sections`，个别数取试算表），不触发下级节点；推送后刷新（`consol_push_service._refresh_notes`）与试算表事件（`consol_note_formula_refresh_handler`）对全部节点按公式覆盖，会把从单体附注拉来的数冲掉。

## R1 标题行库（四版：国企 / 上市 × 单体 / 合并）

- R1.1 一个模块管表头识别：逐列表头路径（与展示 / Word 导出同一 `header_rows` 口径）、列语义键（期间 × 计量，期间同义词归一）、比例列、标签列。读取层、映射生成器、库目录都只调它，不再各写一份。
- R1.2 一份手工维护的词表 `note_table_header_vocabulary.json`：期末 / 期初同义词、分组同义词、比例列规则、续表标记规则、逐表覆盖（列语义键 / 续表关系，每条必填理由）。
- R1.3 一份生成的库目录 `note_table_header_library.json`：四版每张表的标题行（`header_rows`）、逐列路径与语义键、表名期间、续表关系；输出确定（无时间戳），`--check` 有漂移即 exit 2。
- R1.4 续表认定：只认标记（表名以「续」开头，或带「（续）」「（续：…）」「（续表）」），永续债 / 继续涉入 / 手续费 / 存续 / 后续 / 持续 / 连续不算；主表 = 同节内前面最近的同基名非续表（裸「续：」取前面最近的非续表）；分两类：列续（同行、补期间或补列）、行续（同列、补行）；自指、并列表误用续表标记、找不到主表都进异常清单。
- R1.5 单体↔合并对应：每张合并表在单体对应章节里按「表名证据 + 列语义键重合度」选表（含其列续表），目录里写明选中哪张表、怎么选中的、逐列对应、未对上的列；映射生成器用同一结果写 `consol_note_section_mapping.json` 的单体表名。
- R1.6 异常清单进目录：续表自指 / 并列表误标 / 无主表、多级表头首格跨数据列、表头行混入数据、同表两列语义键相同、名称含「续」但非续表（旧规则会误判）。种子缺陷只报告不擅改（见 R4）。

## R2 读取层收口到标题行库

- R2.1 `consol_note_standalone_reader` 删除自带的表头解析、同义词表、续表判定，改调 R1 模块；对外函数签名不变。
- R2.2 单体表按名字没找到对应表时，按列语义键重合度兜底（唯一最高且覆盖 ≥ 一半金额列才选），并在读取结果里写明「按表头结构认到」。
- R2.3 行续表的行并入主表（列语义键能对上的才并）；列续表按行名对行（现状保留）。
- R2.4 既有 V186 链路测试与端到端测试不回退。

## R3 重新汇总 = 节点子树逐节点更新 + 自下而上汇总

- R3.1 所选节点子树按后序逐节点处理，每个章节一个 SAVEPOINT：
  - 数据叶子：按已确认映射从本企业单体附注拉数（V186 `apply_detail_refresh(node_key=叶子)`）；
  - 差额节点：按抵销 / 调整分录算差额（公式内核 `fill_by_formula(node_key=差额节点)`）；
  - 汇总节点：= Σ 直接下级节点已保存的附注数（下级汇总节点用其汇总结果）+ 差额节点；合计 / 小计按本表数据重算；手工 / 锁定单元格不动；写来源标记 `subtree_aggregate` 与下级构成。
- R3.2 某章节没有明细模板绑定、某企业未确认映射、整节锁定等按原因跳过并逐节点回报；没有任何下级企业数据时汇总节点不写（不把只有差额的结果当合并数）。
- R3.3 与合并推送共用并发锁（进程锁 + PG 事务级咨询锁）。
- R3.4 端点 `POST /api/consolidation/notes/{pid}/{year}/reaggregate` 改走子树汇总，响应保留现有字段（`sections_processed` / `sections_updated` / `errors` / `results` / `failures` / `status`），新增逐节点摘要。
- R3.5 后台按公式刷新（推送后刷新、试算表事件）不覆盖来源为 `detail_mapping` / `subtree_aggregate` 的节点数据：公式值有变化只标 `is_stale` 并记录最新公式值，由用户重新汇总；差额节点照常按公式刷新。用户主动「按公式填入」行为不变。
- R3.6 前端合并附注页：按钮说明改为新语义；完成提示按节点汇报（拉数 / 差额 / 汇总 / 待确认映射企业）。
