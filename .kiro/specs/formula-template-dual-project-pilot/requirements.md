# 需求文档：S6　公式模板双项目试点

> **本 spec 由 `formula-hub-integrity-closure` 按需求 17.5 创建（design §8.1 的 S 系列交接）。**
> 创建时只有本文件：它的作用是让「formula-hub-integrity-closure 没做、但已知必须做」的事有明确的负责范围与触发条件，
> 不在归档时丢失。实施前需补 design.md 与 tasks.md，并按三件套纪律先做「现状 grep 确认」
> —— 下面每条都是 `formula-hub-integrity-closure` 实施期的现读结论，**启动时必须重新现算**（memory 方法论铁律①②）。

## 1. 负责范围
- 后端模板链路用真 PG 回滚事务验证；登录态浏览器 UAT 使用专用【测试】项目并在结束后走平台清理，两个验证层不混称为同一事务。
- 模板回滚发版、版本 diff、新增 slot。
- 订阅 / 退订的所有写入口按目标项目 edit 权限门控（现在工具栏订阅按钮没有展示层门控）。

## 2. 依赖与先后
依赖 S4（durable outbox）—— 模板发版会扇出到全部订阅项目，没有 outbox 不敢在真实项目试点。

## 3. 触发条件

有第二个真实项目愿意做模板订阅试点时。

## 4. 承接自 `formula-hub-integrity-closure` 的具体欠账
本 spec 真库 `formula_template` 0 行、`formula_publish` 0 行 ⇒ 模板链路从未有真实数据流经过。

## 5. 不属于本 spec

- `formula-hub-integrity-closure` 已交付的部分不回填改写（历史档案 append-only）；本 spec 只做上面第 1 节列出的事。
- 决策项 X1~X5（共享库迁移与推送、存量归属行升级、真实项目报表重算、门禁切 enforce、D1~D15 默认值确认）
  属用户决定，不由本 spec 代为执行。

## 6. 设计阶段补充（2026-10-29）

- 已补 design.md / tasks.md。现状复核见 design §1：后端发版已支持新增公式位，缺的是界面、回滚发版与版本对比。
- P2-4 四个小缺口已纳入本 spec，具体契约与验收见 design §6~§7。

## 7. 开工前裁决（2026-10-31）

- **UAT 分层**：服务层 / PG 契约测试可以在回滚事务内执行；跨 HTTP 的登录态浏览器 UAT 使用专用【测试】项目，完成后走平台删除路径并逐表对账，不声称浏览器请求共享一个事务。
- **测试项目拓扑**：实现阶段先固定为一个模板来源项目 A、两个订阅项目 B/C；B 预置本项目适配，C 不预置本项目适配。若实际只允许两个项目，必须在 UAT 记录中明确 A 同时承担哪个订阅角色，不能省略来源项目。
- **真实试点门**：本次代码实现不写真实项目。真实试点须由用户点名来源 / 订阅项目和时间，并单独明确允许真实写入；先执行 preview，再执行 publish / rollback，不自动退订、不删除真实数据。
- **P2-4**：纳入本 spec。适用范围兼容校验、共享范围收窄 409、发版计划去 N+1、模板详情到项目订阅入口均为交付范围。
- **收窄策略**：不自动退订。更新共享范围后，只要任一现有订阅项目的有效成员按新可见性规则看不到模板，就返回 409 和可授权展示的项目清单。
- **S4 门槛**：模板发版必须经 `record_changes` → commit → `publish_pending`，不得恢复 `publish_events`；S4 浏览器传播验收未闭合前，只允许做离线 / 回滚事务测试，不执行双项目浏览器 UAT。
