# 公式管理深度优化 — requirements.md

> spec: `formula-management-deep-optimization`
> 创建日期: 2026-10-22
> 范围: 6 项改进（推送收窄/健康度总览/调试模拟器/表间审核扩展/反向校验/版本时间轴）
> 优先级: P1~P2，排除 P3 模板市场化（当前单事务所 ROI 不足）

## 一、背景

公式管理已覆盖 15 个取数函数、80 码推送注册、三层继承六域统一、模板完整联动。
在核心机制扎实的基础上，本 spec 聚焦**用户体验深度打磨和数据链可见性提升**。

## 三、需求

### R1 推送跳过项收窄

**现状**：真库实测 skipped=66 / coverage=327 / fallback_to_total=104。
`find_row` 三级匹配（精确→去后缀→包含）已较完善，但仍有 66 条跳过。

**需求**：
- R1.1 分析 66 条 skip 的分类原因（缺行/多义命中/模板不一致），输出分类清单
- R1.2 增加第四级匹配：别名表 `note_row_aliases`（JSON 文件，`{标签: [别名1, 别名2]}`），精确匹配别名后映射到真实行
- R1.3 棘轮：`_MAX_SKIPPED` 从当前值（按真库实测重定基线）只许降、不许升
- R1.4 fallback_to_total 的逐条裁决：哪些是合理的（合计行汇总确实正确），哪些应该消除

**验收**：skip 数下降且棘轮收紧；别名表有维护入口

### R2 项目级公式健康度总览

**现状**：公式看板只展示当前底稿/当前域的覆盖率。缺少项目级全景视图。
已有基础设施：`formula_push/coverage.py` 覆盖率计算、`stale_summary_aggregate` 过期汇总、`formula_settings/pending.py` 待确认查询。

**需求**：
- R2.1 新端点 `GET /api/formula-health/{project_id}/{year}` 返回项目公式健康度聚合数据
- R2.2 六维度健康指标：
  - 推送覆盖率（D~N 各循环接入率）
  - 推送成功率（最近一次 run 的 written/skipped/conflict 分布）
  - 公式配置率（报表行/附注/底稿有公式 vs 无公式的比例）
  - 冲突待确认数（FormulaSyncItem status=pending 的计数）
  - 表间审核通过率（最近一次 cross_check 的 pass/fail）
  - 过期链占比（stale 的报表/附注/底稿数量）
- R2.3 前端新增「📊 公式健康度」面板（可嵌入 FormulaManagerDialog 看板弹窗或独立路由页）
- R2.4 支持按循环/域下钻查看明细

**验收**：面板六维度数据准确；点击可下钻

### R3 公式调试/模拟器

**现状**：公式 trace 只在计算后被动展示（tooltip），没有交互式即时调试。
已有基础设施：`FormulaContext.from_simple_map` 可构造轻量上下文、`execute` 返回带 trace 的 `FormulaResult`。

**需求**：
- R3.1 新端点 `POST /api/formula/debug` 接收公式文本和上下文快照，返回逐步求值 trace
- R3.2 `FormulaEditDialog` 增加「▶ 调试运行」按钮：编辑区输入公式后可即时看到逐步求值结果
- R3.3 trace 可视化：树形展示每一步（函数调用→参数解析→取数→中间结果→最终值）
- R3.4 异常定位：取数失败/函数不支持/语法错误时，高亮标红出错位置和原因
- R3.5 上下文快照：自动从当前底稿/报表/试算表取最新数据构造调试上下文

**验收**：编辑公式→点击调试→即时看到逐步求值；错误时精确标红

### R4 表间审核跨模块扩展

**现状**：`cross_check_rules.py` 的 `_evaluate` 走 `evaluate_formula_result`（报表路径），已支持 TB/SUM_TB/ROW/SUM_ROW/REPORT/WP/NOTE。
但 PREV/AUX/ADJ 在报表路径被硬置 0（`function_support_matrix.py` 确认）。
表间审核规则当前只能对**同一报表路径**可达的数据做审核。

**需求**：
- R4.1 扩展表间审核 resolver 支持 PREV（对比上期报表值）
- R4.2 扩展表间审核 resolver 支持 AUX（辅助余额维度数据校验）
- R4.3 审核规则编辑器增加 PREV/AUX 函数按钮和参数提示
- R4.4 规则模板：预置常用跨模块审核规则（如「报表合计 = TB 汇总」「附注合计 = 报表行」）

**验收**：表间审核可以用 PREV/AUX 函数；预置规则可一键导入

### R5 推送反向校验

**现状**：推送是单向的。`FormulaPushPanel` 展示推送结果（written/skipped/conflict），但无法直观看到推送值与源头值是否一致。
已有：`FormulaPushState` 模型记录每个地址的推送状态、`results.py` 有完整的 PushItem 数据结构。

**需求**：
- R5.1 新端点 `GET /api/formula-push/{project_id}/{year}/verify` 返回反向校验结果
- R5.2 校验逻辑：对每个已推送的地址，重新取源头值，对比目标当前值
- R5.3 差异分类：一致/数值偏差（标偏差额）/目标被手工改过/源头已更新未推送
- R5.4 前端在 FormulaPushPanel 增加「🔄 反向校验」按钮和结果面板

**验收**：点击校验→展示每个已推送地址的一致性状态；不一致项标红

### R6 公式版本时间轴

**现状**：`FormulaHistoryTab` 展示变更列表（从 `audit_log_entries WHERE action_type='formula.changed'` 查询），但是纯列表形式。
`formula_publish` 表记录全局发布历史。

**需求**：
- R6.1 新端点 `GET /api/formula-timeline/{project_id}/{year}` 聚合公式变更时间轴
- R6.2 时间轴数据源合并：公式审计日志 + 全局发布历史 + 模板更新 + 推送触发 + 冲突解决
- R6.3 前端新增时间轴可视化组件（横轴时间，按事件类型着色标注）
- R6.4 点击事件可展开详情（谁改了什么、改前值、改后值、影响范围）
- R6.5 支持按域/公式位过滤

**验收**：时间轴展示完整的公式生命周期事件；点击可查看详情

## 四、非功能需求

- NF1: 所有新端点必须挂 `require_project_access("readonly")` 项目鉴权
- NF2: 前端所有文案中文（技术术语 SQL/API/UUID 等保留英文）
- NF3: 新增组件 ≤500 行；超限登记白名单
- NF4: 后端新端点配 pytest 测试覆盖核心路径
