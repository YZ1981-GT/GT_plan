# 需求：附件平台跨模块闭环

> 基线：`ff8ccd354`。承接 2026-11-01 附件跨模块评估，用户要求“按建议逐一修复”。

## 范围与裁决

- 本 spec 覆盖普通附件、证据治理、底稿证据、凭证、合同、函证、归档/签发、报告/附注/交付件溯源、知识库和 AI 对话附件。
- 领域实体不合并：项目证据、知识文档、AI 临时附件保留各自 ACL 与生命周期；统一不可变字节、安全摄入、读取和预览原语。
- 不自动把客户证据放入全所 RAG；跨域复用必须由用户显式发起并记录来源版本、hash、项目、年度和操作者。
- 本轮只做 additive schema 和兼容切换，不删除 legacy 列、alias 或历史版本。共享库数据迁移、真实项目 purge 均须另行放行。
- 已声明证据缺口、未回函且无替代程序、关键证据 OCR 未确认、判定 `unknown` 均阻断签发/归档；普通未确认 OCR 只提示。无声明是 `not_declared`，不阻断。

## R1　封堵附件路径读取

1. 删除公开 `POST /api/projects/{project_id}/attachments` 元数据建档能力；内部可信存储落地仍可建 Attachment。
2. 所有附件本地读取、Office 预览、OCR、归档和物理删除统一走项目级 resolver；真实路径必须位于 `{ATTACHMENT_LOCAL_STORAGE_ROOT}/{project_id}`。
3. resolver 必须按 realpath 拦截 `..`、跨项目路径、符号链接/junction、UNC、目录及未知 scheme；拒绝发生在内容读取前。
4. 下载/预览不回显路径；SVG/HTML 等活动内容不得内联执行。

## R2　项目永久删除安全闭环

1. 单条、批量、清空项目回收站共用一个 purge service。
2. 每个项目在同一显式数据库事务内锁定、复核软删状态、预检 legal hold 和项目外引用，再按完整依赖闭包删除；任一步失败则该项目零变化。
3. 禁止 session 级关闭 FK 后只删直接子表；禁止吞异常和虚增成功数。
4. 提交前仅收集文件引用；提交成功后再删除无人引用的本地文件。Paperless 删除失败必须进入可观察回执。

## R3　证据就绪度单一来源

1. 唯一服务返回 `ready/not_ready/not_declared/unknown`，并给出缺失类型、函证明细、凭证样本、关键 OCR 状态和原因。
2. 底稿附件视图、QC-17、`/evidence/sufficiency`、签发门和归档门使用同一判定结果。
3. 查询异常不得变成“满足”；正式动作按范围裁决 fail-closed。
4. 旧 sufficiency 字段保留兼容窗口，但必须从新状态派生。

## R4　合同证据用户闭环

1. D4 合同原件在用户确认 OCR 或手工填写后，以合同号+对方名称写稳定 `contract_key`；修改身份时幂等改绑，删除卡片/附件时同步解除后端位置关系。
2. 提供本项目合同证据批量查询；只返回当前用户可见底稿。
3. D4 显示“他稿已有”，支持预览和引用到本底稿，不复制文件。
4. 合同完整性按逐合同身份判断，不能只看是否存在任意 contract 类型附件。

## R5　函证附件原子化与能力一致

1. 新增单一 multipart 端点，在一次数据库事务内完成上传、配对校验、挂载、reference 和日志；失败补偿已落盘对象。
2. 回函列表返回 `can_apply_reply`、阻断原因和可恢复 OCR 比对摘要；刷新后可继续人工确认。
3. 回填端点复用同一能力判定，并验证附件确为本函证 inbound link。
4. 函证中心、底稿汇总和律师函入口使用同一 readonly/capability。

## R6　附件溯源进入报表、附注和交付件

1. 统一 trace 直接读取底稿权威 `EvidenceLink/AttachmentWorkingPaper`，不为底稿证据双写 AttachmentLineage。
2. `AttachmentLineage` 只承载报表行、附注章节和交付件章节；目标类型与稳定 ref 受白名单校验并具幂等唯一约束。
3. 报表、附注、交付件现有溯源入口能关联、解除并预览附件；跨项目和软删附件不可见。

## R7　不可变字节与版本兼容收敛

1. 新增内部不可变字节对象，记录 hash、大小、MIME、opaque storage key、安全状态和 actor；不提供按 blob ID 直接下载的公开 API。
2. `AttachmentVersion` 与二进制 `KnowledgeDocument` 可选引用字节对象；旧存储列保留镜像。
3. 普通附件新写通过兼容编排同时产生稳定根和不可变版本；旧 ID 经 alias 精确解析，旧 ID 不漂到当前版本。
4. 治理读取直接返回已校验字节或绑定版本/hash 的受控 locator；异步 finalize 必须有 worker，否则禁用异步模式。

## R8　知识库与 AI 的显式桥

1. 知识上传复用文件数/大小、扩展名+MIME、恶意内容、隔离与安全读取；下载必须验证知识存储根和真实路径。
2. public/系统知识目录写入收紧到管理员或明确知识管理员；递归删除必须逐项验证子树管理权并清理索引。
3. “知识文档转项目证据”钉住知识版本/blob/hash，保留两侧 ACL，不随知识新版本自动变化。
4. AI 现有会话附件真正进入 Native/DSH 上下文；项目附件可显式临时加入对话，逐项按项目+底稿可见性授权并钉版本，不复制、不晋升。

## R9　前端可靠性与体验

1. 附件、行级证据、凭证和知识列表区分空、加载失败、无权限，提供重试。
2. 项目附件页按能力隐藏写操作；预览统一序号+AbortController+及时 revoke；后台上传禁止重叠批次。
3. 缓存具 TTL/容量/项目退出清理；大列表分页或虚拟化。
4. 关键入口支持键盘、焦点恢复、中文 aria/alt/title 与 390/768px 布局。

## R10　验证

- 后端端点级与 PG 测试覆盖权限、事务、版本、路径、legal hold、跨项目、补偿和回执。
- 前端 Vitest 覆盖能力、竞态、缓存和请求契约；静态守卫必须有正反变异。
- Playwright 真实覆盖底稿行证据、凭证跨稿复用、合同跨稿复用、函证、知识晋升、AI 项目附件、报表/附注/交付件溯源、归档包。
- 候选树相对干净 HEAD 不增加 lint/type/test 失败；外部依赖未验证必须如实保留未完成状态。
