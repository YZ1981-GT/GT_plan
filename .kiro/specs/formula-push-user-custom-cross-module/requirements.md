# 需求：用户自定义公式 — 跨表格 / 跨科目 / 跨模块

> 前置：`formula-push-all-subjects-rollout`（公式管理基础设施）已完成。
> 本 spec 解决的是**用户侧**公式编辑能力，与批 B~E 的**系统自动推送**互补。

## 1. 现状

公式管理面板已有三层能力（全部已交付）：
- **L0 预设公式**：`prefill_formula_mapping.json` 的系统预设（只读）
- **L1 用户自定义公式**：`wp_formula` / `wp_user_formula` 表，用户可新增/修改/删除
- **L2 公式求值**：`formula_engine.execute` 支持 `TB()`/`SUM_TB()`/`ADJ()`/`ROW()`/`REPORT()`

### 1.1 已有的跨引用函数

| 函数 | 语义 | 实现状态 |
|------|------|----------|
| `TB('1001','期末余额')` | 试算表科目值 | ✅ 已有 |
| `SUM_TB('1001~1099','期末余额')` | 试算表范围汇总 | ✅ 已有 |
| `ADJ('1001','aje_net')` | 调整分录净额 | ✅ 已有 |
| `ROW('BS-001')` | 报表行当期值 | ✅ 已有（`report_engine` 缓存） |
| `REPORT('BS-001','期末')` | 报表行指定列 | ✅ 已有 |
| `WP('E1','E1-1','item_id')` | 底稿单元格 | 🔴 **未实现** |
| `NOTE('五、1','货币资金','库存现金','期末余额')` | 附注单元格 | 🔴 **未实现** |

### 1.2 缺口

| 缺口 | 影响 |
|------|------|
| 跨底稿引用 `WP()` | 审计师不能在 K1 审定表里引用 D2 的审定合计 |
| 跨模块引用 `NOTE()` | 报表公式不能引用附注值做勾稽校验 |
| 用户公式与系统推送的优先级 | 同一 `item_id` 既有用户公式又有推送规则时谁优先？ |
| 用户公式的触发时机 | 用户公式何时求值？每次打开页面？保存时？事件驱动？ |
| 跨科目依赖图 | K1 引用 D2 → D2 审定合计变化后 K1 是否自动重算？ |

## 2. 目标

在现有 L0~L2 基础上补齐跨表格 / 跨科目 / 跨模块的用户自定义公式能力，使审计师可以在公式管理面板中编辑任意跨域公式。

## 3. 范围

| # | 需求 | 验收标准 |
|---|------|----------|
| U1 | `WP()` 跨底稿引用 | `WP('D2','D2-1','D2-1-audited-receivable')` 在 K1 公式管理面板中可求值 |
| U2 | `NOTE()` 跨模块引用 | `NOTE('五、1','货币资金','库存现金','end_amount')` 可求值 |
| U3 | 用户公式 vs 系统推送优先级 | 系统推送目标（`policy=system/derived`）不允许用户公式覆盖；editable 目标允许 |
| U4 | 用户公式触发时机 | 打开公式管理面板时求值 + 保存时验证；不自动持久化（由用户点「应用」） |
| U5 | 跨科目依赖图（可选） | D2 审定合计变化 → 引用它的 K1 用户公式标 stale |
| U6 | 公式管理面板 UI | 跨引用函数的自动补全 + 错误提示 + 地址选择器 |
| U7 | 跨模块表间审核 | 公式管理「表间审核」tab 的 `left_ref` / `right_ref` 支持 `WP()` / `NOTE()` |

## 4. 不做

- 系统自动推送规则的编辑（推送规则只由后端清单声明，用户不能改）
- 合并报表 / 合并附注的跨模块引用（独立体系）
- 程序表 auto_data_source（不属于公式管理）

## 5. 与系统推送的关系

```
                ┌─────────────────────┐
                │  公式管理面板        │
                │  ├─ 📤 公式推送     │ ← 系统自动（批 A~E）
                │  ├─ ✏️ 用户自定义   │ ← 本 spec
                │  ├─ 📜 历史         │
                │  └─ 🔍 表间审核     │ ← 本 spec（跨模块部分）
                └─────────────────────┘
```

- **系统推送**（批 A~E）：后端算后端写，规则声明式，用户通过面板查看/试跑/采用
- **用户自定义**（本 spec）：用户在面板里编辑公式，手动应用，结果写入 `wp_user_formula`

两者共用同一个 `formula_engine.execute` 内核（L1），函数注册表统一。
