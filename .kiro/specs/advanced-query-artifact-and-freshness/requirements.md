# 需求文档：高级查询查询证据与时效（advanced-query-artifact-and-freshness）

## 概述

来源：用户 2026-11-04 给出的高级查询实施顺序第 2 阶段：「Phase 1：查询证据与时效。交付 QueryRun；QueryArtifact；来源版本向量；stale 判定；服务端查询历史；查询结果顶部的范围与版本信息」。前置阶段 0 已在 [`advanced-query-linkage-closure`](../advanced-query-linkage-closure/tasks.md) 收口（远端分支 v1.0.105）。

现状（2026-11-04 现扫，细节与锚点见 design §0）：
- 查询不留服务端记录。查询历史只有弹窗有，存在浏览器本地 `gt:cq:history`，最多 10 条，不含条件与列；页面版与构建器没有历史。
- 「导出全部」在服务端写临时文件，发完即删除。导出审计只记行数与列；文件本身、文件摘要、导出时的数据版本都不留存，导出件事后无法证明「是当时那份数据」。
- 查询结果不带数据版本。编排器缓存 30 秒、COUNT 凭证 600 秒，这期间数据变化仍会返回旧结果、旧总数。
- 现成可用的强版本信号只有四表的生效数据集（数据集内的行不改写）。`updated_at` 不可靠：试算表至少 4 处执行语句改 `audited_amount` 不写 `updated_at`，底稿 10 处、报表 1 处、附注 1 处同类（AST 口径，排除 docstring）。

目标：查询结果可以当审计证据用。每次查询都说得清「查的是什么、在什么范围、基于哪一版数据」；事后能判断结果是否已过期、为什么过期；导出文件不可改写、可校验、可追溯到查询定义与数据版本；查询历史存在服务端，换浏览器、换电脑都还在。

范围：业务视图（弹窗 `CustomQueryDialog`、页面版 `CustomQueryTab`，含模板执行）与高级构建器（`AdvancedQueryBuilder`）三个宿主，及其后端执行与导出链路。不含（属 Phase 2 `advanced-query-evidence-review-archive-linkage`，本 spec 只在 design §11 预留接口）：导出为附件、关联底稿 / 单元格 / 凭证、从结果建问题单、复核快照、通知分派、归档清单纳入查询证据。

约束：新 router 在 `backend/app/router_registry/system.py` 注册；service 只 flush、router 统一 commit；提交前的非阻塞写入包 `begin_nested()`；迁移 `V{n}` / `R{n}` 成对、DDL 一律 `IF NOT EXISTS`、版本号实施时现取；三层一致（迁移 + ORM `Mapped[]` + service）；判断「代码是否做了 X」用 AST；新模块与调用方同一次提交；写入型测试只在回滚事务里进行、只写名称带【测试】的项目。

术语：
- **运行记录（QueryRun）**：某用户在某入口、按某查询定义、在某一版数据上执行的记录。同用户、同入口、同定义、同版本只有一条，重复执行累计次数。
- **查询证据（QueryArtifact）**：一次「导出全部」产生的不可改写文件及其清单（manifest）。
- **版本向量**：本次查询涉及的每张来源表在查询范围内的版本（称「分量」）的集合；**版本摘要**是版本向量规范序列化后的 SHA-256。
- **分量依据**：数据集（项目年度生效数据集编号）、内容摘要（范围内每行内容去掉时间戳后的摘要）、行版本（PostgreSQL 行系统列 `xmin` 的摘要）、更新时间（行数 + 最近 `updated_at`，弱判据）、范围（本人循环范围 / 构建器作用域）。
- **过期判定**：按运行记录保存的分量范围重新采集并逐个比较，结论为 current（未变化）/ stale（已过期）/ unknown（无法判定）。

## 1. 功能需求与验收标准

### R1 运行记录（QueryRun）
- R1.1 业务视图（`POST /api/custom-query/execute`、`POST /api/custom-query/templates/{id}/execute`）与构建器（`POST /api/query/execute`）执行成功后登记运行记录。身份 = 用户 + 入口 + 定义摘要 + 版本摘要；同一身份重复执行只累加执行次数、更新最近执行时间与最近总数；距上次更新不足 60 秒的重复执行不更新记录（翻页、连续点查询不制造写入）。
- R1.2 定义 = 规范化后的请求：业务视图为 `QueryRequest` 去掉 `limit` / `offset` / `count_token`，构建器为 `QueryDSL` 去掉同样三项；导出请求的 `headers` / `file_name` 不进定义。翻页、改每页行数命中同一定义；键序不同、UUID 大小写不同的同义请求得到同一定义摘要（PBT 证明）。
- R1.3 身份字段（用户、入口、来源键、项目、年度、定义、定义摘要、版本向量、版本摘要、范围、显示标签、采集时间、创建时间）写入后不可修改，由数据库触发器拒绝；可改字段只有执行次数、最近执行时间、最近总数、最近提示、隐藏时间、更新时间。
- R1.4 模板执行登记 `origin = template` 与模板编号，定义取模板解析后实际执行的请求；其余登记 `origin = direct`。
- R1.5 execute 响应新增可选键 `run`：运行编号、是否已登记、采集时间（UTC）、定义摘要、版本摘要、范围、各分量摘要、是否含弱判据。业务视图与构建器既有响应键、类型、状态码不变。
- R1.6 登记失败（迁移未落库、写库出错）不影响查询结果：响应 `run.recorded = false` 并带中文原因，日志记 WARNING；不返回 500，也不报成已登记。

### R2 来源版本向量
- R2.1 版本向量在查询主语句之前采集（采集先于取数）。由此「未变化」的结论不会错：采集之后提交的写入，下次比较时一定显出；代价是查询进行中提交的写入也会被报为已变化。
- R2.2 分量依据按来源表登记（design §4.3）：
  - 科目余额、序时账、辅助余额、辅助明细 → 数据集：项目年度当前生效数据集的编号与激活时间（与 `DatasetService.get_active_dataset_id` 同一排序）；没有生效数据集时改按行版本，并在分量说明里写明。
  - 试算表、报表、报表配置、调整分录、未调整错报、底稿索引、工时、重要性、报表行次映射、科目表、人员 → 内容摘要：范围内行数 + 每行内容（去掉 `created_at` / `updated_at`）的摘要。
  - 底稿、附注、合并附注、合并工作底稿、项目（含大 JSON 列）→ 行版本：范围内行数 + `id:xmin` 的摘要。
  - 业务视图另有范围分量（本人循环范围）；构建器另有范围分量（作用域项目集合摘要、角色、因循环范围排除的项目数）；带 `acnr_targets` 的查询另加底稿行版本分量。
  - 每个分量另记最近更新时间，只用于说明，不参与比较。
- R2.3 业务视图全部数据源形态（注册表源与别名、`report_{类型}`、`consol_unit:{单位}:{类型}`、`workpaper:` 叶子、附注目录与章节、`tb_summary` / `worksheet` / `ws_*`、底稿选区）与构建器白名单的全部表，都在登记表里有对应项；缺一项即守卫失败。
- R2.4 内容摘要超过 50,000 行时改按行版本；行版本超过 200,000 行时改按「行数 + 最近更新时间」，该分量标为弱判据。
- R2.5 每个分量在独立 SAVEPOINT 内采集，语句超时 2 秒；采集失败的分量记下中文原因，不让查询失败，也不污染本请求的事务。
- R2.6 版本摘要纳入业务视图编排器缓存键、构建器缓存键与两处 COUNT 凭证主体：数据变化后不再命中旧缓存，也不再复用旧总数。
- R2.7 报表类分量记录本次解析出的报表准则；判定时准则不同即算变化，并写明原因。

### R3 过期判定
- R3.1 `GET /api/custom-query/runs/{run_id}/freshness`：按运行记录保存的分量范围重新采集、逐个比较。全部一致 → current；任一分量变化 → stale；没有变化但有分量采集失败 → unknown。返回每个变化分量的中文原因（生效数据集切换、行数变化、内容变化、准则变化、循环范围或作用域变化）、前后行数与最近更新时间、是否含弱判据、判定时间。
- R3.2 `GET /api/custom-query/artifacts/{artifact_id}/freshness`：同一判定，比较对象是证据记录的版本向量。
- R3.3 判定只采集分量，不重跑查询、不写库、不记审计；单次判定在共享库最大作用域上 ≤ 100 ms（实测记录）。
- R3.4 current 的文案写成「自查询开始以来未检测到来源变化」；含弱判据时追加「部分来源仅按更新时间判断，未写更新时间的改动可能检测不到」。

### R4 查询证据（QueryArtifact）
- R4.1 业务视图与构建器的「导出全部」各生成一条证据：文件写进证据目录（缺省 `{STORAGE_ROOT}/query_artifacts/`），记录文件名、大小、SHA-256、数据行数、列（键与表头）、运行编号、定义摘要、版本向量与版本摘要、范围、导出人、导出时间，以及清单（规范 JSON）与清单的 SHA-256。
- R4.2 导出文件的「查询说明」sheet 在现有各行之后增加四行：查询编号（运行编号）、证据编号、数据版本（各分量摘要）、版本摘要（前 16 位）。
- R4.3 证据的身份字段写入后不可修改（触发器）；状态只能从 ready 变为 purged；文件不覆盖、不改写，每次导出都是新编号、新文件。
- R4.4 `GET /api/custom-query/artifacts/{id}/download` 先流式重算文件大小与 SHA-256：与记录一致才返回文件；不一致返回 409 `QUERY_ARTIFACT_INTEGRITY` 并记审计；已清理返回 410 `QUERY_ARTIFACT_PURGED`。
- R4.5 `GET /api/custom-query/artifacts/{id}/manifest` 返回清单 JSON，响应头 `X-Manifest-SHA256` 等于对返回内容按规范序列化重算的摘要，也等于库中记录。
- R4.6 导出响应头新增 `X-Query-Run-Id`、`X-Query-Artifact-Id`、`X-Query-Artifact-Status`（`stored` / `unavailable`）。证据保存失败时导出照常完成（与现状相同），状态为 `unavailable`，前端提示「已导出，但未保存为查询证据：<原因>」，导出审计记下原因。
- R4.7 「导出当前页」仍由前端生成、不产生证据，菜单项写明「不保存为证据」。

### R5 服务端查询历史
- R5.1 `GET /api/custom-query/runs?entry=&project_id=&limit=`：本人、未隐藏的运行记录，同一定义只取最近一次，按最近执行时间倒序；每项含项目名、年度、数据源名、执行次数、最近总数、该定义下的证据数。
- R5.2 `GET /api/custom-query/runs/{id}`：定义（供回放）、范围、版本分量、该定义下的证据列表。
- R5.3 `DELETE /api/custom-query/runs/{id}` 与 `POST /api/custom-query/runs/clear?entry=` 只把记录标为隐藏，不删除；隐藏的运行仍可经证据追溯。同一身份再次执行时取消隐藏。
- R5.4 `GET /api/custom-query/artifacts?entry=&project_id=&limit=`：本人的证据，含已清理的（标明状态）。
- R5.5 弹窗「历史」改读服务端。本地 `gt:cq:history` 停用，新版本首次加载时删除该键，不导入（本地条目没有条件与列，还原不出定义）。
- R5.6 页面版与构建器新增同一个「历史与证据」抽屉（弹窗也用它）。「重新查询」把定义写回宿主状态后执行（构建器写回 DSL 与项目范围）；定义里有宿主不支持的设置时列出这些设置，由用户选择继续或取消，不静默丢弃。

### R6 查询结果顶部的范围与版本信息
- R6.1 三个宿主的结果区顶部显示同一个信息条：范围（项目、年度、数据源、条件数、循环范围；构建器为项目范围、所涉表、未按项目过滤的表）、版本（每个分量一行：生效数据集激活时间、行数、最近更新时间）、采集时间（北京时间）、时效状态。
- R6.2 信息条提供「检查是否过期」；页面重新可见且距上次检查超过 60 秒时自动检查一次；检查中、检查失败都有提示；同一宿主同时最多一个检查请求，过时的响应丢弃。
- R6.3 已过期时显示变化原因与「重新查询」；未登记时显示「本次查询未记录，无法判断是否过期」；含弱判据时显示 R3.4 的说明。
- R6.4 构建器原有结果范围标签的文案与判定由信息条承接，测试锚点 `aqb-result-scope` 保留。
- R6.5 翻页后运行编号变了（两次翻页之间数据有变化）时提示「数据已变化，本页与之前各页可能不一致」。
- R6.6 文案全中文；时间经 `fmtDateTime` / `parseServerTime` 显示；行数带千分位。

### R7 权限与审计
- R7.1 运行记录与证据只对创建者可见；非创建者（含 admin）访问一律返回 404 `QUERY_RUN_NOT_FOUND` / `QUERY_ARTIFACT_NOT_FOUND`，不暴露记录是否存在。
- R7.2 创建者读详情、判定、下载、读清单前重验访问：业务视图记录经 `ownership_guard.assert_target_accessible` 校验项目，失去访问返回 403 `FORBIDDEN_PROJECT`；构建器记录先过 `resolve_builder_access`，并且记录的项目集合仍须在本人当前构建器作用域内，否则 403 `QUERY_SCOPE_REVOKED`。列表接口按同一规则过滤，已无权访问的项目的记录不返回。
- R7.3 证据下载记审计 `custom_query.artifact_download`（不节流）；完整性校验失败记 `custom_query.artifact_integrity_failed`；导出审计 `custom_query.export` 增加证据编号、清单摘要、运行编号、版本摘要。
- R7.4 新端点有表驱动权限测试（创建者 / 同项目其他成员 / 非成员 / admin 非创建者 / 创建者失去项目访问 / 创建者失去构建器准入 / 未登录）；端点鉴权基线守卫各维度计数不增加；路由遮蔽守卫通过。

### R8 迁移、降级与保留
- R8.1 一组迁移（`V{n}` + `R{n}`），号在实施时取「磁盘（含未跟踪）、共享库已应用、远端分支」三处最大值 + 1（2026-11-04 三处均为 V251）。
- R8.2 迁移未落库时：查询照常（`run.recorded = false`）；导出照常（证据 `unavailable`）；历史与证据接口返回 503 `QUERY_EVIDENCE_UNAVAILABLE`「查询证据功能尚未启用（数据库迁移未执行）」。
- R8.3 保留：证据缺省保留 30 天（`QUERY_ARTIFACT_RETENTION_DAYS`），到期删除文件、记录标为 purged（清单与摘要保留）；运行记录每人保留最近 500 条且 90 天内执行过的（`QUERY_RUN_KEEP_PER_USER` / `QUERY_RUN_RETENTION_DAYS`），被未清理证据引用的不删。清理由导出清理 worker 每小时在主副本执行，日志记删除数；证据目录里超过 1 天的 `.partial` 残留一并清除。
- R8.4 共享库执行迁移前须用户放行；开发服务器热重载不跑迁移，需全量重启或调用 `MigrationRunner(...).run_pending()`。

## 2. 非功能需求

- N1 性能：执行时采集版本向量的额外耗时 p95 ≤ 30 ms（共享库最大作用域、项目级来源，实测记录，不作 CI 硬断言）；导出文件在证据目录内用同盘临时文件写成后原子改名，SHA-256 流式计算，不把整个文件读进内存。
- N2 兼容：execute / export 既有响应键、类型、状态码不变；`run` 键与三个响应头是新增；前端忽略不认识的键。
- N3 行数门：`routers/custom_query.py`（1990 行，白名单上限 2006）不增行，执行主体移到服务模块；`CustomQueryDialog.vue`（1431 / 1500）净增 ≤ 0；新文件 ≤ 800（.py）/ 1500（.vue / .ts）。
- N4 测试：单测 + 真 PG（回滚事务）+ PBT（max_examples=5）+ 前端 vitest + 磁盘变异 + 候选栈浏览器写后读回 + 性能实测；判据里的数字一律在测试内现算，不写死。

## 3. 待用户确认（附推荐默认值，未确认时按默认值实施）

- D1 证据缺省保留天数：建议 30 天（可配置；Phase 2 被关联或归档的证据另行固定，不受到期清理）。
- D2 运行记录保留：建议每人最近 500 条且 90 天内执行过。
- D3 共享库迁移放行时机：任务 1 完成、候选树全绿之后。
- D4 现状确认中发现的范围外 P0（design §12.1：报表生成运行记录在 PostgreSQL 上写不进去，三条报表生成路径失败）的处置：另立 spec / 交原作者 / 本会话先修。
