# 需求文档：LLM 联动与审计实务闭环

> 用户 2026-11-01 在平台 LLM 模块分析后裁定“按建议来，逐一修复”。本 spec 承接该分析中除明确延后的 pgvector、DSH 全量扩面和 8 个插件实现之外的改进项。

## 1. 目标

平台应把现有“模型底座统一、业务调用分散”的状态收敛为可验证的 AI 任务链：用户选择的上下文真实进入模型，模型回答能回到证据，人工确认后精确写入业务版本，并可追溯、失效和回退。

## 2. Chat Run 接线真实性

1. `mentions`、`attachment_ids`、`review_mode`、`sheet_name` 必须由 Native/DSH 引擎真实消费；未支持的能力必须在 capability 中如实关闭且前端隐藏。
2. mention、附件和复核提示词必须逐项重新授权，客户端 label、正文和项目断言不能作为权威数据。
3. 宿主、mention、附件、复核 prompt、知识命中必须共用一个 token 预算和 Context Manifest，明确列出 included、trimmed、denied、unavailable。
4. citation 事件、前端显示、跳转和消息持久化必须使用同一字段契约；跳转时重新鉴权。
5. 每次成功 Run 必须记录实际模型、部署位置、是否兜底和前序失败；不能只记录首选模型。

## 3. 上下文与知识权限

1. 文件夹级对话必须逐文档判权、稳定排序，并在 manifest 中逐篇登记实际纳入的文档。
2. 全局、项目、底稿、附注、报表和知识库宿主的范围提示必须与服务端实际检索行为一致。
3. 有项目但无具体文档的顶栏助手不得静默退回无项目全局模式；应构造明确的项目概览宿主或提示用户选择资源。
4. 未保存编辑必须明确提示未纳入；后续通过受限 `draft_overlay` 纳入时，须绑定已授权宿主、基线版本和内容 hash。

## 4. 鉴权与数据边界

1. 所有活跃 AI 路由必须做项目/对象级权限校验；前端未挂载不能作为豁免理由。
2. AI 动作能力拆为 ask、draft、review、adopt、agent；QC/EQCR 可进行只读独立复核，但不能采纳或写回。
3. 模型配置必须区分本机、事务所私有服务、经批准外部服务及禁止处理客户数据的端点；任务声明允许的信任域与脱敏级别。
4. 发生服务器兜底时，界面与审计记录必须显示实际部署位置；不允许将可兜底的引擎声明为 `local_only`。
5. 内部 metrics/health 信息不得向未授权用户暴露运行容量或模型状态。

## 5. 统一模型执行契约

1. LLM 错误不得再以普通正文返回。公共执行结果必须是 typed result，区分 success、unavailable、timeout、rejected、invalid_output。
2. 只有 success 结果可以形成草稿；失败不能携带固定置信度、成功提示或可采纳 message。
3. 模型名、部署位置、兜底、usage、error code 必须来自实际执行结果，不能硬编码。
4. 对话式与一键式功能可保留不同 API，但必须复用统一的任务规范、上下文计划、模型网关、验证器和草稿身份。

## 6. 审计专业边界与事实验证

1. AI 可以提取、摘要、草拟、提出假设和建议程序；不得独立决定最终审计意见、重大会计估计、舞弊结论、合并范围或签发状态。
2. 专业边界按 `task_code` 和输出类型执行，不用脆弱的关键词匹配。
3. 底稿复核应先运行确定性检查，再由 LLM 补充疑点。AI 不能单独产生“复核通过”。
4. 解析失败、未知风险、证据不足、程序未完成、服务不可用一律为 `manual_review_required` 或阻断状态，不能是 pass。
5. 数字、日期、主体和准则依据必须带可定位来源；数字类事实必须与权威业务数据逐值核对。

## 7. 附注和底稿实务闭环

1. 附注变动分析的本期/上期数据由服务端从权威附注表格、报表、TB 和调整数据加载，前端不提交事实数值。
2. 续写、改写、政策和分析必须先展示 diff/预览，再进入同一待确认链，不直接覆盖编辑器。
3. 批量附注预填和批量复核改为耐久任务，支持幂等、取消、恢复、逐项重试和持久进度。
4. 每个批量草稿必须有稳定 generation/message ID；用户采纳已经看到的版本，不能再次生成。
5. 人工确认后由业务服务按目标字段/单元格和基线版本执行 CAS patch；写回沿用项目权限、编辑锁、合并锁和领域事件。
6. 写回记录 before/after 版本与 hash，并提供与 AI generation 关联的撤销操作。
7. AI 待确认状态加载失败时必须显示“状态不可用”，不能伪装为 0 条。

## 8. Prompt、留痕和观测

1. 建立版本化 `AiTaskSpec`/Prompt Registry：任务代码、风险级别、角色、信任域、上下文 recipe、prompt 版本、输出 schema、验证器和写回策略。
2. 每次生成记录 prompt/version/hash、模型配置、有效采样参数、应用版本、上下文条目版本/hash、输出 hash 和人工处置。
3. 统一观测至少包含首 token 时间、总时延、输出速度、实际模型/部署、兜底率、错误率、token 与估算成本。
4. 建立无客户数据的金标集与真实模型 canary；普通 CI 使用 deterministic fake，发布前环境验证真实 transport、引用和结构化输出。

## 9. 非目标

1. 本轮不强制启用 pgvector；词法检索继续作为知识正文权威路径，向量模型仍不得跨模型兜底。
2. 本轮不扩大 DSH 项目 allowlist；先修共同上下文、权限、预算和多 worker 状态。
3. 本轮不实现 8 个插件 stub；只隐藏执行入口或明确标记开发中。
4. 不允许 AI 绕过既有 TB 发布门、附注编辑门、项目归档锁、合并锁和底稿编辑锁。
