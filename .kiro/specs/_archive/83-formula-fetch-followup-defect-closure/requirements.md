## R2 初次预填三参 PREV 逐格定位表

1. 新增按模板逐格的定位表：映射表里每个三参 PREV 格（`prefill_formula_mapping.json`）对应模板里的确切单元格（sheet + A1）与动作：`write`（目标格不是公式，写值）/ `verify`（目标格是模板公式，不改写，写核对批注）/ `none`（模板没有对应格，写明原因）。
2. 定位表由生成脚本从模板扫描得出（幂等、无时间戳、带 `--check`），歧义格人工裁定后登记，不靠运行时列头关键词猜。
3. 初次预填按定位表落值：`write` 写上年同底稿取数结果（取不到不写、不写 0）；`verify` 只加批注写明上年值与来源；同一套取值走 `PriorWpFieldResolver`（与重新预填 / 公式运行时同一来源）。
4. 重新预填叠加有效公式时，三参 PREV 公式位的落格也用定位表。
5. 守卫：每个三参 PREV 格在定位表里恰有一条；目标格存在、列头属上年 / 期初语义、公式标记与模板一致；模板变化时 `--check` 打红。

## R3 两个以「PREV 恒为空」为前提的陈旧测试改写

`backend/tests/test_prefill_wp_prev_resolution.py`、`backend/tests/four_table/test_k_cycle_preset_closure.py` 按现行语义改写：三参取上年同底稿数（有上年数据 → 值；没有 → 空 + 原因，不为 0），两参 = 科目 + 列；保留仍有效的守卫意图（锚点 SQL 对真实 schema 有效、不读 cells 键等），删掉对已删函数的依赖。

## R4 鉴权缺口

1. 地址库接口（`/api/address-registry` 下的搜索 / 统计 / 解析 / 校验 / 失效缓存）校验项目成员权限（只读级）；「清空全部项目缓存」只许管理员。
2. 生成底稿两个端点（`/working-papers/generate`、`generate-from-codes`）及同文件新建自定义底稿的三个端点挂项目级编辑权限；前端对无编辑权限的角色隐藏或禁用入口。
3. 底稿模板清单（`/api/workpapers/template-list?project_id=`）校验项目只读权限。
4. `mcp_tools`、`address_mention` 不再写死 `soe` 与年度 0：按项目口径与审计年度取。
5. 鉴权基线守卫同步下调，补端点级测试：未登录 401、非成员 403、该放行的角色真能用。

## R5 引用校验名副其实

1. `/api/acnr/resolve` 对试算表 / 报表 / 附注 / 辅助余额引用不再一律返回存在：有项目上下文时按项目真实数据判定；没有项目上下文时返回「无法确认」而不是存在；复合表达式不是单个引用，不返回存在。
2. 引用校验（地址库校验与保存前校验）与求值口径一致：试算表科目按前缀（与求值同口径）；报表行限本项目适用的报表配置；附注按本项目本年度附注的章节 / 行 / 列（与严格求值同一套匹配）。
3. 附注公式集保存接口在服务端校验引用，悬空引用 422 并列出原因；附注公式执行时 NOTE 引用按行、列取数（与校验同口径），不再一律取合计。
4. 前端保存前校验不再被 ACNR 的「存在」短路，校验请求带项目上下文。

## R6 推错数的规则

1. F2 存货附注：存货跌价准备 1461 不再按正数并入；按账面余额 / 跌价准备 / 账面价值写合计行；科目名为「商品进销差价」等备抵的按减项。
2. K4 其他流动负债、D5 应收款项融资没有标准科目：不取试算表（删试算表取数规则与附注主表规则），格子交给用户填写，写明原因。
3. G / H / I / K 审定表族的「审定合计（原值）/ 净值」：按各底稿前端真实持久化的行清单或合计取数（现状全部读错键、恒为 0）；累计折旧 / 累计摊销 / 减值准备等备抵按减项；读不到时不写假的 0。H1 / I1 附注主表按账面价值（原值 − 累计折旧/摊销 − 减值准备）。
4. 报表 BS-037 其他非流动资产取不存在的 1911 ⇒ 公式置空（用户可在项目层配置），按公式同步内核发布；BS-028 固定资产、BS-032 无形资产补减减值准备（1603 / 1703）。自动填充公式不得把这些行回填成错码。
5. 改动后真库 dry-run 逐地址对比推送结果，变化逐条可解释。

## R7 底稿求值器「本期发生额」

1. 底稿求值器（`wp_formula_eval_service`）的 `本期发生额` = 审定数 − 期初余额（与 L1 预载、推送取数同口径），`TB` 与 `SUM_TB` 都按此取；删死分支。
2. 不认识的列名报错，不再静默按审定数取。

3. `test_business_category_pbt` 全部通过。
