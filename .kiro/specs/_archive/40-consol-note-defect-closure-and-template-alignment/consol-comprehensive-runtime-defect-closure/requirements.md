# 合并模块运行缺陷收口：需求

日期：2026-10-08。来源：`docs/proposals/consolidation-module-comprehensive-problem-recommendation-2026-10-07.md`，CP-01～CP-07。

## 边界

复用归档的合并单源推送、节点隔离和附注刷新资产，不回填旧归档任务。
真实项目只读；不得通过刷新、审批、发布、迁移或重启现有服务取得验收证据。
隔离测试必须覆盖实际生产函数；SQLite 与合成浏览器证据不升级为真实 PG 业务验收。

## R1 Word 结构保真（CP-02）

1. 空标题是合并表头占位，不是删除金额列的依据；保留声明的所有叶子列。
2. 规范化表头后按真实层数渲染，保留合并跨度，不把表头放进金额数据区。
3. DOCX 保存后重新读取，逐列验证独特非零金额及层级；兼容现有 `_column_groups`。

## R2 节点上下文（CP-01）

1. 左树、试算、差额表和普通报表使用同一受控 `node_key`；下拉及下钻同步左树。
2. 右键查看报表先应用节点身份；非汇总节点差额表明确不适用，不静默回根。
3. 取消旧请求并校验响应身份；节点、项目、年度、类型切换和卸载后旧响应不得覆盖新视图。
4. 穿透与当前视图作用域绑定；差额列仍使用自己的 `col.node_key`。
5. JSON 工作底稿保持项目/年度/CAS 边界，不伪造节点作用域，不用节点变化强制重挂。

## R3 推送结果（CP-03）

1. 逐章统计区分刷新、失败、锁定/人工保护跳过及基础条件缺失；锁定不能算成功刷新。
2. steps 保留结构化统计和 warnings；partial/failed 不得写成 succeeded。
3. 保留 run 的 running/succeeded/partial/failed 契约；已有步骤成功且附注失败时 run 为 partial。
4. SSE 完成通知后页面重读权威 run；中文状态区分部分成功，不能清除失败提示。
5. 真实 `_refresh_notes` 的提交、stale 和保护行为与外层故障注入分别验证。

## R4 附注结构与变体（CP-04/05）

1. 国企三级表头及上市嵌入式子表头使用规范化结构，逐列及合并范围可对账。
2. 切换模板立即使旧章节配置失效并重读同章节；防止旧请求返回和旧配置跨变体保存。
3. 未保存内容须明确确认后才切换；切换或只读加载不能自动写库。

## R5 业务约束与主链（CP-06/07）

1. individual 仅计单体 `audited_amount` 一次，非零 AJE/RJE/wp_adjustment 与合并分录分开验。
2. 三码身份去重，全等继续确认；只有校验通过且用户确认合并范围才一次创建三角色。
3. 范围确认独立于项目向导确认；角色保留现有 parent/hq/branch 聚合语义和稳定键。
4. CP-07 复用现有公式、披露载荷构造器和运行模型，禁止复制 Python 复杂披露算法或第二写入方。
5. 主链差集、来源版本和关闭页面能力按实际产物验证；未完成工程项明确登记，不能标为外部阻塞。
