# Requirements Document

## Introduction

D0-1 函证结果汇总表是收入循环最核心的函证底稿——D0 系列 8 个底稿的中心枢纽。当前实现（GtGridSheet 只读 28 列平铺网格）无法编辑且信息架构混乱：录入明细 + 派生统计 + 样本选择叙述 + 审计说明 + 审计结论 + 编制指引 六种职责缝在一个 sheet 里。

本 spec 为函证类底稿做专用 Vue 组件（`confirmation-summary`），将 D0-1 的 6 个功能区块拆为清晰的交互区域：
1. **明细登记** → master-detail（7 列主列表 + 展开生命周期分步面板）
2. **函证情况统计** → 自动汇总看板（5 科目 × 7 指标实时聚合）
3. **样本选择** → 表单区（测试总体/特定样本/抽样方法/过程叙述）
4. **审计说明** → 5 专题 textarea 区
5. **审计结论** → radio(A/B/C) + 自由文本
6. **编制说明** → 移到已有编制指导侧栏（纯静态指引）

按科目 Tab 切换视图（替代 Excel 分页复制列的做法），支持增删行 + 右键菜单 + 枚举下拉 + 保存持久化。

## Glossary

- **函证明细行**：一笔函证的完整 28 字段记录，对应原 Excel 数据行
- **生命周期阶段**：① 发函纪要 ② 发函信息 ③ 回函跟踪 ④ 金额确认/替代程序 → 审计结论
- **master-detail**：列表主视图（7 关键列）+ 行展开/抽屉详情（28 字段按阶段分区）
- **科目 Tab**：应收账款 / 应收票据 / 合同资产 / 合同负债 / 应收款项融资 / 本期销售（按实际项目动态显示）
- **枚举列**：绑定后端 dictKey 的下拉字段
- **派生字段**：从其他字段自动计算的只读字段
- **D0-2 引用**：被询证单位名称从 D0-2（核实被函证单位信息）底稿关联获取

## Requirements

### 需求 1：科目 Tab 切换 + Master 列表

**用户故事**：作为审计助理，我希望按科目分 Tab 查看函证明细，不必横向滚动 28 列。

#### 验收标准
1. WHEN 打开 D0-1 sheet THEN 系统 SHALL 渲染科目 Tab 切换区（从明细行"账户/交易"字段自动去重生成 Tab，如：应收账款 | 合同负债 | 本期销售）
2. WHEN 切换 Tab THEN master 列表 SHALL 仅显示该科目的函证行
3. THE master 列表 SHALL 显示 7 列：序号 | 被询证单位 | 金额 | 是否回函 | 是否相符 | 回函金额 | 审计结论
4. WHEN 列表 SHALL 支持排序（按金额/序号）和快速筛选（是否回函/是否相符）
5. WHEN 底稿只读 THEN 列表为只读；detail 面板可查看不可编辑
6. THE 科目 Tab 右侧 SHALL 有"全部"选项（不筛选，显示所有科目函证行）

### 需求 2：生命周期分步 Detail（条件字段）

**用户故事**：作为审计助理，我希望填写函证详情时按工作流分步，只看到当前阶段需填的字段。

#### 验收标准
1. WHEN 点击行展开/双击行 THEN 系统 SHALL 在行下方展开 detail 面板（或右侧抽屉），按 4 阶段分区：
   - ① 发函纪要：选取样本目的 / 被询证单位名称 / 账户交易(枚举) / 金额
   - ② 发函信息：函证方式(枚举) / 发函日期 / 发函单号 / 收件地址 / 地址核查是否一致(枚举)
   - ③ 回函跟踪：是否收到回函(枚举) / 回函方式(枚举) / 是否相符(枚举) / 回函日期 / 回函快递单号 / 回函发出地址 / 发函地址与回函地址是否一致(枚举)
   - ④ 金额确认与替代：回函金额 / 差异(自动算) / 可确认金额 / 调节索引(D0-4) / 其他说明 / 是否替代(枚举) / 替代后可确认 / 替代后不可确认 / 替代程序索引号
   - 审计结论（文本）
2. WHEN "是否收到回函"选"否" THEN ③ 回函详情灰掉/折叠，④ 替代程序段展开
3. WHEN "是否收到回函"选"是" THEN ③ 展开，④ 替代程序段折叠
4. WHEN "是否相符"选"相符" THEN "差异"自动置 0 只读
5. THE "差异" SHALL = 金额 − 回函金额（自动计算只读）
6. WHEN 用户修改 detail 字段 THEN master 列表对应列实时更新 + 标记 dirty

### 需求 3：自动汇总看板（5 科目 × 7 指标）

**用户故事**：作为现场经理，我希望一眼看到函证整体完成情况。

#### 验收标准
1. THE 页面顶部 SHALL 渲染可折叠汇总看板，按科目（应收账款/应收票据/合同资产/合同负债/应收款项融资/本期销售）分列，含 7 行指标：
   - 本期账面金额（需用户填 or 从 TB 取）
   - 发函金额（= 该科目明细行金额 SUM）
   - 发函占账面比例%
   - 回函确认金额（= 该科目已回函且相符的明细行金额 SUM）
   - 回函可确认占发函比例%
   - 替代测试确认金额（= 该科目替代后可确认 SUM）
   - 回函+替代占账面比例%
2. WHEN 明细行增删/修改 THEN 看板 SHALL 实时重算
3. WHEN 某关键指标异常（回函率<70% / 可确认占比<80%）THEN 标橙/红
4. THE 看板 SHALL 支持折叠/展开（默认展开）

### 需求 4：样本选择表单区

**用户故事**：作为审计助理，我需要记录抽样决策过程（总体/方法/样本量）。

#### 验收标准
1. THE 明细区下方 SHALL 渲染"样本选择"折叠区，含以下可编辑字段：
   - 测试总体描述（textarea：如"应收账款账面余额XX、客户XX个…"）
   - 特定样本描述（textarea：大额/关联方/异常）
   - 抽样总体描述（textarea）
   - 确定的抽样样本量（textarea，按科目分）
   - 抽样方法（select：随机选样/系统选样/货币单元抽样/随意选样）
   - 抽样过程描述（textarea：使用什么工具、选了多少客户）
2. WHEN 底稿只读 THEN 上述字段全只读
3. THE 样本选择内容 SHALL 随保存持久化到 html_data

### 需求 5：审计说明 5 专题文本区

**用户故事**：作为审计助理，我需要对函证过程中的 5 个专题记录分析判断。

#### 验收标准
1. THE 样本选择区下方 SHALL 渲染"审计说明"折叠区，含 5 个专题 textarea：
   - 1. 对询证函保持的控制的说明
   - 2. 对误差的分析（含误差构成条件阈值）
   - 3. 对以传真或电子邮件形式收到的回函的可靠性的考虑（关联 D0-7）
   - 4. 针对不符事项的程序
   - 5. 针对未回函的替代程序
2. EACH textarea SHALL 有 placeholder 提示示例文本
3. WHEN 底稿只读 THEN 全只读
4. THE 内容 SHALL 随保存持久化

### 需求 6：审计结论区（A/B/C 选择 + 自由文本）

**用户故事**：作为审计助理，我需要选择审计结论模板并补充具体内容。

#### 验收标准
1. THE 审计说明区下方 SHALL 渲染"审计结论"区，含：
   - radio 选择：A（未见异常）/ B（重大不符需调整，其余未见异常）/ C（重大未调整/审计范围受限，不可确认）
   - textarea 自由补充（B/C 选项时展开详情输入）
2. WHEN 选 A THEN textarea 隐藏/折叠
3. WHEN 选 B 或 C THEN textarea 展开（placeholder 提示具体事项描述）
4. THE 选择 + 文本 SHALL 随保存持久化

### 需求 7：枚举字典

#### 验收标准
1. THE 后端 `_DICTS` SHALL 定义：
   - `confirmation_account_type`：应收账款/应付账款/预收账款/预付账款/合同负债/合同资产/其他应收款/其他应付款/本期销售/银行存款/短期借款/应收票据/应收款项融资
   - `confirmation_method`：积极式/消极式
   - `confirmation_reply_method`：原件/传真/电子邮件/电子函证平台
   - `yes_no`：是/否
   - `confirmation_match`：相符/不符/部分相符
   - `sampling_method`：随机选样/系统选样/货币单元抽样/随意选样
2. EACH 枚举字段 SHALL 渲染 el-select（filterable + allow-create 兜底）
3. WHEN 字典缺失 THEN 降级为 el-input

### 需求 8：被询证单位名称引用 D0-2

#### 验收标准
1. WHEN 填写"被询证单位名称" THEN 系统 SHALL 提供搜索建议（从 D0-2 底稿 parsed_data 提取已核实的单位列表）
2. IF D0-2 数据不可用 THEN 系统 SHALL 允许自由输入（不阻塞）
3. THE 引用 SHALL 走 API 查询（不硬编码），支持随 D0-2 更新同步

### 需求 9：增删行 + 右键菜单 + 保存

#### 验收标准
1. THE 工具栏 SHALL 含"新增函证""批量删除""保存"按钮
2. WHEN 新增 THEN 在末尾插入空行（序号自增），自动打开 detail
3. WHEN 右键行 THEN 弹菜单：复制行 / 在上方插入 / 在下方插入 / 删除 / 复制索引号
4. WHEN 保存 THEN emit save 走既有 `POST /save` 链路
5. THE 保存载荷格式 SHALL 为结构化 JSON（`{rows: [...], summary, sampling, notes, conclusion}`），后端 wp_html_save 照常接受
6. WHEN 只读 THEN 工具栏增删/保存禁用

### 需求 10：编制说明移侧栏

#### 验收标准
1. THE 原 Excel 行 36-63 的编制说明/操作指引 SHALL 移到编制指导侧栏（wp_guidance 面板）
2. THE 数据组件 SHALL 不包含准则条文和注意事项
3. WHEN 用户点击编制指导按钮 THEN 展示 D0-1 专属函证编制指引

### 需求 11：跨底稿联动接口（本期声明，后续实现）

#### 验收标准
1. WHEN "是否相符=不符" THEN 标注"需建差异调节(D0-4)"
2. WHEN "是否收到回函=否" THEN 标注"需替代程序(D0-5/D0-6)"
3. THE componentType SHALL 注册为 `confirmation-summary`

### 需求 12：不回归

#### 验收标准
1. 原 GtGridSheet 只读渲染（其他 sheet）不受影响
2. D0-1 旧 grid cells 格式 htmlData 兼容降级为只读网格（不崩）
3. 既有 render-config 测试零回归

### 需求 13：双视图切换（列表视图 + 完整表格视图）

**用户故事**：作为习惯 Excel 的审计师，我希望除了清爽的列表视图，也能切到完整 28 列宽表视图，沿用网格选区/复制/粘贴等熟悉操作。

#### 验收标准
1. THE 函证组件 SHALL 提供视图切换：「列表视图」(master-detail，默认) 和「完整表格视图」(28 列宽表)
2. WHEN 完整表格视图 THEN 系统 SHALL 沿用上一轮已落地的网格美化：分组表头按组着色(5色) / 冻结首列 / 斑马纹行 / 空值淡化
3. WHEN 完整表格视图 THEN 单元格 SHALL 按列类型可编辑（枚举→el-select / 数值→el-input-number / 文本→el-input），只读模式全 span
4. WHEN 切换视图 THEN 两视图共享同一份明细数据（编辑互通，dirty 一致）
5. THE 视图偏好 SHALL 记忆（localStorage，按用户）

### 需求 14：单元格选区与复制粘贴（完整表格视图）

**用户故事**：作为审计师，我希望在宽表里像 Excel 一样选区、复制、粘贴、看选区求和。

#### 验收标准
1. THE 完整表格视图 SHALL 复用 `useCellSelection`：单击选中 / Ctrl+单击多选 / Shift 范围选 / 鼠标拖拽框选
2. WHEN 复制选区 THEN 系统 SHALL 输出 TSV + HTML 双格式（兼容粘贴到 Excel/Word）
3. WHEN 粘贴 THEN 系统 SHALL 从右键/选中单元格起按 TSV 解析填充（只读模式禁用）
4. WHEN 多选数值单元格 THEN 系统 SHALL 显示选区统计（求和/计数/平均，状态栏或右键菜单）
5. WHEN 右键单元格 THEN `CellContextMenu` SHALL 含完整项：复制 / 粘贴 / 求和(多选) / 在上方插入行 / 在下方插入行 / 删除行 / 复制索引号
6. WHEN 只读模式 THEN 仅保留复制/求和等只读项，粘贴/插入/删除禁用

### 需求 15：自动取数减少录入负担

**用户故事**：作为审计助理，我不想把抽样已选定的函证清单和账面数据重新手敲一遍——系统应自动带入。

#### 验收标准
1. WHEN 看板"本期账面金额"THEN 系统 SHALL 优先从 `trial_balance` 自动取该科目审定额（TB 取数），用户可覆盖
2. WHEN 新增/导入函证行 THEN 系统 SHALL 支持从抽样底稿或 D0-2 带入"被询证单位/账户交易/金额"（有来源时自动填，无来源时手填）
3. WHEN 新增函证行 THEN "询证函索引号" SHALL 按规则自动生成（如 D0-1-001 递增），用户可改
4. WHERE 字段为自动取数来源 THE 系统 SHALL 视觉标识（如浅色/图标）区分"自动带入"与"手工录入"
5. IF 自动取数来源不可用 THEN 系统 SHALL 降级为手填，不阻塞

### 需求 16：批量导入函证清单

**用户故事**：作为审计助理，我希望从抽样结果或 Excel 一次性导入几十笔函证，而非逐行手敲。

#### 验收标准
1. THE 工具栏 SHALL 含"导入清单"和"导出模板"按钮
2. WHEN 导出模板 THEN 系统 SHALL 输出含表头的空白 xlsx 供离线填写
3. WHEN 导入 Excel THEN 系统 SHALL 解析 → 预览弹窗（匹配/跳过统计）→ 确认后批量新增函证行
4. WHEN 导入数据缺列或格式错 THEN 系统 SHALL 在预览中标错并跳过该行，不中断整体导入
5. WHEN 只读模式 THEN 导入禁用，导出模板仍可用

### 需求 17：可确认金额按业务规则自动计算

**用户故事**：作为审计助理，我希望系统按函证准则自动算可确认金额，而不是我手算（易错且不体现审计逻辑）。

#### 验收标准
1. THE "可确认金额" SHALL 按以下规则自动计算（只读，用户可手工覆盖并留痕）：
   - WHEN 是否相符 = 相符 THEN 可确认金额 = 金额
   - WHEN 是否相符 = 不符 THEN 可确认金额 = 回函金额（差异部分待 D0-4 调节）
   - WHEN 未收到回函 AND 函证方式 = 消极式 THEN 可确认金额 = 金额（消极式未回视同认可）
   - WHEN 未收到回函 AND 函证方式 = 积极式 THEN 可确认金额 = 替代后可确认金额（须替代程序）
2. THE "差异" SHALL = 金额 − 回函金额（相符时强制 0）
3. WHEN 计算依赖字段（函证方式/是否回函/是否相符/回函金额/替代结果）变化 THEN 可确认金额 SHALL 实时重算
4. WHEN 用户手工覆盖自动值 THEN 系统 SHALL 标记该单元格为"手工覆盖"以示区别

### 需求 18：跨底稿引用可跳转

**用户故事**：作为审计助理，我希望从函证行直接跳到差异调节(D0-4)和替代程序(D0-5/D0-6)底稿。

#### 验收标准
1. WHEN "是否相符 = 不符" AND 存在差异 THEN "调节索引(D0-4)"字段 SHALL 渲染为可点击链接，点击跳转 D0-4 底稿
2. WHEN "替代程序索引号"有值 THEN SHALL 渲染为可点击链接，跳转 D0-5/D0-6
3. THE 跳转 SHALL 复用既有 ref_index/jump_route 机制（addressRegistry 或 cross_wp_references）
4. WHEN 引用目标底稿不存在 THEN 系统 SHALL 提示"目标底稿未创建"（本期不自动创建）

### 需求 19：函证覆盖率/确认率质量红线警示

**用户故事**：作为质控复核人，我希望系统对函证证据不足的情况给出明确警示，而非埋在数字里。

#### 验收标准
1. THE 看板 SHALL 计算并显著展示两个质量指标（按科目 + 合计）：
   - 函证覆盖率 = 发函金额 / 账面金额
   - 确认覆盖率 = (回函确认 + 替代确认) / 账面金额
2. WHEN 确认覆盖率 < 阈值（默认 80%）THEN 系统 SHALL 红色警示 + 文案"函证确认证据可能不足，需评估替代程序充分性"
3. WHEN 函证覆盖率 < 阈值（默认 50%）THEN 系统 SHALL 橙色提示
4. THE 阈值 SHALL 可配置（默认值内置，后续接重要性/抽样参数）

### 需求 20：聚焦核心、避免过度设计

**用户故事**：作为审计助理，我希望页面聚焦高频操作（导入清单→标回函状态→看汇总），辅助内容不干扰。

#### 验收标准
1. THE 页面默认布局 SHALL 突出核心三步：① 明细清单（导入/录入）② 回函状态与金额填写 ③ 汇总看板
2. THE 辅助区块（样本选择 / 审计说明 / 审计结论）SHALL 默认折叠，按需展开
3. THE 完整表格视图 SHALL 非默认（列表视图为默认），避免一上来就是 28 列宽表吓退用户
4. WHEN 用户首次进入 THEN 看板 + 明细列表 SHALL 直接可见，无需额外点击

## Non-Goals

- 不实现跨底稿自动创建（D0-4/D0-5 自动填充行）
- 不改 OnlyOffice "完整Excel" 路径
- 不做实时协同编辑
- 不改其他底稿的渲染方式

## 函证模块协同（cross-cutting，遵循 confirmation-module-coordination）

D0-1 是函证子系统的**枢纽与主数据 SSOT**，承担如下协同职责（详见 `confirmation-module-coordination` spec）：

- **主数据 SSOT**：D0-1 以 confirm_index 为主键单源持有函证主数据（subject/entity_name/book_amount/confirm_method/reply_method/reply_status/reply_amount/is_consistent/confirmation_status）；D0-3~D0-8 只读引用，不存副本
- **状态机**：D0-1 维护 confirmation_status（12 态），看板展示全项目状态分布 + 停滞预警
- **下游分发**：D0-1 提供"分发到下游"——差异≠0→D0-4 / 未回函→D0-5或D0-6(按科目) / 电子回函→D0-7，与下游"从 D0-1 带入"双向等价去重
- **统一枚举**：所有枚举归 confirmation_dicts 命名空间复用
- **共享 UI Kit**：看板/状态徽章(绿/橙/红)/金额格式/网格美化/自动取数标识 用 ConfirmationKit 统一
- **跨表导航**：选中某函证显示"本笔相关底稿"导航条（D0-2|D0-3|D0-7|D0-4|D0-4b|D0-5/6|D0-8）
