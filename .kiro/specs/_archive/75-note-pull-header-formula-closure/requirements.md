# 附注取数 / 多级表头 / 公式管理收口 — 需求

> 用户 2026-10-26：「分析合并附注与单体附注，特别是表头涉及合并单元格的附注表（如应收账款子表），要跟 Word 模板对应，单体可参照底稿披露表，国企对国企、上市对上市；分析标题行与序号、每张表的预设公式与公式管理；单体附注涉及报表项目的表格都从底稿披露表获取……目标是刷新和披露刷新可以自动从底稿披露表获取数据，避免重复工作；公式管理是数据溯源和自动更新的主要工具，要在平台内配置好；合并附注从单体附注拉取……其他需要改进的一并告知。该修改直接修改好。」

现状实证（2026-10-26 现读代码 + 真库只读 + 事务回滚探针）见 design §1，这里只列需求。

## R1 止损：不许写错数、不许误标待更新

1. 后端「披露表 builder」（`disclosure_builders/`，2026-10-22 引入）不是与前端披露 Tab 同口径的实现：D2 账龄期末恒 0、坏账准备恒 0、变动表全 0；70 个标准 builder 只产出一张以章节标题命名的两行表。它们不得再出现在任何写附注的路径上（底稿保存事件、「从披露表刷新」端点）。
2. 底稿保存事件刷新附注时，章节表格不是从底稿披露表同步来的（没有同步指纹），不得标「披露表数据为空」待更新。
3. 守卫：除 builder 服务自身外，生产代码不得调用 `build_and_sync` / `build_for_wp_code`。

## R2 附注「刷新」真的从底稿取数

1. 附注编辑器「🔄 刷新 / 🔁 全部刷新 / 生成附注」前调用的 `pull-from-workpapers` 按项目准则（国企 / 上市）找到章节对应的底稿，执行公式推送（试算表审定数 → 底稿披露项 → 附注主表，人工 / 锁定格保留），逐章节回报写入 / 保留 / 跳过及原因。
2. 前端不再静默吞掉 `pull-from-workpapers` 的结果和错误：刷新提示里列出公式推送写入数与跳过原因。
3. 离屏取数：附注刷新时，对已接入「离屏同步」的底稿，在附注页按底稿披露 Tab 同一套代码（同一个 composable + 同一个 `buildXSyncPayload`）现算披露表并同步到附注，不必打开底稿。首个接入 D2 应收账款（国企 八、5 / 上市 五、5 全部子表）；未接入的底稿列入只许变短的清单，刷新提示点名「需打开底稿披露表保存一次」。

## R3 附注公式：每张表都有预设公式，公式管理能看、能改、能自动更新

1. 公式执行（「应用自动运算」/ 刷新后重算）对多表章节逐表执行并写入编辑器与 Word 实际读取的 `_tables`（原先只写顶层首表镜像，用户看不见）。
2. 公式目标带表维度：第 1 张表 `行:列`（兼容旧数据），第 n+1 张表 `t{n}:行:列`；预设公式（纵向合计 / 横向平衡 / 账面价值）按每张表的结构生成。
3. 附注公式弹窗新增公式可选「表 / 行 / 列」作为目标（原先目标列不可编辑、新增的公式保存时被当空行丢弃却提示「已保存」），列表显示可读的「表名 · 行名 · 列名」。
4. 刷新（R2）后对刷新过的章节执行附注公式，合计与跨表引用随底稿 / 试算表自动更新；人工 / 锁定格不动。
5. 公式执行跳过的单元格写明原因（哪条引用取不到）；读取附注排除已删除记录。

## R4 多级表头（合并单元格）与 Word / 底稿披露表对应

1. 单体附注编辑器支持任意层级表头（按 `multi_header` 递归），不再丢掉中间层分组下的列；扁平列显示末段列名，不显示「/」路径。
2. 期间层还原：模板为两层表头按期间拆开的表，按底稿披露表还原期间这一层 —— 底稿是一张表并列两期的（如国企应收账款「按坏账准备计提方法分类披露」期末数 + 期初数 11 列）合成一张三层表显示与导出；底稿是每期一张、期间写在最上层的（如国企组合计提分表、上市分类披露表）加回期间这一层。依据由生成器从「模板 ↔ 底稿披露表」配对结果产出（`--check` 守卫），不靠猜。
3. Word 导出（模板模式与程序化模式）与编辑器同一口径：合成后的表与 Word 样例表叶子列数一致时克隆 Word 表头；否则按多级表头渲染（不再只有两行）。
4. 模板数据：国企 八、31 第 1 张表的显示分组与推送骨架分组不一致改为一致；国企 八、18「发起 / 规模」单列分组改为一列「发起规模」。

## R5 标题行 / 序号 / 合计

1. 合并附注行类型推断：「小计」判为小计（原先被判成合计）。
2. 单体编辑器结构编辑后的合计重算按段（小计 / 合计分段），与后端同口径；删行不删可扩位 / 分组标题 / 合计 / 小计行。
3. 空表判定（编辑器「本期无此情形」与 Word 导出省略空表同一口径）：合计 / 小计行有非零数值即非空（原先只有合计行有数——如公式推送合计行兜底写入——的表被判空，导出时整表丢失）。
4. Word 导出：额外表 / 续表的表题剔除编制指引括注；块内表题字面编号「（N）」在模板里原本连续时，删表后按保留顺序重排。

## R6 合并附注从单体附注拉数

1. 集团模板下推修复两处导入错误（`DisclosureNote` 模块不存在致每家子企业都失败；结构锁模型导错模块致锁从不生效），下推端点补合并锁检查。
2. 行匹配：历史规则排在模糊匹配之前；`exact_id`（下推行号精确命中）可自动确认；映射弹窗按后端 `auto_confirmable` 判「就绪 / 待确认」（模糊匹配不再一律显示就绪），匹配方式全部中文。
3. 一键自动映射：对未绑定明细模板的合并附注章节，以合并附注模板行为明细模板自动绑定，并自动确认全部来源行都能精确 / 别名 / 行号命中的企业组；其余列入待确认清单（企业 + 行名）。之后「🔄 重新汇总」即可拉数。

## 非目标（本 spec 不做，见 design §9 建议清单）

- 其余 77 个底稿的离屏同步接入（框架与清单本 spec 交付，逐个接入另立 spec）。
- 单体附注改存三层表头（本 spec 只做显示 / 导出还原，不迁移存储）。
- V202 表退役、合并「前五名」跨企业重排。
