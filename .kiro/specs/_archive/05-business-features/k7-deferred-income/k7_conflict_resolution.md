## 2. 公式数量差异分析

### 2.1 K7-1 审定表：预期49 vs 实际50

**原因**：xlsx中包含1个额外的底稿目录引用公式（如`=底稿目录!F5`），design中计为49个"功能公式"不含引用标头。

**决议**：✅ 无实质冲突。design文档中的49指功能运算公式，实际含1个引用标头=50总公式。组件开发以xlsx实际结构为准。

### 2.2 K7-2 明细表：预期21 vs 实际102

**原因**：design文档中"21公式"指去重后的公式模式数（如`=C11+D11-E11`为1个模式），xlsx中实际有41行×多列重复公式=102个单元格公式。

**决议**：✅ 无实质冲突。组件开发以xlsx 102公式为准（含所有行的重复公式）。公式模式确认：
- `期末=期初+增加-分摊`（负债类）→ 多行重复
- `审定=未审+AJE+RJE` → 多行重复
- `合计=SUM(区间)` → 多列

### 2.3 K7-4 测算表：预期23 vs 实际87

**原因**：design文档中"23公式"指去重后的公式模式数，xlsx中26行×多列重复分摊公式=87个单元格。

**决议**：✅ 无实质冲突。组件开发以xlsx 87公式为准。公式模式确认：
- `直线分摊=补助总额/分摊期总期数×本期期数`
- `期末余额=补助总额-累计分摊`
- `差异=测算-企业`
- `摊销结束日=DATE(YEAR(起始日)+年限,MONTH,DAY)`
- `本期应摊月数=IF(...)`条件判断

## 5. 冲突清单与决议

### 🔶 冲突C1：分摊计入科目 - md旧规 vs xlsx新规 vs CAS16(2017修订)

**冲突描述**：
- **md底稿模板库**（编制说明）："借记本科目，贷记'营业外收入'科目" → 仅提及K12
- **xlsx K7-2明细表**（列名）："转入其他收益" → 仅提及K10
- **CAS16(2017修订)**：与日常活动相关→其他收益(K10)；与日常活动无关→营业外收入(K12)

**决议**：
- md编制说明为CAS16修订前旧文本，未更新。**以CAS16(2017修订)为准**
- xlsx K7-2列名"转入其他收益"反映了新规主流路径，但**未覆盖非日常活动场景**
- **组件设计**：分摊去向需支持两条路径(K10+K12)，由用户在明细表标注"是否与日常活动相关"决定联动方向
- **联动实现**：GtIndexChip分摊去向→K10其他收益(日常) / K12营业外收入(非日常)

**影响**：design.md中已正确设计双路径联动（K10+K12），无需修改。

---

### 🔶 冲突C2：Sheet数量差异 - 11 vs 6+附注

**冲突描述**：
- xlsx实际11个sheet
- md底稿目录列6个底稿(K7A/K7-1~K7-5)+附注双版本+会计提示=9项

**决议**：
- GT_Custom为系统隐藏sheet，不组件化 ✅
- 会计提示为辅助参考，走OO fallback ✅
- 底稿目录为导航，不计入审计底稿数
- **实际功能sheet = 9个**（目录+K7A+K7-1~K7-5+2附注），与design.md一致

---

### ✅ 无冲突：审定表分组方式

md审定表明确按"与资产相关/与收益相关/其他"三行分组，xlsx通过SUMIF公式聚合明细表数据到审定表：
```
C7=SUMIF('明细表K7-2'!$B$11:$B$21,$A7,'明细表K7-2'!$C$11:$C$21)
```
B列为"所属类别"，与design.md一致。

## 6. 关键公式链验证

### 6.1 K7-1 ↔ K7-2 交叉验证

```
审定表K7-1.期初 = SUMIF(明细表K7-2.类别=类别, 明细表K7-2.期初)
审定表K7-1.期末 = SUMIF(明细表K7-2.类别=类别, 明细表K7-2.期末)
```
→ **adjudicationVsDetail** computed: 审定合计 vs 明细合计应恒等

### 6.2 K7-2 ↔ K7-4 交叉验证

```
明细表K7-2.本期分摊(企业) vs 测算表K7-4.本期应分摊(测算)
差异 = K7-4测算 - K7-2企业
```
→ **detailVsCalc** computed: 差异>重要性→红色标记

### 6.3 K7-4 分摊引擎公式链

```typescript
// xlsx实际公式翻译：
calcStraightLineAmort(total, totalPeriods, currentPeriods):
  G11 = B11 + E11           // 补助总额 = 原始金额 + 追加
  K11 = IF(C11=0, 0, ...)   // 本期应摊月数（含日期判断）
  L11 = G11 / (I11*12) * K11 // 本期应分摊 = 总额 / (年限×12) × 本期月数

calcRemainingBalance(total, accumulated):
  O11 = G11 - N11           // 期末余额 = 补助总额 - 累计分摊

calcAmortVariance(calculated, booked):
  P11 = L11 - M11           // 差异 = 测算分摊 - 企业分摊
```

## 8. 开发注意事项（Phase1+使用）

1. **分摊粒度**：xlsx K7-4按月计算（`I11*12`转月），非按年。design中`totalPeriods`应为月数或在引擎内转换
2. **日期逻辑**：K7-4含摊销结束日判断`IF(J11>$D$9,...)`，分摊引擎需考虑中途到期场景
3. **明细表列名**：xlsx K7-2有"转入其他收益"列但无"转入营业外收入"列，组件需增加去向选择字段
4. **检查表K7-5**：含`H21='明细表K7-2'!N22`跨sheet引用，确认为分摊金额占比计算
5. **GT_Custom sheet**：系统配置sheet，wp_code_overrides跳过不映射
