## 二、权益类方向验证（贷方）

### 2.1 xlsx证据

**明细表M8-2核心公式：**
```
E10 = B10 + C10 - D10    // 未审期末 = 期初 + 本期增加 - 本期减少
O10 = L10 + M10 - N10    // 审定期末 = 审定期初 + 审定增加 - 审定减少
L10 = B10 + F10 + G10    // 审定期初 = 未审期初 + 期初账项调整 + 期初重分类
```

**附注公式（上市/国企均一致）：**
```
E7 = B7 + C7 - D7        // 期末余额 = 期初余额 + 本期增加 - 本期减少
```

### 2.2 md证据

md明细表M8-2列头：`项目 | 期初数 | 本期增加 | 本期减少 | 期末数`  
审计目标："一般风险准备以恰当的金额包括在财务报表中"

### 2.3 结论

**✅ 完全一致。**  
- 权益类贷方科目铁律：`期末 = 期初 + 贷方(增加) - 借方(减少)`
- xlsx公式 `E=B+C-D` 精确对应此逻辑
- 与M5/M7/M9等其他权益类底稿方向一致

## 四、风险资产1.5%计提标准验证

### 4.1 xlsx证据

**测试表M8-4列结构（row 8-9 headers）：**
```
A: 项目
B: 本期增加额-计提
C: 本期增加额-其它
D: 提取-标准
E: 提取-基数
F: 提取-比例（注）
G: 应计金额 = E×F (基数×比例)
H: 差异 = B-G (实际计提-应计)
I: 差异原因
J: 相关依据索引号
K: 相关数据来源索引号
```

**核心公式：**
```
G10 = E10 * F10    // 应计金额 = 基数 × 比例
H10 = B10 - G10    // 差异 = 本期计提 - 应计金额
```

### 4.2 md证据

md测试表M8-4结构完全对应：
- 列名：`项目 | 计提 | 其它 | 标准 | 基数 | 比例（注） | 应计金额 | 差异 | 差异原因 | 相关依据索引号 | 相关数据来源索引号`
- 程序4："获取一般风险储备的计提及标准的相关文件，检查是否已按照**相关行业规定**计提"

### 4.3 法规依据（业务逻辑参考）

根据《金融企业准备金计提管理办法》（财金〔2012〕20号）：
- 一般风险准备：**不低于风险资产期末余额的1.5%**
- 银行业：按贷款余额等风险资产计提
- 证券业：按净资本或风险资产计提
- 保险业：按净资产或风险资产计提

### 4.4 结论

**✅ 完全一致。**  
- xlsx公式 `G=E×F` 即"应计金额=基数×比例"
- "比例（注）"列默认为1.5%（各机构可按行业规定调整）
- 差异公式 `H=B-G` 用于审计师核实计提是否充足
- **计提公式引擎**：`calcRiskProvision(riskAssets, rate) = riskAssets × rate`

## 六、发现的差异与冲突解决

### 6.1 无实质性冲突

本次交叉验证**未发现任何实质性冲突**。两个源在业务逻辑层面完全一致。

### 6.2 非冲突型补充信息

| 编号 | 差异描述 | 来源优先级 | 解决方案 |
|------|----------|-----------|----------|
| D-01 | xlsx有84个审定表公式细节，md仅描述结构框架 | xlsx权威(列名/公式) | 以xlsx公式为准实现引擎 |
| D-02 | md明确金融企业适用性，xlsx无显式行业字段 | md权威(业务逻辑) | 实现行业守卫：industry_category判断 |
| D-03 | xlsx测试表F列标注"比例（注）"，无具体1.5%数值 | md权威(业务规则) | 默认率1.5%作为提示（可由用户修改） |
| D-04 | xlsx中程序表第1步写"获取或编制**专项储备**明细表"（复用M7模板文本未改） | xlsx结构权威/md内容权威 | 实际功能为一般风险准备，按M8业务逻辑实现 |
| D-05 | md列出5个底稿（M8A/M8-1/M8-2/M8-3/M8-4），xlsx还有2个附注sheet | xlsx权威(完整结构) | 附注(上市/国企)也作为子组件实现 |

### 6.3 M8A程序表文本勘误（D-04详解）

xlsx M8A程序表序号1原文："获取或编制**专项储备**明细表，完成以下工作..."  
md M8A同一条也写的"获取或编制**专项储备**明细表"。

这是致同模板从M7(专项储备)复制到M8时未修改的文本残留。实际业务应为"一般风险准备"。

**解决**：前端UI显示修正为"获取或编制一般风险准备明细表"，不影响公式引擎和逻辑。
