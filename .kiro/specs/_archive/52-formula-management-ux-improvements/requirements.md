# 公式管理体验优化 — 需求文档

> spec: `formula-management-ux-improvements`
> 前置：`formula-global-settings-sync`（全局设置/模板/同步内核，已完成 35/36）
> 前置：`chain-closure-phase2-formula-push-engine`（推送引擎 80 码，已完成 18/18）
> 前置：`formula-management-runtime-closure`（运行时接线，cross_check_results 持久化已完成）

## 一、背景

公式管理是平台灵魂功能。经 ROI 评估，后端架构（6 域统一 + 纯函数同步内核 + 事件级联 + 80 码推送）已高度完成。改进集中在**用户体验层**：公式编辑效率、信息可发现性、批量操作效率。

砍掉 F（跨项目对比，改动大收益低）。C（模板发现性）降为最后批次（涉及向导改动需产品拍板）。

## 二、需求分批

### A 批：公式编辑器实时语法校验 + 地址选择增强

**现状**：FormulaEditDialog 已接 ACNR store 选址，但公式输入框无实时语法校验（只在后端保存时报错）。FormulaManagerDialog 的快捷按钮（TB/WP/NOTE/ROW）只插入空模板文本。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| A1 | 公式输入框增加实时语法高亮 | 输入 `TB('1001','期末余额')` 时函数名蓝色、参数绿色、语法错误红色下划线 |
| A2 | 快捷按钮点击后弹出参数选择器 | 点击 TB 按钮 → 弹出科目选择下拉（ACNR tbAddresses）→ 选中后自动填入正确参数 |
| A3 | 输入时实时校验 + 错误提示 | 输入 debounce 500ms 后校验：函数名拼写、引号配对、参数格式；错误行内提示 |
| A4 | 公式自动补全 | 输入 `TB(` 后弹出科目代码补全列表；输入 `ROW(` 后弹出行次补全列表 |

### B 批：公式推送覆盖率仪表盘

**现状**：`formula_push_coverage.json` 已有 80 码等级清册。前端推送 Tab 只在未接入底稿显示「尚未接入自动推送」空状态。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| B1 | 公式看板增加「推送覆盖率」卡片 | 显示已接入 N/总计 M 个底稿编码，百分比进度条 |
| B2 | 覆盖率按循环展示 | D/E/F/G/H/I/J/K/L/M/N 各循环的接入/总数，A/B/C/S 标注「不需推送」及原因 |
| B3 | 未接入底稿改进空状态 | 替换笼统「尚未接入」为具体原因文案（如 "B 类底稿为控制了解/计划类，不涉及数值回写试算表"） |

### D 批：待确认智能分组 + 批量适配

**现状**：FormulaPendingSyncDialog 平铺所有待确认项，只有域 tag 标签。大量冲突时体验差。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| D1 | 待确认弹窗按域分组折叠 | 待确认项按 report/note/wp 等域分组，每组可折叠/展开，组头显示域名+数量 |
| D2 | 组级批量操作 | 每组有「全部采用」/「全部保留」按钮，操作本组所有项 |
| D3 | 来源标签增强 | 每组标注来源（全局发布 / 模板更新 / 其他项目推送），帮助用户判断优先级 |

### E 批：表间审核历史查看

**现状**：`cross_check_results` 表已有持久化（`persist_cross_check_results` + `cross_check_run` observability），但公式管理弹窗的表间审核只显示实时执行结果，无历史记录。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| E1 | 表间审核增加「执行历史」视图 | 在表间审核模式下增加历史 tab，显示 `draft_refresh_audit` 运行记录列表 |
| E2 | 历史明细展开 | 点击历史记录展示该次运行的逐条勾稽结果（pass/fail/diff），数据来自 `cross_check_results` |
| E3 | 执行结果对比 | 两次执行结果横向对比（同 rule_id 的上次值 vs 本次值），高亮差异 |

### G 批：公式依赖关系可视化

**现状**：`formula_reverse_index` + `linkage_graph_builder` + `note_formula_dependency_service` 后端完整。ForceGraph 全景图有技术基础。但公式管理弹窗没有依赖图入口。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| G1 | 公式管理增加「依赖关系」Tab 或面板 | 选中一个公式行后，侧面板或 Tab 显示「引用了谁」和「被谁引用」的树形列表 |
| G2 | 依赖关系点击跳转 | 点击依赖项可跳转到对应公式行（同弹窗内切换节点），支持多级追溯 |
| G3 | 后端提供单公式依赖查询端点 | `GET /api/projects/{pid}/formula-settings/dependencies?addr_id=...` 返回上下游依赖链 |

### C 批：模板发现性提升（最后批次，需产品拍板）

**现状**：ProjectWizard 只有 BasicInfoStep，无公式模板选择。模板入口在公式管理弹窗 toolbar 的小按钮里。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| C1 | 项目创建成功后的引导提示 | 项目创建成功后弹提示「建议订阅事务所标准公式模板」，可点击跳转或稍后设置 |
| C2 | 模板列表增加推荐标签 | 按适用准则匹配当前项目类型的模板标「推荐」 |
| C3 | 订阅前预览差异 | 点击「订阅」前弹出模板与当前项目公式的差异对比表 |

## 三、非功能需求

| 编号 | 要求 |
|------|------|
| NF1 | 全部 UI 文本中文化（技术术语 TB/WP/NOTE/ACNR 保留英文） |
| NF2 | 公式语法校验 debounce ≤ 500ms，不阻塞输入 |
| NF3 | 依赖查询端点响应 ≤ 200ms（缓存命中时） |
| NF4 | 各批次独立可交付，不互相依赖 |
