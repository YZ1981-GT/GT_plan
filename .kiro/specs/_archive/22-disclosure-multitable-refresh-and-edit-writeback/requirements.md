# 附注多表刷新与编辑反写闭环

## 目标与现状（2026-10-04）
- 普通附注生成/空详情重建把所有表交给首表 binding；增量更新只读 `table_template`，可将多表降维。
- AR 四组模板与 binding 已漂移：国企两组模板 13 表/binding 11 表，上市两组 17/15；另有列头与行标签漂移。
- 前端 `useNoteTableProjection` 为纯读副本，宿主修改副本却由 `useNotePersist` 保存原始 `table_data`。
- 已核对历史 spec：`_archive/08-disclosure-notes/disclosure-note-formula-data-population`、`d2-ar-disclosure-template-alignment`；不回填历史任务。

## 验收要求
### R1 多表构建与刷新
1. `_build_table_data` 按显式、0-based `table_index` 调 `get_binding_for_table`，缺表不得借首表。
2. 生成、空详情重建、增量更新共用完整章节构表，保留 `_tables`、首表镜像、列元数据、表名、说明与校验元数据。
3. 增量更新扫描所有表的科目依赖，保护 manual/locked；底稿同步来源不得覆盖。
4. 局部公式求值的单表 ctx index 0 保持；binding_id 和 value 列索引协议保持。
### R2 AR 四组校准
1. 仅校准 `八、5`、`十二、应收账款`、`五、5`、`十六、应收账款`；表顺序、声明索引、表头、行键以当前模板为准。
2. 无法证明分桶/类别/比例来源时保 manual/None，禁止复制试算表 1122 总额到各明细。
3. 重复标签与重复语义按出现位置解析；上年同表坐标显式带表号，合法显式跨表引用不改。
4. 非目标章节及有效注解保留；派生合计元数据按新行位置校准；生成工具支持幂等 `--check`。
### R3 编辑到保存
1. 保持投影纯读；以不序列化的源坐标显式反写值、标签、纵向合计与横向公式。
2. 非首表、合并续表、行数不齐、legacy 单表均写回正确原表；null/0 不丢失。
3. 底稿来源 `sub_table_data` 为真源，反写业务字段及过滤前真实行；坐标歧义须拒绝，不猜首表。
4. 保存前校验并提交尚未反写的投影编辑，发送完整 raw 多表；不得以合并投影覆盖 raw 首表。
5. 导出选择按投影源集合展开；单源普通表结构编辑/撤销接稳定原件，多源续表及业务键子表结构编辑明确禁用并提示。
### R4 防御验证与交付
1. 新守卫先复现首表串取、增量降维、投影编辑未保存；区别数字/同标签覆盖多表。
2. 后端定向 pytest、前端 Vitest、诊断与局部类型检查；工具崩溃不算通过。
3. Playwright 在请求全拦截/合成数据下实测宿主编辑、保存及重载，不写真实业务库。
4. 保留所有并行 dirty 改动，不提交/push；任务状态绑定实际证据。

## 非目标与诚实边界
- 不批量修存量 `_cell_meta.semantic` 污染，不清手工/锁定值，不自动重生成真实项目。
- 不改合并节点隔离、legacy 合并 aggregation 持久化、溯源 API 的 table_index、章节级公式管理坐标、恢复模板首表 API。
- 不改并行 `useAutoSave.ts`；真实历史数据刷新需另外授权与核验。
