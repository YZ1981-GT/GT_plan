# 需求文档：调整分录大厅——录入、导入导出、推送与复核通知收口（adjustment-hall-entry-review-closure）

## 概述

用户 2026-10-31：调整分录模块要能正常录入、导出模板导入数据、推送到调整大厅、推送给其他相关人员；要能跑起来、联动好、体验好、够实用。

范围：调整分录大厅（`views/Adjustments.vue` + `/api/projects/{pid}/adjustments`）、底稿调整 tab 推送到大厅（`useAdjustmentCentralSync`）、Excel 模板导出与导入、复核流转与站内通知。

不在范围：客户已入账（`adjustment-client-booking-status`，另立）；协作接力的功能扩展；81 个底稿调整 tab 的界面改造（只改它们共用的 composable）。

## 需求 1：录入

1. 科目下拉列出本项目全部标准科目（有已确认报表行映射的带报表项目），按编码排序、可搜索；传年度时附试算表审定数作参考余额。项目没有标准科目时提示先做科目映射。
2. 新建、修改、导入共用一套行校验：每行必须有科目；金额不能为负（冲减录入相反方向）；同一行借贷不能同时有数；整组借贷合计相等且大于 0；金额按分舍入。违反时返回中文原因并指明第几行。
3. 编号可自定义：填写时同项目同年度不得与未删除的分录组重复；不填自动编号，自动编号跳过已被占用的号。
4. 快捷模板按科目名称在本项目科目中匹配，匹配不到的行留空让用户选；模板科目名称符合现行准则。
5. 保存后提示如实：草稿不进试算表，提交复核并批准后才计入审定数。
6. 去掉无处存放的「调整目的」与无实际作用的批量模式；表格上粘贴多行改为打开新建弹窗预填，由用户确认保存。

## 需求 2：导出模板与导入数据

1. 调整分录导入走项目级端点：项目编辑权限、未归档、未合并锁定，年度必填。旧通用导入端点对项目数据类型同样校验项目编辑权限，调整分录类型缺年度时拒绝。
2. 分组规则：同编号多行合并为一笔；未填编号的连续行按借贷平衡自动切分为一笔；类型只能是 AJE / RJE；金额无法识别、为负、同一行借贷都有数时报错，不再静默按 0 / AJE。
3. 预检：上传后先返回逐笔解析结果（来源行号、科目解析结果、借贷合计、可导入或错误原因；覆盖模式标「新建 / 替换 / 跳过」），不写库。
4. 导入逐笔独立保存点：一笔失败不影响其他笔；覆盖模式的「删旧建新」在同一保存点内，失败时旧分录保留。
5. 导入结果停留在弹窗：成功 / 跳过 / 失败逐笔原因；关闭后刷新列表与汇总；可一键把本次导入的分录提交复核。
6. 模板「关注事项」与实际规则一致（编号留空规则、借贷互斥、金额非负、精确到分）。
7. 导出汇总导出全部分录（不截断），增加复核状态列。

## 需求 3：底稿推送到调整大厅

1. 推送结果区分新建 / 更新 / 未变化，前端如实提示；更新时原为待复核或已驳回的，提示已回到草稿、需重新提交。
2. 内容未变化不重发通知；按解析后的标准科目反查受影响底稿的负责人。
3. 失败显示后端给出的中文原因（含协作锁定），不重复弹窗。
4. 大厅显示来源底稿编码（按底稿索引查，不靠猜编号前缀），来源底稿已删除时标注。

## 需求 4：提交复核与通知相关人员

1. 有编辑权限的成员可把草稿 / 已驳回的分录（单笔或批量）提交复核；可选择通知哪些复核人（默认本项目全部有复核权限的其他成员），可填备注。
2. 待复核的分录可由有编辑权限的成员撤回提交，回到草稿。
3. 有复核权限的成员可单笔或批量通过 / 驳回（驳回必填原因，批量可逐笔原因）；已批准的可撤回复核。批量逐笔独立处理，返回逐笔结果。
4. 站内通知：提交 → 所选复核人；通过 / 驳回 / 撤回复核 → 分录编制人；手工来源的分录通过或撤回复核（会改试算表）→ 受影响科目对应底稿的负责人。不通知操作人自己；一次批量操作对每个接收人只发一条汇总通知。通知与状态变更同一事务提交，单条写失败不影响其余。
5. 点通知跳转到调整大厅并定位、高亮对应分录（`?focus=`），带上分录年度。
6. 复核、撤回复核会改试算表，受合并锁定约束。

## 需求 5：大厅页面体验

1. 状态筛选（全部 / 草稿 / 待复核 / 已批准 / 已驳回）带计数；类型、来源、编制人、仅看协作中筛选可用。
2. 操作按状态与权限显示：草稿（编辑、提交复核、删除）、待复核（通过、驳回、撤回提交）、已驳回（编辑、重新提交、删除、AJE 可转错报）、已批准（撤回复核）；协作、历史等低频操作收进「更多」。写操作有加载态，失败显示中文原因；撤回复核、删除、驳回有确认。
3. 列表显示驳回原因、复核人与复核时间；取全部分录，不止前 200 组。
4. 修复 F5 所列失效入口；可批量删除选中的草稿 / 已驳回分录。

## 需求 6：联动

1. 批准 / 撤回复核后的重算链路不变（ADJUSTMENT_APPROVED / ADJUSTMENT_REVIEW_REVOKED → 试算表重算 → TRIAL_BALANCE_UPDATED → 公式推送、报表、附注过期）。
2. 提交、撤回提交、批量复核同样经 SSE 广播 `adjustment:review-changed`，在线的大厅与底稿调整 tab 刷新状态。
3. 删除从未生效的协作确认回写（它以固定行模型覆盖底稿，对多数 tab 不适用）。

## 需求 7：验收

1. 后端测试：行校验、编号、提交 / 复核 / 撤回状态机与权限、通知接收人、导入分组与保存点；真库 PG 用例在回滚事务内验证通知落库。
2. 前端单测覆盖新组件与操作逻辑；单区域 vue-tsc 与 ESLint 通过。
3. 【测试】项目浏览器实测全流程，写入数据按表对账清理。
4. 既有测试失败集合与 HEAD 对比不新增；关键守卫做磁盘变异。
