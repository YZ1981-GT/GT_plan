# 需求文档：公式全局设置、项目适配与一处修改全处生效（formula-global-settings-sync）

> 来源：用户 2026-10-20 两条指令 ——「一定要实现全局设置，可以应用到其他，不同项目可以各自适配」「要打通公式，一处改可以应用到全部，如果有冲突的地方，弹窗让用户自行确认」；以及同日公式管理评估（对话结论，未落文档）。
> 类型：新功能 + 既有写路径收口。不新建公式引擎，不改公式语法。

## 背景（现状核查，2026-10-20 现读代码 + 只读查真库）

- 报表公式已有两层：全局行（`report_config.applicable_standard` 为准则码，仅 admin 可写）与项目行（`project:{id}`）。但报表生成 `ReportEngine._load_report_configs` 与合并报表 `consol_report_values` 只按准则码加载，**项目行从不参与报表生成**；只有 4 个取数层读取方按「项目行优先」取科目口径。
- 全局行没有版本号，项目行不记录「基于哪一版全局」：旧「同步主模板」用「公式不相等」判断项目改过，模板修正永远到不了改过的项目，还会顺手清掉过期标记。
- 其余公式只有项目层（试算表科目明细、表间审核规则、附注用户公式、底稿用户公式）或只有模板层（合并附注公式），没有「全局设置 → 各项目继承」的机制。
- 变更传播：公式保存后的过期标记大多命中 0 个下游（依赖图里没有对应节点）；底稿公式保存不发任何事件。
- 真库：报表公式 761 条全在准则行；项目行只有 1 个项目 183 行且与全局逐条相同；试算表科目明细与表间审核用户规则均 0 个项目使用；活跃项目 17 个、已归档 0 个。
- 现有公式模板（2026-10-20 现读 + 查库）：
  - 公式管理中心「保存为模板 / 引用模板」走共享配置模板（`shared_config_templates`，`config_type=formula_config`），本质是一次性快照：引用时前端逐行写回，只填没有公式的行、不覆盖已有公式；项目未落项目级公式时，写回目标是全局模板行（admin 会改到全部项目，非 admin 逐行 403）；附注段、底稿段只存不写回；撤销只在本次会话内有效。
  - 引用关系不记录模板版本，模板更新不通知、不传播；`is_customized` 从未写入；引用次数每点一次加一。
  - 可见性：个人模板只有创建者能看到（界面写的是「我参与的项目可引用」）；集团模板只对从集团母项目保存、其直接下级项目可见。
  - 7 个端点只校验登录：任何人可经接口创建「事务所默认」模板、修改任何人的模板、删除集团 / 事务所模板、按 id 读任意模板、给任意项目写引用记录。
  - 模板库「公式预设库」的自定义预设写入代码仓库内被 git 跟踪的 JSON 文件（多实例与部署都不一致）。
  - 真库：共享模板 0 个、引用 0 次；自定义预设 0 条。与报表「主模板」、本 spec 的全局设置都没有联动。

## 术语

- **公式位**：一条公式在所属域内的稳定身份，与从哪个页面编辑无关（如报表域 `balance_sheet:BS-002`）。
- **系统预设**：随平台发布的种子（代码 / JSON），只读。
- **全局设置**：事务所级、对使用该准则（或模板类型）的全部项目生效的公式定义，存数据库，有版本号。
- **本项目适配**：某项目对某公式位的自有定义，记录所依据的全局版本与当时的全局定义（基线）。
- **公式模板**：命名、有版本的公式集合（可含多个域），可共享给他人，由项目订阅使用。
- **订阅**：项目引用模板的方式。模板作为该项目的一层参与有效定义，模板更新按 R4 / R5 同步；不是一次性复制。
- **有效定义**：本项目适配 ?? 订阅的模板 ?? 全局设置 ?? 系统预设。
- **冲突**：全局定义变了，而本项目适配相对基线也改过，且与新全局不同。
- **待确认事项**：需要项目成员决定的同步项（冲突、管理员暂缓应用到本项目）。

## R1 三层模型与有效定义

1. 每个公式位的有效定义 SHALL 为「本项目适配 → 本项目订阅的公式模板 → 全局设置 → 系统预设」中第一个存在的定义；本项目适配标记为「已停用」时，有效定义为空（该公式位在本项目不生效）。
2. 报表生成、按 stale 行重算、增量重算、合并报表求值、取数层科目口径、公式管理中心展示 SHALL 使用同一个有效定义解析函数；不得再有只读准则行或只读项目行的旁路。
3. 项目适配与全局相同、且从未被项目修改（定义 = 基线）的行 SHALL 视为「跟随全局」，全局更新时自动跟随。
4. 公式管理中心每条公式 SHALL 标出来源：全局 / 本项目 / 暂缓采用（固定在旧全局版本）/ 待确认。

## R2 全局设置的编辑、版本与留痕

1. 全局设置的写操作 SHALL 仅限 admin；非 admin 返回 403，且零写入。
2. 每个全局公式位 SHALL 有版本号；定义变化时版本 +1。更新已有全局公式位 SHALL 携带 expected_version：缺失返回 428，不一致返回 409，冲突时整批不写。
3. 每次全局变更 SHALL 写一条哈希链审计（无项目维度），并按受影响项目各写一条应用审计（带 project_id）。
4. 只改说明类字段（描述、来源标注）SHALL 不产生冲突：已适配的项目保留自己的说明。

## R3 发布前影响预览

1. 管理员提交一组全局变更后，系统 SHALL 在不写库的前提下返回影响预览：使用该准则的全部未删除项目（含状态），以及每个项目每个公式位的分类：
   - 直接生效：本项目无适配；
   - 自动跟随：本项目适配仍等于基线；
   - 已一致：本项目适配已等于新全局；
   - 冲突：本项目适配相对基线改过，且不同于新全局；
   - 冻结：项目已归档。
2. 冲突 SHALL 给出三方对比：原全局（本项目基线）/ 新全局 / 本项目当前。
3. 预览 SHALL 给出各分类计数与受影响项目数；同一请求重复预览结果相同。

## R4 发布与冲突确认（管理员侧弹窗）

1. 发布 SHALL 先展示 R3 预览弹窗；管理员可逐项目选择「本次应用 / 暂缓」（默认应用；冻结项目不可应用），可对每处冲突选择「采用新全局 / 保留本项目 / 交项目确认」（默认交项目确认），并提供批量选择。
2. 发布 SHALL 原子：全局定义、各项目适配、待确认事项、发布记录、审计在同一事务；任一失败全部回滚，零部分写入。
3. 各分类的发布效果 SHALL 为：
   - 直接生效：不写项目适配；
   - 自动跟随：项目适配改为新全局，基线更新为新版本；
   - 已一致：只更新基线；
   - 冲突 + 采用新全局：项目适配改为新全局，基线更新；
   - 冲突 + 保留本项目：项目适配不变，基线更新为新版本（视为已知悉）；
   - 冲突 + 交项目确认：项目适配与基线不变，生成待确认事项；
   - 暂缓 / 冻结：项目固定在旧全局定义（写一条固定的项目适配），暂缓生成待确认事项，冻结不生成。
4. 同一公式位已有未处理的待确认事项时，新的发布 SHALL 更新该事项的「新全局」为最新定义，不重复生成。
5. 发布记录 SHALL 可查询：变更内容、发布人、时间、各分类计数。
6. 同一准则的两次发布 SHALL 串行；后到的发布在版本校验失败时返回 409。

## R5 项目侧待确认弹窗

1. 项目成员进入项目时，若存在本项目待确认事项，系统 SHALL 弹窗提示，列出每处的三方对比与原因（冲突 / 管理员暂缓）。
2. 用户 SHALL 可逐条或批量选择「采用新全局 / 保留本项目 / 手工修改」；「稍后处理」关闭弹窗但保留提醒入口（角标），同一会话内同一项目不重复自动弹出。
3. 处理 SHALL 需要本项目 edit 权限；只读成员可查看不可处理。
4. 处理后有效定义立即按选择生效，并触发 R8 传播；处理结果留审计。

## R6 本项目适配

1. 在项目上下文修改任一公式位 SHALL 写入本项目适配（不存在则新建，基线取当时的有效全局定义），不影响其他项目；需要本项目 edit 权限；更新已有适配携带版本做 CAS。
2. 用户 SHALL 可「恢复为全局」：删除本项目适配，有效定义回到全局。
3. 项目适配的每次写入 SHALL 写带 project_id 的哈希链审计，项目「公式历史」可查到。

## R7 一处修改，应用到全部

1. 在项目内保存公式时，用户 SHALL 可选择应用范围：仅本项目（默认）/ 设为全局并应用到全部项目 / 应用到指定项目。
2. 「设为全局」SHALL 仅 admin 可选，提交后走 R3 预览与 R4 发布；非 admin 不显示该选项。
3. 「应用到指定项目」SHALL 只列出当前用户有 edit 权限的项目；每个目标项目按 R3 规则分类（以目标项目当前有效定义为基线）；有冲突时弹窗逐条确认（采用 / 保留目标项目 / 交目标项目确认）。
4. 同一项目内，一个公式位的修改 SHALL 让所有使用该公式位的页面（试算平衡表汇总、报表、穿透、附注取数）读到同一有效定义，不存在只改了其中一处的情况。

## R8 变更传播

1. 任一项目的有效定义变化（全局发布、项目适配保存 / 恢复、待确认处理、应用到其他项目）SHALL 在事务提交后对该项目发出一次变更事件，携带域与公式位列表。
2. 报表域 SHALL 把变化的行、以及经 ROW / SUM_ROW 直接或间接引用它们的行标记为过期，并对项目当前审计年度重算这些行；重算失败的行保留过期标记并可见。
3. 其他域 SHALL 按各自消费方式失效（见 R10）。
4. 传播失败 SHALL 不回滚已提交的定义变更，但必须记录降级日志。
5. 冻结（已归档）项目 SHALL 不重算。

## R9 既有写路径收口

1. 报表配置的新增、修改、删除，「报表预设落入项目」（物化 / 克隆），旧「同步主模板」，主模板候选审批回填，公式历史回滚，SHALL 都维护版本与基线，并经同一同步内核；不得存在绕过版本的写入。
2. 旧「同步主模板」SHALL 改为按基线判断：跟随全局的行自动更新，改过且不同的行生成待确认事项，不再清除过期标记了事。
3. 公式历史回滚 SHALL 按配置行身份与版本定位，不再按行次 `LIMIT 1`；定位不到时返回 404，不得返回成功。
4. 管理员直接修改全局报表行（不经预览）SHALL 等同于「全部应用 + 冲突交项目确认」的发布。

## R10 覆盖的公式域

| 域 | 公式位身份 | 全局作用范围 | 项目层存储 | 消费方与传播 |
|---|---|---|---|---|
| 报表（含试算平衡表汇总、合并报表） | 报表类型 + 行次 | 适用准则（4 种） | `report_config` 项目行 | 报表生成 / 合并求值 / 取数层；标过期并重算 |
| 试算表科目明细 | 科目编码（新增行用自定义编码） | 全部准则通用 | 统一设置表 | 公式管理中心与试算表取数面板；通知刷新 |
| 表间审核规则 | 分组 + 规则编号 | 适用准则 | 统一设置表 | 报表勾稽执行；与 7 条内置勾稽一起执行 |
| 底稿单元格公式 | 底稿编码 + sheet + 单元格 | 全部准则通用 | `wp_formula` 自定义行 | 底稿预填；标底稿待刷新 |
| 附注表格公式 | 模板类型 + 章节 + 目标格 | 模板类型 | 统一设置表 | 附注公式执行；标附注过期 |
| 合并附注公式 | 模板类型 + 章节 + 行 + 列 | 模板类型 | 统一设置表 | 合并附注填数；重新填数 |

1. 每个域 SHALL 实现同一套适配接口（列全局、列项目、写全局、写项目、找受影响项目、传播），共享同一同步内核与弹窗。
2. 表间审核用户规则 SHALL 接入报表勾稽执行（现状：只保存不执行）。
3. 公式推送规则（`formula_push_rules.json`）不在本 spec 范围：仍为系统预设，项目侧沿用「采用 / 锁定」。

## R11 安全与一致性

1. 读全局设置：已登录即可；读项目有效定义与待确认事项：项目 readonly；写项目适配、处理待确认、应用到指定项目：每个目标项目 edit；写全局、发布、设为全局：admin。
2. 任何拒绝 SHALL 零写入、零事件。
3. 发布、应用到指定项目 SHALL 支持重复提交不重复生效（版本校验 + 同一发布请求号幂等）。
4. 已归档项目 SHALL 不被改动定义（只写固定行以保持旧定义），不重算。
5. PG 专用语句（行锁、咨询锁）SHALL 有 SQLite 方言判断，测试库可跑。

## R12 验证

1. 同步分类内核 SHALL 有单元测试与性质测试（hypothesis `max_examples=5`），覆盖五种分类与三种冲突处理。
2. 端点 SHALL 有 TestClient 测试，走真实鉴权链：admin 放行；非 admin 写全局 403 且零写入；项目 edit 放行；readonly 写 403；非成员 403。
3. 迁移 SHALL 在本地 PG 上执行（与启动同一路径），回滚脚本可执行。
4. SHALL 有浏览器实测：管理员在全局设置改一条报表公式 → 预览看到冲突 → 发布 → 有适配的项目进入时弹窗 → 选择后报表值按新定义重算。
5. 改动前后跑相关既有测试，确认没有新增失败（与改动前同批对照）。

## R13 公式模板：创建、共享、订阅、更新与全局联动

1. 用户 SHALL 可把以下内容保存为公式模板：本项目当前有效定义（可选域与公式位）、全局设置的副本、手工编辑。模板有名称、说明、适用准则或模板类型、版本号。
2. 共享范围 SHALL 为：个人（仅本人）、项目组（所属项目的全部成员）、集团（所属集团根项目及其全部下级项目的成员）、事务所（全体）。可见性由服务端判定，列表与详情同一口径；创建事务所模板仅 admin，创建项目组 / 集团模板需所属项目 edit。
3. 项目订阅模板（每个域最多订阅一个）时，系统 SHALL 先预览：模板的每个公式位相对本项目当前状态，分为直接生效 / 已一致 / 冲突。冲突弹窗给出三方对比，可逐条或批量选择「采用模板 / 保留本项目」；确认后写订阅，并记录所订阅的模板版本。
4. 模板修改 SHALL 生成新版本。所有者发布新版本时，走与全局发布相同的预览、项目勾选、冲突决策与待确认流程，范围是订阅该模板的项目；未处理的冲突进入各项目的待确认弹窗。
5. 退订时 SHALL 弹窗选择「保留模板公式为本项目适配」或「回到全局」；选回到全局时，与全局不同的已适配公式位逐条确认。
6. 全局变化时：模板未定义的公式位按全局正常同步；模板已定义的公式位在订阅项目里不变，模板所有者在模板管理里看到「模板与新全局不一致」提示，可一键并入模板（生成新版本）。
7. admin SHALL 可把模板「设为全局」，走 R3 / R4；其他人可把模板「提交为全局候选」，由 admin 审核后发布。
8. 模板详情 SHALL 显示订阅项目、各自订阅版本、是否有本地修改（由三方比较得出）、是否有待确认事项。
9. 修改与删除模板仅限所有者或 admin；删除前须先没有订阅项目。订阅、退订需目标项目 edit。保存、发布、订阅、退订、设为全局都写审计。
10. 公式管理中心的「保存为模板 / 引用模板 / 撤销引用」SHALL 改走本机制；引用只写本项目层，绝不写全局行。
11. 测试 SHALL 覆盖可见性矩阵（四种共享范围 × 所有者 / 成员 / 非成员 / admin），以及订阅、发布新版本、退订的端到端流程。

## R14 既有模板机制收口

1. 共享配置模板端点（全部配置类型）SHALL 补鉴权：创建事务所模板仅 admin；集团模板需所属项目 edit；修改 / 删除仅所有者或 admin；详情按可见性判定；引用与引用历史需目标项目权限。其他配置类型的业务行为不变。
2. 共享配置模板的 `formula_config` 类型入口 SHALL 下线（真库 0 条，无数据迁移）。
3. 公式预设库的自定义预设 SHALL 不再写入代码仓库内的 JSON 文件，改存数据库（事务所级模板或全局候选）；草稿刷新的读取口径不变（自定义优先于基线）。
