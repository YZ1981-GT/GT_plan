# 需求：AI 面板「采纳」「转存笔记」选择目标位置与文件

## 背景（2026-10-20 浏览器复现）

项目列表页（`/projects`，URL 无 projectId / wpId）右侧「AI 审计助手」落在**全局知识模式**：

1. 点 AI 回复下的「采纳」→ `POST /api/ai-chat/adopt` 返回 404「资源不存在或不可访问」。请求体 `host={global_knowledge}`；后端 `adopt_message` 对无项目、无写动作的宿主直接拒绝。面板没有任何让用户指定「采纳到哪里」的入口；即使前端改发某个底稿宿主，`load_authoritative_message` 也会因「消息所在会话 ≠ 目标宿主」拒绝。报表宿主（无实例 UUID）、知识库宿主（无项目）同样恒失败。
2. 多选回复后点「转存笔记」→ 前端直接提示「当前页面无项目上下文，无法保存项目笔记」，不发请求。
3. 隐藏缺陷：前端笔记请求体是 `host:{type,id,project_id_assertion,year_assertion}` 且不带 `session_id`，而后端 `NoteSaveRequestBody`（`extra="forbid"`）要求扁平的 `host_type/host_id/project_id/year/session_id`。浏览器实测该请求体恒 422（缺 host_type / host_id / session_id）⇒ **转存笔记在任何宿主下都从未成功过**；唯一前端守卫（Property 21）不检查请求体形状。
4. 隐藏缺陷：`save_note` 不校验消息所在会话的项目 ⇒ 客户端发 P2 宿主 + P1 会话的消息即可把 P1 对话存进 P2 的项目笔记。

## R1 采纳：宿主不能作为采纳目标时让用户选择目标

1. 当前宿主是底稿或附注（有项目）时，「采纳」保持直接提交到当前文件，成功提示写明「待确认」。
2. 其余宿主（全局知识、报表、知识库文件夹/文档）点「采纳」弹出「采纳到…」对话框：选择项目 → 目标类型（底稿 / 附注章节）→ 目标文件，可选填目标位置（如单元格、段落）。
3. 来源宿主带项目（报表、带项目的知识库宿主）时项目锁定为该项目。
4. 对话框说明采纳不会直接改写文件：内容进入该项目「AI 生成内容待确认」，在目标页面确认后生效。
5. 成功提示写明目标文件；失败在对话框内显示原因并可重试，对话框不关闭。
6. 列表加载失败 / 为空时给出中文原因（如「该项目暂无已生成的底稿」「项目未设置审计年度」）。

## R2 采纳安全（跨宿主）

1. 请求体新增可选 `source_host`（消息所在会话的宿主）；不带时行为与现状完全一致（同宿主严格绑定）。
2. 来源与目标不同时：来源类型只能是全局知识 / 报表 / 知识库文件夹 / 知识库文档；目标类型只能是底稿 / 附注；来源有项目时目标必须同项目；来源与目标属于同一用户。
3. 来源宿主按读权限授权，目标宿主按采纳（写）权限授权；任一不满足、或消息不属于来源会话 → 不可枚举 404 + 内部 denial 审计，零副作用。
4. 采纳哈希链审计增加来源宿主类型与 ID（同宿主时与目标相同），仍不含正文。

## R3 转存笔记：让用户确认名称与保存位置

1. 「转存笔记」弹出对话框：笔记名称（必填，≤100 字）+ 保存位置。
2. 当前宿主有项目时，保存位置固定为本项目的「AI 对话笔记」文件夹并明确展示。
3. 当前宿主无项目时，用户在「项目笔记」（选项目，保存到该项目「AI 对话笔记」，首次自动创建）与「知识库文件夹」（只列有新建权限的文件夹）之间选择；知识库文件夹宿主默认选中当前文件夹。
4. 提示「同一位置已有同名笔记时保存为新版本，原版本保留」。
5. 成功后提示实际保存位置与名称，并提供「在知识库中查看」入口；失败保留选择与名称，可重试。

## R4 转存笔记契约与安全

1. 请求体与后端模型一致（扁平字段）；`session_id` 改为可选，服务端由消息反查唯一会话（传入时必须一致；消息跨多个会话 → 拒绝）。
2. 保存位置 `target_project_id` / `target_folder_id` 二选一；都不传时用宿主项目，宿主也无项目 → 明确报错「请选择笔记保存位置」。
3. 消息所在会话有项目时：只能保存到该项目（指定其他项目或知识库文件夹 → 拒绝）；默认路径同样校验，堵住缺陷 4。
4. 目标授权：项目 = 角色允许 + 项目成员（管理员不受限）且项目存在；文件夹 = 角色可写 + 可在该文件夹新建。不存在与无权同一句中文原因。
5. 授权与位置校验都在占用幂等收据之前完成；幂等键按「消息集合 + 名称 + 位置」复用：失败重试复用，任一变化换新键。
6. 文件夹目标的文档访问级别继承文件夹；项目目标沿用项目组可见。

## R5 验证

1. 真实 PostgreSQL 守卫覆盖 R2 / R4 每条规则的允许与拒绝，含零副作用断言，并有变异证明。
2. 前端 vitest 覆盖采纳 / 笔记请求体，且请求体字段从后端模型源码解析对账（跨语言契约守卫）。
3. 浏览器实测：全局模式采纳到底稿、转存到项目笔记与知识库文件夹，核对落库后清理测试数据。
