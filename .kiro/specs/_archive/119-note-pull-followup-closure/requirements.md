# 附注取数收口后续建议逐项修复 — 需求

## 背景

承接 `note-pull-header-formula-closure`（25/25，未提交）design §9 的改进建议与交付说明里的工程项。用户 2026-10-27：
「按建议再逐一修复，都修复好后，整体复盘下，有问题及时修复，最后同步远端，在干净的临时检出里跑一遍要提交的代码、
重新生成清册，再提交」。

范围 = §9 全部条目 + 交付说明补的 4 个工程项。现状实证见 design §1；其中「单体附注存储升级为三层表头」实证前提不成立
（模板层没有三层表头），按 design §1 F14 / §5 R4 裁决不做存储改动。

## 取数

### R1 附注离屏同步扩到其余底稿
1. provider 可以一次写多个章节（42 个 builder 返回多章节数组），返回 `sections[]`；运行结果按章节逐条回报。
2. 用工厂登记 provider：声明取数方式（底稿回复 / 底稿 FormData / 渲染配置 / 账龄配置）、composable、快照函数、载荷
   builder、章节；离屏时不触发界面提示、AI、受限资产等副作用。
3. Tab 与 provider 调同一个快照函数与同一个发送函数（不复制计算逻辑）；每接入一组底稿有「离屏载荷 = Tab 载荷」用例。
4. 冻结清单只许变短；仍未接入的底稿逐码写明原因（如「快照依赖外壳传入的跨表数据，待抽出」）。
5. 共用章节（五、8 / 八、9 等）的多个 provider 依次写入，不清掉其他底稿的子表。

### R2 子表推送规则清点与修复
1. 静态分桶（字段能否取到值、表名是否在该口径模板里、是否命中合计行兜底裁决）与真库探针（国企 / 上市各一个项目，
   回滚事务、逐规则动作与原因），结论写进 design。
2. 删掉永远写不出数的子表规则（字段不映射到取数行的期末 / 期初值）；表名逐口径声明；生成器同步改，重跑不补回。
3. 引擎：子表规则只按精确表名定位，不回退到首表、不按章节标题改投到别的章节；取数行缺少某个值键时跳过并说明，
   不抛异常（原 `row[f"{vk}_resolved"]` 会让整张底稿回滚）。
4. 主表规则的章节号与注册表一致（实证 H10 / L6 / N3 / F5 错挂），修正后由守卫钉住。
5. 守卫：每条附注规则在其声明口径下章节与表都存在、字段可取到值；真库棘轮按新结果重定。

### R3 附注权威源按章节交接 + 前后端对拍
1. 主表审定数由公式推送负责：底稿披露同步写入时，推送最近一次写入的格保持推送值，不一致的格在响应里逐格回报
   （前端提示「以试算表审定数为准」）。
2. 「章节由底稿同步过」只认底稿披露同步；公式推送不再写同步指纹，离屏同步「已有人工填写不覆盖」的保护恢复有效。
3. HTML 同步入口按表名合并子表（原先整体替换，没推送的子表丢失）。
4. 交接规则写进 design（ADR）；守卫钉住「推送写过的格不被披露同步改掉」「推送不写同步指纹」。

## 表头

### R4 三层表头（核实）
1. 核实单体模板是否有原生三层表头；期间层（ADR-3）只在显示 / 导出还原、不改存储。结论与理由写进 design，不做存储升级。

### R5 bindings「manual 占位」不再挡住推送与公式
1. 生成附注时，没有 binding、或 binding 为 manual 且没有预填值的格不标 manual（`_cell_meta` 记 `unbound`）。
2. 编辑器里用户改了数值的格标为人工（推送 / 公式 / 刷新不改，可「恢复自动」）。
3. 存量修复工具：只把「manual、值为空、无预填值」的格改回自动；dry-run 报数；【测试】项目实写，真实项目只出报告。

### R6 合并附注空表头不显示「列N」
1. 合并模板生成时标签列表头为空，取单体同名表的首列表头；取不到留空。
2. 前端不显示「列N」兜底；【测试】合并项目已存的表头随之修正。

## 公式

### R7 多合计分段预设
1. 段首合计（「一、…合计」在本段第一行、下面是本段明细）按段生成合计构成；段内「其中：」只允许是段内第一行（列举本段
   构成），其他位置仍判不准。前后端同一判定，golden 重生成，判不准的计数下降并逐表核对。

### R8 中文预设名
1. 旧生成器的求和结果不再覆盖按结构生成的预设；覆盖率统计用同一套预设。
2. 模板里出现的每个中文预设名都有去处（审核规则或明确不生成），补上「期间衔接」，守卫钉住。

### R9 删除 `note_total_recalc`
1. 无生产调用方的模块与专属测试删除，引用它的注释与测试改指现行实现。

## 合并

### R10 「前五名」类表跨企业重排
1. 识别前 N 名表；合并数按单位汇总后按期末余额重排取前 N，合计重算；比例列按合并口径分母重算，分母取不到留空并回报
   原因；集团内单位不进排名。汇总节点只能基于下级已保存的前 N，界面写明是近似。

### R11 同名多行映射按出现顺序
1. 来源行带出现序号；映射可声明序号（不声明 = 全部同名行，兼容旧规则）；建议、自动映射、拉数按（行名, 序号）取行；
   同一映射不重复累加。

### R12 取消勾选的可选行不拉数
1. 读取层带出下推可选标志；拉数跳过 `_pushed_optional_active = false` 的行；结构指纹不含该标志。

### R13 子企业下推固定行保护（后端）
1. 保存子企业附注时，原有的下推固定行不能删除、改名或去掉下推标记，违反时 409 并列出行名；加行、改数照常。

### R14 子企业编辑器

### R15 合并写入跳过「……」占位行
1. 拉数与重新汇总写合并附注时不写占位行；手工 / 锁定格按行名重映射，不错位。
