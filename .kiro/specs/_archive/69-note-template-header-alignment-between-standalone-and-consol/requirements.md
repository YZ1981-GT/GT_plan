# 单体与合并附注模板列名统一对齐

## 背景

合并附注的「📋 明细映射」从各子企业单体附注拉取数据时，需要按列名匹配把单体表的列值填到合并表的对应列上。当前单体模板和合并模板**各自独立生成**，同一张业务表的列名存在大量不一致，导致读取层无法自动认列，用户看到「部分列未对上」的警告。

## 现状（2026-10-23 全量扫描）

- **575 张子表**按表名匹配成功（上市版 + 国企版合并模板 ↔ 单体模板）
- **528 处列名差异**，310 种模式

### 差异分类

| 类别 | 典型模式 | 处数 | 根因 |
|------|---------|------|------|
| A. 列数不同 | 合并 8 列 vs 单体 6 列 | ~130 | 合并模板拆了更多期间列、或包含单体没有的列 |
| B. 科目名替代属性名 | `应收账款` ↔ `账面余额` | ~30 | 单体用科目名当列头，合并用计量属性名 |
| C. 期间词不一致 | `期末余额` ↔ `期末数`；`期初余额` ↔ `年初余额` | ~15 | 上市版用「余额」，国企版用「数」 |
| D. 分组层级不同 | `账面余额/比例(%)` ↔ `比例(%)`；三级路径 ↔ 二级 | ~15 | 合并把 _column_groups 编进全路径，单体没有 |
| E. 完全不同的列语义 | 变动表整表结构不一致 | ~340 | 合并与单体的表体设计完全不同，非列名问题 |

### 影响

- 明细映射预览时「部分列未对上」的企业数 = 真库 234/710（33%）
- 读取层 `consol_note_standalone_reader` 按歧义不填的列 = 实际可用数据的漏失
- 公式推送种子和标题行库已经按合并模板的列路径建立了取数规则，两侧不一致会导致推送写到错位的列

## 需求

### R1：单体模板列名向合并模板对齐

对 B/C/D 三类差异（约 60 处），修改**单体模板** JSON 中 `sub_tables[].headers` 和 `_column_groups` 的列名，使其与合并模板在去掉期间前缀后完全一致。

**选择改单体而非改合并的理由**：
1. 合并模板的列路径（含期间前缀 + 分组路径）已被公式推送种子（420 条 `formula_push_rules.json`）、标题行库（`note_table_header_library.json`）、公式管理地址库引用，改合并的级联影响远大于改单体
2. 单体模板的列名只被单体附注编辑器显示和 `note_writer` 写入时使用，改名后编辑器显示更规范，写入路径不受影响（按位置写）
3. 业务上，「账面余额」比「应收账款」更适合做列头——列头应该是计量属性，不是科目名

#### R1.1 B 类：科目名 → 属性名

| 单体现值 | 改为 | 涉及科目 |
|---------|------|---------|
| `应收账款` | `账面余额` | 应收账款(D5)、应收票据(D4)、其他应收款(D9)组合计提表 |
| `应收票据` | `账面余额` | 应收票据(D4)按单项计提表 |
| `收入` | `主营业务收入` | 营业收入/成本(D64/D65)国企版 |
| `成本` | `主营业务成本` | 营业收入/成本(D64/D65)国企版 |

#### R1.2 C 类：期间词归一

| 单体现值 | 改为 | 条件 |
|---------|------|------|
| `期末数` | `期末余额` | 上市版中与合并模板不一致的表 |
| `期初数` | `期初余额` | 同上 |
| `年初余额` | `期初余额` | 国企版变动表 |
| `上年年末数` | `上年年末余额` | 上市版 |

#### R1.3 D 类：分组层级补齐

单体模板有 `_column_groups` 但 headers 只写了二级名（如 `比例(%)`），而合并模板的全路径是 `账面余额/比例(%)`。修正单体 headers 使其**在与 _column_groups 组合后**形成的全路径与合并模板去掉期间前缀后一致。

### R2：A/E 类暂不改（列数不同 / 结构完全不同）

这两类是表体设计不同，不是列名问题。改模板结构需要同步改编辑器、写入器、行匹配，工作量大且可能破坏已有数据。登记为已知限制，后续按科目逐个立 spec 处理。

### R3：读取层期间词表扩充

在 `consol_note_standalone_reader` 的期间归一词表中，把 R1.2 的同义对补全，确保即使旧版单体模板（用户已有的 `disclosure_notes` 数据）也能正确匹配。

### R4：守卫——禁止新增不一致

新建一个测试，在测试时自动扫描两套模板的全部子表列名差异，断言 B/C/D 类差异数 = 0。新增模板表时如果列名不一致，该测试会打红。

## 验收标准

- [ ] AC1：B/C/D 三类列名差异全部修复，守卫测试断言 0
- [ ] AC2：单体附注编辑器打开各章节不报错，列名显示正确
- [ ] AC3：合并附注明细映射预览中「部分列未对上」的企业数下降（234 → 守卫定基线）
- [ ] AC4：现有后端测试全绿（单体附注 + 合并附注 + 公式推送 + 标题行库相关）
- [ ] AC5：读取层期间词表覆盖 R1.2 全部同义对
