> 承接：`audit-year-calendar-fallback-ratchet` 任务 8.5 与其范围外登记、`procedure-chain-followup-closure` 5.3 的遗留。

## R1 试算表取数契约（前端 37 处不带年度 ⇒ 422 被吞成「待取数」）

现状（2026-10-26 现扫）：前端直接 `GET /api/projects/{id}/trial-balance` 84 处（65 个文件），另有 `useAuditData` 变量拼址 2 处、`FormulaBar` 调不存在的 `GET /api/trial-balance`、`useFormulaParamCache` 不带年度。端点 `year` 必填、不认 `account_prefix` / `account_code(s)` / `limit`，也不回 `wp_*` 三列与发生额 / 上年数；前端读了 20 多种端点从不返回的字段（`debit_amount` / `period_credit` / `ending_balance` / `prior_*` …）⇒ 即使带上年度也静默得 0。

1. 端点 `year` 可省：省略时按项目审计年度取（与 `require_project_audit_year` 同口径），项目没填年度 ⇒ 422「未设置审计年度，请先在项目基本信息中填写」。
2. 端点认 `account_prefix`（逗号分隔，按标准科目码前缀筛）；`include_movement=true` 回本期借 / 贷方发生额（`period_debit` / `period_credit`，与未审数同一叶子 + 映射口径）；`include_prior=true` 回上年审定数 `prior_audited_amount`（来源与报表上期同为 `prior_year_context.resolve_prior_source`，取不到为 null，不代入 0）；每行补回 `wp_adjustment` / `wp_publish_base` / `wp_published_at`。
3. 前端只有一个试算表取数入口（`services/trialBalanceRows.ts`）：类型化行、两种响应形状（列表 / v1 残留的 `{data, warning}`）统一解包、按前缀取行、损益发生额按与后端 `pl_occurrence` 相同的借贷拆分；`getTrialBalance` 与 `workpaperAuditYear` 的取数函数委托给它。
4. 84 处 + 上述 4 处全部改走该入口，读取的字段只用端点真实返回的字段；拿不到的数显示「待取数」/ 原因，不得静默写 0。
5. 守卫：①前端源码里除该入口外不得直接 GET 试算表列表端点；②后端响应键集合 == 前端行类型键集合（跨语言契约）；③端点年度省略 / 缺失 / 前缀 / 发生额 / 上年 / `wp_*` 有测试。
6. 浏览器实测：重药安徽 H3-14 6051 勾稽、D2-7、J1-8、G11 取数不再「待取数」，数值与试算表页一致。

## R2 审计年度空值类型债（约 440 条 `number | null` 与 `number` 不符）

现状：全量 vue-tsc 对比 `213f19816` 新增 440 条（TS2322 266 / TS2345 174，305 种）。抽查证明「运行时已按 null 分支处理」不成立：`useAdjustmentCentralSync` 年度为空仍发同步请求（422 后提示「同步到集中登记失败」）、抽凭引擎 / 截止测试默认截止日拼成 `null-12-31`、挂凭计数与导入照发请求。

1. 共用组件与组合式函数（抽凭引擎、截止测试抽样、集中调整同步、附注同步条、挂凭列表等）显式接受 `number | null`：读请求年度为空不发、显示空态；写 / 用户触发的请求不发并提示「未设置审计年度…」。
2. 调用处按同一规则加门控，禁止用非空断言 `!` 或 `as number` 消除类型错误。
3. 视图页（报表、试算表、调整分录、交付中心、审计报告、现金流量表、错报、合伙人签字等）年度为空时读请求不发、写操作提示，不得出现 422 错误弹窗。
4. 全量 vue-tsc 对比 HEAD：本 spec 范围内新增的这 440 条清零，且不引入新错误；`audit-year-calendar-fallback-ratchet` 任务 8.5 据此勾选并指向本 spec。

## R3 表头引用外部工作簿（15 个模板显示示例文字）

现状：表头区（前 10 行 × 12 列）有外部链接单格引用 `=[N]页签!A2` 的模板 15 个、574 格（2026-10-26 现扫），打开时显示模板缓存的示例（「会计期间：202X年度」「被审计单位：ABC公司」「编制人：张XX」）。

1. 每一页表头区的外部引用按缓存值归类处理：
   - 表头标签（编制单位 / 被审计单位 / 会计期间 / 截止日 / 编制人 / 复核人 / 编制日期 / 复核日期 …）：本册有同名页签且该格是同一标签 ⇒ 改成本册引用（随表头页填写）；否则改成静态标签文字，示例部分去掉，能填的项填本项目值。
   - 底稿索引号（`F2-18`）：改成静态文字（该页自己的索引）。
   - 缓存为空、本册有同名页签且该格是表头标签 ⇒ 改成本册引用。
   - 数据（金额、银行名称、复合公式）：不动。
2. 改写后的格与引用它们的本册单格引用一并写入新的缓存值，按缓存值读取的界面（HTML 渲染）与重算后的显示一致。
3. 原「表头靠外部链接、填不进去」的回执原因只在仍有未处理的表头标签外部引用时出现。
