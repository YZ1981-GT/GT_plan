## 6. 🔴 顺带查出的模板债（已登记，不改字节）

### 6.1 区① SUMIF 匹配区多含合计行

`F8 = SUMIF('明细表F4-2'!$D$11:$D$32, ...)` —— 匹配区/求和区都到 **R32**，而实测 `明细表F4-2` 的数据区是 **R11~R31**，**R32 是合计行**（`A32='合计'`、`E32=SUM(E11:E31)`）。

因 `D32` 为空、不匹配任何款项性质标签，实际不会重复计入 ⇒ **不严谨但无计算错误**。登记为模板治理债。

### 6.2 区② 引用 `N32`/`U32` 是正确的

实测确认 `明细表F4-2` 的 R32 是合计行且 `N32=SUM(N11:N31)`、`U32` 同理 ⇒ 账龄区按列取合计值**正确**，与 `F5-7!G31` 越界引用不同型，**不是缺陷**。

### 6.3 🔴 `明细表F4-2` 数据验证语义错位（新发现）

```
DV  C11:C18   list  "合并范围内关联方,合并范围外关联方,非关联方"   ← 正确（C 列=关联方类型）
DV  D11:D18   list  "货款,工程款,设备款,服务费,其他"              ← 正确（D 列=款项性质）
DV  C19:D31   list  "货款,工程款,设备款,服务费,其他"              ← 🔴 区域跨 C/D 两列
```

`C19:D31` 让 **C19:C31 挂上了「款项性质」枚举**，而 C 列语义是「关联方类型」。同列上半段（C11:C18）挂的才是正确枚举。

与 F4-6 的 `B8:B11` DV 悬空引用（`formula1=$N$7:$N$14` 而 N 列全空）同类但更严重（指向语义错误的枚举，会引导填错值）。
