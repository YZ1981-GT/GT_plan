## P0

### R1 编辑器首屏底稿详情只有一个来源
现状：Shell（`useEditorMode`，经 apiProxy）与 Univer 核心（`useEditorUniver` → `getWorkpaper`，直接用 utils/http）同时 GET 同一底稿详情，GET 去重取消先发的那一发；
核心把详情写进只读 computed（写入被丢弃）后按 Shell 的空详情判「底稿文件尚未生成」；H1A 这类 HTML 册因此拿不到 wp_code、归类不加载、停在错误页。实测 5 次 3 次。
1. 打开编辑器时同一底稿详情的并发请求共享同一个在途结果，不再互相取消。
2. 请求被取消不得判为「底稿文件尚未生成」或「加载底稿失败」；取消后重取一次。
3. 子组件与保存流程不再写只读详情；详情更新统一交回 Shell。
4. 卸载 Univer 核心时只摘自己的事件监听，不清掉其他组件的。
5. 用真实 http 去重复现两发并发：修复前红（2 发、先发被取消、no_file），修复后 1 发、无错误页。

### R2 编辑锁鉴权
现状：`/api/editing-locks` 五个端点只要求登录；审计员对打不开（404）的底稿仍能取锁续期，管理员打开时被锁成只读；活跃锁列表跨项目可见。
1. 底稿锁的取锁 / 续期须通过与保存同级的底稿门：看不见或无编辑权 ⇒ 404，且不建锁行、不清理他人过期锁；附注锁、报告锁（资源 id = `{项目}_note` / `{项目}_report`）按项目成员级别判。
2. 续期被拒时释放本人在该资源上的锁。
3. 强制接管只给底稿全权身份（admin / 主管范围 / 项目负责人）；能看见但不是全权 ⇒ 403；强制接管同样记录窗口标识。
4. 释放只认锁持有者（现状保持）。
5. 活跃锁列表只给 admin。
6. 前端只在可编辑时取锁；取锁 / 续期被拒不弹全局错误、不显示「他人正在编辑」；续期失败停止心跳并标记不再持锁；强制接管失败给出提示。

### R3 模板复制
现状：复制写 wp_index 与 working_paper 同一次 flush，PG 上先插 working_paper ⇒ 外键违例 500（SQLite 测试不查外键故绿）；来源底稿 / 来源项目不校验权限（跨项目读）；复制产物 `file_path=''`；前端「覆盖」实际未实现。
1. 复制落库不再违反外键（真 PG 用例钉住）。
2. 单份复制：来源底稿须对当前用户可见（底稿门）；整循环复制：须是来源项目成员，且逐份可见，不可见的跳过并写明原因；无权与不存在一律 404，不泄露存在性。
3. 复制产物落本底稿自己的文件（按模板目录生成，不复制源项目文件内容）；失败时清理已落文件。
4. 前端去掉未实现的「覆盖」选项；结果按复制 / 跳过 / 失败计数提示，不再「全部跳过也提示完成」。

## P1 程序表链路

### R4 裁剪 / 恢复后状态一致
1. 细裁与恢复在同一事务对齐程序表覆盖值里的状态（裁剪 ⇒ 不适用；恢复 ⇒ 待执行），不留「无人执行却执行中」。
2. 恢复回执带「需重新委派」与原执行人；页面提示「已恢复执行，原执行人已清除，请重新委派」。
3. 裁剪 / 恢复 / 改状态成功后刷新行归属与任务视图，不显示过期执行人。
4. 状态控件拆分：适用行可选「待执行 / 执行中 / 已完成」，裁剪与恢复执行是独立动作。

### R5 程序裁剪页「进入程序表」直达程序表页签（不落到底稿目录）。
### R6 没有页名的嵌入控制台（A10~A17 / B 类汇总包）：细裁、恢复、行归属按底稿编码定位程序表并落任务；定位不到时与现状一致只在页面标记，并提示「仅页面标记，未写入任务」。
### R7 行级权限读不到时整表只读、显示原因与「重试」，不再整表放开。
### R8 程序步骤覆盖值批量写：新增批量端点，一次请求一次提交，失败项逐条回报并提示用户（不再逐字段静默吞错）。
### R9 前置环节横幅按当前底稿编码请求，详情加载后（及换底稿时）更新；没有前置环节的循环不请求（不再兜底 E1）。
### R10 无权 / 已删除 / 不存在的底稿：编辑器给一句中性的中文提示与「返回底稿列表」，不显示英文码、不说「稍后重试」；能力快照随之失败时不再另报一条错误。

## P1 生成与人员

### R11 生成回执统一
1. 所有建底稿入口经同一保留范围判定（含链路编排、模板复制）。
2. 统一回执：新建 / 已存在 / 已裁 / 在回收站 / 空白册 / 失败 / 表头未填；失败不计入新建。
3. 链路编排逐码保存点：单码失败不回滚已建（不再整会话 rollback），复制模板失败计入失败而非新建。
4. IPO / B60：模板复制失败不计入新建并进失败；D4 包装透传已裁 / 在回收站。
5. 自定义单张：表头没填上写进回执与提示（不再固定「表头已自动填充」）。
6. 模板集生成：请求内不填表头（性能约束），回执如实写明未填表头的数量。

### R12 人员档案删除
1. 删除人员需 admin（现状只要求登录）。
2. 有有效项目分配时默认拒绝（409，列出项目）；带确认参数时同事务撤销其项目分配与项目成员行。
3. 委派选到无有效账号的人员时，提示写明原因与处理办法。

### R13 委派预览前置导入：异常窄化，失败时如实回报「未就绪」且计数不虚报；不跨模块调用私有方法。
### R14 存量底稿文件：提供 dry-run 报告工具（无文件 / 占位路径 / 指向模板 / 文件缺失分别计数）；`--apply` 需用户放行后才执行。

## P2 请求收敛与工程化

### R15 关联底稿 chip：同一轮渲染合并为批量解析（每批 ≤50），禁用的 chip 不解析，同参数在途共享。
### R16 编辑器打开时项目详情 / 底稿详情的并发请求共享在途结果，不因附加配置绕开共享。
### R17 导入进度轮询：没有进行中的导入时降频（30 秒），有任务时 5 秒；页面隐藏暂停（现状保持）。
### R18 底稿移入 / 恢复回收站写 append-only 领域事件（操作人、原因类别、原因、编码、底稿 id、请求 id）；去向 JSON 保留兼容；回收站「删除人」读事件。
### R19 程序行归属端点在路由内显式挂底稿门，不依赖注册表按路径注入，注册表不重复挂。
### R20 测试盲区：设 `GT_REQUIRE_PG=1` 时 pg_only 用例被跳过即失败；PG 地址识别含 `postgres://`；本 spec 涉及外键的 SQLite 用例开启外键检查。
### R21 跨角色端到端：PG 回滚事务内的接口级用例（admin / 经理 / 审计员：裁剪 → 生成 → 委派 → 可见 → 编辑锁 → 恢复）；Playwright 可重放脚本（环境变量指定【测试】项目与账号，未配置即跳过）。
