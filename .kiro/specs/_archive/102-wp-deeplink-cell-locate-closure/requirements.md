# 需求文档：底稿深链单元格定位收口（wp-deeplink-cell-locate-closure）

> 用户 2026-10-30：「先推送，之后修复单元格定位缺陷，以后按建议来」。缺陷由 acnr-foundation-defect-closure 台账 RV7.6-02 浏览器复测发现（其 tasks.md T16「复测（RV7.6-02）」与勘误两行）。

## 背景（2026-10-30 现查）

- **浏览器现象**：短链 `/workpapers/{E1}?sheet=E1-14&cell=C10` 未登录打开 → 登录 → 进入编辑器，3 次独立运行都切到了 E1-14 页签，但都没有单元格高亮，也没有任何提示。
- **原因一：定位事件丢失。** `WorkpaperEditor.vue` 在 onMounted 里 nextTick + 300ms 发 `workpaper:locate-cell`；`GtWpRenderer` 要等 onMounted 里 `fetchComponentType` 与 `wpClassification.load` 两次请求返回、`useHtmlRenderer` 为真才挂载（实测它自己的 render-config 请求在进入编辑器后 1.09 / 1.14 / 1.10 秒才发出）。事件发出时没有监听者。`GtWpRenderer.onLocateCell` 在渲染配置未到时也直接 return，不排队、不提示。`GtWpRenderer` 声明了 `initialCell` 属性但从未使用，编辑器只传 `initial-sheet`（页签能切到 E1-14 靠的是它）。
- **原因二：网页视图没有单元格锚点。** `useCellLocate` 的首选判据是 `[data-cell-ref]`，全前端没有任何组件渲染这个属性（`git grep data-cell-ref` 只命中 `useCellLocate.ts` 自己）；其余判据靠 `value` / `label`，深链不带这两项。el-table 类还把 `B5` 的行号当成整页第 5 个 `.el-table__row`，查找范围是整个 document，可能高亮到别的表或侧栏。
- **Univer 路径同样丢**：`UniverEditorCore` 在 `univerAPI` 就绪前收到事件直接 return，而深链事件早于它挂载；它也只切 sheet、不滚到单元格。
- **归档 spec 勘误**：`_archive/05-business-features/wp-locate-foundation` Task 4.2「WorkpaperEditor onMounted 读 query 触发定位」标完成，实现有上述时序问题；其「9 类 HTML componentType 全覆盖」不成立。归档文件不改，勘误登记在本 spec（design §6）。
- **E1-14 模板**（`backend/wp_templates/E/E1-14至E1-15  货币资金 -分析程序（Leap应对措施-分析程序）.xlsx` 的「货币资金分析表E1-14」，52 行）：货币资金构成 13~18 行（15~17 为库存现金 / 银行存款 / 其他货币资金，18 合计）；其他货币资金 20~29 行（22~28 七类，29 合计）；30 行 F3-2 交叉索引说明；比例分析 32~41 行（34~40 七项，41 为「……」占位）；审计说明 43~48 行；审计结论 50 行。网页视图 `E1TabAnalysis.vue` 三张表的行顺序与模板一致，没有合计行，也没有上期 / 前期结构比与上期变动列；比例表第 8 项「银行存款÷货币资金（集中度）」对应模板 41 行占位。

## 需求

### 需求 1：定位请求不丢
1.1 深链 `?cell=` 打开 HTML 底稿时，编辑器把 sheet / cell 作为初始属性交给 `GtWpRenderer`；渲染配置到达后执行一次定位，不依赖固定延时。
1.2 编辑器内发出的 `workpaper:locate-cell`（侧栏精细化检查、复核标记、版本搜索、批注等）在渲染配置未到时排队、到达后执行；排队只保留最后一个请求。
1.3 Univer 路径的深链事件改在编辑模式判定完成、走 Univer 分支之后再发。
1.4 HTML 路径不再由编辑器发深链事件，同一深链只执行一次。

### 需求 2：只在本渲染器范围内定位，不高亮错位置
2.1 DOM 查找限定在本 `GtWpRenderer` 根元素内。
2.2 去掉「单元格行号 = 第 N 个表格行」的猜测。
2.3 组件可通过 `defineExpose({ locateCell })` 提供定位钩子；渲染器先问组件，再在本渲染器内找 `[data-cell-ref]`。

### 需求 3：结果可见
3.1 定位成功：目标滚到可见处并加 `gt-locate-highlight`（3 秒）。
3.2 sheet 找不到：沿用现有提示「已打开底稿但未能定位到目标位置（可能已变更）」。
3.3 sheet 找到、单元格找不到：只提示一次并写明 sheet 与单元格，如「「货币资金分析表E1-14」的网页视图里没有单元格 C10 的对应位置」。
3.4 组件内容异步加载时，分几次重试（累计约 2 秒）后再判定找不到；新请求到来时放弃旧请求的重试。

### 需求 4：E1-14 先接入单元格锚点（试点）
4.1 按模板行列定位：构成表 15~17 行 × C/D/E/G/I 列、其他货币资金 22~28 行 × C/E/G 列、比例分析 34~41 行 × C/D/E/F/H~K 列定位到单元格；这些行的其他列定位到整行；30 行定位到 F3-2 交叉索引提示；43~48 行定位到审计说明；50 行定位到审计结论。定位时先切到对应区段页签。
4.2 合计行（18、29）以及模板有、网页视图没有的位置按需求 3.3 提示。
4.3 锚点表登记的模板行号与行标签必须与模板文件一致（后端测试读模板逐行校验，模板改了即红）。

### 需求 5：验证
5.1 单元测试覆盖需求 1~4，关键判据做变异证明。
5.2 浏览器实测：【测试】ACNR下钻走查_2025 经平台回收站临时恢复、结束放回；未登录短链 → 登录 → 编辑器，C16（单元格级）、B30（交叉索引提示）、C10（无对应位置的提示）各 3 次独立运行；按「本次走查的所有写请求」逐表对账。

## 不在范围
- ACNR 目录单元格坐标纠错：现查 435 个未停用单元格中 25 个落在合并区域内（非左上角）、41 个本身是文字格；E1-14 的 C10「货币资金余额变动率」在合并的程序说明行 A10:K10 内，C15 实为库存现金本期金额，B30 为空，三条来自 `backend/data/e_address_registry_seed.json`。纠错需重新发布目录，建议在 acnr-foundation-defect-closure 后续处理（审计脚本与明细见 design §5）。
- 其余底稿组件接入锚点：本 spec 只做机制与 E1-14 试点。
- 试算表 / 错报 / 合并 / 报表溯源弹窗把 `wp_code` 当 `wpId` 发事件、且所在页面没有渲染器，事件无人接收（另行处理）。
