> 程序表执行人编辑刷新后丢失一项按用户要求放在 `audit-year-calendar-fallback-ratchet` 任务 0。现状为 2026-10-25 现查，计数会漂，判据不写死行号。

## R1 用户接口（任务 1）

现状：`GET /api/users` 不要求登录，返回全部用户（无 `is_active`）；没有改用户的接口，用户管理页只有「编辑」且保存时带空密码；
`routers/security.py` 锁定账户引用未定义的 `db` / `HTTPException`（一调即 500）、任何登录用户都能调，安全查询类接口只要求登录；
`/api/users/{user_id}/private-storage*` 不鉴权、改语言不校验本人。

1. `GET /api/users` 须登录，返回 `is_active`。
2. 新增 `PUT /api/users/{id}`（仅 admin）：可改邮箱、角色、启用状态、重置密码（非空才改）；不能停用或降级自己；停用 / 降级后必须仍有至少一个启用的 admin。
3. 锁定账户仅 admin，复用 2 的停用逻辑（被锁用户下一次请求即 401）；登录尝试 / 会话 / 审计日志导出仅 admin。
4. 私有存储、改语言：本人或 admin。
5. 用户管理页：显示状态、启用 / 停用（二次确认）；编辑不带密码，另有「重置密码」；角色选项与后端一致。
6. 不在范围：公开注册（`POST /api/auth/register`，登录页在用；是否关闭属产品决定）、用户删除（唯一约束与历史引用）。

## R2 程序行定义导入与逐行委派（任务 2）

现状：`PROCEDURE_ROW_TASKS_ENABLED` 默认关；程序行定义只有裁剪服务在用户裁剪时顺带写入，`ProcedureBackfillRunner` 没有调用方 ⇒ 新项目委派预览恒 0 个目标、无提示；
控制台的「委派」按钮依赖开关注入的行任务字段；物化端点只要求登录。

1. 委派预览先按当前程序表版本导入本项目的程序行定义（已有的不动），只取当前版本，并把新建的行任务绑到已生成的底稿；回执写明导入 / 绑定数。
2. 控制台在开关关闭时也给管理者「委派」按钮：对该行按需建行任务后进入委派对话框（沿用 preview → apply）。
3. 物化端点要求本项目委派人。
4. 开关保持关闭；开启的前提（覆盖冻结、跨项目定义、版本混用、事务隔离、分页）写进 design，不在本 spec 开启。

## R3 四个小问题（任务 3）

1. 底稿列表「编制人」恒为「—」：列表接口只回编制人 id。改为回姓名（人员档案姓名优先，否则用户名）。
2. 回收站「删除人」恒空：列表项没有删除人。底稿取回收轨迹里的操作人，其他类型取 `updated_by`；删除项目时记删除人与删除时间。
3. 生成底稿后 `file_path` 为空或指向共享模板（D2 / E1 是区间模板，H1 直接指向模板目录）：生成时按项目落独立文件（与按编码生成同一套落文件 / 填表头 / 失败清理）；
   任何写入都不得落到模板目录（在线编辑保存遇到模板路径改为先复制到项目目录）；打开底稿时懒加载落了文件就回写 `file_path`。真实项目存量（约 2150 行）只出报告，批量回填待用户确认。
4. 委派人角色只认英文角色码：改为与 `assignment_service` 的合伙人 / 经理别名同源（含中文）。
