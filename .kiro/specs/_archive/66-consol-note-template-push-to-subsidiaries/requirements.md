# 集团级附注披露模板下推

## 背景

当前合并附注从单体附注拉取数据时，行匹配依赖七级匹配算法（精确→别名→全局别名→模板库→上年→模糊→手动）。对于固定行（库存现金、银行存款等），模板行名天然一致，匹配率 96%+。但对于**动态行**（各企业根据实际情况新增的客户名、项目名等明细），行名来自底稿披露表，不同企业的写法不同，导致大量 `manual` 匹配需要人工逐条确认。

**核心矛盾**：合并负责人知道集团层面需要披露哪些行（固定行 + 可选行），但没有机制把这个统一的行结构**下推**给各子企业，子企业只能各自按底稿自行编制，导致行名不一致。

## 现有机制与不足

| 机制 | 能力 | 不足 |
|------|------|------|
| 明细映射（V186） | 拉取时按行名匹配 | 动态行匹配率低 |
| 结构锁（V200） | 冻结子企业行结构 | 只冻结不下发，必须先有行才能锁 |
| 映射规则模板复用 | 跨项目复用映射规则 | 只复用映射关系，不下推行结构 |
| 科目参考推荐 | 子企业看到推荐科目码 | 只读提示，不产生行 |

**缺失的一环**：合并负责人定义行结构 → 推送到子企业 → 子企业在骨架上填数 → 合并拉数时行名一致、零匹配成本。

## 需求

### R1：集团附注披露模板

合并负责人可以在合并项目中为每个附注章节定义**集团级披露模板**，包含三类行：

- **固定行**（`required`）：集团统一披露的行，子企业不可删除、不可改名
- **可选行**（`optional`）：集团建议披露的行，子企业可以取消勾选（取消后该行不在该企业的附注中出现）
- **动态行区**（`dynamic_zone`）：子企业可以在此区域自行添加行（如具体客户名、项目名），但不能在固定行区域新增

每行包含：`row_id`（稳定 UUID）、`label`（行名）、`row_type`（data/total/subtotal）、`category`（required/optional/dynamic_zone）。

### R2：模板下推

合并负责人点击「下推模板」后：

1. 系统遍历企业树的全部数据叶子（子企业项目）
2. 对每家子企业，在 `disclosure_notes` 中为目标章节预生成行骨架：
   - **固定行**：直接写入（行名从模板取，金额为空）
   - **可选行**：写入并标 `optional=true`（子企业可以在附注编辑器中勾选/取消）
   - **动态行区**：在首个合计行之前留一个占位标记 `dynamic_zone_marker`
3. 下推后对该章节自动激活结构锁（固定行不可删改名，动态行区可增删）
4. 子企业附注编辑器对被锁的固定行显示🔒图标，不允许删除和改名操作

### R3：子企业在骨架上工作

子企业打开附注编辑器后看到：
- 固定行（🔒）：行名锁定，只能填金额
- 可选行（☐/☑）：可以勾选/取消
- 动态行区（「➕ 添加行」按钮）：可以新增行，填入行名和金额
- 底稿推送的行：通过公式推送种子填充金额（现有链路不变）

### R4：拉数时行名一致

合并拉数时（明细映射 apply）：
- 固定行：`row_id` 一致（UUID 从模板传到子企业再传回合并），零匹配成本
- 可选行：同上
- 动态行：走现有七级匹配（行名来自子企业自行添加）

**预期效果**：固定行 + 可选行的匹配率从当前 96% 提升到 100%（按 `row_id` 精确匹配），只有真正的动态行需要人工确认。

### R5：模板版本管理与增量更新

- 模板有版本号，每次修改生成新版本
- 集团修改模板后重新下推：只做增量更新（新增行补入、改名行更新名字），不覆盖子企业已填的金额
- 子企业如果已有更新版本之前的行结构，增量合并时标注冲突让合并负责人决策

### R6：降级与兼容

- 子企业不是合并项目的成员（独立项目）→ 不推送，该企业在明细映射中走现有七级匹配
- 子企业附注已有数据且行名与下推的固定行名不一致 → 按别名匹配尝试认同，认不到的提示冲突
- 下推失败（子企业项目不存在、权限不足等）→ 逐家报告失败原因，不影响其他子企业

## 验收标准

- [ ] AC1：合并项目中可以为每个章节创建集团级披露模板（固定行 + 可选行 + 动态行区）
- [ ] AC2：下推后子企业附注章节出现预生成的行骨架，固定行带🔒标记
- [ ] AC3：子企业可以在动态行区新增行，不可以删除或改名固定行
- [ ] AC4：合并拉数时，固定行按 `row_id` 精确匹配，不走模糊匹配
- [ ] AC5：模板新版本增量下推不覆盖子企业已填的金额
- [ ] AC6：下推失败的子企业逐家报告原因
- [ ] AC7：未参与下推的子企业走现有七级匹配，不受影响
