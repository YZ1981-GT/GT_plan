承接 `.agents/tasks/attachment-linkage-assessment-2026-10-27.md` 的 Spec C（用户 2026-10-27「按建议来」）。前置：Spec A（安全底线）、Spec B（底稿证据入口 `workpaper_evidence_intake` / `uploadWorkpaperEvidence` / 行级证据 `evidence_links`）、`attachment-inline-preview`（`RowEvidenceEye` / 覆盖守卫，函证替代程序 5 页在豁免清单里等本 spec）已交付。

## 需求 1　汇总表行与函证附件

1.1 函证汇总表（列表视图）每行显示该笔函证的发函件数 / 回函件数（取函证中心列表接口已有计数，按行上的 `_hub_confirmation_id` 对应；未同步到函证中心的行显示「未同步」）。
1.2 点击计数打开函证附件抽屉（与函证中心同一组件），在底稿内即可挂发函件 / 回函件、预览、识别比对；抽屉里有改动后刷新计数。
1.3 只读（复核 / 已归档）时只能查看，不能挂载、解绑、识别或回填。
1.4 抽屉按挂载记录 id 解绑；上传时间、配对发函件名取接口真实字段（函证中心页同时受益）。
1.5 「同步到函证中心」与保存后的自动同步都要把函证 id 写回行上（`_hub_confirmation_id`），已有台账按 id / 名称 + 类型命中时更新、不重复新建；手动同步写回了 id 而没有未保存改动时随即保存（否则刷新后又是「未同步」），Excel 导入后标未保存。
1.6 「是否收到回函」按三态读：是 / 否 / 未填（前端 `confirmation/replyStatus.ts`，后端 `services/confirmation_reply_flag.py`，同一份可识别写法）。字符串「否」不算已回函；同步到函证中心的状态、带入替代程序的未回函单位、列表「回函」列、回函统计、舞弊风险与差异导入、各循环 Excel 导入导出都按这一口径；未填不当「否」（不带入替代程序）。

## 需求 2　回函识别先识别再比对

2.1 抽屉「识别比对」：附件没有识别文本时，先经平台 OCR 路由（本机优先、服务器兜底）识别原件并把全文写回附件，再抽取比对；识别失败如实报错（服务不可用 / 原件读不到 / 没识别到文字），附件标「识别失败」，不返回任何比对结论。
2.2 识别与比对都不改函证状态；回填仍走现有「确认回填」（人工确认）。
2.3 回函件挂载后不自动识别（识别耗时、可能调外部服务），抽屉里显示「未识别 / 识别中 / 已识别 / 识别失败」与识别按钮。

## 需求 3　替代程序按单据类型识别

3.1 替代程序检查表每行有附件列：编辑态「📎」上传单据，任何状态下有附件都显示小眼睛；上传走 Spec B 入口，附件只挂到本行（行级证据：表页 = 替代程序页编码、单元格 = `row:{行 id}`）。
3.2 上传时选单据类型：银行回单 / 回款单、发票、发运 / 物流单据、对账单（证券 / 往来）、合同 / 协议、记账凭证，或「仅上传，不识别」；各类型按本区块的列给出可识别的项目，只列本区块用得上的类型。
3.3 识别结果逐项列出（列名 / 识别值 / 本行现值），只预选本行为空的列，已有值的列不覆盖；确认后只写这些列，不把整个回执并入行数据。
3.4 修 L0-5 识别路径缺底稿 id，L0-5 与其余 8 页同一套交互。

## 需求 4　跟函、对象核实、差异调节的行级附件

4.1 三处每行可挂附件（Spec B 行级证据），列表可见、可预览、可移除（只移除行链接，附件保留在项目附件里）；只读时只能查看。
4.2 附件类型缺省：跟函 = 审计证据（照片 / 回执），对象核实 = 支持文件，差异调节 = 支持文件。

## 需求 5　函证类型补齐与律师询证函

5.1 函证类型加 legal（律师）、other（其他）；创建 / 更新 / 批量同步只收六个类型（其余 422）；创建、筛选、标签全部中文显示；legal / other 不参与「从底稿导入」候选。
5.2 A12-1 律师询证函：本底稿的律师事务所可登记为函证中心的一笔律师函证（按本底稿 + 类型唯一对应），卡片上显示该笔函证的状态与发函 / 回函件数，并能打开同一附件抽屉；事务所名称改了可一键更新。
5.3 A12-1 声明「律师询证函回函」为应收集证据。

## 需求 6　证据声明按函证逐笔统计

6.1 函证底稿的「函证」证据声明改为按该底稿所在工作簿（同一编码族，如 D0 / D0-1 … D0-8）登记的函证逐笔判定：已回函（有回函件，或状态为已回函 / 相符 / 差异）；未回函但做了替代程序（替代程序页有该函证对象的行且行上有附件）；其余为缺证据，原因分「未发函」（无发函件且状态为待发函）与「未回函且未做替代程序」。缺证据为 0 才算满足；该工作簿没有登记函证时沿用原判定。
6.2 底稿附件抽屉的「应收集证据」显示汇总（共 N 笔：已回函 a、替代程序 b、缺证据 c）与缺证据清单（函证对象名 + 原因）；不阻断编制。
6.3 缺证据时给补救提示：缺口全是律师函（A12-1 没有替代程序页）⇒「请在本底稿「函证中心」卡片上传律师回函」；否则「请在函证中心上传回函，或在替代程序页对应行上传单据」。缺证据清单每项带函证类型。

## 需求 7　验证

7.1 接口测试：抽屉识别在无文本时先识别（OCR 打桩在识别前置函数的下一层）、识别失败不出比对结论；替代程序各单据类型字段抽取、只挂本行；函证类型校验与 legal / other 候选为空；证据声明逐笔判定的四种组合与工作簿族。
7.2 组件测试：汇总表计数与打开抽屉、只读隐藏写操作、按挂载记录 id 解绑；替代程序附件列只读可见、走入口且只回填空字段；跟函 / 对象核实 / 差异调节行级附件；A12-1 卡片登记与只读。
7.3 变异：design §6 逐条，红在预期断言，恢复后 sha256 一致。
7.4 走查：远端线候选树私有前后端 +【测试】项目（汇总表同步、挂发函 / 回函件识别比对、替代程序识别、跟函附件、证据声明、A12-1），数据走平台路径清理对账。

## 勘误（设计阶段复核，2026-10-27）

- 原写「D05 / D06 / F05 / F06 / H05 / K05 / K06 一律调 `d4/contract-ocr`」：D05 / D06 / F05 / F06 没有行级识别；H05 / K05 / K06 / G06 有，但映射键与合同识别回执不匹配（见现状表）。
- 原 5.2 写「每家律师事务所一行」：A12-1 是一封函一张底稿，按底稿对应一笔函证。
- 原 6.1 写「已发函、已回函、替代程序三者都没有才缺证据」，与 6.2 的三分类（已回函 / 替代程序 / 缺证据）矛盾：已发函未回函且未做替代程序同样缺证据，按 6.2 改。
- 新发现：函证附件抽屉解绑按 `att.id` 取值，挂载列表接口只返回 `link_id`（并入需求 1.4，走查时复现）。
- 新发现（实施任务 4）：`syncHubFromSummary` 引的是 `@/utils/http`（返回 AxiosResponse）却按业务数据读 `res.items` / `created.id`，自动同步按 `http.post` 的返回读 `res.hub_ids` ⇒ 两条同步路径都从不写回 `_hub_confirmation_id`，手动同步每次都重复建函证且提示「暂无需要同步」；唯一的单测把桩写成直接返回业务数据，掩盖了它（并入需求 1.5）。

## 走查新发现（任务 11，2026-10-27 ~ 28；处置与证据见 design §8）

- 手动「同步到函证中心」写回了函证 id 却不落库，刷新后计数列又是「未同步」；Excel 导入不标未保存（并入 1.5）。
- 后端时间带 `+00:00` 时区，前端 5 处「没有 Z 就补 Z」拼出非法时间，界面显示 `NaN-NaN-NaN`（并入 1.4）。
- 「是否收到回函」填「否」被当成已回函（字符串真值），同步把函证推成已回函（新增 1.6）。
- 替代程序页公司名称与 A12-1 的 15 个输入框只绑 `:model-value` + `@change`，键入不显示。
- 同一用户另开标签页打开底稿被送回登录页：会话接力回执里的用户对象是响应式代理（`BroadcastChannel.postMessage` 抛 `DataCloneError`），且应用挂载与会话接力并行、路由守卫先判了未登录。
- 编辑页没把只读传给 HTML 渲染器：多窗口编辑锁的横幅写「所有保存已禁用」，页面仍可编辑。
- 律师函缺回函时提示「在替代程序页对应行上传单据」，A12-1 没有替代程序页（新增 6.3）。
