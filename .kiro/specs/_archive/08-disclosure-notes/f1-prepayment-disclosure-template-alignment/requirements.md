# F1 预付款项披露表 ↔ 附注模板对齐 — 需求

## 背景

预付账款（F1）披露分三层：

1. **底稿披露表**：`F1TabDisclosureListed.vue` / `F1TabDisclosureSoe.vue`
2. **同步映射**：`f1DisclosureSyncPayload.ts`（子表名 + `columns`）
3. **附注模板**：`note_template_listed.json` §五、7 / `note_template_soe.json` §八、7

三层权威源（三者互相印证）：

| 源 | 路径 | 权威内容 |
|----|------|---------|
| 底稿源模板 | `基础数据/…/F 存货循环/F1 预付账款.xlsx` 的 `附注披露信息(上市公司)` / `附注披露信息(国企)` | 表清单、列结构、行标签、取数指向 |
| 附注模版 | `基础数据/附注模版/{上市,国企}报表附注.md` §预付款项 | 附注行集合（含 `小计` / `减：减值准备` / `合计`） |
| 校验预设 | `backend/data/note_check_preset_formulas.json` F7-1~F7-14（listed / soe 双份） | 列存在性与勾稽口径（可裁决前两者冲突） |

## 已确认缺陷

### 附注模板（两版）

| # | 位置 | 缺陷 |
|---|------|------|
| N1 | listed §五、7 T1「预付款项按账龄披露」 | 两级表头被压平成 `["账龄","期末余额","上年年末余额"]`（应 5 列：账龄 + 期末余额{金额,比例%} + 上年年末余额{金额,比例%}）；无 `columns` / `_column_groups`；残留 `row_type: header_label` 假数据行 |
| N2 | soe §八、7 T1「预付款项按账龄列示」 | 同 N1（应 5 列：账龄 + 期末数{金额,比例（%）} + 期初数{金额,比例（%）}） |
| N3 | listed §五、7 T3 | 表名叫「单位名称」（实为标签列列头，不是表名）→ TAB 页签显示为列名 |
| N4 | soe §八、7 T3 | **表名与 T2 重复**（都叫「账龄超过1年的大额预付款项」）→ 与同步载荷键 `按欠款方归集的期末余额前五名的预付款项` 错位，形成孤儿子表（附注 TAB 永空 + 底稿数据丢失） |
| N5 | 两版全部 6 张表 | 无 `columns`（列元数据）→ 同步前渲染无列语义 |
| N6 | 两版全部 6 张表 | 无 `guidance`（TAB 页签编制提示） |
| N7 | 两版 T2/T3 | 仅有 `合计` 行，缺源模板的空白明细行骨架（listed T2=3 行 / T3=5 行；soe T2=5 行 / T3=5 行） |

### 底稿披露表

| # | 位置 | 缺陷 |
|---|------|------|
| W1 | listed (1) 账龄表 | `减：减值准备` 被做成表外独立小控件（`impairment-row`），且只有期末一个数 → 与附注 T1 的 `小计`/`减：减值准备`/`合计` 三行结构不同构；F7-7 要求「期末/期初各独立校验」，缺上年年末减值准备 |
| W2 | listed (2) 超1年重要 | 列结构错位：现为 `债务人名称/期末余额/占比/未偿还原因`，源模板与 F7-9(listed) 明确为 `债务人名称/账面余额/占预付款项合计的比例（%）/减值准备`（上市版**无**「账龄」「未结算的原因」列）；`impairment` 字段已存在却未渲染 |
| W3 | soe (1) 账龄表 | 保留源 xlsx 的 7 列（含期末/期初「坏账准备」列），但附注侧为 5 列 + `减：减值准备` 行 → 同步载荷 `columns` 推 7 列会覆盖附注两级结构 |
| W4 | soe (2) 卡片标题 | 写作「账龄超过1年的**重要**预付款项」，源模板与附注均为「账龄超过1年的**大额**预付款项」 |
| W5 | soe (3) 前五名 | 列头「坏账准备」，附注模版与 F7-13(soe) 均为「减值准备」 |
| W6 | 两版 | 源模板括注说明（未及时结算原因 / 按预付对象集中度汇总或分别披露）未作为方法论上下文内嵌 |

### 同步载荷

| # | 位置 | 缺陷 |
|---|------|------|
| S1 | `F1_LISTED_COLUMNS.预付款项按账龄披露` | label 写作 `期末数-金额` 扁平串，未用 `group` → 附注渲染不出两级表头 |
| S2 | `F1_LISTED_COLUMNS.账龄超过1年的重要预付款项` | 第 4 列为 `reason`「未偿还原因」，应为 `impairment`「减值准备」；第 2 列 label 应为「账面余额」 |
| S3 | `F1_LISTED_COLUMNS.单位名称` | 键随附注旧表名，需随 T3 改名迁移并上报 `_removed_table_keys` |
| S4 | `F1_SOE_COLUMNS.预付款项按账龄列示` | 7 列扁平 label，应收敛为 5 列 + `group`；坏账准备聚合进 `减：减值准备` 行 |
| S5 | `F1_SOE_COLUMNS.按欠款方归集的…` | 第 4 列 label「坏账准备」应为「减值准备」 |
| S6 | `buildF1SoeSubTableData` | 账龄表只推 `合计`，缺 `小计` / `减：减值准备`（F7-6/F7-7 无法校验） |
| S7 | 既有测试 | `useF1DisclosureListed.spec.ts` / `useF1DisclosureSoe.spec.ts` 断言 `sheet_name === 'F1-note-listed'/'F1-note-soe'`（陈旧合成标识），实现早已改为真实 tab 名 → 2 个**预存在失败** |

## 需求

### R1 附注模板结构对齐（幂等脚本 + 契约测试）

- **R1.1** listed §五、7 / soe §八、7 的 T1 恢复 5 列两级表头（`headers` 叶子列 + `columns[].group` + `_column_groups`），删除 `header_label` 假行。
- **R1.2** listed T3 改名为「按预付对象归集的预付款项期末余额前五名单位情况」；soe T3 改名为「按欠款方归集的期末余额前五名的预付款项」（消重名）。
- **R1.3** 6 张表全部补 `columns`（键与同步载荷逐字一致）。
- **R1.4** 6 张表全部补 `guidance`，内容只取源模板括注 / 附注模版说明，或以「勾稽：」前缀标注的 F7-* 校验口径。
- **R1.5** T2/T3 补空白明细行骨架（行数取源模板）。
- **R1.6** 修订以幂等脚本 `backend/scripts/fix/fix_note_prepayment_structure.py` 实施，支持 `--dry-run` / `--check`，打 `_aligned_by` 标记；结构自洽校验（列数一致 / 分组不越界不重叠 / 表名唯一 / 无 `header_label`）。

### R2 底稿上市披露表对齐

- **R2.1** (1) 账龄表把 `小计` / `减：减值准备` / `合计` 并入表内为行，`减：减值准备` 的期末与上年年末两格均可编辑；删除表外 `impairment-row` 小控件。
- **R2.2** (2) 超1年重要表列结构改为 `债务人名称 / 账面余额 / 占预付款项合计的比例（%）/ 减值准备`；`减值准备` 可编辑并入合计。
- **R2.3** 「未及时结算原因」不再占列（上市版模板无此列），改为行展开区（`el-table type="expand"`）录入，并提供「据此生成说明」按钮把各债务人原因汇编进 (2) 的说明文本框。
- **R2.4** 内嵌源模板括注为方法论上下文块（琥珀色左边线 + 浅黄背景）。

### R3 底稿国企披露表对齐

- **R3.1** (1) 账龄表保留源 xlsx 的期末/期初「减值准备」列（列头由「坏账准备」改为「减值准备」，与附注模版口径一致），并新增 `小计` / `合计` 行；同步时按 5 列附注结构投影，逐段减值准备聚合为 `减：减值准备` 行、`合计 = 小计 − 减：减值准备`。
- **R3.2** (2) 卡片标题改为「账龄超过1年的大额预付款项」。
- **R3.3** (3) 前五名列头「坏账准备」→「减值准备」。
- **R3.4** 内嵌源模板方法论上下文块。

### R4 同步载荷契约

- **R4.1** listed / soe T1 的 `columns` 带 `group`，`_column_groups` 由后端 `_extract_column_groups` 产出两级表头。
- **R4.2** 单级表头的表（T2/T3）在标签列标 `flat: true`，抑制后端前缀反猜父表头。
- **R4.3** listed 载荷上报 `_removed_table_keys: ['单位名称']`，且不含本次推送的键。
- **R4.4** soe 账龄子表推 `各账龄段 + 小计 + 减：减值准备 + 合计` 四类行。
- **R4.5** 子表名与 `note_template_*.json` 的 `tables[].name` 逐字一致；`columns[0].label` 与 `headers[0]` 一致。

### R5 账龄枚举（3年段 / 5年段 / 自定义）

- **R5.1** 两版账龄表行集合随 `useF1AgingScope` 生效段动态生成（表级覆盖 > 项目配置 > 科目默认 THREE_YEAR），不硬编码四档。
- **R5.2** 附注模板 seed 骨架保持源模板默认 3 年段四档（F1 默认 `THREE_YEAR`）；同步时整表覆盖行 → 5 年段/自定义自动生效。
- **R5.3** 账龄标签：上市 `1年以内/1至2年/2至3年/3年以上/3至4年/4至5年/5年以上`；国企首档 `1年以内（含1年）`；自定义段回退 `segment.label`。
- **R5.4** soe (2) 超1年行的账龄下拉选项排除首档、随生效段联动（已实现，加测试锁定）。

### R6 测试与回归

- **R6.1** 后端 `backend/tests/services/test_note_prepayment_structure.py`：锁 6 张表名 / 列数 / `_column_groups` / `guidance` / 无 `header_label` / `--check` 通过。
- **R6.2** 前端 `f1NoteSubtableContract.spec.ts`：子表名逐字对齐 note_template、`columns[0].label === headers[0]`、`headers` 无空串、两级表头齐备、全表 guidance。
- **R6.3** 修正 S7 两个陈旧断言（改断言真实 tab 名）。
- **R6.4** `f1DisclosureColumns.spec.ts` 更新为新列契约。
- **R6.5** Playwright 实测：两版披露表编辑 → 同步 → 附注 §五、7 / §八、7 TAB 数与两级表头正确。

## 非目标

- 不改 F1-1 审定表 / F1-2 明细表 / F1-4 / F1-5 结构。
- 不改 `note_check_preset_formulas.json`（它是裁决依据，不是修订对象）。
- 不为既有项目回填 `disclosure_notes.table_data._tables`（生成时快照，仅新建项目 / 重新生成附注生效）。
