# D1 应收票据披露表与附注对齐 — 需求

## 背景

D1（应收票据）已有完整的披露 Tab（`D1TabDisclosure.vue`，`variant='listed'|'soe'` 双版）
与同步链路（`buildD1SyncPayload` 覆盖上市 14 张 / 国企 12 张子表 + `_note_texts` + 自动同步）。
但按源模板 `backend/wp_templates/D/D1 应收票据.xlsx` 的两个披露 sheet
（`附注披露信息（上市公司）` / `附注披露信息（国企）`）逐格核对后，发现三类欠账：

1. **模板 JSON 侧**：`note_template_listed.json` 五、4 与 `note_template_soe.json` 八、4
   共 26 张表 **全部 `columns=null`（未表态）+ 全部无 `guidance`**，且 `headers` 被
   md 重建脚本压扁成单级（源模板多处是两级表头）。
2. **底稿披露表侧**：上市版**完全缺失**「组合计提项目：银行承兑汇票 / 商业承兑汇票」
   两张表的录入界面（源模板 R76~R89），单项计提明细行也缺「计提依据」列 →
   附注对应 3 张表恒为空骨架；另有固定行/列名与源模板不符。
3. **同步载荷侧**：部分 `group` 名与源模板/UI 不一致（国企主表、上市组合表），
   国企转回表把数值列绑成文本字段。

## 权威源与裁决

| 源 | 角色 |
|---|---|
| `backend/wp_templates/D/D1 应收票据.xlsx` | 运行时权威，列结构/行骨架/父表头/提示文字 |
| `note_check_preset_formulas.json` 的 `F4-*`（应收票据） | 勾稽与列语义裁决者 |
| `note_template_{listed,soe}.json` 五、4 / 八、4 | 附注交付形状（本 spec 修订对象） |

裁决要点：

- 源模板主表把期间标签写了两遍（父表头「期末余额」下子列也叫「期末余额」）。
  按预设 `F4-3a`（账面余额 − 坏账准备 = 账面价值）取子列名
  **账面余额 / 坏账准备 / 账面价值**，父表头保留期间名。
- 平台只支持**两级**表头（`ColumnDef.group` → `_column_groups`，前端
  `DisclosureEditor.activeTableColumns` 只认扁平 `{group,start,span}`，树形会崩）。
  国企分类表源模板是三级（期末数 > 账面余额 > 金额），顶层期间已在表名里
  （`（期末数）`/`（续：期初数）`），故只保留下两级。
- **同表并列双期 → `group`；拆表双期 → `flat`**（期间已在表名中，单组跨全部数据列
  不携带分组信息，且必须显式 `flat` 抑制 `_infer_groups_from_headers` 前缀推断）。
- 上市核销逐项表源模板第 2 列字面是「应收票据」，预设 `F4-29` 明确为
  「应收票据性质」→ 取预设。
- 坏账准备变动公式取源模板（期初 + 计提 − 收回或转回 − 核销 − 其他变动 = 期末），
  预设 `F4-7` 的「+ 其他变动」是从应收账款泛化复制而来，不采纳。

## 需求

### R1 模板 JSON 列结构与提示齐备

- **R1.1** 五、4 的 14 张表、八、4 的 12 张表每张都有 `columns`，且在 `group` 与
  `flat` 之间明确表态；`headers` = 各列叶子 label；两级表头的表同时写
  `_column_groups`（与 `columns.group` 派生结果一致），单级表头的表删除 `_column_groups`。
- **R1.2** 每张表有 `guidance`，内容只取源模板红字 / 附注括注 / 15 号文条款，
  或以「勾稽：」前缀标注的 `F4-*` 预设，不自造披露口径。
- **R1.3** 行骨架对齐源模板；删除被压扁成 `row_type: header_label` 的假数据行。
- **R1.4** 修订以幂等脚本落地（`--dry-run` / `--check` / `_aligned_by` 标记），
  禁止手改 JSON；`--check` 挂 CI。

### R2 底稿披露表结构对齐源模板

- **R2.1** 上市版补「组合计提项目：银行承兑汇票」「组合计提项目：商业承兑汇票」
  两张录入表：名称列按项目账龄段枚举点选（允许自定义出票人类型），
  期末余额 / 上年年末余额 双期并列各 3 列（应收票据 / 坏账准备 / 预期信用损失率(%)），
  支持「按账龄段生成」（双期成对生成）与命名后新增行。
- **R2.2** 上市版分类表（期末 / 上年年末）补「计提依据」列（仅单项明细行可编辑），
  补父表头「期末余额」/「上年年末余额」，列名对齐源模板
  （账面余额 → 金额、损失率(%) → 预期信用损失率(%)）。
- **R2.3** 「期末因出票人未履约而其转（为）应收账款的票据」固定行只保留
  「商业承兑票据」（源模板与模板 JSON 均只列商业承兑）；两版都支持增删行。
- **R2.4** 质押 / 背书贴现 / 转应收账款三表的固定行名用「银行承兑票据 / 商业承兑票据」
  （与源模板、模板 JSON 逐字一致）；首列表头为「种类」；
  上市版金额列补「期末」前缀（期末终止确认金额 / 期末未终止确认金额 / 期末转应收账款金额）。
- **R2.5** 国企组合计提表小计行名为「商业承兑汇票小计：」「银行承兑汇票小计：」。
- **R2.6** 国企转回表列名为「转回或收回原因、方式」；
  「转回或收回前累计已计提坏账准备金额」改为金额录入并进合计行。

### R3 同步载荷与模板逐字一致

- **R3.1** 每张子表名与模板 `tables[].name` 逐字一致，标签列头 = 该表 `headers[0]`。
- **R3.2** `group` 名与源模板一致：国企主表 `期末数`/`期初数`；
  上市组合表 `期末余额`/`上年年末余额`；上市分类表按期间分组；
  国企分类表 `账面余额`/`坏账准备` + `账面价值` 单列；
  国企变动表 `本期变动情况`。
- **R3.3** 拆表双期与单期表显式 `flat`。
- **R3.4** 国企转回表 `cumulative_provision` 为 `amount` 格式并取新的数值字段。

### R4 契约与实测

- **R4.1** 接入 `runDisclosureSubtableContract`（5 条 Property：表名逐字 / 章节存在 /
  group·flat 表态 / 标签纯文本 / 标签列头对齐）。
- **R4.2** 后端结构测试锁死 R1（表名齐备唯一、columns 表态、`_column_groups` 自洽、
  guidance 齐备、无 `header_label`）。
- **R4.3** 浏览器实测：上市 + 国企两个披露 Tab 录入 → 点「同步到附注」→
  附注 五、4 / 八、4 的 TAB 数、表头层级、文本框内容与披露表一致。

## 非目标

- 不改附注渲染机制（两级表头唯一机制 = `ColumnDef.group` → `_column_groups`）。
- 不做 legacy 快照迁移（既有项目的 `_tables` 是生成时快照，改模板只对
  新建项目 / 重新生成附注生效；存量靠底稿「同步到附注」整表覆盖）。
- 不动 `applicable_standards` 前端全链缺失问题（跨前后端 schema 变更，另有 spec）。

# 第二阶段：实测暴露的既有缺陷修复

第一阶段（结构对齐）浏览器实测时暴露 9 项既有缺陷，均非本 spec 引入，但其中 3 项会
持续污染附注数据、7 个 AI 按钮完全空转。本阶段逐一收口。

## R5 坏账分类表比率列必须可推导、不可漂移

- **R5.1** 「比例(%)」= 该行账面余额 ÷ **合计行**账面余额 × 100（预设 `F4-25`），
  合计行恒为 100。禁止把比率持久化后跨行相加 —— 实测「按组合计提坏账准备」行
  显示 162.50%（商承录入时分母 30 万 → 1.0，银承录入时分母 80 万 → 0.625，相加 1.625）。
- **R5.2** 「预期信用损失率(%)」= 坏账准备 ÷ 账面余额 × 100（预设 `F4-12`）。
  国企分类表「按组合计提坏账准备」行的该值当前硬编码 0，实测附注显示 `-`。
- **R5.3** 「账面价值」= 账面余额 − 坏账准备（预设 `F4-11`）。
- **R5.4** 三个派生列一律**读时推导**（单一真源 = 用户录入的 账面余额 / 坏账准备），
  不再依赖持久化值；导入路径写进来的旧值同样被推导覆盖。
- **R5.5** 国企组合计提表（账龄行）小计与合计行的损失率同样按 R5.2 推导。

## R6 AI 辅助必须真正可用

- **R6.1** 请求体字段与后端 `AiGenerateRequest` 一致（`section_id` / `related_data` /
  `existing_content`）；响应按 `generated_text` 读取。当前 D1 发的是 `section` / `context`
  → 必然 422，被 `catch` 吞成「AI生成失败」；披露 5 个 + 审定表 2 个按钮全部空转。
- **R6.2** 后端按 `section_id` 提供 D1 披露专属 prompt：每条 ≥20 字，写明源模板 /
  15 号文口径 + 「不得虚构」约束（铁律：prompt 过短会诱导自造披露内容）。
- **R6.3** 新增 section 必须同时登记后端 prompt 表与前端子节键，并有参数化测试守住
  「每个前端会发出的 section_id 都有专属 prompt」。

## R7 校对附注必须比对同一张表

- **R7.1** 「校对附注」定位主表（`应收票据` / `应收票据分类`）的合计行，
  取「期末账面价值」与本页主表期末账面价值比较。当前 `pickNoteTotal` 遍历所有表取
  第一个非零数，实测抓到「期末已质押的应收票据」合计 80000 → 误报差异。
- **R7.2** 本页主表未取数（审定表 D1-1 未加载）时提示「本页主表未取数」，
  不得报成数据不一致。

## R8 平台级数值格式单一真源

- **R8.1** 披露表只读金额走 `stores/displayPrefs` 的 `fmtAmount()`（千分符 + 2 位小数 +
  默认「元」+ localStorage 持久化）。当前 `D1TabDisclosure` 是 D1 十六个 Tab 里唯一
  自带 `fmtAmt` 的。
- **R8.2** 比率列统一 `fmtPct`（内部存分数，展示乘 100）。

## R9 国企坏账变动表「其中：」下可录明细

- **R9.1** 「按组合计提预期信用损失的应收票据」下的「其中：」可新增/删除命名明细行，
  各行 6 个变动列可录入，期末数按 `期初 + 计提 − 收回或转回 − 核销 − 其他变动` 推导。
- **R9.2** 「其中：」下明细行之和 = 按组合计提行（预设 `F4-20`）：有明细时按组合计提行
  改为汇总只读。
- **R9.3** 明细行随同步推入附注 八、4 的变动表（插在「其中：」之后），保持行序。

## R10 披露内部勾稽校验面板

- **R10.1** 新增纯函数引擎，覆盖源模板/预设**可判定**的勾稽：
  `F4-3`（主表明细和 = 合计）、`F4-3a`（账面余额 − 坏账准备 = 账面价值）、
  `F4-8/9/10`（主表合计 = 分类表合计，三列）、`F4-11/12/25`（分类表纵向）、
  `F4-4/5`（分类表单项/组合行 = 明细小计）、`F4-6`（分类表坏账准备 = 变动表期末）、
  `F4-7`（变动表逐行平衡）、`F4-19/20`（变动表纵向与「其中：」）、
  `F4-21/22/23/24`（质押/背书/转应收/核销各表明细和 = 合计）、
  核销金额 = 变动表「本期核销」。
- **R10.2** 相等类容差 0.01 元；返回 `{label, rule, left, right, diff, level, detail, refs}`。
- **R10.3** 展示为紧凑单行 bar + 折叠明细表 + 规则 tooltip + `GtIndexChip` 追溯，
  两个变体各自适用的规则集不同（上市无国企变动表多列、国企无上市双期明细表）。

## R11 关键披露项支持附件与 OCR

- **R11.1** 核销（履行的核销程序）、质押、背书贴现三处支持 📎 附件上传，
  复用平台既有底稿附件通道，附件与底稿 sheet 绑定。
- **R11.2** 不新建上传后端；沿用 `useWpAttachments` 式既有能力，缺失则只做入口不造服务。

## R12 导入导出覆盖全部录入面

- **R12.1** 导出模板 / 导出数据 / 导入数据覆盖上市「组合计提项目：银行/商业承兑汇票」
  双期明细与国企「转回或收回前累计已计提坏账准备金额」。
- **R12.2** 列名与界面、附注模板三方一致（`期末终止确认金额` 而非 `终止确认金额`；
  `预期信用损失率(%)` 半角括号）。
- **R12.3** 后端镜像的前端常量用读 `.ts` 源码的正则契约测试守住，防双真源漂移。
