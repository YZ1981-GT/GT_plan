# Requirements Document

N1 递延所得税资产披露表与附注对齐

## Introduction

把 N1 递延所得税资产的**三层披露链路**（底稿披露组件 / 同步映射 / 附注模板 JSON）
全部对齐致同 2025 修订版源模板 `N1 递延所得税资产.xlsx` 的两张披露 sheet，
并让底稿披露表的内容能真实推送到附注 §五、30（上市）/ §八、31（国企）。

范围覆盖：底稿两个披露 Tab 按源模板重建（上市 4 表 / 国企 5 表，含两级表头与分段小计）、
披露内部勾稽校验、附注模板结构幂等修订（列压扁与缺表修复 + `columns` 表态 + `guidance`
+ `text_sections`）、同步载荷重写、契约守卫与实测验收。

## Glossary

| 术语 | 含义 |
|------|------|
| 表 1 / 表（1） | 源模板「未经抵销的递延所得税资产和递延所得税负债」（两级表头 5 列） |
| 子列序 | 表 1 两级表头下的两个子列顺序；🔴 上市与国企在源模板里**相反** |
| 分段 | 表 1 / 国企表 2 内部的「递延所得税资产段 / 递延所得税负债段」，各段末置小计 |
| 互抵明细 | 国企源模板（2）B「递延所得税资产和递延所得税负债互抵明细」（2 列），原整张缺失 |
| `flat` 三态 | `ColumnDef.flat`：`None`=未声明（后端回退前缀推断）/ 任一列带 `flat`=显式单级 / 有 `group`=显式分组 |
| `guidance` | 附注 `tables[].guidance`，渲染为附注模块 TAB 页签的编制提示 |
| seed 路径 | 新建项目 / 重新生成附注时用模板骨架生成 `table_data` |
| 投影路径 | `_source=workpaper` 记录读取时由 `note_sub_table_projector` 把 `sub_table_data` 投影成 `_tables` |

## Requirements

### 背景

`N1 递延所得税资产.xlsx` 有两张披露 sheet（`附注披露信息（上市公司）` A1:K54 / `附注披露信息（国企）` A1:IV74）。
2026-07-30 逐 sheet 精读源模板后与三层现状（底稿披露组件 / 同步映射 / 附注模板 JSON）比对，发现**三层全部偏离源模板**：

### 现状缺陷（实证）

**层一：底稿披露组件（自造结构，源模板一张表都没对上）**

| 源模板（上市 4 表） | `N1TabDisclosureListed.vue` 现状 |
|---|---|
| （1）未经抵销的递延所得税资产和递延所得税负债 —— 两级表头 5 列（项目 + 期末余额{可抵扣/应纳税暂时性差异, 递延所得税资产/负债} + 上年年末余额{同}）；行 = 资产段标题 + 7 项 + 小 计 + 负债段标题 + 5 项 + 小计 | 「一、已确认递延所得税资产明细」7 列自造（可抵扣暂时性差异/适用税率/期初余额/本期确认/本期转回/期末余额）；**无两级表头、无负债段、无分段小计** |
| （2）以抵销后净额列示的递延所得税资产或负债 —— 5 列 | **完全缺失** |
| （3）未确认递延所得税资产的可抵扣暂时性差异及可抵扣亏损明细 —— 3 列 + 合 计 | 「三、」4 列自造（可抵扣暂时性差异·可弥补亏损 / 未确认递延税资产 / 未确认原因）；**无双期、无合计** |
| （4）未确认递延所得税资产的可抵扣亏损将于以下年度到期 —— 4 列（年 份/期末余额/上年年末余额/备注）+ 合 计 | 「四、」4 列自造（到期年度/不确认金额/上期不确认金额/不确认原因）；**无合计** |
| 说明 R30 / 提示 R31 R32 / 注 R43 / 注 R53 | **全无** |
| 勾稽 R54：表（3）「可抵扣亏损」行 = 表（4）合 计 | **无** |
| —— | 「二、递延所得税资产余额变动表」**源模板无此表** |
| —— | 「五、与 N3 递延所得税负债对应关系」**源模板无此表** |

国企侧同理：源模板 **5 张表**（多一张「（2）B、递延所得税资产和递延所得税负债互抵明细」2 列），
现有 `N1TabDisclosureSoe.vue` 是 6 个自造 section（含账面价值/计税基础/确认依据等源模板披露 sheet 没有的审计过程列）。

**层二：附注模板 JSON**

| 项 | listed 五、30 | soe 八、31 |
|---|---|---|
| 表 1 列 | 3 列（应 5 列两级） | 3 列（应 5 列两级） |
| 表 1 残留假数据行 | `{label:"项目", row_type:"header_label"}` | 同 |
| 表 2 列 | 5 列 ✓ | **3 列（应 5 列）** + 假数据行 |
| 缺表 | —— | **缺「递延所得税资产和递延所得税负债互抵明细」** |
| `columns` 表态 | 4 表全 0（既无 `group` 也无 `flat`） | 4 表全 0 |
| `guidance` | 全无 | 全无 |
| `text_sections` | 表标题为无 `#` 前缀纯文本 → 被当正文；缺 R31/R32/R43/R53 | 用 `### ` 前缀 ✓ 但缺前置披露口径说明 |

表 1 / 表 2 的列压扁 + `header_label` 假数据行是 `rebuild_note_from_md.py` 已知的多级表头压扁 bug 的签名。

**层三：同步映射 `n1NoteSectionMap.ts`**

- `twoPeriodColumns()` 给表 1 推 3 列 → 跟随了压扁后的模板
- `netOffsetColumns('soe')` 返回 3 列 → 国企表 2 结构性错误
- 只覆盖 4 张表 → 国企第 5 张表（互抵明细）无同步入口

## 需求

### R1 底稿披露表按源模板重建（上市）

**用户故事**：作为审计助理，我在 N1 底稿的「附注披露信息（上市公司）」页要看到与致同源模板逐字一致的 4 张披露表，这样我填的内容才能直接作为附注交付物。

1.1 表（1）渲染两级表头 5 列：标签列 `项  目`；父表头 `期末余额`（跨 2）/ `上年年末余额`（跨 2）；子列 `可抵扣/应纳税暂时性差异`、`递延所得税资产/负债`（**上市子列序：暂时性差异在前**）。
1.2 表（1）行骨架 = 源模板：`递延所得税资产：`（分组标题）+ 7 项（资产减值准备 / 可抵扣亏损 / 内部交易未实现利润 / 公允价值变动 / 租赁负债 / 购入摊销年限小于税法规定的资产 / 其他）+ `小 计`；`递延所得税负债：`（分组标题）+ 5 项（购入摊销年限大于税法规定的资产 / 可供出售金融资产公允价值变动 / 投资性房地产公允价值变动 / 使用权资产 / 其他）+ `小计`。两段均支持动态增行。
1.3 表（2）以抵销后净额列示 —— 5 列（项  目 / 递延所得税资产和负债期末互抵金额 / 抵销后递延所得税资产或负债期末余额 / 递延所得税资产和负债期初互抵金额 / 抵销后递延所得税资产或负债期初余额），2 行（递延所得税资产 / 递延所得税负债）。
1.4 表（3）3 列（项  目 / 期末余额 / 上年年末余额），行 = 可抵扣暂时性差异 / 可抵扣亏损 / `合  计`（公式行）。
1.5 表（4）4 列（年  份 / 期末余额 / 上年年末余额 / 备注），行 = 逐到期年度 + `合  计`；年度行支持增删。
1.6 表（1）下方保留源模板 R30 说明文本框（可编辑，缺省文案取源模板）与 R31/R32 两条提示（只读方法论上下文）。表（3）下方注 R43、表（4）下方注 R53 作只读提示。
1.7 金额只读展示走 `displayPrefs.fmtAmount`；可编辑金额走 `WpAmountInput`（`el-input` 承载千分符）。

### R2 底稿披露表按源模板重建（国企）

2.1 前置口径说明（源模板 R7）：不以抵销后净额列示按（1）披露，以抵销后净额列示按（2）披露 —— 作为方法论上下文置顶。
2.2 表（1）A、已确认递延所得税资产和递延所得税负债 —— 两级表头 5 列，父表头 `期末余额` / `年初余额`；**子列序与上市相反**：`递延所得税资产/负债` 在前、`可抵扣/应纳税暂时性差异` 在后。行骨架同 R1.2，但分组标题为 `一、递延所得税资产` / `递延所得税负债：`，负债段第 4 项为 `租赁形成`（上市为 `使用权资产`）。
2.3 表（2）A、互抵后的递延所得税资产或负债及对应的互抵后可抵扣或应纳税暂时性差异 —— 5 列单级（项  目 / 报告期末互抵后的递延所得税资产或负债 / 报告期末互抵后的可抵扣或应纳税暂时性差异 / 报告年初互抵后的递延所得税资产或负债 / 报告年初互抵后的可抵扣或应纳税暂时性差异）；行 = `一、递延所得税资产` + 7 项 + `小 计` + `二、递延所得税负债` + 5 项 + `小 计`。
2.4 表（3）B、递延所得税资产和递延所得税负债互抵明细 —— 2 列（项  目 / 本期互抵金额），支持动态增行。
2.5 表（4）未确认递延所得税资产明细 —— 3 列（项  目 / 期末余额 / 年初余额）+ `合  计`。
2.6 表（5）未确认递延所得税资产的可抵扣亏损将于以下年度到期 —— 4 列（年  份 / 期末余额 / 年初余额 / 备注）+ `合  计`。
2.7 提示 R30 / 注 R31 / 注 R73 作只读上下文。

### R3 披露内部勾稽校验

3.1 表（1）资产段 `小 计` = 段内各项之和；负债段 `小计` 同理（源模板 `=SUM(B13:B20)` / `=SUM(B23:B28)`）。
3.2 表（3）`合  计` = 可抵扣暂时性差异 + 可抵扣亏损（源模板 `=B39+B40`）。
3.3 表（4）`合  计` = 各年度之和（源模板 `=SUM(B46:B51)`）。
3.4 跨表勾稽：表（4）`合  计` = 表（3）「可抵扣亏损」行（源模板 R54 `=B40=B52` / `=C40=C52`），期末与上年年末/年初两列各校验一次。
3.5 国企额外：表（2）资产段 `小 计` / 负债段 `小 计` = 段内各项之和。
3.6 校验结果用紧凑单行 bar + 可折叠明细表呈现，每条给出规则说明与 `GtIndexChip` 追溯（范式沿用 `H1DisclosureConsistencyPanel`）。容差 0.01 元。

### R4 附注模板 JSON 结构修订

4.1 listed 五、30 表 1 恢复 5 列 + `_column_groups`（`期末余额` start=1 span=2 / `上年年末余额` start=3 span=2），删 `header_label` 假数据行。
4.2 soe 八、31 表 1 恢复 5 列 + `_column_groups`（`期末余额` / `年初余额`），子列序按国企源模板（资产/负债在前），删假数据行。
4.3 soe 八、31 表 2 从 3 列恢复为 5 列单级，行骨架补齐资产段/负债段明细 + 小计（对齐表 1 行集合），删假数据行。
4.4 soe 八、31 新增表「递延所得税资产和递延所得税负债互抵明细」（2 列），插在表 2 之后。
4.5 两版全部表补 `columns`（单级标 `flat`、两级标 `group`），使 seed 路径不被 `_infer_groups_from_headers` 塞凭空父表头。
4.6 两版全部表补 `guidance`（TAB 页签编制提示）—— 内容只许取源模板红字/括注、附注模板既有【提示】【注】、以「勾稽：」前缀标注的工具侧校验口径，禁止自造披露要求。
4.7 `text_sections` 修订：表标题统一 `#### ` 前缀（避免被当正文），补齐源模板实质披露文本（listed R30/R31/R32/R43/R53；soe R7/R30/R31/R73）。
4.8 **行集合不动原则**：两版表 1 的明细行标签保持附注模板既有（md 派生）集合，不改成源 xlsx 的行名 —— 附注是交付物、行骨架仅为初始骨架，同步时由底稿整表覆盖。仅国企表 2 因原为 2 行简写而按表 1 行集合补齐骨架。
4.9 修订必须是幂等脚本（`--dry-run` / `--check` / `_aligned_by` 标记），禁止手改 JSON（下次 `rebuild_note_from_md.py` 会覆盖）。

### R5 同步映射与推送

5.1 `n1NoteSectionMap.ts` 的 `columns` 与源模板/附注模板逐字一致：表 1 两级（`group`）、其余单级（`flat`）。
5.2 覆盖国企 5 张表（含互抵明细）。
5.3 `sub_table_data` 与 `columns` 键集合恒等；子表名逐字取自附注模板 `tables[].name`。
5.4 结构行（分组标题 / 小计 / 合计）随载荷推送，`is_total` 标注到位；行型判定先去空白（源模板写的是 `小 计`、`合  计`）。
5.5 取不到的金额写 `null`（禁 0 冒充）。
5.6 表名变更（国企新增表、无重命名）时按 `disclosureSyncedTables` 机制上报 `_removed_table_keys`，同步成功后才 `markSynced`。
5.7 两个披露 Tab 均接 `useDisclosureAutoSync`（编辑防抖自动同步），并保留手动「同步到附注」按钮。

### R6 契约与守卫

6.1 接入共享 helper `runDisclosureSubtableContract`（5 条 Property）。
6.2 新增 `n1NoteSubtableContract.spec.ts`：子表名逐字、`_column_groups` 齐备、全表 guidance 非空、headers 无空串、双向键集（模板表名 ⊆ 映射值 且 映射值 ⊆ 模板表名）。
6.3 后端 `test_note_deferred_tax_structure.py`：表数/列数/`_column_groups`/`columns` 表态/guidance/text_sections 前缀/幂等（重跑逐字节相等）。
6.4 `build*Columns` 登记 `disclosureColumnsCoverage.spec.ts` 的 `P1_ROUTE`。
6.5 勾稽引擎纯函数单测 + PBT。
6.6 CI 挂 `--check`。

### R7 实测验收

7.1 Playwright/chrome-devtools 实测：两个披露 Tab 渲染真两级表头（父表头文案不串味）、勾稽 bar 正确、编辑触发自动同步。
7.2 postgres 只读比对 `disclosure_notes` 落库：`sub_table_data` 键数、`_sub_table_columns`、`_last_sync_at` 变化。
7.3 交付说明必须写清：改模板 JSON 只对**新建项目 / 重新生成附注**生效；既有项目须由底稿「同步到附注」整表覆盖。

## 非目标

- 不改附注表名（除国企新增表）：改名会产生孤儿表且收益低；措辞差异（源 xlsx「不以抵销后的净额列示」vs 附注「未经抵销的…」）以附注模板为准。
- 不改 listed 表 2 的 `上年年末` 措辞为源 xlsx 的 `期初`：附注全节统一用 `上年年末`，源 xlsx 表 2 用「期初」属其内部不一致。
- 不动 N1-1~N1-5 审计过程底稿（现有自造披露列中属审计过程的内容留在 N1-2/N1-4，不搬进披露表）。
- 不接 `applicable_standards` gating（前端全链缺失，属跨前后端 schema 变更，已另有记录待立 spec）。
