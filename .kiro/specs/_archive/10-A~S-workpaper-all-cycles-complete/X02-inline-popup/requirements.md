# 子底稿弹窗式联动 — 需求文档

## 概述

A1 程序表中引用的子底稿（A1-11/A1-12/A1-17/A1-18）不再独立打开为全屏页面，而是在 A1 程序表对应步骤旁以弹窗形式展示内容+完成操作。体现审计程序的关联性和联动性。

## 设计原则

- 需要时才弹窗，而非平开列示
- 弹窗内可完成操作（填写/签字/标记），无需跳转
- 弹窗完成状态回显到 A1 程序表（如已完成标绿）

## 涉及底稿

### A1-11 业务报告签发流转控制表
- **内容**：签字审批链（项目经理→合伙人→质控复核人→IT/税务专家→翻译复核人），每人一行（姓名+日期）
- **文号规则 sheet 不纳入**（由独立系统负责）
- **弹窗触发点**：A1 程序表第 14 步（"草拟一份恰当的审计报告"）
- **弹窗内容**：签字审批链表格，各审批人签字+日期填写
- **联动**：签字完成后 A1 程序表对应步骤标记已完成

### A1-12 重大事项决定程序的履行情况核查表
- **内容**：14 条需提交专业技术委员会讨论的情形（序号+描述+是否适用+索引号）+ 第二部分自由填写区
- **适用范围**：仅审计业务；适用于 A/B 类业务 + 执行 A/B 类复核流程的 C 类 + 存在专业分歧需专委会审核的 C 类
- **弹窗触发点**：A1 程序表第 15 步（"完成重大会计、审计事项决定程序的履行情况检查表"）
- **弹窗内容**：
  - 头部：业务分类标记（自动从 project.business_category 读取）+ 是否首次承接
  - 主体：14 条适用性判断（是否适用 下拉 + 索引号填写）
  - 底部：重大业务咨询/分歧事项 自由文本区
- **智能联动**：
  - 根据 business_category 自动提示是否需要填写（C 类非特定情形提示"本表不适用"）
  - 条目中引用的业务报告类型(A1~A8)可关联项目报告类型判定

### A1-17 对应数据程序表
- **内容**：3 个审计程序步骤（对应数据的考虑事项：保留意见影响/未解决事项影响/重大错报影响）
- **弹窗触发点**：A1 程序表第 6 步（"追踪比较数字到以前年度财务报表"，旁边标有 A1-17）
- **弹窗内容**：3 个程序步骤 + 是否适用 + 执行说明
- **联动**：3 步全部完成后 A1 程序表第 6 步标记已完成

### A1-18 采用新金融工具准则衔接影响数核对
- **内容**：混合型底稿 = 审计目标(文本) + 审计过程(5步) + 3个调节表(权益/分类/权益工具投资明细) + 审计说明 + 审计结论
- **弹窗触发点**：与金融工具相关的审计程序步骤（或从底稿列表点击）
- **弹窗内容**：
  - Tab 1：审计目标 + 5步审计过程（程序表形式）
  - Tab 2：表一 权益调节表（7项×留存收益/其他综合收益 两列）
  - Tab 3：表二 分类调节表（原分类→新分类映射 × 金额列）
  - Tab 4：表三 权益工具投资明细表
  - Tab 5：审计说明 + 审计结论（富文本）
- **联动**：调节表金额可从序时账金融工具科目(1101/1501/1503等)取数

## 功能需求

### 1. 弹窗组件框架
- 1.1 在 GtAProgramConsole 中，检测程序步骤关联的子底稿 wp_code
- 1.2 子底稿链接（如 "A1-17" 标签）点击时弹出 el-dialog 而非路由跳转
- 1.3 弹窗大小自适应内容（小型如 A1-17 用 600px，大型如 A1-18 用 80% 宽度）
- 1.4 弹窗内加载对应子底稿内容组件

### 2. 子底稿内容渲染
- 2.1 A1-11：签字审批链表格（姓名+日期输入框 × N 行审批人）
- 2.2 A1-12：适用性核查列表（14 条 + 自由文本区）
- 2.3 A1-17：程序步骤卡片（3 条，每条有适用/执行说明/状态）
- 2.4 A1-18：Tab 式多面板（程序+调节表+结论）

### 3. 状态持久化
- 3.1 弹窗内填写的数据保存到 checklist_responses 表（复用 A1-15/A1-16 的 UPSERT 机制）
- 3.2 item_id 格式：`{wp_code}-{seq}`（如 A1-17-001、A1-12-003）
- 3.3 A1-18 调节表数据保存到 working_paper.parsed_data（JSONB，非按行存）

### 4. 完成状态回显
- 4.1 子底稿弹窗完成后，A1 程序表对应步骤旁显示绿色"已完成"徽章
- 4.2 完成判定规则：
  - A1-11：所有必填签字人已签字
  - A1-12：14 条全部标记了"是否适用"
  - A1-17：3 个步骤全部标记状态
  - A1-18：审计结论已填写

### 5. 适用性自动判定
- 5.1 A1-12 根据 project.business_category 判断是否需要填写
- 5.2 A1-18 根据项目是否涉及金融工具判断（可由用户手动标记适用/不适用）

## 非功能需求

- 弹窗内组件懒加载（不影响 A1 程序表首次渲染速度）
- 弹窗关闭时自动保存未保存的变更（复用 sendBeacon 机制）
- 所有用户可见文本中文
