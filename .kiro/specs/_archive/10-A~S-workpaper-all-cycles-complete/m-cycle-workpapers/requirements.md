# M 类底稿（股东权益循环）— 需求文档

## 1. 概述

M 类底稿覆盖"实质性程序—股东权益循环"阶段（审计循环代号 M），**无独立 C 类控制测试**——权益变动走企业层面控制 C1。根据 B50 风险评估结果执行实质性程序。包含 **10 个科目、10 个模板文件、约 50+ 个子底稿 sheet**。

M 类特殊性：M6（未分配利润）= 期初 + 本年净利润 - 分配，需联动损益合计。M2（实收资本/股本）涉及验资/工商变更核实。

## 3. 术语表

- **股东权益循环系统（Equity_Cycle_System）**：平台中负责 M 类底稿的子系统
- **未分配利润（Retained_Earnings）**：期初+净利润-分配的累计数（M6）
- **其他综合收益（Other_Comprehensive_Income）**：不计入损益但影响权益的利得/损失（M9）
- **库存股（Treasury_Stock）**：企业回购的本公司股份（M3）

## 5. 各组详细需求

### M1: 应付股利
**需求：** M1A程序表 + M1-1审定表 + M1-2明细 + M1-3分配决议核实 + M1-4调整分录

### M2: 实收资本（股本）
**需求：** M2A程序表 + M2-1审定表 + M2-2明细 + M2-3验资报告核实 + M2-4工商变更核实 + M2-5股权结构表 + M2-6调整分录
- M2-3 验资报告核实→`d-form-table`（结构化检查）
- M2-4 工商变更核实→`d-form-table`

### M3: 库存股
**需求：** M3A程序表 + M3-1审定表 + M3-2明细 + M3-3回购/注销检查 + M3-4调整分录

### M4: 资本公积
**需求：** M4A程序表 + M4-1审定表 + M4-2明细 + M4-3变动分析 + M4-4来源检查 + M4-5股份支付联动 + M4-6调整分录
- M4-5 与 J3 股份支付联动→通过 ref_index

### M5: 盈余公积
**需求：** M5A程序表 + M5-1审定表 + M5-2明细 + M5-3法定/任意提取验证 + M5-4调整分录

### M6: 未分配利润（联动损益合计）
**需求：** M6A程序表 + M6-1审定表 + M6-2勾稽表 + M6-3利润分配方案 + M6-4以前年度调整 + M6-5损益联动验证 + M6-6调整分录
- M6-2 勾稽表（期初+净利润-提取盈余-分配=期末）→`audit-sheet`
- M6-5 损益联动验证（D~N 全部损益类科目审定额合计=净利润）→`audit-sheet`

### M7: 专项储备
**需求：** M7A程序表 + M7-1审定表 + M7-2明细 + M7-3安全生产费用检查 + M7-4调整分录

### M8: 一般风险准备
**需求：** M8A程序表 + M8-1审定表 + M8-2明细 + M8-3提取比例验证 + M8-4调整分录
- 金融企业特殊科目，非金融企业标"不适用"

### M9: 其他综合收益
**需求：** M9A程序表 + M9-1审定表 + M9-2明细 + M9-3分类检查 + M9-4来源追溯 + M9-5转损益检查 + M9-6调整分录
- M9-3 OCI 分类（不能重分类进损益 vs 可以重分类）→`d-form-table`

### M10: 其他权益工具
**需求：** M10A程序表 + M10-1审定表 + M10-2明细 + M10-3分类条件检查 + M10-4调整分录
- M10-3 权益/负债分类判断（永续债条件）→`d-form-table`

## 7. 技术约束

- wp_code 规则：M1~M10 共 10 组（无函证、无 M0）
- componentType：验资/分类检查→d-form-table，勾稽表/损益联动→audit-sheet
- 审定表回写正则：`^M\d+-1$`
- M6 损益联动：需汇总 D~N 全部损益类科目审定额
- M8 适用性：金融企业才适用（applicable_when: industry IN ['banking','insurance','securities']）

## 9. 跨循环依赖提示

> 📌 **全局交叉索引**：`.kiro/specs/CYCLE-CROSS-REFERENCE.md`

- **前置依赖**：D~N 全部 P2 审定表完成后才能实施 M6 损益联动（P5 阶段）
- **B23 穿行编号**：M 无独立 B23——走 B22A（企业层面控制穿行）
- **C 类编号**：M 无独立 C 类——使用 C1（企业层面控制）
- **完整链路**：B22A 穿行→C1 企业层面控制→M{n}A 实质性程序表
- **后续被依赖**：M6 未分配利润是审计最终闭环数据之一，A17 总结需引用
- **跨循环联动**：J3→M4（股份支付）；G8→M9（OCI）；D~N 全损益→M6
- **新增 resolver**：`income_statement_total`（M6 需 D~N 损益科目 audited_amount 合计）
- **⚠️ M6 是联动依赖链最长的底稿——必须所有损益循环审定完成后才能执行 P5**
