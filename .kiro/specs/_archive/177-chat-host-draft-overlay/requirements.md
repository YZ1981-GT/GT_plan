# 需求文档：Chat 宿主通用未保存草稿纳入（draft overlay）

> 承接 `llm-linkage-audit-practice-closure` 需求 3.4 的后半句。原文：
> 「未保存编辑必须明确提示未纳入；**后续**通过受限 `draft_overlay` 纳入时，须绑定已授权宿主、基线版本和内容 hash。」
>
> 该 spec 已交付前半句（提示未纳入，浏览器双态实测通过），并把后半句显式登记为「另立 spec」。
> 本 spec 承接后半句。

## 1. 目标

让 AI 对话在「用户有未保存修改」时，可以选择把**当前未保存草稿**纳入本轮上下文，而不是只提示「未纳入」。

前提是必须**可验证地**绑定：已授权宿主、基线版本、内容 hash。任何一项对不上都不得纳入。

## 2. 纳入语义

1. 纳入的是**当前编辑器内存里的未保存内容**，不是库里的旧版本。
2. 纳入时必须携带：
   - `host_type` / `host_id`（已通过宿主鉴权）
   - `baseline_version`（该宿主在**打开编辑器时**的业务版本，用于判定草稿基于哪一版）
   - `content_hash`（未保存正文的 sha256）
   - `content_length`
3. 服务端必须重新鉴权宿主（不能信客户端断言的项目/宿主归属）。
4. 服务端必须核对 `baseline_version` 仍是该宿主的当前版本；若已变化，纳入**降级为只读提示**（说明草稿基于旧版本），不得静默使用。
5. Manifest 必须能区分「已保存内容」与「未保存草稿」两种来源，前端在消息上标注。

## 3. 宿主范围

第一批只做**底稿（workpaper）** 宿主：
- 底稿 HTML 编辑器与 Univer 编辑器都可能存在未保存修改；
- 需要从编辑器拿「当前内存正文」与「打开时的版本」两个值。

附注（note）宿主已有 `note_ai.py` 的 `draft_overlay`（ADR-LLM-014 附注生成链路），**不在本 spec 范围**，但两者语义必须一致（同一套字段命名与校验口径），避免出现两套 overlay 契约。

## 4. 安全与边界

1. 未保存草稿按**不可信内容**处理：必须经 `delimit_untrusted_content` 类包装，模型不得执行其中的指令。
2. 草稿不得进入任何持久化的 AI 产物（`ai_content_log` / DraftArtifact），只能作为本轮上下文。
3. 草稿内容不得写入 metrics / 日志 / 审计链 payload（只存 hash 与长度）。
4. 用户必须能显式关闭「纳入未保存草稿」（默认关闭，避免误把半成品当权威数据）。

## 5. 与既有机制的关系

1. **不新建第二套确认流**：本 spec 只影响 Chat Run 的上下文装配（`ContextPlan`），不涉及 DraftArtifact / CAS 写回。
2. **不改既有「提示未纳入」文案**：默认关闭时仍显示现有提示；开启时才改为「使用当前未保存草稿」。
3. **复用 `ContextPlan` manifest**：新增 `source_type` 取值（如 `draft_overlay:workpaper`），不新造清单结构。

## 6. 验收判据

1. 默认关闭时，行为与现状完全一致（提示未纳入）。
2. 开启后，manifest 出现未保存草稿条目，且带 `baseline_version` 与 `content_hash`。
3. 草稿基于旧版本时（`baseline_version` 已过期），纳入被拒绝并给出中文原因，**不得静默使用旧草稿**。
4. 跨项目草稿无法纳入（服务端重新鉴权）。
5. 草稿内容不出现在 metrics / 日志 / 审计链 payload。
6. 端到端：底稿编辑器改一处不保存 → 开启 overlay → 提问 → 模型回答引用该改动 → manifest 可核对。
