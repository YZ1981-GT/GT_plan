# 设计：复用现有内核并修正接缝

## 1. 隔离与所有权
候选位于 `tmp_formula_integrity/wt`，分离头基线 `3ea9e5697`。主工作区只读，不提交、不推送、不迁移、不写共享库。
S2 在途变更按差异块集成；能力目录、severity、附注执行分支不得回退。每个并行实施单元限定文件所有权。

## 2. 取数与编辑安全（R1/R2）
报表 PREV/AUX 在求值入口明确拒绝；WP 执行器按指定年度精确选择，缺失、歧义、非数值抛出明确来源错误，合法零正常返回。
审核 ROW 缓存保留 NULL，交既有严格求值器处理。按当前各域定义区分金额计算、非零通过与非零提示。
前端编辑篮以 domain/scope 绑定，编辑、预览和发布冻结同一上下文，切换时隔离旧篮并拒绝过期响应。
模板同步稳定顺序锁项目后重读计划，旧预览不能默默获得覆盖权；本地编辑推进 pending revision，旧确认返回409。
保留既有逐slot upstream/version，连续升级不清除其他版本的暂缓项。

## 3. 来源与展示（R3）
沿用 formula_inputs、report_row_compute、formula_provenance；输入展示保留200条上限但总数与摘要取全量。
Tooltip 分开显示 applied_attempt 与 last_calculation；传真实 attempt id/formula_used，只用于审定值。
请求缓存采用上下文键与代际防护。穿透与映射构成固定项目年度，不把映射关系称为实际公式输入。
目录保留S2能力登记，项目结果透传到真实挂点；未运行、读取失败、无持久结果分别展示。

## 4. 传播回执与幂等（R4）
outbox 保存完整 slot_keys，复用现有 JSON payload 以整体赋值保存 receipt，无新增迁移。
回执分派发状态、业务动作结果、异步 operation 状态：partial、queued、no_consumer、stale 均不等价全部完成。
投递上下文以 outbox id 固定操作幂等键及年度，重放复用同一 operation；历史按精确键查找，不依赖最近100条。
状态查询先按来源过滤再分页，并解析持久回执和关联operation；校对发现问题不是传输异常。

## 5. 验收（R5）
八反例分别落隔离生产路径测试：零/缺失、两年度、同slot跨scope、模板锁前竞争、旧revision、新版本保留暂缓、201/2000首中末、非完整业务状态。
多项目与角色使用SQLite/隔离ASGI夹具，测试子进程显式指定不存在的PG库，杜绝默认连接共享库。
前端复用已装依赖，隔离安装而非 node_modules 联接。运行时使用独立网络夹具或独立服务。
新增测试均由本次用户明确要求的反例验收驱动；不扩大为全仓测试重写。
未完成的真实PG、浏览器或服务环境验收必须如实登记，不能用静态接线代替。
