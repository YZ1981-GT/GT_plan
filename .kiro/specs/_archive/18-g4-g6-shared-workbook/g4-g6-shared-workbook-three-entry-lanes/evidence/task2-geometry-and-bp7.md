## 4. BP-7 按值定位：G4-main

**扫描文件**：61 个 G4 相关 .ts/.vue 文件

**`useG4MainDetail.ts`（受管表 G4-2 的主 composable）**：
- L249-250: `generateId()` = `` `g4d-${Date.now()}-${Math.random().toString(36).slice(2, 8)}` ``
  ⇒ **已带 `Math.random()` 后缀**，同毫秒不撞 id
- L442: `p.id ?? generateId()` ⇒ 有 id 用已有，无 id 铸新的
- L591: `.map((r, i) => ({ ...r, seq: i + 1 }))` ⇒ 只修 `seq` 不碰 `id`

**结论：G4-main 无 BP-7 缺陷**。`Date.now()` 搭配 `Math.random()` 后缀是稳定 id 生成模式
（与 G6-sppi 的 `fv-${Date.now()}-${seq}` 纯序号回退**不同型**）。
slice 的 `capability_target_blocked_by` 列了 BP-7 但 BP 正文只展开了 G6-sppi ⇒ **如实登记
「slice 的 blocked_by 与 BP 正文不一致」**（裁决 G46-H4）。

🔴 **其余 G4 文件的 `map((r, i)` / `i + 1` 均用于 `seq` 排序号**（显示序号），不是行身份 `id`：
- `useG4EclImpairmentCalc.ts` / `useG4EclStageClassification.ts` / `useG4EclReversalWriteOff.ts`：
  `r.seq = i + 1`（seq 排序号）+ `id: r.id || crypto.randomUUID()`（id 用 UUID 铸新）
- `useG4MainAdjustment.ts`：`generateId()` = `` `g4adj-${Date.now().toString(36)}-${Math.random()...}` ``
- `useG4SppiInventory.ts`：`` `g4inv-${Date.now()}-${Math.random()...}` ``

**全部 `Date.now()` 写法都搭配 `Math.random()` 后缀**，无纯下标回退。
