# 需求：公式管理残留安全与可用性收口

## 背景

基线 `29b4028810445050da0d0d26b0007dc8c42740d`。公式中枢 S1~S10 已修复大部分执行正确性，但本轮现场复核发现：附注模板端点全部无鉴权、模板 ID 可参与路径拼接、公式建议恒空、增强输入器只挂死分支、读取失败仍显示空态、自动补公式警告在多数入口丢失。

本 spec 只处理不需产品拍板、且不与 S2/S3/S5/S8/S9/S10 并发范围重叠的缺陷。

## R1 附注模板端点安全

1. `/api/note-templates/**` 与 `/api/report-templates/excel-formulas/**` 所有端点必须要求登录。
2. 自定义模板 create/update/delete/rollback 只允许 `admin`、`partner`；只读和校验端点允许已登录用户。
3. `created_by`、`changed_by` 必须取服务端当前用户，不信任请求体。
4. 自定义模板 ID 必须是平台生成的 UUID；任意 `../`、绝对路径、分隔符或非 UUID 输入不能触达模板目录外文件。
5. 不改变成功响应主体和现有合法模板文件格式。

## R2 公式建议可用

1. 有效报表定义同时保留上游定义对象与稳定比较快照，二者不能混用。
2. 当前项目公式为空、上游全局或预设公式非空时，公式管理必须显示可应用建议。
3. 保存后层级判定继续使用稳定快照，不能因对象引用或字段顺序误判。

## R3 真实编辑器接入增强输入

1. 真实 `FormulaEditDialog` 使用 `FormulaInput`，提供语法高亮、函数补全、科目/行次/底稿参数补全。
2. 存在语法错误时禁用保存，并给中文提示；打开时已存在的公式也必须立即校验，组件卸载要取消定时器；后端校验仍保留为最终边界。
3. 删除 `FormulaManagerDialog` 中永不可达的旧行内编辑模板、参数选择器和双写逻辑；既有编程式 `saveEdit` 兼容适配可保留，但只能委托统一保存链。被真实编辑器内置选择器完全取代且零调用的 `FormulaParamPicker` 一并删除。

## R4 故障不得伪装为空数据

1. 公式历史加载失败显示明确错误和重试入口，不显示“暂无公式变更记录”。
2. 项目或年度变化时立即清除上一项目历史和试算表明细公式状态；陈旧响应不能覆盖当前项目。
3. 试算表科目明细公式端点的 4xx/5xx 必须进入错误提示，不能由 `validateStatus < 600` 吞掉。

## R5 自动补公式警告可见

1. `fill_all_formulas()` 的 warnings 必须在 `/fill-formulas`、`/seed`、模板库 `seed-all` 和正式 CLI 中可见。
2. 模板库批量结果区分错误与非阻断提示；存在提示时不能弹“全部成功且无问题”。
3. warnings 不改变事务成功状态，不把“有意拒绝生成嵌套合计公式”误标成失败。

## R6 公式管理宿主可构建

1. `ThreeColumnLayout` 中公式管理首次挂载 helper 只能导入一次；重复声明不得阻断全站 Vite 构建。

## 非目标

- 不实现 S2 一致性五态、S3 唯一写方、S5 来源信封、S8 CI、S9 利润链、S10 哈希链。
- 不重新种子化共享库，不发布公式，不写真实项目，不改 S5 三个未跟踪文件。
- 不改变附注自定义模板的可见范围、删除策略或历史版本数据模型；这些需要产品裁决。
