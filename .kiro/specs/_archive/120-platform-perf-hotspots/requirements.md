# 平台响应速度热点 — 需求

用户 2026-10-27「前后端的处理速度不太好，太慢了」→ 实测分析 → 「按你建议来」。
实测数据与口径见 design §1；本文件只写要达到什么。

## 背景（重药安徽 2025，929 张底稿，admin 账号，2026-10-27 实测）

- 常用轻接口后端 7~30ms，不是瓶颈。慢集中在下面几处。
- 后端每次重启后约 1 分钟里所有接口 3~6 秒：8 天 715 条超过 3 秒的慢请求中 615 条落在 16 个分钟里，抽查最大的 4 个都是重启后启动预热的那一分钟；开发后端因并发会话改代码每天重启 54~130 次。
- 打开 D2：render-config 14.7MB（同一份 916KB 的数据复制进 15 个页签），前端请求 2 次；编制说明请求 2 次，后端每次都把 render-config 整套重算。
- 底稿列表、试算表：分 10 次串行拉全部底稿（每页约 190ms）；底稿列表切视图整页重建；列表页主线程卡 1~1.7 秒。
- 数据库：JIT 占热查询约 75%，work_mem 4MB 让位图扫描退化。

## R0 编译错误（顺带发现）

- R0.1 `GtChecklistTable.vue` 当前编译失败（开发服请求它返回 500，A1-15/A1-16 核对表、A1 总览核对表页签打不开，生产构建也因此失败）。修复后开发服返回 200，组件单测通过。
- R0.2 `MyTemplatesDialog.vue` 同类编译错误（无引用方）一并修。
- AC：全仓 `.vue` 用 Vite 同一编译器扫描，真实编译失败 0 个。

## R1 render-config 不重复下发整册共享数据

- R1.1 新增可选查询参数 `share_html_data`。开启时，内容相同（只差 `sheet_name`）的页签 html_data 只在响应顶层 `shared_html_data` 放一份，各页签只保留差异键并带 `html_data_ref`。
- R1.2 不带参数时响应与现在逐字节相同（自行请求 render-config 的 30 多个组件不受影响）。
- R1.3 前端 `useWpRenderer` 开启该参数，并在一处展开：下游拿到的每个页签 html_data 与不带参数时深度相等，且页签之间互不共享对象。
- AC：D2 响应体 14.7MB 降到 2MB 以下；展开结果与不带参数的响应逐页深度相等（单测 + 真库对拍）。

## R2 D 循环渲染器每次请求只跑一次

- R2.1 d1~d7 七个渲染器的输出与页签无关（d1/d2 只多一个 `sheet_name`），同一请求内按 componentType 只跑一次，其余页签复用并补本页 `sheet_name`。
- AC：真库 D1~D7 底稿开关前后 render-config 逐页深度相等；D2 render-config 后端耗时下降（记录实测）。

## R3 编制说明不再整套渲染

- R3.1 guidance 端点只用页签清册（`sheet_name / sheet_code / sheet_code_reason / whole_workbook / componentType` 与 `template_version`），改为只算清册：不跑渲染器、不取模板网格、不做各类注入与自动取数。
- AC：真库全部底稿清册字段与完整渲染逐条相等；guidance 响应与 ETag 不变；D2 guidance 后端耗时下降。

## R4 打开底稿不重复请求

- R4.1 编辑器外壳不再单独请求 render-config（它只用 `decision_trace`）：HTML 模式从 GtWpRenderer 取，Univer 模式复用已有的目录请求。
- R4.2 编制说明面板等页签上下文确定后再请求；拿不到页签上下文（加载失败、重定向、不适用、无页签）时按整册请求一次。
- AC：浏览器打开 D2，render-config 1 次、guidance 1 次。

## R5 一次取回全部可见底稿

- R5.1 新增 `GET /api/projects/{project_id}/working-papers-all`：鉴权与可见性判定和分页端点完全相同，按同一排序返回全部可见项，项字段与分页端点一致，支持同样的过滤参数。
- R5.2 前端 `listWorkpapers` 以及底稿目录页签、挂凭弹窗、程序裁剪委派建议改用它；同一项目同参数的并发请求共享一次。
- AC：与分页端点逐页拼接的结果逐条相等（admin / 主管 / 审计员三种可见性，PG 测试）；底稿列表、试算表、底稿目录页签各只发 1 次底稿清单请求。

## R6 底稿列表切视图不整页重建

- R6.1 路由可声明「只改查询参数时不重建页面」，底稿列表启用；页面自己响应 `view` / `filter` 参数变化。
- AC：切视图、勾「仅看待重算」不再重新拉数；已在底稿列表时点联动横条「查看详情」仍切到待重算列表；其他页面行为不变。

## R7 底稿列表主线程不卡

- R7.1 底稿清单与索引改为浅层响应式（整体替换），列表合并与各视图派生改用按键查找。
- AC：浏览器实测底稿列表页最长长任务 < 300ms（原 1.7s），视图内容不变。

## R8 启动预热不长时间占住事件循环

- R8.1 先测量当前预热期间事件循环的最长阻塞段与位置，再把测得的长同步段挪出事件循环线程，必要时让预热在 entry 之间让请求先走。
- AC：预热期间轻接口 p95 < 500ms（原 3~6s）；预热产出（注册 adapter 数、基线预热数）不变；既有预热测试全绿。

## R9 数据库参数

- R9.1 无需重启的：`jit = off`、`work_mem = 32MB`（ALTER SYSTEM，存在数据卷里）。
- R9.2 需要重启的 `shared_buffers`、`pg_stat_statements`：等用户定时间。
- AC：序时账聚合热查询 0.56s → 约 0.3s。

## 范围外（登记，不在本 spec 做）

- 每个请求固定的鉴权 / 中间件开销（单请求 7~10ms，面向 6000 并发再做）。
- 外壳静态带入公式管理弹窗等、底稿编辑器静态带入 Univer / vue-office 的懒加载。
- 生产构建恢复：`npm run build` 的全量 vue-tsc 内存溢出；`src/shell/formula` 下两个文件在浏览器代码里引用 `node:fs` / `node:path`。
