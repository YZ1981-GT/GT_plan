# 取数结果错误 / 底稿生成流程 / 测试欠账 收口 —— 需求

> 来源：`formula-governance-coverage-closure` 交付时登记的范围外发现（design §2.2 / §9），用户 2026-10-23 指定其中 8 项修复，
> 地址库上限「最多取 50000 条，放大 10 倍先」。

## R1 推送规则取数科目与试算表一致（原「5 条推送规则恒推 0」）

- R1.1 H6 固定资产清理、I1 无形资产减值准备、H9 租赁负债、I2 开发支出四条系统规则推出的是试算表里该项目的真实审定数，不再恒为 0。
- R1.2 规则公式里的科目与该底稿推送取数（binding）的科目一致；binding 只用试算表标准科目码（不带映射表的字母后缀）。
- R1.3 没有对应标准科目的规则（I5 其他非流动资产）不推数，不能拿别的科目（1901 待处理财产损溢）顶替；该格交给用户填写。
- R1.4 同根因、科目错位但不推 0 的规则（推出的是别的科目的数）一并纠正，以平台既有的科目口径单一来源为准。
- R1.5 守卫「推送取数给不出数的系统公式」清单清零，并新增守卫：binding 科目必须是标准科目表里的码。

## R2 PREV 三参（上年同底稿取数）不再恒取 0

- R2.1 `PREV('底稿','表','字段')` 按「上年数据 + 本底稿该字段的现行取数定义」求值：同项目有上年试算表用同项目上年；否则用上年项目
  （显式关联的上年项目，否则同企业代码、上一审计年度、同报表口径的唯一项目）。
- R2.2 取不到数（无上年数据、上年项目不唯一、字段没有取数定义、上年数据里没有该科目以外的原因）写明原因，不代入 0；
  底稿可编辑公式保存时不再以「不支持」拒收三参 PREV。
- R2.3 预填充（初次生成与重新预填）、底稿可编辑公式、表间审核等所有求值路径口径一致。
- R2.4 两参 `PREV('科目','列')` 的上年来源与三参一致（同项目上年 → 上年项目）。

## R3 地址库一次最多取 50000 条（原 5000）

- R3.1 前端地址库一次加载上限 50000，后端接口上限 50000（超过返回 422，不静默截断）。
- R3.2 接口回报真实匹配总数与是否截断；前端截断时提示一次，截断的域不当作「完整」使用。
- R3.3 选择器在附注 / 底稿 / 辅助余额域有数据后插入的引用与登记写法一致（能通过保存校验）。
- R3.4 切换项目 / 并发刷新时不把上一个项目的地址当成当前项目的。

## R4 生成底稿保留用户裁剪结果

- R4.1 `POST /working-papers/generate` 接收 `selected_templates`，只生成选中的底稿；不传时整套生成（兼容旧调用方）。
- R4.2 选中但不在模板集里的编码如实回报，不静默丢弃。

## R5 按编码生成认得多页底稿

- R5.1 `generate-from-codes` 对 E1 这类多页底稿复制真实模板（与其他生成入口同一解析：底稿模板目录索引 + 多文件合并 + 场景裁剪）。
- R5.2 找不到模板时如实回报（单列），底稿名称取平台名称源，不再叫「底稿E1」。
- R5.3 准则转换生成路径的同款逻辑一并纠正。

## R6 自定义底稿编辑器按项目口径保存公式

- R6.1 保存公式时模板口径取本项目（上市 / 国企），不再写死国企。
- R6.2 后端未收到口径时按项目自身口径校验，不默认国企。

## R7 d-cycle 保存相关测试恢复有效

- R7.1 `tests/d_cycle_extraction` 中因测试替身过时而失败的用例（假会话缺 `get`、`list_formulas` 形参改名）按现行端点签名与鉴权链修复，
  守卫重新真正执行到断言。
- R7.2 其余失败逐条定根因：生产缺陷修生产代码，契约过时按现行契约更新并说明依据。

## R8 后端 pytest 不带额外参数即可启动

- R8.1 不带 `-p no:playwright` 运行 pytest 能正常启动（测试目录不再遮蔽已安装的包）。
- R8.2 需要真实浏览器与开发服务的抽样测试默认跳过，显式开启才运行。
- R8.3 守卫：测试目录的直接子项不得与已安装包 / 标准库同名地进入导入路径；测试文件不得依赖「测试目录在导入路径首位」。
