# 附注正文导入、批量编制与集团内容模板

## 1. 概述

本功能包含三条共用“预览后确认”内核的路径：

1. **外部文档导入**：上传 Word/PDF，解析章节并预填到“报表科目以外”的叙述性章节；
2. **知识库预填**：选择有权限的知识库文档，按相同流程解析、匹配和编辑；
3. **附注内容模板**：把某企业全部附注富文本保存为不可变版本，其他企业按章节选择性引用。

用户仍可维持现状逐章节编辑；批量能力是增量入口，不取代单章保存。

## 2. 术语与范围

- **叙述性章节（narrative）**：公司基本情况、编制基础、会计政策、会计估计、税项等非报表科目解释章节。
- **报表科目解释章节（account_explanation）**：货币资金、应收账款等对具体报表科目作进一步说明的章节。
- **容器章节（container）**：只承载标题和子章节、本身没有可编辑正文的目录节点。
- **全套内容模板**：保存 narrative + account_explanation 的全部富文本快照；不保存或覆盖 `table_data`。
- **确认写入**：业务操作确认，不等于审计复核“已确认”；批量写入后的章节状态统一为 `draft`。

章节类型必须由后端章节目录根据当前 `template_type + report_scope + note_template_variant_matrix` 判定，禁止前端按 `content_type` 或标题猜测。

## 3. 用户故事与验收标准

### US-1 上传并解析附注文档
**作为**审计助理/现场经理，**我希望**上传 Word/PDF 附注文档并看到结构化章节，**以便**批量编制叙述性附注。

- AC-1.1 支持单个 `.docx` / `.pdf` 文件，最大 50MB；后端同时校验扩展名、MIME 和文件签名。
- AC-1.2 DOCX 按文档 XML body 顺序混排读取段落和表格，识别 Heading、GTNoteHeading、outline level；不得把段落和表格分开遍历后重排。
- AC-1.3 PDF 使用 PyMuPDF 的 block/line/span 信息识别字号和粗体；纯文本兜底仅作低置信候选。
- AC-1.4 返回章节层级、标题、正文 HTML、解析置信度和警告；保留基础段落、列表、加粗、斜体和表格结构。
- AC-1.5 扫描件、加密、损坏、页数/解压体积超限时给出中文原因，不静默返回“解析成功但内容为空”。
- AC-1.6 （第 23 组，2026-10-15 用户拍板）解析结果是章节树：每个标题带层级和上级标题（`parent_source_id`，顶层为空）。DOCX 按标题样式 / 段落大纲级别 / 样式沿基样式链继承的大纲级别（段落自设的优先）；PDF 有书签目录时按书签（标题与层级取书签，书签找不到对应标题行的报警告、不猜），无书签时与纯文字一样按标题编号排位（「一、」>「（一）」>「1.」/「1、」/「X、」>「（1）」>「①」），PDF 同一行的多段文字先合并再判定，无编号的标题按字号；PDF 页眉页脚不进正文；知识库多篇文档各自成树。左栏按树缩进显示。

### US-2 双栏批量编辑
**作为**审计助理/现场经理，**我希望**左侧核对来源，右侧集中编辑目标章节，**以便**一次完成多章二次修改。

- AC-2.1 弹窗占视窗约 90% × 80vh，双栏可拖拽，支持按标题搜索及“仅看未匹配/仅看已变更”。
- AC-2.2 左侧章节可折叠，只读 HTML 必须消毒；显示来源标题、层级、置信度和匹配状态。
- AC-2.3 右侧仅列出 `section_kind=narrative` 的叶子章节，按父章节分组；不得混入报表科目解释章节或纯容器节点。
- AC-2.4 右侧采用折叠/懒挂载编辑器，避免同时创建全部 `NoteRichTextEditor` 实例。
- AC-2.5 已有内容、空内容、已预填、已编辑、并发冲突分别有清晰状态；关闭有未保存修改的弹窗必须二次确认。

### US-3 安全、可解释的章节匹配
**作为**编制者，**我希望**系统只自动采用确定的章节映射，**以便**避免相似标题导致整章错填。

- AC-3.1 同模板优先使用目标行 UUID / 规范 section_code；跨模板优先使用 `note_template_variant_matrix` 和显式章节别名。
- AC-3.2 复用 `note_section_matcher` 的别名及禁止匹配对；禁止 SequenceMatcher、编辑距离、关键词重合率等模糊算法直接形成权威映射。
- AC-3.3 标题规范化精确匹配仅作为可解释候选；任何不唯一、低置信或禁止对都必须由用户手动选择目标章节。
- AC-3.4 一个源章节最多映射一个目标章节，一个目标章节最多接受一个源章节；冲突时不得自动覆盖。
- AC-3.5 一键预填只处理已确认映射；未匹配目标保持原值。
- AC-3.6 （第 23 组，2026-10-15 用户拍板）上传 / 知识库按章节树逐级定位：先在目标项目章节树的一级章里按标题定位来源的一级章，再只在已定位章的子节点里定位其下小标题，逐级向下。目标树取 `section_id / parent_section_id`；不在树上的行（无 section_id、上级不存在）不参与定位，只能手工指定。
- AC-3.7 定位不上一律交给用户，系统不自行处理：找不到、同名多个、上级未定位的标题都标为需人工对应，不到其他章节按标题找、不就近并入、不按编号推测。用户可手工指定目标节；也可以先把上级标题对应到目标章，重新预览后其下小标题在该章内定位。
- AC-3.8 目标节是叶子时，来源该节以下的小标题与正文按原顺序并入该节正文（小标题转加粗段落）。来源标题自身的正文落在已定位目标上：目标有子节点时落到其下与之同名的唯一正文节（如「一、1 公司基本情况」），没有则作为「章首正文」单独列出、需人工对应。
- AC-3.9 内容模板来源仍按章节编号（同模板同编号 / 科目映射矩阵）；编号对不上时只在同一章内按标题找。

### US-4 预览后原子批量写入
**作为**编制者，**我希望**确认的一批章节要么全部写入、要么全部不写，**以便**避免附注处于半完成状态。

- AC-4.1 写入前由服务端返回新增/替换/追加数量、逐章前后摘要、消毒或变量替换警告及 `preview_digest`。
- AC-4.2 apply 请求携带逐章 `target_note_id`、预期内容 hash/`updated_at`、模式及 `preview_digest`。
- AC-4.3 服务端对目标行 `FOR UPDATE`，任一章节已变化、无权、缺失或内容非法时返回 409/422 并整体回滚。
- AC-4.4 apply 支持稳定 `X-Mutation-Id`；同键同载荷重试返回同一结果，同键不同载荷返回 409。
- AC-4.5 成功后一次提交全部章节，逐章发布失效事件；前端清空详情缓存并强制刷新当前章节和目录树。
- AC-4.6 写入章节设置 `status=draft`、`is_local_override=true`，防止后续生成/AI 批填静默覆盖。

### US-5 参考知识库预填
**作为**编制者，**我希望**选择知识库文档作为来源，**以便**复用已有政策和历史文档。

- AC-5.1 弹窗提供“从知识库选择”，支持选择最多 5 篇文档并显示名称/版本。
- AC-5.2 后端必须通过 `KnowledgeIndexService.load_documents(..., user, project_id)` 逐篇判权后读取正文；禁止按客户端 ID 裸查 `content_text`。
- AC-5.3 无权、已删除或正文为空的文档不泄露存在性，并在结果中给出可理解提示。
- AC-5.4 Markdown/HTML heading 与中文章节标题可解析，后续匹配、编辑、预览、apply 与上传路径共用同一内核。

### US-6 入口与单章兼容
**作为**编制者，**我希望**批量入口清楚且不影响现有单章流程，**以便**按场景选择操作方式。

- AC-6.1 “导入导出”菜单新增“上传附注文档”；批量弹窗内可改选知识库来源。
- AC-6.2 顶部新增“保存为内容模板”“引用内容模板”，但不与现有结构模板按钮混用同名文案。
- AC-6.3 无编辑权限、归档、合并锁或 EQCR 场景只读/隐藏写入口；后端仍必须独立拒绝越权请求。
- AC-6.4 原有单章编辑和始终可见的保存按钮继续工作，包括把 table 型章节的富文本清空后保存、切换章节再返回仍显示新值。

### US-7 保存全套附注内容模板
**作为**现场经理/合伙人，**我希望**把已编制项目的全部附注富文本保存为集团模板，**以便**下属或兄弟企业复用。

- AC-7.1 保存由专用后端端点按 `project_id + year` 一次查询生成快照；浏览器不得逐章抓详情或提交可伪造的来源信息。
- AC-7.2 快照包含每章 `section_id/note_section/section_title/section_kind/content_type/text_content/content_hash/status/is_stale/quality_flags`，但不含 `table_data`。
- AC-7.3 企业名称、来源项目、年度、模板类型、报表口径、保存人、保存时间均由服务端权威数据生成。
- AC-7.4 同名模板再次保存创建不可变新版本；内容 hash 未变化时返回现有版本，不制造空版本。
- AC-7.5 保存前先调用服务端 snapshot-preview，展示有内容/空白/占位文本/草稿/stale/企业特有风险章节数量和 `snapshot_digest`；集团发布必须二次确认，正式保存时重算并校验 digest，来源已变化则返回 409 重新预检。
- AC-7.6 个人模板仅本人可见；集团模板归属由服务端解析到 canonical group root，只有经理/合伙人可发布。
- AC-7.7 普通用户不能创建 system/public 模板；事务所级模板留给管理员独立治理。

### US-8 选择模板与固定版本
**作为**下属企业编制者，**我希望**看到本项目有权访问的模板及版本来源，**以便**选对参照版本。

- AC-8.1 列表只返回本人个人模板和同集团模板；异集团、仅知道 UUID 的直接详情请求统一返回 404。
- AC-8.2 展示模板名、说明、来源企业/年度、标准、报表口径、版本、保存人/时间、章节数及质量摘要。
- AC-8.3 默认选择最新版，同时允许查看历史不可变版本；应用记录必须固定到具体 `version_id + content_hash`。
- AC-8.4 引用后形成目标项目本地副本，不自动随模板升级；有新版本时只提示，用户重新预览后才可应用。
- AC-8.5 模板标准或报表口径与目标不一致时显示醒目警告，跨变体只允许显式矩阵/别名映射自动建议。

### US-9 按章节选择性引用
**作为**编制者，**我希望**从全套模板中只选择适用章节，**以便**避免覆盖本企业特有内容。

- AC-9.1 预览按三组展示：
  - 🟢 **推荐引用**：目标为空、模板有内容、映射确定、同标准/口径且无高风险标记；默认勾选。
  - 🟡 **需复核**：目标已有内容，或属于报表科目解释/企业特有/跨标准/含风险标记；默认不勾选。
  - ⚪ **不可用**：模板无内容、无目标章节、映射不唯一或被禁止匹配；不可勾选并说明原因。
- AC-9.2 模板保存的是 narrative + account_explanation 全套正文；报表科目解释章节必须出现在“需复核”而非默认推荐。
- AC-9.3 已有内容支持“替换”或“追加”，默认替换；追加必须在差异预览后显式选择。
- AC-9.4 差异查看使用独立并排预览（现有/拟写入），不只依赖 hover 截断文本。
- AC-9.5 模板中存在但目标不存在的章节不自动创建，提示先新增章节；本期不改变附注结构。
- AC-9.6 勾选摘要显示总数、新增、替换、追加、高风险和未映射数量。

### US-10 目标变量替换与内容安全
**作为**编制者，**我希望**引用时自动替换明确的企业变量并提示残留风险，**以便**避免把来源企业信息带入目标附注。

- AC-10.1 服务端仅对确定性变量（公司名称、年度、报表期间、币种、金额单位等）使用现有段落变量体系生成拟写入内容。
- AC-10.2 每个替换在预览中显示“原值→目标值”，用户可逐项撤销；禁止用 LLM 静默改写正文。
- AC-10.3 来源企业名称、地址、法定代表人、具体日期/金额等未解决残留进入 `quality_flags`，对应章节默认归入“需复核”。
- AC-10.4 上传、知识库、模板及最终写入的 HTML 均经后端允许列表消毒，前端展示再用 `useSanitize.sanitizeHtml` 二次消毒。
- AC-10.5 “追加”只拼接业务正文和结构性空段，不把“引用自模板”文字或审计元数据写进最终财务报表附注。

### US-11 溯源、审计与批量事件
**作为**复核者，**我希望**知道每章来自哪个来源和版本，**以便**追踪批量变更。

- AC-11.1 每次批量 apply 记录来源类型（upload/knowledge/template）、固定模板版本或知识库版本、映射、模式、前后 hash、目标项目/年度、操作人和时间。
- AC-11.2 目标章节 `template_lineage` 追加内容模板来源条目，不覆盖既有集团基线 lineage。
- AC-11.3 溯源只在平台 UI/审计记录中展示，不进入导出的附注正文。
- AC-11.4 批量提交后所有已改章节均触发 `NOTE_SECTION_SAVED` 等价失效语义，不能只通知第一章或把全项目误标为未知变更。
- AC-11.5 软删除模板不删除不可变版本和历史应用记录；历史应用仍能证明当时引用的版本。

## 4. 非功能性需求

- NFR-1 新建专用附注内容模板/版本/批量应用领域模型，不把富文本权威快照塞入现有可变 `shared_config_templates.config_data`。
- NFR-2 新增 `V187` / `R187` 成对迁移；DB 约束、ORM `Mapped[]`、Pydantic schema 和 service 方法四层一致。
- NFR-3 服务仅 `flush`，router/coordinator 统一 commit；apply 为单事务、幂等、并发安全。
- NFR-4 所有 project/template/doc ID 视为不可信；list/detail/preview/apply 分别执行 readonly/edit/模板可见性检查，直接 ID 不得绕过。
- NFR-5 上传按流/有界读取，限制文件字节、PDF 页数、DOCX 解压体积、章节数、单章 HTML 和批次总字节；具体阈值须由真实样本探针确认并配硬上限。
- NFR-6 50 页以内文字版文档解析目标 ≤5 秒；解析、预览和应用均显示独立进度。
- NFR-7 HTML 允许标签/属性只有附注编辑器所需最小集合；禁止 script/iframe/object/embed、on*、危险 URL 和任意 style。
- NFR-8 右侧编辑器懒挂载，模板列表不返回整包正文；正文仅在详情/预览阶段加载。
- NFR-9 新 router 必须登记到 `backend/app/router_registry/report.py`；静态路由不得置于 disclosure GET catch-all 之后。

## 5. 范围排除

- 不导入或引用 `table_data`、公式、金额单元格和附注章节结构。
- 不自动创建目标缺失章节。
- 不对扫描件 PDF 在本弹窗执行 OCR；提示先上传知识库走现有 OCR 链或提供文字版。
- 不做模糊匹配自动应用，不让 LLM 决定章节映射或目标变量替换。
- 不允许普通用户发布事务所全局/public 模板。
- 不自动把模板新版本推送到已引用项目，只提供版本提示和重新预览。
- 不改变现有 `note_template` 结构模板或 `GroupNoteTemplateBaseline` 的业务语义。
