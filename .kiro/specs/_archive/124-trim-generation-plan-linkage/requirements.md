# 需求：程序裁剪 → 生成底稿联动（生成计划）

## 背景（2026-10-28 现读代码 + 真库）

- 「⬇️ 生成底稿」第二步 `WorkpaperTrimDialog` 出自归档 spec `workpaper-header-and-metadata`（按 A/B/C 业务分类勾选）；`procedure-trim-generation-delegation-chain` 只补了需求 2.5「已粗裁的不预选」，当时裁定「生成前按模板细裁（方案二）另立项」，之后没有立项。
- 两边不是同一份目录：裁剪页按程序行（`gt_template_library.json`，331 行，含 `D2-1至D2-4` 这类区间），弹窗按底稿编码（`wp_account_mapping.json`，1025 个），中间只靠编码继承 / 区间展开换算。
- 重庆医药集团医疗器械有限公司_2025：粗裁记录只有 D 循环 17 行，是打开裁剪页时默认 D 页签自动初始化的（同一时刻建、从未改过），其余 14 个循环没有记录；弹窗没勾的 31 个是业务分类（项目未填，按 C 类）判的。
- 把 331 条程序行全标不适用，仍有 48 个编码照样生成：D2 / D4 / E1 / F2 四张母码审定表，B 类 26 个、A 类 15 个、S 类 3 个。
- 弹窗取消勾选不写回、不要理由、不留痕；生成只要项目编辑权限，裁剪要委派人（经理以上）。
- 第一步选的模板集没传给第二步；弹窗不显示已生成 / 在回收站；循环顺序按数据文件原顺序。
- 两页之间没有跳转；裁剪页固定从 D 打开；保存粗裁后只问「前往委派」。

## 用户裁决（2026-10-28「按建议来」）

1. 弹窗只保留「本次生成哪些循环」这一级；逐个底稿的排除一律走裁剪页（有理由、有权限、留痕）。
2. B / A / S 那些裁剪页裁不到的文档不再停在谁都管不着的状态；A18 这类上市专用的仍按业务分类给建议。
3. 方案二（生成前按模板细裁、先委派后生成）仍单独立项，本 spec 只把粗裁和生成接通。

实施收口约束：生成计划与粗裁变更共享项目级 PG 事务咨询锁，生成取锁后重新读取 scope；粗裁 preview 带 ProcedureInstance 状态摘要，旧 preview 不能覆盖新决定。项目目录 SQL 异常返回 503，禁止伪装成「未选择模板」后回退全局目录；归档 / 删除项目在委派门被拒并重设 RLS。重叠区间回报与 execute-wins 结论一致且保留全部决定者；跨循环标准码不能作为自定义行劫持生成，软删模板集在计划和生成中都视为不存在。

勘误（设计阶段逐个核对 44 个文档）：分析时建议把它们设为「必做、不可裁」，但其中多数是按条件才需要的（13 份业务约定书变体 B5-1~B5-9-2、IPO / 再融资专项 S32 / S35、内控 / IPO / 国企 / 监管 B60A~D、IT 审计 B60-2-x / A27、专家 B60-3、非大型国企 A24 与大型国企 A25 二选一）。设成必做会强制生成全部 13 份约定书和 IPO 专项，所以改为在裁剪页补成可裁的程序行；没有程序行管的默认执行，适用性分裂的子码沿用原决定行状态，保证补齐前后生成判定不变，见 design §2.3 / §6.5。

## R1 生成计划（后端只读）

1.1 `GET /api/projects/{project_id}/procedure-scope/generation-plan?template_set_id=` 按循环返回生成计划；项目成员只读级别即可查看。
1.2 每个编码一个状态，互斥，按优先级：已裁剪 > 在回收站 > 已生成 > 业务分类不生成 > 将生成。前三类与生成接口同一判定（`plan_generation` / `TrimmedScope`）。
1.3 每个循环给出粗裁状态：未打开（没有程序行）/ 未保存（有程序行、没人保存过）/ 已保存（最近一次保存人与时间）。「保存」= 粗裁应用凭证已消费、且其中有该循环的粗裁条目。
1.4 「业务分类不生成」只用于未打开 / 未保存的循环（即默认方案）；已保存的循环以程序行为准，业务分类不适用但程序行执行的编码照常生成，并标出冲突。
1.5 每个编码回报决定它的程序行；母码跟随下级程序行（R4）的单独标明。
1.6 只列所选模板集的编码；模板集不存在返回 404；不传时用全部模板编码。
1.7 读不到粗裁结果返回 503（与生成接口同口径）。
1.8 `GET /api/projects/{project_id}/procedure-scope/confirmations` 单独返回各循环粗裁状态（裁剪页用）。
1.9 两个接口进程序链契约（JSON Schema + OpenAPI 子集 + 契约测试）。

## R2 生成弹窗（底稿列表页与裁剪页共用）

2.1 一个弹窗完成：选模板集、看业务分类、按循环汇总（粗裁状态，将生成 / 已生成 / 在回收站 / 已裁剪 / 业务分类不生成的数量），展开看程序行与底稿。
2.2 只能按循环勾选本次生成范围，不能逐个底稿取消；将生成为 0 的循环不可勾选。
2.3 生成时发送所选循环里「将生成」的编码；回执提示沿用 `summarizeWorkpaperGenerateResult`。
2.4 有未保存 / 未打开粗裁的循环要醒目提示，并能「去程序裁剪」直接到对应循环。
2.5 循环顺序与裁剪页一致（B C D E F G H I J K L M N A S，其他排最后）。
2.6 计划读取失败在弹窗内说明原因，生成按钮不可用。
2.7 删掉旧的两步弹窗（ElMessageBox 选模板集 + `WorkpaperTrimDialog`）。

## R3 裁剪页联动

3.1 工具栏「⬇️ 生成底稿」打开同一弹窗，默认只勾当前循环；生成后刷新本循环（行上「未生成」随之更新）。权限与底稿列表页相同（项目内可编辑、项目未归档）。
3.2 保存粗裁成功后提示「生成本循环底稿 / 前往委派」，关掉提示则留在本页。
3.3 支持 `?cycle=` 打开指定循环（非法值忽略）；从弹窗跳过来时提示保存后可直接生成。
3.4 「裁剪建议」列显示业务分类建议：本行底稿按项目业务分类全部不适用 ⇒ 建议裁剪，附理由；委派人可一键按建议裁剪（理由自动填好，仍需保存）；本循环有这类建议时提供批量按建议裁剪。
3.5 表格工具栏显示本循环粗裁状态（已保存：谁、何时 / 未保存）。
3.6 行操作「未生成」的提示改为指向「⬇️ 生成底稿」。
3.7 「来源」列区分补充的程序行（R5）。
3.8 弹窗里点「去程序裁剪」切换循环时走本页已有的未保存修改确认，不丢修改。

## R4 母码跟随下级程序行

4.1 实质性程序循环（D~N）的编码，本身和各级母码都没有程序行、但有下级程序行（普通行，或区间行的成员）时，跟随下级：下级程序行全部已裁才算已裁，决定者回报下级程序行。
4.2 B / C / A / S 不用这条规则。
4.3 所有用 `TrimmedScope` 的入口（生成、委派、回收站恢复、粗裁应用联动、计划）同时生效；契约 README 与共享用例同步。
4.4 用只读探针核对真库：规则变化后新判为已裁的编码清单；有已生成底稿的如实报告，不自动移入回收站。

## R5 裁剪页补齐程序行

5.1 初始化一个循环时，把该循环模板编码中没有任何程序行决定的（R4 之后），以及业务分类适用性与所在程序行不同的子码，补成程序行：编码 = 底稿编码，名称取模板清单，排在原有程序行之后；没有程序行管的默认执行，适用性分裂的子码沿用原决定行的状态与理由，补齐前后每个编码的生成判定不变。
5.2 已初始化的循环再次初始化时只补缺的，幂等；并发初始化不重复（PG 咨询锁）。
5.3 补齐只经初始化接口（委派人门）；只读成员打开裁剪页不触发补齐，计划接口对未补齐的编码按默认判定。
5.4 补齐不改已有行的状态与理由，不移动、不删除任何底稿。

## R6 底稿列表页

6.1 工具栏加「✂️ 程序裁剪」入口。
6.2 「⬇️ 生成底稿」的提示文案改为按程序裁剪结果生成。

## 非功能

- 鉴权：计划 / 粗裁状态接口 readonly；补齐沿用初始化接口的委派人门；生成沿用 edit。
- 不新增迁移（粗裁状态取已有的粗裁应用凭证）。
- 界面文字全中文。
- 行数门：`ProcedureTrimming.vue` ≤ 4212（白名单 4012 +5%），新逻辑放组合式函数与新组件。
- 验收：后端单测 + 契约测试 + PG 测试；前端 vitest；单区域 vue-tsc；磁盘变异；浏览器实测（真实项目只读查看，写入只在【测试】项目）。
