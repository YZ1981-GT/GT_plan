# 需求文档：凭证身份、底稿回写与预审/年审阶段（voucher-identity-writeback-and-audit-phase）

## 概述

问题来源：`.agents/tasks/voucher-module-assessment-2026-10-27.md`（下称「评估报告」）的 M1~M4、Y1、Y2、Y4、Y5 与第六节第 3、4、7 条。用户 2026-10-27 拍板：

1. 多借多贷在底稿上按金额精确配对，配不上的标「多科目」并附整张凭证分录，不推算金额；
2. 年审抽样总体弹窗让用户选：a 只抽剩余期间；b 全年扣除预审已检样本、两阶段合并评价（默认 b）；
3. 凭证键、回写、阶段合成本 spec 分阶段做；增量追加与调整分录「客户已入账」各自单独立 spec（`ledger-incremental-append-true-merge`、`adjustment-client-booking-status`）。

目标：

- 平台上任何地方说「一张凭证」「一条分录」都指同一个东西，账套重导后身份不变；
- 一张多借多贷凭证可以回写进它涉及的每张底稿，每张底稿只取自己科目的分录，金额能与凭证对平；
- 预审做过的样本在年审不重复、不被覆盖，年审按用户选的口径抽样和评价。

分三个阶段交付：A 凭证身份（B、C 与另两个 spec 的前置）→ B 项目审计阶段与回写契约 → C 年审口径、合并评价与存续核对。

铁律：

1. 凭证键与分录指纹只有一个实现：后端一个模块、前端一个工具，跨语言一致性测试钉住。
2. 回写不编造金额：配不上就标「多科目」并附整张凭证分录。
3. 回填不丢已填内容、不重复：任何模式都不得覆盖其他阶段的行和手工行；重复导入幂等。
4. 每条守卫有磁盘变异证明；改动后用真实序时账数据与【测试】项目浏览器实测。

术语：

- **凭证键**：(年度, 主体编码, 凭证日期, 凭证字, 凭证号)。凭证字即 `tb_ledger.voucher_type`，为空按空串参与。
- **借贷栏**：一条分录记在借方栏还是贷方栏，按「哪一栏非零」判定，不按金额正负。
- **分录指纹**：凭证键 + 科目编码 + 借贷栏 + 金额 + 同组序号（定义见需求 1.3）。
- **配对**：为样本分录找出凭证内与它对应的对方分录及金额。
- **阶段**：预审 / 年审，取项目设置的「当前审计阶段」。**预审截止日**：预审覆盖期间的最后一天。
- **年审抽样口径**：a 剩余期间（预审截止日次日至审计期末）；b 全年扣除预审已检样本。
- **宿主**：内嵌抽凭引擎或提供「从序时账挂入导入」的底稿 tab（现算 78 个引擎宿主、60 个挂凭导入宿主）。
- **行元数据**：底稿凭证检查行上记录凭证键、分录指纹、阶段、批次、来源、配对状态的附加字段。

## 需求 1：凭证键与分录指纹（阶段 A）

1. 凭证键 = (年度, 主体编码, 凭证日期, 凭证字, 凭证号)，凭证字为空按空串参与；凭证键有一种规范字符串形式，可作字典键并写入 JSON 留痕。
2. 借贷栏：只有借方栏非零为借，只有贷方栏非零为贷；两栏都非零或都为零为「不明」。不明的分录照样有分录指纹（借贷栏记「不明」），用于去重与排除，但不参与配对；抽样结果和挂凭回拉在该行上标注「借贷栏不明」。
3. 分录指纹 = 凭证键 + 科目编码 + 借贷栏 + 金额（2 位小数，带符号）+ 同组序号。同组 = 凭证键、科目、借贷栏、金额都相同的分录，按摘要再按行 id 排序，序号从 0 起。摘要不进指纹，客户改摘要不改变分录身份。
4. 后端一个模块、前端一个工具实现以上三项；同一组样例两边输出逐字相同（跨语言一致性测试）。
5. 6 套真实账现算：凭证键个数等于 DISTINCT (日期, 凭证字, 号)；FY-0003 与 ZZ-0003（四川物流 2025-01-07）得到两个不同凭证键。

## 需求 2：全链路改用凭证键（阶段 A）

1. 凭证穿透（序时账穿透、下钻）按凭证键定位，接口增加凭证字参数。只传日期和号时，若命中多个凭证字，返回候选清单让用户选，不合并分录。
2. 对方科目补全与完整分录按凭证键分组，查询按样本日期收窄，不再按凭证号取全年。
3. 抽样单位「整张凭证」按凭证键聚合，抽中带出该凭证在过滤范围内的分录；总体笔数按凭证键计。
4. 已抽排除（本底稿、项目级、年审排除预审）、跨底稿重复提示、项目级抽样概览、引擎登记表、回填幂等键全部改用凭证键或分录指纹；只有凭证号的旧日志按旧口径兼容，并在抽凭历史上标「旧记录按凭证号排除」。
5. 挂凭：手工侧去重键 = 凭证键 + 目标底稿；挂凭记录保存凭证字；回拉按凭证键取分录。
6. 截止测试的「排除已提取」同口径。
7. 守卫：抽样、穿透、登记相关后端模块不得出现只按凭证号定位凭证的查询；现存清零后基线为 0。

## 需求 3：多借多贷金额精确配对（阶段 B）

1. 样本分录所在一侧只有这一条分录：对方每条分录按各自金额列出。对方只有一个科目：对方科目 + 样本金额。
2. 两侧都有多条分录：先做等额一对一配对（优先不同科目），再做一对多、多对一的子集等额配对；只接受唯一解；同科目借贷对冲只在唯一解时成立。
3. 无解或多解：对方科目标「多科目」，附整张凭证分录；不按比例分摊，不推算金额。
4. 配对成功时，样本的对方金额合计等于样本金额；属性测试守住。
5. 红字分录按借贷栏和带符号金额参与配对；多对多配对时红字与蓝字不互相凑数（需求 3.1 的单边只有一行的情形不受此限）。
6. 分录超过上限（默认 200 行）的凭证不做配对，标「多科目」，附「对方科目汇总（非配对）」与查看整张凭证的入口，不把全部分录写进底稿行。
7. 配对只在后端实现一次；抽凭结果、凭证穿透、挂凭回拉都返回同一配对结果；前端只消费结果。
8. 测试向量：四川物流 FY-0012 的两笔银行付款（2,000 + 1,680）配对到应付职工薪酬 3,680；管理费用 3,680 配对到贷方应付职工薪酬 3,680。

## 需求 4：回写契约（阶段 B）

1. 底稿凭证检查行带行元数据（凭证键、分录指纹、阶段、批次、来源、配对状态）；宿主保存再读取、在线编辑往返后元数据不丢。
2. 回填模式只有两种：「追加」按分录指纹去重；「替换本阶段抽凭行」只删同阶段、来源为抽凭的行，其中已填核对结果或附件的行先列出并确认。旧的「合并」按「追加」处理。
3. 已在表里的分录再次出现时保留原行全部内容，不覆盖核对结果和附件。
4. 「从序时账挂入导入」幂等：已在表里的分录不再插入，提示「已存在 N 行」。
5. 同一底稿里手工挂凭与抽凭命中同一分录只保留一行，来源记为两者。
6. 撤销抽凭：引擎通知宿主删除该批次的行；有已填内容的行先确认，取消确认则不撤销；提示语如实说明删了几行。
7. 78 个引擎宿主与 60 个挂凭导入宿主全部改用共享回填函数，D2 的 replace 映射与 K3 的空操作在接入时修正；守卫列出未接入宿主，只许减少，交付时为 0。
8. 底稿行显示阶段标签与配对状态，「多科目」行可展开看整张凭证分录。

## 需求 5：一张凭证挂多张底稿（阶段 B）

1. 挂凭弹窗可多选底稿，推荐底稿默认勾选；一次提交，逐条返回成功、已存在或失败原因。
2. 序时账明细层与凭证层显示该凭证已挂或已抽于哪些底稿（底稿编码、来源、阶段）。
3. 修正 `useAttachedVouchers.attachVoucher` 的过期注释。

## 需求 6：项目审计阶段与预审截止日（阶段 B，先于宿主接入）

1. 项目设置新增「当前审计阶段」（预审 / 年审，缺省年审）与「预审截止日」；项目经理、合伙人可改，改动写审计日志。
2. 抽凭、挂凭、挂凭回拉生成的行，阶段取项目当前阶段；宿主不再传写死的阶段；引擎界面显示当前阶段与预审截止日。
3. 年审阶段预审行只读（不可改、不可删）；预审阶段不限制。
4. G5、K1、J1、M1、M2 的「本期 / 期后」改用独立字段，不再占用阶段。
5. 守卫：宿主不得给引擎传字面量阶段；接口只接受预审、年审两个值，其他值返回 422。

## 需求 7：年审抽样口径与两阶段评价（阶段 C）

1. 年审阶段在某底稿发起抽凭时，若该底稿有未撤销的预审批次或预审行，弹窗让用户选口径：a 只抽剩余期间；b 全年扣除预审已检样本（缺省）。弹窗显示预审批次数、预审样本数、预审截止日；该底稿上次的选择作为下次缺省。
2. 口径 a：抽样日期范围锁定为预审截止日次日至审计期末。项目未设预审截止日时，提示先设置，或采用预审批次期间的上限并在留痕中注明。
3. 口径 b：抽样框 = 全年分录 − 本底稿预审已检分录（预审抽凭批次的分录指纹 ∪ 预审手工挂凭在本底稿科目范围内的分录）；按分录指纹排除，账套重导后仍生效。
4. 口径、预审截止日、排除清单规模写入批次留痕；抽凭历史与抽样记录显示口径。
5. 全年合并评价：口径 a = 预审推断错报 + 年审推断错报（两段总体不重叠），错报上限同样相加；口径 b = 预审已检样本的实际错报 + 年审推断错报（年审总体已扣除预审已检项目），错报上限 = 预审实际错报 + 年审错报上限。合并结果与全年可容忍错报比较给出全年结论；两阶段科目范围不一致时提示「仅供参考」。
6. 批次评价新增「样本实际错报合计」（缺省不写，旧记录输出不变）；合并评价写入年审批次评价并投影到抽样记录。

## 需求 8：预审样本存续核对（阶段 C）

1. 账套重导激活后，带预审行的底稿可一键核对：每条预审分录在当前账套中为「未变 / 分录已改 / 凭证已删除 / 疑似重编号」（疑似重编号 = 同日期、同科目、同借贷栏、同金额的其他凭证）。
2. 底稿行显示核对状态，非「未变」的行醒目标注，可逐行确认；确认结果连同账套版本记入行元数据。
3. 项目级抽样概览显示各底稿未确认的变动行数。

## 需求 9：守卫与验收

1. 每个阶段的守卫都有磁盘变异证明，记录「变异 → 打红的测试 → 还原核对」。
2. 真实账测试向量：FY-0012 配对、ZZ-0003 与 FY-0003 分开、医疗器械银行存款整张凭证抽样单位数 = 8,592。
3. 【测试】项目浏览器实测：预审抽凭并填核对 → 切年审 → 重导全年账 → 存续核对 → 弹窗选 b 年审抽凭 → 底稿无重复行、预审行只读、排除生效；一张多借多贷凭证挂两张底稿后各取各的分录、金额对平；撤销后底稿行回滚。清理走平台路径并对账。
