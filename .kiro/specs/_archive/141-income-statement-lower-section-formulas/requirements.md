# 需求文档：S9　利润表净利润以下行的公式补全

> **本 spec 由 `formula-hub-integrity-closure` 按需求 17.5 创建（design §8.1 的 S 系列交接）。**
> 创建时只有本文件：它的作用是让「formula-hub-integrity-closure 没做、但已知必须做」的事有明确的负责范围与触发条件，
> 不在归档时丢失。实施前需补 design.md 与 tasks.md，并按三件套纪律先做「现状 grep 确认」
> —— 下面每条都是 `formula-hub-integrity-closure` 实施期的现读结论，**启动时必须重新现算**（memory 方法论铁律①②）。

## 1. 负责范围
- 利润表「净利润」以下各行（国企 IS-046 / 048 / 049 / 053 / 054 / 072，上市 IS-029~032 / 049）真库无公式、活项目全为 0（F34）。
- 归属行（IS-074 / 075、IS-051 / 052）的组成行就在这批里 ⇒ 现在归属行算出来恒为 0。
- 本 spec D14 的默认只做到「组成行未定义公式」以 warning 可见（需求 6.4），补全归本 spec。

## 2. 依赖与先后
依赖 `formula-hub-integrity-closure` ADR-FHIC-05（三路统一逐行计算）与 ADR-FHIC-23（归属行种子 + 合计行守卫）已落地。

## 3. 触发条件

决策项 X2（存量 8 行归属行升级）执行后，归属行有了正确公式但组成行仍为 0 ⇒ 立即启动。

## 4. 承接自 `formula-hub-integrity-closure` 的具体欠账
- 本 spec 任务 18 范围外登记：四套「综合收益总额」合计行现存 `SUM_ROW` 只加其他综合收益一段、不含净利润，
  按需求 6.1 写入归属行后「归母 + 少数 ≠ 综合收益总额」—— 组成行都是 0 时看不出，补全后会暴露。

## 5. 不属于本 spec

- `formula-hub-integrity-closure` 已交付的部分不回填改写（历史档案 append-only）；本 spec 只做上面第 1 节列出的事。
- 决策项 X1~X5（共享库迁移与推送、存量归属行升级、真实项目报表重算、门禁切 enforce、D1~D15 默认值确认）
  属用户决定，不由本 spec 代为执行。

## 6. 设计阶段补充（2026-10-29）

- 已补 design.md / tasks.md。现状复核见 design §1：净利润的上游也是坏的（营业利润无公式、利润总额三套写错、五个叶子行无取数），交接清单还漏列了上市 IS-024 等行；建议范围扩到整条利润链（design §4 D1）。
- 国企利润表小计行排在明细之前，需要报表按依赖拓扑序求值，建议从 S1 移入本 spec（design §4 D2）。
- 两个外部前提：①活项目试算表与报表是旧代码算出、没再重算的陈旧结果（报表营业收入 4/5 为负，华氏是三级科目全加再取负），现行代码重算即为自然正数；不需另立 spec，按已有的类别更正与符号迁移脚本做运维，须用户放行（design §1 第 9、12 行，§4 D3）。②手工输入行在重新生成时被写成 0（design §4 D5）。
