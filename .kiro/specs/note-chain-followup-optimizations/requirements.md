# 附注链后续优化 — 需求

## 背景

承接 `note-disclosure-formula-and-consolidation-chain-closure`（v1.0.42）的后续建议。开工前现算（远端 `9f1cb9c7b`）：
并发 spec `note-pull-residual-governance-closure`（v1.0.43）已完成 11 个离屏 provider（78/78）、M 循环自动同步、
`五、42 / 八、42` 写权、G7 附注侧清册与合并真实 UAT，本 spec 不重复；其登记的下一轮 P1（离屏运行观测、PG 连接饱和）也不在本轮。

本轮只做五件事：附注公式在底稿来源章节上真正生效；每个附注单元格可查最终来源；合并拉数同名行按所在分组判别；
标题行库可修的未对应列；附注页告警与提示失效。

## R1 附注公式按显示视图生效

1. 底稿来源章节（`_source` 为 workpaper / workpaper_html 且 `sub_table_data` 可投影）的公式列表、目标清单、保存校验、执行与覆盖率统计，
   一律以编辑器 / Word 导出看到的同一份显示视图（`effective_table_data`）为准；非底稿来源章节行为不变。
2. 执行结果写回投影来源：`sub_table_data[子表][源行][业务列键]`，不再写进隐藏的旧 `_tables` 或顶层镜像。
3. 底稿披露表是这些表的数值权威：预设公式（合计、账面价值）只补空格；底稿已有值且与公式结果不一致时不改写，逐格回报差异。
   用户公式（全局 / 本项目适配）按用户意图覆盖，并在结果中标明覆盖了底稿值。
4. 存过的旧 `_formulas` 只适用于其生成时的存储结构；显示视图是投影时不再套用。
5. 不新增迁移；推送、同步、binding refill 的写入位置与人工 / 锁定保护不变。

## R2 单元格最终来源诊断

1. 新增只读接口，按章节 + 表序号（可选行 / 列）返回每格：当前值、最终来源（人工 / 锁定 / 整节人工覆盖 / 用户公式 / 预设公式 /
   公式推送 / binding 取数 / 底稿披露表同步 / 模板生成）、是否已核实、候选来源（规则、层级、推送状态、绑定、同步时间）与冲突说明。
2. 判定顺序与运行时一致：`prepare → headless → push → refill → note formulas`，人工 / 锁定 / 整节覆盖优先。
3. 接口与同目录只读接口同一鉴权（项目 readonly），不调用任何会写库的物化或执行函数。
4. 单元格溯源弹窗显示最终来源与冲突，并带表序号；原 binding 溯源接口支持表序号，多表章节不再一律读第 1 张表。

## R3 合并同名行按分组判别

1. 读取单体来源行时同时给出所在分组（最近的分组头 / 「其中」上级行）与组内序号；二者不进结构指纹，已确认规则与绑定不失效。
2. 映射建议遇同名多行时先按分组配对；分组对不上只按出现顺序配对的建议不可自动确认，须用户在弹窗确认。
3. 新确认的映射可带分组；apply 遇同名多行且映射带分组时只取该组的行，组内找不到时不跨组兜底。旧映射（无分组）行为不变。
4. 映射弹窗显示同名行所在分组。

## R4 标题行库可修未对应列

1. 逐条核对现算未对应列，只修「同一含义、写法不同」与「列角色认错」两类；结构确实不同的保持未对应并写明原因。
2. 优先逐表覆盖（带 reason）；只有跨表无歧义的长词才加全局别名。
3. 重新生成库文件与对应文件，`--check` 通过；覆盖率棘轮按现算收紧，钉住的逐列对应测试不破。

## R5 附注页告警与提示失效

1. 附注编辑路由在过渡动画内渲染单一元素根，消除「非元素根无法动画」告警。
2. 批注提示在无批注时不再渲染片段根，外层提示的触发属性落到真实元素；附注单元格校验提示与批注提示都能触发。
3. 报表页公式提示包金额单元格的同类问题一并消除。

2. PG 连接饱和已由并发 spec 列为下一轮 P1，本轮只在设计中记录建议。
