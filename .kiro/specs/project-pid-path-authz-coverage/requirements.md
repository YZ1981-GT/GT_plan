# 需求：路径参数写成 `{pid}` 的项目接口鉴权覆盖

来源：`platform-performance-residual-findings-closure` design §8.2（用户 2026-10-31「属于鉴权范围，另立 spec」）。

## 背景（现算，2026-10-31，`app.main.app`）

- 项目段路径参数：`{project_id}` 947 条路由，`{pid}` 49 条。鉴权基线守卫 `test_project_endpoint_authorization_baseline.py` 三个维度（装饰器路径无鉴权 / 仅登录棘轮 / 路由前缀维）都只认字面量 `{project_id}` ⇒ 49 条 `{pid}` 路由从未进入视野。
- 49 条里：22 条程序裁剪 / 委派 / 投递 / 主编走 `require_project_delegator_pid`；5 条版本链与 1 条程序复核对话走底稿门 / 任务门（`enforce_wp_gate` / `enforce_task_gate`，带路径项目）；2 条程序复核写入按「任务属于路径项目 + 当前参与者」；抽凭 4 条、抽样阶段 5 条按底稿权限并校验底稿属于路径项目。
- 真实欠账：
  - `review_prompt.py` 全文件 7 个端点一个鉴权依赖都没有（未登录也能调）：批量 AI 复核（逐张调大模型、写复核结果）、复核进度、导出复核报告（项目数据外泄）、单底稿 AI 复核（读底稿内容、写复核结果）、复核发现状态更新（改任意项目的记录）、提示词覆盖率、调用指标。
  - `cutoff_sampling.py` 4 个端点仅登录：任意登录用户可按任意项目取序时账、往任意底稿写抽样日志与版本快照、撤销记录。
  - `voucher_sampling.py` 历史、对比 2 个端点仅登录：按底稿 id / 记录 id 跨项目读取。

## R1 扫描口径

1. 鉴权基线守卫把「项目段参数」从字面量 `{project_id}` 扩到 `/projects/{任意名}`，三个维度同一口径；扩口径后的分母须 ≥ 原分母 + 49。
2. 双向自检：注入的 `{pid}` 无鉴权样本必须被抓到；带项目级鉴权的 `{pid}` 样本不得误报。

## R2 修真实欠账

1. 批量 AI 复核项目 review 级；复核进度、导出复核报告项目只读级；单底稿 AI 复核按底稿所属项目 review 级（底稿不存在 404）；复核发现状态更新按该发现所属项目 review 级（不存在 404）；提示词覆盖率、调用指标须登录。
2. 截止测试：提取 / 回填 / 撤销按底稿编辑权、历史按底稿只读权，底稿须属于路径项目，否则 403（与抽凭同口径）。
3. 抽凭历史按底稿只读权且底稿属于路径项目；抽凭对比的两条记录须属于路径项目（否则按不存在 404），并有记录所在底稿的只读权。
4. 收紧不得误伤：鉴权依赖放在取数 / 写入之前；前端调用方已带登录令牌，不改前端。

## R3 已有对象级鉴权的计入项目级

1. 底稿门、任务门、程序复核参与者判定计入「项目级」token，每个 token 都有可伪证用例（函数里真校验了路径项目 / 对象归属）。

## R4 基线

1. 「仅登录不校项目」两个棘轮按新口径重算后写入；扩口径带进来的 `{pid}` 端点修完后不得留在仅登录档。

## 验收

- 端点级用例（真实请求）：每个修过的端点 未登录 401、非成员 403、成员放行；跨项目底稿 / 记录 403 或 404。
- `test_project_endpoint_authorization_baseline.py`、`test_x3_entry_coverage_ledger.py`、受影响模块既有用例全绿；既有调用这些端点的用例按新鉴权补身份，不放宽门禁。
- 不提交、不推送；未实测的项标 `[ ]*`。
