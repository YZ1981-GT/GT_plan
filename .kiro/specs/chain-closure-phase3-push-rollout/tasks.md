## 阶段三硬验收矩阵（2026-10-01，追加式）

> 本节是任务 16~19 的可执行收口边界，不新增第五套公式系统。每一行都必须有「基线/修复后/故障注入」三类证据；只写在工作树、只勾选任务、或只证明调用发生，均不得视为完成。计数和路径在执行时现算，禁止把本节示例数字当基线。

| 闭环段 | 必须证明的真实行为 | 最低证据与故障注入 |
|---|---|---|
| 四表入库 → TB 未审数 → `TRIAL_BALANCE_UPDATED` | 激活数据集入库后，未审数仍由映射聚合产生；事件携带项目、审计年度和受影响科目，且只触发对应 binding | 真 ORM 集成测试覆盖 active/superseded/staged 三态、父子科目和重导入；删事件发布或改错年度必须红；`formula_push` 取数失败必须零业务写入并留失败运行记录 |
| TB 未审数 → 底稿明细 | 只刷新已存在且属于四表带入的种子行；用户新增行、用户字段、缺失目标行不被后端创建或覆盖 | E1/K1 binding 真数据测试 + 前后端夹具逐值对拍；移除种子行过滤或把缺行改为自动建行必须红；成功写入必须含 `project_id`、版本递增和更新时间 |
| 底稿明细 → 披露表/审定表 | 派生键按前端同式重算，系统值由公式推送唯一写入；保存底稿时不把后端独占键回写 | SQLite 真 ORM 端到端 + 前端真 composable 挂载测试；将派生值改回读旧持久化值、或放开前端独占键保存，均必须红 |
| 调整分录大厅复核通过 → AJE/RJE/TB 审定数 | `approved` 是唯一确认点；审批后按统一口径更新 AJE/RJE 和审定数分量，并推送报表、底稿审定/披露、调整大厅可见状态 | 状态机 + TestClient 真请求 + SQLite/PG 集成；draft/审计助理/质控/只读/非成员必须按权限拒绝；审批事件、订阅集合或分量写入任一缺失必须红 |
| 撤回复核 → 全链回退 | `approved → draft` 清空复核人和时间，发布年度事件，重算与过期标记路径与审批对齐，历史触发标签可区分 | TestClient 真请求 + 事件订阅 AST/行为断言；变异为不清复核字段、不发事件、漏订阅或仍保留下游值必须红 |
| 底稿调整 → 调整分录大厅 | 相同内容不写库、不换编号；变化原地更新并保留组号；待复核/驳回回草稿；已复核必须先撤回；前端首次载入不自动同步，编辑后防抖同步 | service 真库/SQLite 测试 + Vitest 真挂载；恢复“软删旧组再新建”、去掉签名去重或首次载入同步，必须红 |
| 审定数单一写入方 | 发布门在同一 UPDATE 写审定数、底稿调整分量、发布基准和时间；审批、重导入、映射变更后保持 `未审 + RJE + AJE + 底稿调整`；其他直写只能减少 | V176/R176 真 PG 两次幂等、回填和回滚；发布→审批→重导入集成测试；AST 直写基线只许减少，去掉分量保留或新增直写点必须红 |
| 附注主表章节交接 | E1 按 `template_type` 只交接上市「五、1」或国企「八、1」；缺表可建与前端逐字一致的骨架；有遮挡数据则跳过并报告；前端不再写主表 | 前后端共享夹具逐字对拍 + 行锁测试 + E1/K1 真 ORM 测试；改一个标签/列定义、放开错误章节或跳过遮挡检查必须红 |
| 公式管理可见可控 | 规则、binding、最近运行、差异状态和手动操作均从真实接口取得；新增 binding 不需改第二处清单；写端点有项目编辑权限 | TestClient 真请求覆盖读/写权限、临时假 binding 注册/撤销和规则子集；恢复 `PUSH_WP_CODES` 或去掉项目权限必须红；全中文 UI 由真挂载断言 |
| 幂等、CAS、冻结和审计追踪 | 同一输入重复推送不产生业务变化；人工值/锁定/复核通过底稿按策略保留；CAS 冲突整张底稿回滚；每次实际运行有触发源、计数和目标明细 | policy/engine 集成测试 + 并发或版本变异；去掉 CAS、冻结判断、上次推送值、运行明细任一项必须红；空写不得递增版本或广播 changed item |
| SSE、失败重试与回环 | 成功和复核状态变化按契约广播；引擎写入不再次发布 `WORKPAPER_SAVED`；业务拒绝与系统故障区分，故障可重试且不冒泡为假成功 | 事件调用点守卫 + SSE 客户端/前端提示条测试；把 `broadcast_raw` 参数错位、同步函数 `await`、失败吞掉或反向发布保存事件，必须红 |
| 真 PG 与零痕迹试跑 | PG 方言、约束、行锁、唯一键、CAS、级联和回滚行为不能由 SQLite 代替；真实项目只在事务内 dry-run，前后指纹逐字相同 | 一次性 schema/临时事务脚本，独立记录 row count、指纹和 rollback 结果；去掉 `project_id`、把时间戳传字符串、或将 dry-run 改为 commit 必须红 |
