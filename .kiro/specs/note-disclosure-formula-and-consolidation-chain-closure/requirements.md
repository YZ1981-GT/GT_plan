# 附注披露取数、公式与合并拉数闭环 — 需求

## 背景

承接已归档 `note-pull-header-formula-closure`、已完成 `note-pull-followup-closure` 与
`consol-note-header-library-and-node-reaggregate`。本轮不重做已交付能力，只修现读生产代码暴露的残留断点。

用户目标：单体项目按国企/上市各自底稿披露表生成附注；表名、顺序与合并表头对应 Word 模板；主表金额取过完调整分录的审定数；
附注刷新、全部刷新、生成和重试不要求再打开底稿；合并附注只从企业树叶子对应的单体附注拉数，不新增合并底稿披露表；公式管理成为
预设公式、项目适配、自动更新与溯源的统一入口。

## R1 权威源和准则隔离

1. 单体附注的章节、表名、表序和合并表头以对应口径 Word/附注模板为结构权威；业务字段与披露明细以同口径底稿披露表 builder 为数据权威。
2. 国企项目只执行国企 builder，上市项目只执行上市 builder；不得把另一口径的表名、列分组或期间词写入本项目。
3. 主表审定金额由公式推送取 TB 审定数；账龄、坏账准备分类、前五名等明细由底稿披露 builder 写入；表内合计、账面价值和用户公式最后执行。
4. 前端重投影 raw 行时必须保留后端按模板增强的 `headers/multi_header/_column_groups`，不得让旧 raw 表头覆盖 Word/模板结构。

## R2 单体刷新顺序与入口一致

1. 完整顺序固定为：读取底稿/章节上下文 → headless 披露 builder → 公式推送审定主表 → binding refill → 附注预设/用户公式 → 重载目录与详情。
2. “刷新”“全部刷新”“生成”“手动重试”“试算表重算后的附注刷新”共用同一编排；不得有只做 refill、未做披露 builder 的伪刷新。
3. `pull-from-workpapers` 支持只准备上下文和只执行推送两个阶段；旧调用默认行为保持兼容。
4. 生成前先同步披露数据，生成后再做 binding 与表内公式，首次生成也不得因章节尚不存在而漏掉审定主表值。

## R3 复数章节映射

1. 注册表的 `listed_sections/soe_sections` 与主 `listed/soe` 键同等有效，并在章节→底稿、章节→sheet、刷新状态、stale 标记中使用。
2. G1、G10、L3 等次级章节单章刷新时必须能找到同一底稿 provider；映射结果去重且顺序稳定。
3. 仍未接入 headless 的 11 个 wp_code 保持显式清单，不以复制 builder 或 TB 猜明细的方式绕开。

## R4 提交后事件、过期与溯源

1. 标准单章/批量披露同步成功后清 `is_stale/stale_source`；被人工覆盖守卫拦下时不得伪清。
2. 单章、批量披露同步及公式推送修改附注后，必须在提交成功后发布逐章节 `NOTE_SECTION_SAVED`，携带真实章节号与来源动作。
3. 事件发布失败不回滚已提交业务；事件不得在事务提交前触发下游读取。
4. 合并附注、地址目录、交付件和 stale 引擎应收到同一事件，不依赖仅供 UI 的 raw SSE。

## R5 公式管理

1. 单体附注节点顶部“应用自动运算”必须执行当前章节的 note 公式端点，不得误走 report 批执行。
2. 公式治理域按实际上下文映射：底稿=`wp`、推送页=`push`、单体附注=`note`、合并附注=`consol_note`，不得回落到 `report`。
3. 预设公式按每张当前表结构现算；公式推送只搬运审定主表，禁止把披露明细伪造成 TB 公式。
4. 公式运行记录、格级状态、来源底稿、规则和章节保持可追溯；人工/锁定格继续保留。

## R6 合并附注拉数安全

1. 企业树叶子的 `project_id` 是唯一单体来源；读取每个来源时按该单体项目自己的模板口径解析表头，而非套用合并项目口径。
2. `header/header_label/title` 行不进入明细映射和金额累加；序号列不作为行名，业务标签列按投影后的 label 读取。
3. 每次 apply 必须服务端复核当前来源结构 hash、当前模板绑定版本、规则项目与章节；不一致即标 mapping stale 并跳过，不能沿用旧规则清 stale。
4. 未绑定、待确认或结构 stale 的叶子使祖先本章节保持 incomplete/stale；允许展示旧数，但不得标成“已最新”。
5. 前 N 名仍走跨企业重排，不伪造逐行 MappingBinding；其单体章节变化也必须进入合并 stale 影响面。
6. 自动映射只自动确认精确/别名等既有安全集合；模糊、结构变化和新增行继续通过用户弹窗确认。

## R7 模板工具与验证

1. 四版 Word 树门禁和底稿披露表对齐门禁继续同时通过；两者口径不同时必须有可伪证理由。
2. 遗留位置式 `phase5_standalone_title` 不得再把“续：”或后续表标题错位写入 JSON；标题/表序检查复用现有树匹配结果或明确退役旧写路径。
3. D2 应收账款作为验收样本：国企 15 张、上市 17 张单体表保持各自结构；合并映射分别按对应子表取数，多级表头不展平错列。
4. 不新增数据库迁移；真实浏览器写入只使用【测试】项目。
