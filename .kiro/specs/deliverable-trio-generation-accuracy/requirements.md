# 交付中心三件套生成准确性（审计报告正文 / 财务报表 / 附注）

## 1. 背景与实测结论

用户在交付中心点「生成审计报告正文 / 生成财务报表 / 生成附注」后，要求产物数据准确、格式满足模板。
2026-10-16 用真实 PG 数据（重药安徽 0ec33ac9、陕西华氏 a7fc75e5、宜宾临港店 c8621493、和平药房 2aa00f57）
在事务回滚下逐份生成并解析产物（探针在仓库外，不落库），结论：**三类产物当前都不能直接出具**。

### 1.1 财务报表（xlsx）—— 数字错位（最严重）
- 模板占位 `{{row:CODE}}` 的编码体系 = `report_config_seed.json`（与模板 100% 一致），但库内 `report_config`
  在 2026-04-29 / 06-16 两次写入后成了两套编号的混合体：soe_standalone 226 个占位中 113 个编码对应的行名与模板不同
  （soe_consolidated 118/226、listed 64/146）。导出按编码取数 ⇒ 安徽 BS「衍生金融资产」= 596,123,623.29（实为应收账款），
  「其他应收款」= 1,112,635,043.04（实为流动资产合计），资产总计 3,176,626,368.55（报表模块为 1,150,653,665.03）；利润表同样错位。
- 减值准备表：前端勾选键 `impairment_provision`，导出器 sheet 映射键 `asset_impairment` ⇒ 该表在四个变体都被删除。
- 上市版权益变动表：sheet 别名缺失 ⇒ 模板矩阵被删，换成三列草表。
- 上期 / 期初列恒为 0：上期按 `year-1` 试算表重算，而项目按年度建立、同项目无上年试算表；资产负债表期初应取本年试算表 `opening_balance`。
- 利润表 / 现金流量表表头显示「2025年12月31日」（应为「2025年度」）；部分模板表头写死年份。
- 报表附注列 11 行指向会计政策章节（如「存货」→「四、存货」，应为「八、10」）。
- 现金流量表全 0（上游未编制）、库内资产负债表本身不平（安徽资产总计与负债和所有者权益总计差 3,940,244.54）——导出无任何提示。
- 报表差异检测（drift）按编码比对，与导出口径同源，修导出时必须同步修，否则确认闸门误拦。

### 1.2 附注（docx）—— 模板内容与库内正文叠加、数据表缺失
- 模板块内的编制指引（「（注：…）」「（提示：…）」「【…】」）、示例文字、空白参考表全部原样保留，库内正文再插一遍 ⇒ 每节内容重复、带指引、带空表；`X.XX` / `xx` 示例值进入交付件。
- `{{seq}}` 单独成段输出「1」，而标题样式自带自动编号 ⇒ 每节出现「1 / 1、货币资金」两行。
- 页眉 `{{company_full_name}}`、`{{audit_year}}年度` 从未替换（每页可见）。
- 单体国企模板删除了合并专用的第七章，Word 自动编号使「财务报表主要项目注释」显示为「七、」，而章节编码、报表附注列、正文交叉引用均为「八、」。
- 多表章节只渲染有占位的表：续表、额外表（如「受限制的货币资金明细」）的库内数据被丢弃，模板空表留在原位。
- 未勾选 / 库内无对应的章节按模板原貌保留（标题 + 指引 + 空表）。
- 生成表格字号 12pt、行高固定 0.7cm（标签换行被截断），与模板表（表样式 27/28、9pt、最小行高 0.6cm、表头重复）不一致；合计行不加粗。
- 库内正文质量：安徽 / 华氏 / 和平 / 医疗器械每家约 150 章正文含「[请补充]」，110+ 章含「审计师提示 / 审计师备注」，40~56 章含「请提供上述数据，我将为您生成…」等大模型对话语；
  根因是 `disclosure_engine._generate_text_with_llm` 通用提示词要求「数据不足请标注需要补充的信息」且不给附注表数据。
- 数据完整性：多数科目附注表在库内为空（安徽「应收账款」13 张表数值全 0，报表应收账款 5.96 亿），导出不提示。

### 1.3 审计报告正文（docx）
- 选「带强调事项段的无保留意见」与标准无保留逐字相同（模板无强调事项段）。
- 保留 / 否定 / 无法表示意见的单体模板含未闭合的 `##NOTE:单体复核:…##`，剥除正则匹配不到 ⇒ 标记和「集团审计」措辞进入交付件；证监会《监管规则适用指引》编制提示框（1×1 表）、「【非上市实体删除（项目合伙人）】」原样保留。
- 落款日期写死「二〇二六年 X 月XX日」，无法表示意见模板写死「二○二二年X月XX日」。
- 正文与目录写「股东权益变动表」，而国企有限公司报表为「所有者权益变动表」。
- 弹窗里的「公司类型 / 公共利益实体」从未传给后端；`missing_fields` 以英文键名展示。
- `audit_report` 表 0 行 ⇒ confirm 不写 `report_body_json`、KAM 校验恒跳过。

## 2. 用户故事与验收标准

### US-1 财务报表数字与模板行一一对应
- AC-1.1 每个模板占位按「编码一致且行名一致 → 行名唯一匹配 → 同名多行按出现顺序」绑定到报表行；编码相同但行名不同不得取数。
- AC-1.2 行名比较忽略空白、全半角括号、序号前缀（一、/（一）/1.）、「其中：/加：/减：」前缀与「（损失以“－”号填列）」类后缀；△▲#* 标记必须一致。
- AC-1.3 导出器、报表差异检测、母公司个别列三处使用同一绑定结果（同源）。
- AC-1.4 安徽 / 华氏 / 宜宾 / 和平四个真实项目导出后，资产负债表各明细行、资产总计、负债和所有者权益总计、利润表营业收入 / 营业利润 / 利润总额 / 净利润与报表模块逐值一致（差 ≤ 0.01）。
- AC-1.5 无法绑定且库内有金额的报表行、以及模板合计与报表合计不一致，均作为导出提醒返回，不静默。

### US-2 报表完整、期间与表头正确
- AC-2.1 勾选的减值准备表、上市 / 合并变体的权益变动表都出现在导出件中，保留模板矩阵格式。
- AC-2.2 资产负债表期初余额 = 本年试算表期初数按同一公式计算（含合计行）；利润表 / 现金流量表上期金额取上年项目报表（无则上年项目试算表重算）；都没有时留空并提醒，不写 0。
- AC-2.3 资产负债表表头为截止日（取项目审计期末，缺省 12 月 31 日），其余报表为「YYYY年度」；表头写死的年份按本年 / 上年替换。
- AC-2.4 权益变动表「综合收益总额 / 净利润」按行名取利润表净利润，不写死行编码。
- AC-2.5 减值准备表填期初、期末余额；本期增减无来源时留空，期末不被模板公式算成错误值，并提醒需补充。
- AC-2.6 报表附注列指向报表项目注释章节（不指向会计政策章节），编号与附注交付件显示一致。

### US-3 附注按模板结构输出库内内容
- AC-3.1 保留章节只输出：模板标题（含自动编号）+ 库内正文 + 库内全部有数表格；模板指引、示例、空白参考表、占位符一律不输出。
- AC-3.2 库内表格按表名对应模板表位；列数一致时套用模板表格式（表样式、列宽、表头合并、字体字号、合计行格式），否则按模板表样式生成；续表 / 额外表不丢失。
- AC-3.3 编号只出现一次；章节被删后编号连续；一级章标题不随章节删除而消失。
- AC-3.4 页眉页脚公司名称、年度替换为项目值。
- AC-3.5 只输出用户勾选且有内容的章节；库内有内容但模板无位置的章节追加到所属章末尾，不丢弃。
- AC-3.6 正文交付前剔除：与标题重复的首行、大模型对话 / 编制提示段落、全部为占位的表格、模板式编制指引括注；剔除数量与残留「[请补充]」章节数作为导出提醒返回。
- AC-3.7 单体国企附注正文与报表附注列的交叉引用编号按交付件实际章节号显示（如「八、1」→「七、1」）。
- AC-3.8 导出提醒列出「报表有余额但附注表为空」的主要科目。

### US-4 审计报告正文按意见类型正确生成
- AC-4.1 「带强调事项段的无保留意见」在「形成审计意见的基础」后插入「强调事项」段（含待补充提示），后续标题序号顺延。
- AC-4.2 交付件无 `##` 标记、无编制提示框、无【…】编制提示；单体报告删除集团审计专用条款，并把示例段落中的合并报表措辞改为单体口径。
- AC-4.3 落款日期：有报告日期用中文日期，否则为「审计年度 + 1」年并保留待填月日。
- AC-4.4 权益变动表名称按企业组织形式（股份有限公司→股东权益，其余→所有者权益），与报表一致。
- AC-4.5 弹窗可选报告模板类型（自动 / 四类企业），选择真实传给后端；待补充字段以中文显示且只列模板实际使用的字段。
- AC-4.6 confirm 后存在 `audit_report` 记录，写入意见类型、模板信息与 `report_body_json`，KAM 校验生效。

### US-5 附注正文生成源头不再产出对话语
- AC-5.1 通用大模型路径提示词禁止输出占位、提问、编制提示与重复标题，并提供本章表格数据；输出经同一套交付过滤后保存。

## 3. 非功能要求
- NFR-1 不改库内 `report_config` 编号体系（平台既有约定以库为准，改编号影响面过大）；绑定在导出读时完成。
- NFR-2 交付导出不落新列、不加迁移；只读失败一律 fail-open 为提醒，不阻断导出。
- NFR-3 保持既有锚点 / 内容控件 / 回填 / 增量刷新链路可用；并发会话在 `note_word_exporter.py`、`deliverable_writeback_service.py` 的未提交改动不得覆盖。
- NFR-4 每项修复配回归测试（真模板 + 合成数据），并用四个真实项目复验。
