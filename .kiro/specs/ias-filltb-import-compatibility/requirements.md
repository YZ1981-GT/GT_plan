# IAS / FillTbTool 导入兼容（A）：需求

## 概述
本 spec 定义账套导入兼容行为，目标是确认结果、四表实际写入和下游状态一致，不是复刻 IAS / FillTbTool 产品。生产现状依据本轮只读源码核实，定位见 `design.md` 的“现状与可复用机制”。
本轮交付为 0、A 两份 spec 与两本离线审阅 Excel；Excel 已生成并通过现有自检，平台产品未实施。实际基线为 HEAD `9684955683720068cf3aad82dfc5502a0194e73c`，分支 `sj-dev1.0`；spec 仅文档交付，无提交或推送。A 的实现及运行验收、真实部署和真实客户数据均未验证。

## 边界与依赖
- A 负责解析、确认合同、期间归并、层级选择、校验和导入链接线；0=`.kiro/specs/ias-filltb-rule-catalog-crosswalk/` 仅交离线目录与编码候选对照，不提供 runtime alias 包。A 参考 0 已核实目录，在现有 identifier/adapter 规则载体内独立实现经确认的语义；本轮 Excel 不直接加载，外部未确认不启用。
- 金额单位检测、换算、舍入及存储单位证明由 `.kiro/specs/platform-global-display-settings-closure/requirements.md` 的 R7/R8 管理；A 只消费其合同，不另建单位实现或放行入口。依赖未就绪仅影响对应激活场景的验收，不阻断 A 其他开发。
- 只使用明确授权的样本和有来源记录的行为说明，独立实现兼容行为；不复制闭源代码、规则资源或许可机制。合成样本须明确标注，不能充当真实客户验收。
- 现场取数工具（IAS 数据采集工具）的财务软件直连、备份还原、SAP RFC、定时采集、整库复制不进入平台；平台只接收其产出的 Excel/CSV 结果文件。工具包中的密码破解、口令读取、数据恢复组件不得进入平台代码、镜像或交付物。对比依据见 `docs/reviews/ias-filltb-fusion/IAS数据采集工具对比分析.md`。
- 不重建增量机制、数据集状态机或权限体系；不批量改写历史账套，不改变已有退役入口的决定。

## 需求与验收标准

### A1 列位置稳定身份
作为导入人员，我希望重复表头和人工确认不会在后台执行时失效。
1. **A1.1** 当 detect 产生列候选时，系统应以 bundle 文件项身份、文件指纹、sheet 定位和零基 `column_index` 标识列；原始表头与层级路径仅作证据，重名文件/列不得互相覆盖。
2. **A1.2** 当用户确认并 submit 时，系统应保留列索引、表类型、辅助列和确认来源，校验索引唯一性、范围及来源版本；worker 应执行同一合同，不得重新识别后覆盖确认或先跳过已确认的 unknown sheet。
3. **A1.3** 当读取旧表头字典时，系统应仅在列可唯一定位时无损转换；歧义、文件结构变化或合同不兼容应要求重新确认，不得回退为按表头覆盖的字典。

### A2 表头语义硬约束
作为导入人员，我希望系统区分年初、期初、本期、累计和借贷方向，而不是只按名称相似度猜测。
1. **A2.1** 当解析多级/合并表头时，系统应联合期间范围、余额/发生额和借/贷/净额语义约束字段；显式冲突不得被别名、列顺序或高分匹配覆盖。
2. **A2.2** 当子表头未知、语义缺失或候选冲突时，系统应展示原始位置、候选与原因并要求确认，不得赋予“精确匹配”置信或未经确认激活。
3. **A2.3** 当选择 adapter 时，系统应记录现有 identifier/adapter 载体内实际执行的规则版本和匹配证据；选中 ID 不代表别名已生效，外部语义未确认或未实现时只能显示通用识别/人工确认，不得伪称该适配器兼容。
4. **A2.4** 当字段之间存在互斥或成对关系时，系统应在映射确认阶段校验：期初净额与期初借/贷分列不得同时作为来源；借、贷分列必须成对出现；“单金额+方向”与借/贷两栏二选一。违反时阻止提交并指明冲突列，不得静默取其中一列。
5. **A2.5** 当列名仅靠子串或编辑距离命中（非精确同义词）时，系统应默认进入人工确认，不得按 50 分阈值自动采用；“会计科目”“余额”“金额”这类歧义词须结合表类型与相邻列判定，不能固定映射到会计期间、期初借方或借方发生额。
6. **A2.6** 当识别 SAP 等外部系统中文导出时，系统应在现有 `adapters/` 载体内支持经 0 审阅确认的字段（如总帐科目、过帐日期、凭证编号、本币金额、借/贷标识、反记帐）；未确认字段保持人工确认，不得仅凭文件名判定适配器生效。

### A3 年度与月度金额语义
作为审计人员，我希望年度金额不被月度字段覆盖，合法零值不被当作缺失。
1. **A3.1** 当来源同时含年初净额与月初净额时，系统应分别保存其语义和原值；年度 `year_opening_debit/credit`、`year_debit/credit` 的既有优先级应保留，0 必须是有效值。
2. **A3.2** 当年度字段缺失时，系统应只采用期间与目标相符的月度数据；不得把非年初月的期初冒称年初，不得拼接不同期间的借贷两侧，也不得因年度值非法而静默兜底。
3. **A3.3** 当净额、借贷分列或方向共存时，系统应沿用既有符号合同并校核一致性；缺值、显式零、非法值必须可区分，冲突保留来源并交人工处理。
4. **A3.4** 当余额表同时有方向列和带符号金额时，系统应区分方向列表示“科目方向”还是“金额方向”：科目方向+借正贷负金额时保留原符号、方向只作校核；金额方向时按方向定号。含义不能由列名和样本唯一判定时须人工确认，不得先取绝对值再按方向定号。
5. **A3.5** 当序时账只有单金额列加方向列（如“发生金额+发生额方向”“本币金额+借/贷标识 S/H”）时，系统应按方向把金额拆到借方或贷方栏；带符号单金额无方向列时按正借负贷拆分并记录依据；拆分后逐凭证校验借贷平衡，不平衡的凭证给出定位。

### A4 跨 sheet/file 期间归并
作为导入人员，我希望多个期间文件得到可解释的区间结果，而不是首行或累计值的错误相加。
1. **A4.1** 当归并余额时，系统应先按项目、年度、主体、币种、科目、辅助身份及期间范围分区，再按期间排序；跨 sheet/file/chunk 采用同一口径，禁止跨主体/币种或跨年混算。
2. **A4.2** 当覆盖目标区间时，系统应取首期期初、末期期末，对互不重叠的月发生额求和，对年累计仅取截止期值而不逐月求和；两种口径并存应对账，不得相加或将累计冒称任意子区间发生额。
3. **A4.3** 当出现重复期间、缺月、乱序、年度边界或来源冲突时，系统应列出覆盖范围、来源和取舍依据；无法证明完整性则保持待确认/阻断，不补零、不静默取首条；增量沿用既有 staged 合并与基准复验。

### A5 科目层级与父子选择
作为审计人员，我希望父子双计被排除，但父级直记金额不会丢失。
1. **A5.1** 当识别父子关系时，系统应优先使用显式父码/级次及科目表证据，再使用经验证的分段或编码前缀规则；无证据不得仅用字符串前缀判亲缘。
2. **A5.2** 当选择汇总行时，系统应在同主体、币种、期间与数据集内核对父子金额；父级直记残差必须展示并由人工决定保留残差、选定权威层或修正来源，未知关系不得静默删除/排除父行。
3. **A5.3** 当计算 TB 或最近祖先映射时，系统应扩展既有 `tb_balance_rollup.leaf_condition/resolved_standard_code` 的共同口径并隔离主体/币种；不得另造排重算法或简单替换为 `startswith`。
4. **A5.4** 当科目编码没有分隔符时，系统应允许在导入确认时录入或沿用项目级科目级次规则（如 `4-2-2-2`），并以该规则作为层级证据；规则与实际编码长度不符的科目列出待确认，不得只按编码总长度推断级次。

### A6 辅助、分录与 CSV
作为导入人员，我希望辅助拆分和文件格式差异不会改变原始金额与身份。
1. **A6.1** 当一行含多辅助维度或多种辅助视图时，系统应保留原行身份，各维度分别核对；主余额只计一次，禁止把不同维度投影重复加总或把相同金额当作重复证据。
2. **A6.2** 当分录金额、凭证号等相同时，系统应保留不同来源行；仅有明确来源身份且经确认的重复输入可排除，并保留排除证据，不得按金额/科目粗去重。
3. **A6.3** 当探测与解析 CSV/TSV 时，系统应消费同一编码、分隔符、引号、表头及起始行合同；文本科目/辅助码保留前导零，非空坏数及非有限数不得写为 0，错误须定位原文件/表/行/列。
4. **A6.4** 当余额表同一主体/币种/科目/辅助组合出现多条同期间行，或凭证表出现日期+类型+编号+科目+借贷金额+摘要完全相同的分录时，系统应在回执中列出重复项及所在行；余额重复须人工选择后才能激活，分录重复只提示不删除。

### A7 全量与增量激活校验
作为审计人员，我希望校验真实覆盖将要生效的数据，而不是因空查询或遗漏接线得到成功。
1. **A7.1** 当执行全量或增量导入时，系统应先做 L1，再对最终 staged 集合执行适用的 L2/L3 与业务校验；查询必须覆盖实际写入行，按主体/币种/期间对账，记录样本数和适用范围；缺表应明确未校验，不能声称跨表通过。
2. **A7.2** 当校验异常、应有数据却扫描为零、合同/来源冲突或必需检查未执行时，系统应 fail-closed，禁止激活；失败不得改变原 active 结果或让无 active 时的 staged 行提前可见。
3. **A7.3** 当请求 force 时，系统应保持现有项目权限、可豁免错误范围和留痕要求；L1、年度越界及合同不确定性不能靠新增豁免放行，A 不扩权、不扩大 force 范围。

### A8 生产链与可见结果
作为导入人员，我希望看到实际完成到哪一步，并能安全使用仍受支持的旧入口。
1. **A8.1** 当写入及激活时，系统应复用 staged/active、激活记录和 outbox；重试、取消及增量基准变化沿用现有机制，确认摘要须与实际写入来源和选择结果一致。
2. **A8.2** 当展示结果时，系统应区分 job 完成、dataset 激活、outbox 投递和下游最终状态；沿用 `validation_summary.auto_map` 等真实结果，低覆盖、失败或尚未反馈不得包装为全部成功。
3. **A8.3** 当 feature flag 切到 legacy 或用户使用旧入口时，系统应沿用该入口的支持/退役状态并证明合同可消费；不支持的新合同应在写入前要求重新确认，不得静默降级丢失语义。
4. **A8.4** 当用户需要整理客户导出的 Excel 时，系统应提供一份可下载的标准导入模板（科目余额表、序时账、辅助余额表、辅助明细表四页，列名为平台精确同义词，含必填说明与样例），用该模板填写的文件应被精确识别、无需人工改列名；模板不复制外部工具的宏或样式。

## 非功能与交付约束
- **N1 可追溯**：引用采用路径+符号；规则版本、确认决策及原始定位可追溯，用户可见原因使用中文，不额外留存未授权原始账套。
- **N2 有界资源**：保留流式解析；跨文件归并不得把全部分录载入内存，资源不足应报告失败或采用受控暂存，不能丢行后成功。
- **N3 验收真实性**：未来验收包含端点、真实生产调用链集成和独占服务 browser；测试数据只用明确标记的隔离合成账套，客户样本和真实部署另需授权。
- **N4 交付状态**：本轮规格与离线 Excel 交付不代表平台产品实现或验收完成；A 的实施任务全部保持未完成。
- **N5 范围外**：外币、数量、汇率、计量单位入库与外币审计；解析 IAS `.AUD` 数据包；财务软件直连与备份还原。三者均不在 A 内，有需要时另立 spec，且 `.AUD` 解包须先确认口令的使用授权。
