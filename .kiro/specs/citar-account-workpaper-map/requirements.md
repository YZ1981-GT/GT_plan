# 需求：底稿映射页增加「科目 → 税审底稿」页签

来源：用户 2026-11-03「底稿映射 - 标准科目编码和标准科目名称，应该是科目到底稿的映射」→ 三种改法中选第 3 种（一页两个页签）。
承接 `citar-pages-data-wiring` R7（该页原为客户科目 → 标准科目映射）与 `tax-workpaper-data-fetch`（税审底稿取数规则）。

## 现状
- 「客户科目 → 标准科目」映射存于 `account_mapping`，试算平衡表、审定报表、税审底稿取数都依赖它。
- 「科目 → 税审底稿」没有独立存储：取数规则（`tax_workpaper_model.json`，1,815 条）按一级科目名 + 明细名找客户科目，再填进底稿格子；36 张底稿带取数规则。

## R1 页签
- 底稿映射页分两个页签：「科目 → 底稿」（默认）、「客户科目 → 标准科目」（原内容原样保留，增删改不变）。
- 第二个页签有余额未映射的科目数显示在页签名上。
- 切换页签不丢第二个页签里未保存的输入。

## R2 「科目 → 底稿」（只读）
- 按本项目本年度账套列出客户科目：编码、名称（按层级缩进）、标准科目（编码 + 名称；未映射标「未映射」）、本期借方、本期贷方、期末余额、对应底稿。
- 对应底稿 = 取数规则实际用到该科目的底稿，口径与税审底稿取数**同一套执行代码**（不另写匹配逻辑）：
  - 需人工填写（manual）的规则不算；
  - 规则用到某科目时，该科目的上级、下级都算进入这张底稿（上级的数含下级，下级的数被上级合计取走）。
- 规则的一级科目指向本科目、但没取到数的底稿单独标出并给原因（如「主营业务成本」下没有「销售商品」明细）。
- 税审底稿目录里标为「无」的底稿不列出。
- 对应底稿显示编号 + 表名，点击打开该张税审底稿。
- 筛选：只看有余额或发生额的科目（默认开）、按底稿、按关键字（编码 / 名称 / 标准科目）；显示「有余额的 N 个科目中 M 个进入税审底稿」。
- 未导入科目余额表、未设置年度时给空态提示。

## R3 联动
- 在第二个页签保存 / 修改映射或自动匹配后，第一个页签重新读取。

## R4 约束
- 新接口只读：挂 `require_project_access("readonly")`，接口级测试覆盖有权限 200、无权限 403。
- 规则里出现的底稿编号必须都在前端底稿目录 `taxWorkpaperIndex.ts` 里（跨语言守卫）。
- eslint / stylelint / 单区域 vue-tsc 通过；浏览器实测两个页签读取、筛选、点底稿跳转。
