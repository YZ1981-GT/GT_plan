# 附件管理模块 · 使用手册

附件模块用于集中管理各审计项目的附件文件（合同、发票、银行回单、产权证、函证回函、支持性证据等），并提供 OCR 识别、底稿关联溯源与证据链治理能力。

---

## 一、模块总览

- **入口**：左侧导航「附件」→ 进入「附件管理」总览，卡片列出你有权限的全部项目。
- **进入项目附件**：点击任意项目卡片 → 进入该项目的附件列表页，进行上传、检索、预览、OCR、关联底稿等操作。
- **权限隔离**：仅显示你有权访问的项目；底稿关联也受可见性隔离约束，未授权的底稿不会出现在关联候选中。

---

## 二、上传附件

在项目附件列表页顶部，有三种上传方式：

| 方式 | 操作 | 说明 |
|------|------|------|
| 单/多文件 | 点「上传文件」选一个或多个 | 支持一次选多份 |
| 文件夹 | 点「上传文件夹」 | 连子目录一并上传 |
| 拖拽 | 把文件/文件夹拖到页面任意处 | 出现「释放文件以上传附件」遮罩即可松手 |

- **支持类型**：PDF / Word / Excel / PPT / 图片 / 文本 / 压缩包 / 邮件 / OFD / CAD。
- **单文件上限 50MB**；超限或不支持的类型会被拦截并提示。
- 上传过程有进度显示；系统会做文件安全校验（内容签名扫描、类型白名单），异常文件会被拒绝。

---

## 三、检索与统计

- **搜索**：顶部输入框按文件名搜索，回车执行。
- **类型筛选**：下拉按 PDF/Word/Excel/图片 等类型过滤。
- **统计卡**：总文件数、总大小、OCR 完成率、已关联底稿数，一眼掌握项目附件全貌。
- 列表每行显示文件类型图标、大小、上传时间；若已关联底稿，会显示 `📋 底稿编号` 溯源标签。

---

## 四、预览与下载

- **预览**：点文件名或行内「预览」按钮，在弹窗中查看（PDF/图片/Office 文档等）。
- **下载**：点行内「下载」按钮，按原始文件名（含中文）保存到本地。

---

## 五、OCR 识别

系统对可识别的附件（如 PDF、图片）自动排队 OCR，抽取文本与关键字段。

- **状态**：识别中 / 已完成 / 待确认 / 失败，列表实时刷新。
- **待确认**：OCR 完成后显示「🔍 待确认」，点它或「确认 OCR 结果」核对抽取内容 → 确认后方可作为后续引用依据。
- **失败重试**：状态为失败时，点「重试 OCR」重新识别。

> OCR 抽取结果是**辅助线索**，须人工确认后才采纳；系统不会未经确认就把 OCR 数字直接落库为审计结论。

---

## 六、关联底稿（溯源）

- 点行内「关联底稿」→ 搜索底稿编号或名称 → 关联，把附件挂到对应底稿作为支持性证据。
- 关联后列表显示 `📋 底稿编号` 标签，点它可直接**跳转到该底稿**。
- 一份附件可作为多份底稿的证据；底稿侧也能反向查看其关联附件。

---

## 七、证据链治理（进阶功能，按需使用）

> **先看这段**：日常审计只用附件页的三件事就够了——**上传 → 确认 OCR → 关联底稿**。
> 「证据链治理」是给**复核、质控、归档**阶段用的进阶工具，把附件从"一份文件"升级为"**经得起复核和监管检查的审计证据**"——保证每份证据「从哪来、被谁改过、被哪些结论引用、能不能篡改、能不能删、归档时对不对得上」全程可追溯。看不懂时可以先不管它，需要时再进来。

**入口**：附件页右上「证据链治理」按钮 → 进入治理中心，共 8 个页签。顶部会显示你的当前角色，很多操作按角色权限开放（如重试 OCR、清理等）。

### 8 个页签分别做什么

| 页签 | 一句话作用 | 什么时候用 | 主要操作 |
|------|-----------|-----------|---------|
| **证据关系** | 查一份证据被哪些底稿/结论引用，以及它一旦变动会「波及」哪些下游 | 换了/改了某份附件，想知道哪些底稿结论要复查 | 按来源或证据双向查引用、查「影响路径」、打开关系抽屉 |
| **OCR 治理** | 把 OCR 当正式任务全程留痕（提交→时间线→人工确认差异→写回） | 关键/批量附件的 OCR 要可追溯、要人工核对识别结果 | 提交任务、看状态时间线、加载字段确认后**写回**、失败重试（需权限） |
| **引用定位** | AI/RAG 用到的每处「引用」都存了快照（哪份证据·第几页·哪个区域·Hash·索引版本） | 想核对「这句结论的依据到底在哪份文件第几页」 | 加载引用、点「定位」跳回原文核对、批量校验；来源变了自动标 stale/失效 |
| **AI 门禁** | AI 生成的内容**必须人工确认才算数**，未确认/被改/依据失效的一律禁止进入正式输出 | 用了 AI 起草底稿结论/附注/报告，要把关后才采纳 | 查状态 → 确认 / 修订 / 拒绝；正式输出前 Preflight 检查、通过才 Finalize |
| **复核证据** | 复核意见绑定「当时看到的证据」并冻结版本；证据一失效，复核自动重开并**阻断完成** | QC / EQCR / 合伙人复核，确保结论基于当时的证据 | 检查阻断状态、加载复核、绑定证据、关闭 / 重开复核 |
| **归档清单** | 归档前清点全部证据（附件版本/证据/OCR/引用/AI/复核/stale 链）做门禁检查，通过才封存 | 项目收尾归档前 | 归档前置门禁 → 构建并封存 → 生成可**离线重算 Hash** 的封存包并验签 |
| **法定保全** | 给涉诉/监管要求保留的证据「上锁」，保全期间任何人（含管理员）都删不掉 | 有诉讼、监管调查等法律留存要求时 | 创建保全、看保护范围、解除；清理须满足**四条件**（已解除∧保留期届满∧已授权∧无引用） |
| **治理指标** | 一屏看证据治理整体是否健康（上传/OCR 排队失败/AI 覆盖/引用可定位/stale 账龄/门禁绕过/归档校验失败等） | 项目负责人/质控看全局健康度 | 加载指标（仅 admin / 经理 / 合伙人可见） |

### 几个反复出现的关键概念（看懂这几个就不慌）

- **人工确认硬门禁**：OCR 抽取、AI 生成都只是"线索"，**必须人工确认**后才能作为正式依据/进入报告——系统不会替你把机器结果当结论。
- **版本冻结 / 不可篡改**：证据一旦被引用/复核，会冻结当时的版本快照；换了新版本，旧引用会被标记「失效（stale）」提醒你复查。
- **stale（失效）传播**：上游证据变了，依赖它的下游（引用、复核、结论）自动被标"待复查"，不会悄悄用旧证据。
- **归档验签**：归档包可离线重新算一遍 Hash 校验，证明封存后没被动过。
- **法定保全**：上锁后连管理员都删不掉，满足法律/监管留存要求。

> 附件本身支持**版本管理**（替换生成新版本、可回滚）；删除为**软删除**并留审计痕迹，均可追溯。

## 八、安全与合规要点

- 单文件 ≤ 50MB，仅允许白名单文件类型。
- 上传做内容签名扫描（拦截可执行/恶意文件）与可读性校验。
- 文件访问经安全通道，列表/接口不暴露服务器真实存储路径。
- 项目与底稿双重可见性隔离：只能看到、操作有权限的资源。

---

## 九、常见问题

- **上传失败/被拒**：检查文件类型是否在支持范围、大小是否超 50MB、文件是否损坏。
- **OCR 一直识别中**：稍候列表会自动刷新；长时间未完成或失败可点「重试 OCR」。
- **关联不到底稿**：确认你对该底稿有访问权限；未授权的底稿不出现在候选中。
- **看不到某项目**：附件总览只展示你有权限的项目，权限由项目委派与角色决定。
