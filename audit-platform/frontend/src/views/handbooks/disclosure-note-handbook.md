# 附注模块 · 使用手册

附注模块负责把「账表导入 → 科目映射 → 试算表 → 报表 → 底稿 → 附注」这条链路上的审计结果，落成一份可交付、可复核、可追溯的财务报表附注。

**一句话理解**：附注里的**数字**主要来自底稿披露表与试算表，**文字**由模板骨架 + 人工编写 + AI 辅助产生。数字不要在附注里手改 —— 一旦某章节被标记为"由底稿驱动"，底稿推送就是唯一权威，你在附注里改的数字会在下次刷新时被覆盖。要改就回到底稿改。

**这份手册的读法**：第一次用附注模块 → 读第四章「标准操作流程」，照着做一遍；某个按钮不敢点 → 查第二章「功能键逐个说明」；数字不对 / 表格是空的 → 查第三章「数据从哪来」+ 第六章「排查决策树」。

## 一、顶部信息条与状态提示

### 1.1 信息条各项含义

| 区域 | 含义 | 你该做什么 |
| --- | --- | --- |
| 单位 / 年度 | 当前编辑的被审计单位与审计年度 | 切换后附注章节树会重新加载；年度切换时若该年度还没有附注，会自动触发一次「生成」 |
| 模板（上市版 / 国企版） | 决定附注章节结构与**章节号体系** | **切换模板会按新模板重新生成全部章节**，请在项目立项阶段确认好（见 5.5） |
| N 个章节 | 当前已生成的附注章节数 | 为 0 说明还没生成，先点「生成」 |
| 金额单位 | 附注展示单位，默认「元」 | 仅影响附注模块的**展示**，不改变底层数据，也不影响导出的数值口径 |
| ✓ 已更新 / 同步状态 | 当前章节的保存状态 | 编辑后 2 分钟会自动保存一次；也可手动保存 |

### 1.2 顶部横幅（按出现频率）

**① 链路进度条：导入 → 映射 → 试算表 → 报表 → 底稿 → 附注**

附注是链路最后一环。前面任一环没打勾，附注对应位置就会取不到数。**附注表格为空时，第一件事是回头看这条进度条，而不是在附注里手填数字。**

**② 「当前项目有 N 处数据过期」/「上游数据已变更（N 张底稿待重算）」**

底稿或试算表改动后，附注的数字就成了旧值。标准处置顺序：

1. 点横幅上的「一键重算」或「点击重算」（重算试算表 / 报表）
2. 回附注点「🔁 全部刷新」（把重算结果拉进附注）

> 重算后可能提示「仍有 N 张底稿正文已保存、重算不覆盖」—— 这类底稿需要你打开它、刷新、再保存一次，系统不会替你改已定稿的底稿正文。

**③ 「该项目尚有 N 段 AI 生成内容待确认」**

AI 产出的文字默认是 pending 状态，**不算定稿**。点「查看明细」逐条确认或退回。定稿交付前这里应该清零。

**④ 归档 / 合并锁定横幅**

项目已归档或处于合并锁定状态时，附注转为只读，所有写操作会被拦截。

## 二、功能键逐个说明

### 2.1 数据操作组（🔄 刷新 / 🔁 全部刷新 / 📝 生成 / ✅ 校验）

| 按钮 | 作用范围 | 内部实际做了什么 |
| --- | --- | --- |
| 🔄 **刷新** | **仅当前打开的章节** | ① 向后端打一次「底稿→附注」同步标记（只标当前节）；② 重算这一个章节；③ 重新载入当前节 |
| 🔁 **全部刷新** | **全部有映射的章节** | ① 对全部有底稿映射的章节打同步标记；② 项目级重算所有映射章节；③ **清空全部章节的前端缓存**；④ 重拉章节树；⑤ 重载当前节 |
| 📝 **生成** | 全部章节 | 按当前模板铺出整套章节骨架（百余节）。**生成前会先打一次同步标记**，因此已由底稿驱动的章节不会被骨架覆盖 |
| ✅ **校验** | 全部章节 | 跑 11 类校验规则，结果写入右侧「校验结果」面板，并刷新左树状态圆点 |

**为什么要区分「刷新」和「全部刷新」**

「刷新」只重载当前节，速度快；但如果你在底稿改了好几张表，其它章节的前端缓存还是旧的，会出现「数据库里已经是新值、界面上还是旧值」的错觉。**改动涉及多张底稿、或看到上游变更横幅时，一律用「全部刷新」**（它会清空全部缓存）。

**刷新后的提示怎么读**

| 提示 | 含义 | 是否需要处理 |
| --- | --- | --- |
| 已刷新 N 个单元格 | 有 N 个格子的数字被上游更新 | 正常 |
| 以下章节需手动重填：… | 这些章节是**纯文字型**，没有可自动取数的表格 | 需人工编写，不是错误 |
| 数据已是最新，无需刷新 | 上游确实没变化 | 正常，**不是失败** |
| M 个章节取数失败：… | 上游缺数据或映射异常 | 按提示的章节名去查对应底稿 |

**「生成」的两个前置确认**

系统在点「生成」时会弹确认框，提示三件事：模板类型是否正确、是否已完成报表生成、是否已把上年附注上传到知识库（供 AI 参照）。这三条都不是硬拦截，但建议按提示确认。

### 2.2 编辑组（➕ 新增 / 📐 表样）

| 按钮 | 用途 | 注意 |
| --- | --- | --- |
| ➕ **新增** | 新增一个自定义附注章节（模板里没有、但本项目需要披露的事项） | 自定义章节没有底稿映射，数字需人工录入或配公式 |
| 📐 **表样** | 编辑当前章节表格的结构（行、列、表头层级） | 改表样属**结构变更**，会影响该表与底稿推送的列对应关系。底稿驱动的章节尽量不要动表样 |

> 章节删除后不会立即消失，可在「已删除」列表里恢复。

### 2.3 版本与口径组（🗂️ 版本 / 📅 上年 / 单体 / 合并）

| 按钮 | 用途 |
| --- | --- |
| 🗂️ **版本** | 查看当前章节历史版本，可对比、回溯 |
| 📅 **上年** | 与上年同章节对比，检查同比波动与列示口径是否延续 |
| **单体** | 切换为单体（母公司）报表附注口径，章节序号自动重算 |
| **合并** | 切换为合并报表附注口径，章节序号自动重算 |

> 单体与合并的章节号体系不同，切换后序号自动按该口径重排，**不需要手工改编号**。

### 2.4 🤖 AI 助手

| 菜单项 | 用途 | 边界 |
| --- | --- | --- |
| 📚 **批量预填充（空/草稿章节）** | 对还没写内容的章节批量生成文字初稿 | 生成结果按章节列在结果弹窗里，**逐章点进去确认采纳**才写入 |
| 💬 **AI 对话** | 就当前附注内容与 AI 讨论、改写 | 采纳需走确认流 |
| 🧠 **AI 智能建议** | 给出披露完整性、措辞方面的建议 | 建议性质，不自动改内容 |

**AI 的三条硬边界**

1. **AI 只碰文字，不碰金额** —— 不产生也不修改任何数字
2. **AI 产出一律进入待确认状态** —— 顶部有待确认数量横幅，未确认不作为定稿
3. **AI 不编造** —— 取不到依据的地方会留「待补充」，不会替你想一个数或一段事实

批量预填充结果弹窗里有三种状态：**已生成**（有初稿可采纳）、**降级**（依据不足，只给了框架）、**跳过**（该章节已有内容，不覆盖）。

### 2.5 ⚙️ 公式管理

配置附注表格的取数公式 —— 即「某个格子的数从哪里来」。可用的取数函数：

| 函数 | 取什么 | 示例 |
| --- | --- | --- |
| `TB(科目码, 列)` | 试算表单科目金额 | `TB('1601','期末余额')` |
| `REPORT(报表行码, 期间)` | 报表行金额 | 引用资产负债表某一行 |
| `NOTE(章节, 字段, 列)` | 其它附注章节的数 | 跨章节引用 |
| `WP(底稿码, 列)` | 底稿数据（列名或单元格地址） | `WP('D1','B5')` |
| `AUX(科目, 维度, 列)` | 辅助核算余额 | 按客户/供应商等维度取数 |
| `PREV(...)` | 上年同期数 | `PREV(TB('1002','期末余额'))` |
| `ROW(行码)` | 本表其它行 | 小计 = 各明细行之和 |

**改公式后必须点「刷新」或「全部刷新」才会重新求值** —— 公式本身不会自动触发计算。

> 附注公式是**项目级灰度开关**控制的功能。若你的项目没有开启，公式配置不会参与求值；是否开启由经理及以上角色设置。

### 2.6 单元格级溯源（右键 / 点格子查看）

附注表格里由公式或底稿推来的数字，可以逐格追溯，会告诉你四件事：

1. **binding（绑定）** —— 这个格子绑的是哪个数据源、哪些科目码、什么聚合方式
2. **展开后的公式** —— 例如 `=SUM(TB('1601','audited_amount'), TB('1602','audited_amount'))`
3. **算出来的值**
4. **命中的原始数据行采样** —— 试算表行 / 序时账 / 辅助余额，用于核对

如果提示「无绑定」，说明该格是人工录入或纯骨架，没有自动取数来源。**这是附注复核最有力的工具** —— 复核时对某个数字有疑问，先看溯源，而不是先问编制人。

### 2.7 手动 / 自动模式切换

单元格有两种模式：

- **auto（自动）** —— 由公式或底稿推数维护，刷新时会被更新
- **manual（手动）** —— 人工接管，刷新不覆盖

两个开关：

| 操作 | 效果 | 用在什么时候 |
| --- | --- | --- |
| **清除自动公式** | 把该章节所有 auto 格切成 manual，**数值保持不变** | 该章节的自动取数口径不对，你决定人工接管 |
| **恢复自动提数** | 从底稿重新提数，manual 格恢复为 auto | 上游修好了，想把控制权交还给系统 |

> 这是「附注里改了数字被刷回去」的正规解法：要么回底稿改（推荐），要么显式切成 manual 接管（口径特殊时）。**不要靠反复手改跟刷新对抗。**

### 2.8 📤 导入导出

| 菜单项 | 用途 | 适用场景 |
| --- | --- | --- |
| 📤 **导出 Word** | 导出正式附注文档（.docx） | 交付、内部复核 |
| 🖨️ **打印预览** | 预览排版效果 | 定稿前检查 |
| 📥 **Excel 导入** | 导入**外部** Excel 附注数据（通用格式） | 客户提供的附注底表 |
| 📦 **离线导出** | 导出**系统格式**的离线编辑包 | 现场无网络、或需要他人协助填写 |
| 📥 **离线导入** | 把离线包填好后导回系统 | 与「离线导出」配对，**只能导回本系统导出的包** |

**两种导入不能互换**：Excel 导入吃的是外部通用格式；离线包是系统自己的格式，带章节标识与结构信息。拿外部 Excel 走离线导入会失败。

**导出 Word 前建议先跑一遍**：✅ 校验 → 📋 就绪度 → 🖨️ 打印预览。

### 2.9 更多（段落变量 / 集团基线）

| 菜单项 | 用途 |
| --- | --- |
| ✏️ **段落变量** | 维护附注文字里的占位变量（单位名称、年度等），导出时统一替换，避免逐节手改 |
| 🏢 **集团基线** | 应用 / 保存 / 对比集团统一的附注章节结构，保证集团内各子企业附注章节一致 |

集团基线的典型用法：在母公司项目上把附注结构调好 → 「保存基线」→ 在各子企业项目上「应用基线」，各子企业章节结构即对齐；「对比」用于检查某个子企业是否偏离了集团口径。

### 2.10 模板与转换

| 按钮 | 用途 |
| --- | --- |
| 💾 **保存为模板** | 把当前项目的附注结构存为可复用模板 |
| 📋 **引用模板** | 套用已有模板结构到当前项目 |
| 🔄 **国企↔上市转换** | **查看**国企版与上市版附注章节的对应规则 |

> 「国企↔上市转换」是**规则查阅**入口，不是一键换体系的开关。真要更换项目的附注体系，走顶部「模板」下拉切换 + 重新「生成」，并按 5.5 的注意事项操作。

### 2.11 📋 就绪度

一张体检表，集中回答三个问题：

| 分类 | 判定依据 | 含义 |
| --- | --- | --- |
| **从未从底稿同步** | 该章节有底稿映射，但从未被标记为底稿驱动 | 数字可能还是空骨架 —— **最需要关注的一类** |
| **没有数据** | 章节内容判定为空 | 要么还没编制，要么确实不适用 |
| **有校验问题 / 上游已变更** | 有 error/warning 级校验发现，或被标记 stale | 按明细逐项处理 |

按钮上的红色角标是待处理项数量。就绪度列表可直接跳转到对应的底稿披露页。

**定稿前应把就绪度清干净** —— 确实不适用的章节，用「本期无此情形」之类的说明写清，而不是留空。

### 2.12 其他

- ↗ **全屏** — 沉浸式编辑，ESC 退出
- 📋 **只读副本** — EQCR 角色标识，该角色仅可查看与复核，不可修改数据
- **左树筛选** — 全部 / 未编制 / 校验异常 / 待补充，配合搜索框快速定位

## 三、附注的数据是从哪来的

按权威性从高到低。**同一个格子被多个来源覆盖时，上面的赢。**

### ① 底稿披露表（数字的主要来源，最高权威）

各审计循环底稿里都有「附注披露信息」页（上市版 / 国企版）。审计人员在底稿上编制完，数据推送到对应附注章节的表格。

**关键机制 —— 「底稿驱动」标记**

一旦某章节被标记为由底稿驱动：

- 附注模板骨架**不再与它合并** —— 底稿推来的表就是该章节的表
- 附注侧刷新时**跳过表格覆盖** —— 不会用骨架把底稿数据冲掉
- 你在附注里手改这些数字，下次刷新会被上游覆盖

**所以：数字有误请回到底稿改，不要在附注改。** 确实需要在附注层接管的，用 2.7 的「清除自动公式」显式切 manual。

**同步是双向可触发的**：

- 底稿侧：在披露页录入后推送（底稿披露页顶部有状态条，显示「是否已同步到附注、上次同步时间」）
- 附注侧：点「🔄 刷新 / 🔁 全部刷新」主动拉取

### ② 附注取数公式（试算表 / 报表 / 上年数）

对没有底稿披露表承载的表格，用「公式管理」配置的规则取数，可引用试算表科目余额（审定数 / 未审数）、报表行金额、其它附注章节、底稿单元格、辅助核算维度、上年同期数（函数清单见 2.5）。

### ③ 附注模板骨架

上市版 / 国企版模板提供章节结构、表格行列、表头与编制说明。「生成」按钮铺的就是这层骨架 —— 它是**结构**，不是数据。

### ④ 人工录入与外部导入

Excel 导入、离线包导入、以及在附注里直接编辑的文字与自定义章节。

### ⑤ AI 辅助文字

仅文字，且需人工确认采纳（边界见 2.4）。

> **报表与附注的关系是"只校验、不写值"** —— 报表不会把数字写进附注，两者的勾稽关系由校验规则检查。所以看到「报表↔附注勾稽不一致」时，要去查两边各自的取数源，而不是等报表把数推过来。

## 四、标准操作流程

### 4.1 首次编制（新项目）

1. **确认前置** —— 顶部链路进度条中「试算表 / 报表 / 底稿」已完成；模板类型（上市 / 国企）已确认
2. **生成骨架** —— 点「📝 生成」，铺出整套附注章节
3. **编制底稿披露表** —— 在各循环底稿的「附注披露信息」页录入披露数据。**这是附注数字的源头，也是整个流程里工作量最大的一步**
4. **拉取数据** —— 回附注点「🔁 全部刷新」
5. **配置剩余取数** —— 对没有底稿承载的表格，用「⚙️ 公式管理」配公式，再刷新
6. **补充文字** —— 逐章编写文字说明；可用「🤖 AI 助手」生成初稿后**逐条确认采纳**
7. **校验与体检** —— 「✅ 校验」处理右侧问题清单；「📋 就绪度」把未同步 / 无数据 / 有问题的章节清干净
8. **定稿交付** —— 「📅 上年」比对同比合理性 → 确认 AI 待确认横幅已清零 → 「🖨️ 打印预览」检查排版 → 「📤 导出 Word」

### 4.2 底稿改动后的增量更新

1. 看顶部是否有「数据过期 / 上游已变更」横幅 → 有则先「一键重算」
2. 只改了一张底稿、只关心对应那一节 → 打开该节点「🔄 刷新」
3. 改动涉及多张底稿 → 点「🔁 全部刷新」
4. 重新「✅ 校验」，看新增问题

### 4.3 复核视角

1. 「📋 就绪度」先看整体成色：从未同步 / 无数据 / 有校验问题各多少
2. 「✅ 校验」看勾稽是否成立，逐条处理 error 级
3. 对有疑问的数字用**单元格溯源**（2.6）追到试算表行 / 底稿单元格
4. 「📅 上年」看同比波动是否有合理解释
5. 确认 AI 待确认内容已清零 —— 未确认的 AI 文字不算定稿
6. 校验发现确认无需修改的，用「确认」功能留痕并写明理由，而不是放着不管

---

## 五、校验规则详解

点「✅ 校验」会跑 11 类规则，规则来自附注校验公式预设（按上市版 / 国企版分别加载）。

### 5.1 规则类型

| 类型 | 检查什么 | 典型场景 |
| --- | --- | --- |
| **余额** | 报表金额 = 附注表合计 | 报表「应收票据期末」= 附注分类表合计行 |
| **其中项** | 各明细行之和 = 合计行 | 「其中：」明细加总是否等于上级行 |
| **宽表** | 横向加总是否成立 | 一行内各列相加 = 该行合计列 |
| **纵向** | 纵向结转是否成立 | 期初 + 本期增减 = 期末 |
| **交叉** | 两张表之间的对应数是否一致 | 同一数字在两张附注表都出现时 |
| **跨科目** | 不同科目间的勾稽 | 关联科目金额关系 |
| **二级明细** | 二级明细与上级是否吻合 | 分类下再分类 |
| **完整性** | 该披露的科目是否都有对应章节 | 试算表有余额但附注没披露 |
| **账龄衔接** | 本年账龄与上年是否衔接 | 上年 1 年以内 → 本年应进入 1-2 年 |
| **LLM 审核** | 文字是否有占位符残留、数字与表格是否矛盾、表述是否空泛 | 定性披露的合理性 |
| **描述** | 不参与数值校验，仅作章节说明 | — |

**规则互斥**：「余额」不与「其中项」/「宽表」同时生效 —— 同一章节同时配了这些规则时，系统保留更具体的那个（其中项 / 宽表），并在日志里记录。

### 5.2 严重度怎么判

| 严重度 | 判定 | 处理要求 |
| --- | --- | --- |
| **error** | 差异金额绝对值 > 0.01 元 | 必须处理或确认 |
| **warning** | 无金额差异（含全部 LLM 审核提示） | 评估后决定 |

**容差按金额规模动态放宽**：小金额（< 1 万）保持 0.01 元；大金额按规模适度放宽，避免「1000 万差 1 元」被误判为不平衡。

### 5.3 LLM 审核是提示，不是判定

LLM 审核产出的都是 warning 级，明确标注为「AI 合理性提示（非权威，仅供参考，未改动任何附注数据）」。它取不到结果或异常时会静默跳过，不会误报、也不会阻断其它规则。**不要把 LLM 提示当成必改项，也不要因为它没报就认为文字没问题。**

### 5.4 校验发现的处置

- **真有问题** → 回上游改（底稿 / 试算表 / 公式），再重新校验
- **口径特殊、确实不需要改** → 用「确认」功能标为「已确认-无需修改」并**写明理由**，留痕供复核

### 5.5 切换模板（上市↔国企）注意事项

切换会按新模板重新生成章节结构，两套体系的章节号与部分表结构并不一一对应。建议：

1. 尽量在**立项阶段**确认模板类型
2. 确需切换时，先「📦 离线导出」留一份备份
3. 切换后用「🔄 国企↔上市转换」查对应规则，逐章核对内容是否落到了正确位置
4. 重新跑「✅ 校验」+「📋 就绪度」

## 六、排查决策树

### 附注表格是空的

1. 顶部链路进度条上游（试算表 / 报表 / 底稿）是否都已完成？→ 缺环先补上游
2. 对应底稿的「附注披露信息」页是否已编制？→ 没编制就去编制
3. 是否点过「🔁 全部刷新」？→ 没点就点一次
4. 打开「📋 就绪度」，该章节是否被标为「从未同步」？→ 是则说明底稿侧还没推过来
5. 该章节是否本就是纯文字型？→ 是则需人工编写，刷新提示里会列出这类章节

### 我在附注里改了数字，刷新后被改回去了

预期行为 —— 该章节由底稿驱动，底稿是唯一权威。两个正规解法：

- **回底稿改**（推荐）
- 口径特殊必须在附注层接管 → 用「清除自动公式」把该章节切成 manual，之后刷新不再覆盖

### 数字对不上，不知道这个格子的数从哪来

用**单元格溯源**（2.6）：能看到绑定的数据源、展开后的公式、算出的值、命中的原始数据行。这是最快的定位手段。

### 校验一直报不平衡，但我核对过金额是对的

1. 看差异金额 —— 是否在容差范围内（小额 0.01 元、大额动态放宽）
2. 看是不是同一章节配了互斥规则（余额 vs 其中项/宽表）
3. 用溯源确认两边取数口径是否一致（审定数 vs 未审数、期末 vs 期初）
4. 确实是口径差异 → 用「确认」留痕说明

### AI 生成的内容没进附注

AI 产出需人工确认采纳。看顶部「AI 生成内容待确认」横幅 → 「查看明细」 → 逐条确认或退回。

### 公式配了但没生效

1. 配完公式后是否点过「刷新 / 全部刷新」？公式不会自动求值
2. 该格是否已被切成 manual？manual 格不吃公式
3. 项目是否开启了附注公式灰度开关？未开启时公式不参与求值

### 刷新提示「M 个章节取数失败」

按提示的章节名去查对应底稿：底稿是否存在、披露页是否编制、映射的科目是否有余额。取数失败通常是上游缺数据，不是附注模块故障。

## 七、几条硬规矩

1. **数字在底稿改，文字在附注写** —— 这是整个模块的设计前提
2. **AI 只碰文字，且必须人工确认** —— 未确认的 AI 内容不算定稿
3. **改公式后必须刷新** —— 公式不会自动求值
4. **定稿前就绪度清零、AI 待确认清零、error 级校验处理完或留痕确认**
5. **模板类型在立项阶段定好** —— 中途切换代价高
6. **对数字有疑问先看溯源** —— 比问人快，也是复核留痕的一部分
