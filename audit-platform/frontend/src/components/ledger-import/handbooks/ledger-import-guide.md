# 账套导入使用文档

账套导入把被审计单位的原始账套文件（余额表 / 序时账 / 辅助账 / 科目表）转成平台标准的**四张底表**，供试算表、报表、底稿、序时账穿透全链路使用。整个过程分四步：**上传 → 识别预检 → 列映射 → 导入入库**，页面顶部步骤条实时指示当前所处阶段。

> 全程无需 Excel 手工整理：系统自动识别表类型和列含义，你只需核对与补全「列映射」这一步。

---

## 一、上传（Step 1）

把账套文件拖到上传区，或点「选择文件」。若拖拽区点击无反应（个别浏览器），用下方「选择文件」按钮兜底。

- **支持格式**：`.xlsx` / `.xlsm` / `.csv` / `.tsv` / `.zip`，单文件最大 **1GB**。
- **多文件**：可一次选多个文件，也可上传 `.zip` 压缩包（系统自动解包内部所有表）。
- **耗时预估**：选好文件后会按总大小估算「上传 + 处理」耗时；总大小超过 **50MB** 视为大文件，会提示建议使用「放到后台继续」。
- **点「开始预检」**：文件上传到服务器并进入识别阶段。大文件识别较慢，首屏 3-5 秒无响应属正常。

> 注意：同一项目、同一年度若已有**进行中**的导入作业，新的导入会被阻塞——请等上一个作业结束或取消后再传。

---

## 二、识别预检（Step 2）

系统读取文件内容，自动识别**年度**、**每个 Sheet 的表类型**和**列含义**，供你核对。

### 顶部信息

- **识别年度 + 置信度**：从文件内容/表头/文件名推断的会计年度。置信度低于 60% 时，确认时会弹出「年度冲突警告」让你复核，也可在提交时手动修改。
- **规模档位（S / M / L / XL）** 与 **预计耗时**：按数据行数估算，帮助你判断是否放后台。
- **规模警告横幅**：数据规模异常时提示，可点「强制继续」忽略后继续。

### Sheet 识别表

每行是一个待导入的 Sheet，逐列核对：

| 列 | 含义 |
|----|------|
| 文件 / Sheet | 来源文件名与工作表名 |
| **识别类型** | 下拉可改：余额表 / 序时账 / 辅助余额 / 辅助明细 / 科目表 / 未知 |
| 置信度 | ≥80% 高（绿）、60-79% 中（黄，建议人工确认）、<60% 低（红，需手动指定） |
| **关键列覆盖** | 该表必需的关键列识别了几列（如 `5/5 已识别` 或 `缺失`） |
| 行数 | 估算数据行数 |
| 状态 | 未识别的 Sheet 显示灰底 + 跳过原因（行数太少 / 表头无法识别 / 列内容不符） |
| 预览 | 查看该 Sheet 前 20 行原始数据 |

- **手动纠正**：识别错的类型可直接在下拉框改（改后标记为「手动指定」）。
- **未知类型的 Sheet 会被自动排除**，不参与导入（例如说明页、封面页）。
- 点「确认并继续」进入列映射。

---

## 三、列映射（Step 3）★ 核心人工核对步骤

系统已按**映射规则**把原始表头自动对到平台标准字段，你在这一步核对、补全、纠正。顶部按 Sheet 分页（tabs），逐个 Sheet 处理。列按重要性分三档：

### 🔴 关键列（必填）

导入所必需的列（如 科目编码、期末余额、发生额等）。**关键列未全部映射，无法点「确认映射并导入」**，缺失列会红色高亮并在顶部列出。

每行展示：`原始列名 → 标准字段下拉（可搜索/可清空）+ 置信度% + 样本值`。

### 🟡 次关键列（推荐，可折叠）

有价值但非硬性必需的列（如 期初余额、月度发生额、辅助维度等）。建议映射以获得更完整的数据，缺失不阻断导入。

### ⚪ 非关键列（折叠）

未识别为标准字段的列，**原样保留到 `raw_extra` 字段**——不丢弃。这些列（如 ERP 的审核人、过账人、凭证状态等）导入后可在「查账 / 序时账穿透」页作为额外列查看。

### 映射辅助功能

- **样本值**：每个原始列旁显示前几行实际取值，帮助判断该列真实含义。
- **字段唯一性**：一个标准字段只能被一个原始列占用，已占用的字段在其它下拉中禁选，避免重复映射。
- **历史映射自动应用**：同结构的表曾映射过，会自动套用并标「🕒 上次映射」；可点「应用全部历史映射」一键套用。
- **从其他项目导入映射**：选择一个参考项目，复用其列映射规则（适合集团内多主体同一套 ERP 导出格式）。

### 映射规则从哪来

识别与映射基于平台内置的**列别名规则库**（表头文字 → 标准字段），叠加**列内容特征**、**Sheet 名信号**与**负向信号**综合打分。规则库覆盖常见 ERP（用友 / 金蝶等）导出的表头写法；识别不准时，人工在此步纠正即可，系统会把你的选择记为历史映射供下次复用。

### 每种表必须有哪些列（关键列清单）

不同表类型的**关键列（必填）**不同——下表列出各类型的关键列与推荐列。上传的原始账套里必须能对应上关键列，否则该表无法导入。

| 表类型 | 🔴 关键列（必须映射，缺一不可导入） | 🟡 推荐列（有则更完整） |
|--------|------------------------------------|------------------------|
| **余额表** | 科目编码、年初借方、年初贷方、本年累计借方、本年累计贷方、期末余额 | 科目名称、期初/本期借贷（月度口径）、期末借/贷、年初余额 |
| **序时账** | 凭证日期、科目编码、借方金额、贷方金额 | 凭证号、摘要、科目名称、对方科目 |
| **辅助余额** | 科目编码、辅助类型（核算维度）、期末余额 | 科目名称、辅助编码、辅助名称、期初/借方/贷方 |
| **辅助明细** | 凭证日期、科目编码、辅助类型、借方金额、贷方金额 | 凭证号、摘要、科目名称、辅助编码、辅助名称 |
| **科目表** | 科目编码、科目名称 | 科目全名、科目级次、借贷方向、是否明细科目 |

> 关键列若原始表没有对应列（如余额表缺「本年累计」），可能是导出口径不同——先在识别预检的「预览」核对原始表头，再在列映射把最接近的列对上；实在没有的关键列，需回原系统重新导出。

### 关键列判定逻辑

- **KEY（关键列）= 硬门槛**：前端「确认映射并导入」按钮受 `allKeyColumnsMapped` 控制，关键列没全部映射就点不动；后端提交时还有一道 SubmitGate 兜底校验，双层保证。
- **RECOMMENDED（次关键列）= 软提示**：不映射也能导入，只是数据不完整（如缺期初余额则无法做期初+发生−期末的滚存勾稽）。
- **OPTIONAL（非关键列）= 全保留**：不识别为标准字段的列一律进 `raw_extra`，不丢弃。
- **替代组（一列顶一个必填）**：有些关键列可由**组合列替代**——例如「期末余额」缺失时，若同时有「期末借方 + 期末贷方」，系统按借正贷负合成期末净额，视为已满足；余额表的「年初余额」也可由「年初借方 + 年初贷方」替代。单个分列（只有借或只有贷）仅用于识别打分，不单独顶替必填。
- **借贷方向符号**：金额列区分借/贷方向，落库按「资产借正贷负、负债权益贷正借负」归一，方向来自 `direction` 列或借贷分列，勿把无符号绝对值当有符号净额。

### 余额表列语义（重要）

余额表存在两套口径，请对照原始表头如实映射，不要混淆：

- **年度口径（年度审计常用）**：年初借/贷、本年累计借/贷、期末借/贷 —— 这些是关键列。
- **月度口径**：期初借/贷、本期借/贷 —— 属推荐列（按月导出时使用）。

系统落库取数时**优先年度口径**（年初余额、本年累计发生额），月度口径作兜底，确保损益类科目取到的是全年发生额而非单月。

## 四、导入入库（Step 4）

点「确认映射并导入」后，作业提交到后台执行，页面显示五段进度：**上传 → 解析 → 校验 → 写入 → 激活**（SSE 实时推送）。

- **解析**：按列映射把原始行转成结构化记录。
- **校验**：借贷平衡、方向、必填字段等校验；损益类科目期末结转后 opening/closing 为空属正常。
- **写入**：落库为四张底表（见下）。
- **激活**：把本次数据集（dataset）标记为 `active`，旧数据集变为 `superseded`。

### 过程中的操作

- **放到后台继续**：进入「写入」阶段后可用。关闭 SSE 但**后端继续跑**，顶栏「导入中」指示器可追踪进度——适合大文件先去做别的工作。关闭或切走页面**不会中断**导入。
- **取消导入**：清理本次 staged（暂存）数据，**不影响已激活的历史数据集**。
- 完成后自动跳转到「查账」页。

> 数据集版本治理：每次导入产生一个新 dataset，经 `staged`（暂存）→ `active`（生效）→ `superseded`（被替代）流转。**重新导入同年度会产生新的 active 数据集，旧的被替代**；请勿在完成前重复提交相同文件。

## 五、四表落库对应关系

| 识别类型 | 落库表 | 用途 |
|----------|--------|------|
| 余额表 | `tb_balance` | 各科目期初/发生/期末，试算表与报表取数源头 |
| 序时账 | `tb_ledger` | 凭证级明细，损益类发生额、序时账穿透、抽凭 |
| 辅助余额 | `tb_aux_balance` | 往来单位/项目/部门等辅助维度余额 |
| 辅助明细 | 序时账（辅助维度） | 辅助维度的凭证明细 |
| 科目表 | `account_chart`（客户科目） | 被审计单位科目体系，供科目映射 |

非关键列统一进各表的 `raw_extra`（JSONB），不丢弃、可在查账页显示为额外列。

## 六、表账凭证三级跳（穿透与回溯）

导入的四表不是孤立的——它们按「表 → 账 → 凭证」三级层层钻取，构成审计穿透（reperformance）与回溯（vouching）的证据链。这是账套导入的核心价值：从一个报表数字一路点到原始记账凭证。

### 主链：表 → 账 → 凭证

1. **表（余额层）** —— 报表科目 / 试算表 / 科目余额（源自 `tb_balance`）。看到某科目期末余额或发生额。
2. **账（序时层）** —— 点科目下钻到该科目的**序时账明细**（源自 `tb_ledger`），逐笔凭证级的借贷发生，回答"这个余额由哪些业务累计而来"。
3. **凭证（原始层）** —— 点某一笔分录下钻到该**记账凭证的完整分录**（借贷全貌 + 摘要 + 对方科目），回答"这笔账对应哪张凭证、借贷是否成对"。

### 辅助链（并行三级）

带往来单位/项目/部门等辅助核算的科目，走辅助维度的三级：

**科目 → 辅助余额（按维度，源自 `tb_aux_balance`）→ 辅助明细账（该维度的凭证明细）**

例如应收账款：科目余额 → 按客户拆分的辅助余额 → 某客户的逐笔明细 → 记账凭证。

### 双向使用

- **向下穿透（自上而下）**：报表数 → 序时账 → 凭证，验证余额的构成与真实性。
- **向上回溯 / 抽凭（自下而上）**：在序时账里按条件抽取样本凭证，或把凭证「挂到底稿」（记入 `sampled_vouchers`，供底稿的凭证检查表复用），完成 vouching。

> 三级跳依赖导入质量：**关键列齐全**（尤其序时账的凭证日期/科目/借贷、辅助表的辅助类型）才能正确逐级钻取；非关键列（审核人/过账人/凭证状态等）随 `raw_extra` 保留，钻到明细时可作额外列查看，辅助职责分离等分析。

## 七、导入之后会自动发生什么

入库激活后，平台**自动**串起后续链路（无需手工触发）：

1. **科目映射**：把客户原始科目自动匹配到 CAS 标准科目（客户科目表不足时从余额表识别生成、标准科目按变体加载）。
2. **试算表生成**：按科目映射聚合余额表，生成 `trial_balance`（未审/审定），带借贷方向符号。
3. **报表映射就绪**：报表模块「一键预设」按项目变体（国企 / 上市，单体 / 合并）映射科目到报表行。

若「报表映射一键预设」只映射出个别科目，多半是科目映射尚未完成——去「科目映射」页点「自动匹配」即可自愈。

## 七、常见问题

- **上方拖拽区点击无反应？** 用下方「选择文件」按钮（原生文件选择兜底）。
- **识别类型错了？** 在识别预检表的「识别类型」下拉直接改，未知的 Sheet 会被排除。
- **确认按钮点不动？** 关键列未全部映射——按顶部红色提示补全缺失的关键列。
- **导入很慢 / 想干别的？** 到「写入」阶段后点「放到后台继续」，顶栏指示器追踪进度。
- **重复导入了同一年度？** 旧数据集被替代（superseded），以最新 active 为准；如担心累加，导入前确认无进行中的同年度作业。
- **额外的 ERP 列去哪了？** 未映射为标准字段的列进了 `raw_extra`，在「查账 / 序时账穿透」页作为额外列可见，不会丢失。
